# M114 lane 0 contracts

`muse.tokens.json` is the only editable source. It uses DTCG `$type`,
`$value` and `{group.token}` aliases. `org.muse-spark-code` extensions name
CSS variables, VS Code variables, four palette overrides and computed CSS
values. `version: 1` is the consumer contract version. No font, stylesheet or
palette is downloaded at runtime.

Run `npm run build:tokens` after a source change, then `npm run check:tokens`.
The check compares all generated bytes and checks every registered use in
light, dark, high contrast light and high contrast dark. Text requires 4.5:1;
large text and UI require 3:1. Alpha backgrounds must name their opaque canvas.
Every colour must have a registered contrast use or appear in the source's
explicit `decorativeColours` list. Decorative marks, effects and disabled
content do not claim text contrast. The initial palettes have 89 pairs,
checked in all four modes.

| Output                                   | Consumer                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `src/webview/tokens.css`                 | The panel, Tasks and What's New: semantic roles, scales and existing layout aliases; CSS only                         |
| `design/tokens/generated/host-roles.css` | Extended VS Code roles for native/editor component migration; import alongside `tokens.css` when these roles are used |
| `design/tokens/generated/muse.css`       | Companion, node and desktop web pages; set `data-ms-theme` to `light`, `dark`, `hc-light` or `hc-dark`                |
| `design/tokens/generated/consumers.json` | TH's QML/Rust/Hyprland/icon/boot generators, TD's true-colour/indexed/monochrome tiers and the native mapping         |

Every entry of `consumers.json.modes[mode][group.token]` contains `type`,
resolved DTCG `value`, `css` and `variable`. `hostRoles[group.token]` names
the matching CSS variable and the ordered VS Code fallback variables. The
native theme message's semantic roles are the colour roles in the table
below. This is a list of inputs for M104/C, not a newly invented wire frame:
C binds the captured MHP theme message to these variables.

The radius scale is xs/sm/md/lg/xl/pill (3/4/6/12/20/999 px) and circle
(50%; native value 0.5). Elevation is flat/raised/popover/overlay. The latter
three read the host widget shadow. High contrast removes shadows, makes the
modal scrim opaque and sets surface alpha to 1 and blur to 0. Consumers use
`--ms-contrast-border` for a contrast border in place of a shadow. Reduced
transparency also removes alpha and blur. Component motion must remain inside
`prefers-reduced-motion: no-preference`; these variables introduce no motion.
Fast/base/slow are 120/180/240 ms. Spacing uses a 4 px scale. UI/code fonts
read the editor's fonts; standalone surfaces use the documented installed
font stacks, with system fallbacks. This lane ships no font files.

The extended role sheet is generated separately to keep unused mappings out
of today's startup CSS. Native/standalone consumers get all resolved tokens
in the JSON. The existing 6 px panel radius and 4 px What's New radius stay
through aliases until P1/P2's component pass.

Stylelint permits raw colour only in the three exact generated CSS files;
it still applies all other rules to those files. ESLint applies the colour
string/template guard to all production TypeScript, including SVG paint,
and keeps the existing native-identity and bundle-error guards. Fixtures
under `test/` remain test data. Generating a token file cannot exempt a
component or another stylesheet.
