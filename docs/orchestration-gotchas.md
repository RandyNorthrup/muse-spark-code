# Orchestration gotchas register

This register records what went wrong, in a way that generalises, while
Muse Spark Code itself was built by a fleet of agents. One orchestrator ran
up to 30 coding and review agents across three rigs (Kubuntu, a Mac mini and
a Windows 11 VM). Each row says what happened, the rule that prevents it, and
which product decision and milestone must enforce that rule. The app ships
its own orchestrator: teams and the scheduler (M96, M96c), paired devices
(M100), the resource governor (M107), Muse Node (M110), scheduled prompts
(M115), the orchestrator playbook (M116) and the capacity estimator (M117).
Users' fleets will meet the same failures.

The owner's ruling (2026-10-06): every orchestration gotcha is documented
here, and the app accounts for it. Each row's owner adds a named test for
its rule. D100 in `PLAN.md` lists the amendments that rows marked
**amend** add to their milestones. Plans and reviews of the milestones above
check this register.

Status: **covered** means an existing decision already states the rule;
**amend** means D100 adds it to the named milestone.
