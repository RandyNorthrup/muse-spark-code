## Delivered behavior

The existing validated Responses stream feeds a display-only accumulator.
The selected model must have an evidence-bearing
`tools.streamingArguments.state === 'yes'` record. An absent resolver,
missing record, `no` or `unknown` preserves the original behavior. There is
no provider-name check or inferred capability.

The accumulator bounds retained arguments and displayed text at
`TOOL_ARGUMENT_PREVIEW_MAX_CHARS` (16,000 characters). It decodes JSON string
escapes, scrubs before and after decoding, and withholds unfinished lines
and incomplete escapes so split credential shapes cannot become visible
before the existing redactor recognizes them. A single-line unfinished
value therefore waits for its closing quote. Redaction retains the existing
redactor's documented credential-shape limits; it is not a detector of
arbitrary secret strings. The done payload replaces the accumulated prefix,
and subsequent deltas do not change it. Saturated, unchanged previews are
not sent again. Provider-authored tool names are also scrubbed.

Preview events require empty executable `args` and bounded display data.
The preview field belongs to the extension's snapshot/event schema, not
the Muse Code wire schema. Deltas and done events cause no execution,
permission question or tool hook. Only the existing terminal-response
admission path executes a tool, using the untouched final call arguments.
The tool retains its preview row ID, replaces the preview, and does not
duplicate history. Failure, cancellation and omitted calls settle their
rows as interrupted. Conflicting message/preview item IDs are refused.

The React tool row shows escaped, selectable text in a lazy component,
with localized preview, waiting and truncation labels. Its preview has no
file, diff, shell or other tool action. The reducer persists the same
display data and replaces it on the actual call. ACP emits the same
localized preview as pending tool content, then clears that content and
updates the original tool call at execution. No preview is emitted as
assistant text or included in model replay. On/off request bodies compare
byte-for-byte equal, including the full unmodified terminal call.

U13 commentary and absent phases are replayed as captured. No production
phase behavior changed. `final_answer` is **not applicable**, because U13
contains none; future or uncaptured phases are not certified by this lane.

## Intentional failure drills

Every drill runs its complete owning test file with repository timeouts,
then restores the mutated source bytes and compares SHA-256. The
[machine-readable receipt](m106-l1-drills.json) names each mutation, expected
failing test, exit code and matching before/after digest. No filtered,
skipped or timeout-raised test is used. All **24 drills** observe exit 1
at the named assertions, with matching restoration digests. The guard groups are:

- Retained/display bounds; authoritative done; ignored late deltas.
- Pre-decode scrub; post-decode scrub; split-token withholding;
  malformed/incomplete string refusal; tool-name scrub.
- Event empty-argument restriction; event bound; MSP wire isolation.
- Selected-model capability; no execution on a delta; row identity;
  interrupted settlement; bounded-prefix deduplication; conflicting wire ID.
- Captured phase replay; preview/model-replay isolation.
- Escaped rendering; runtime language selection; preview replacement.
- ACP preview delivery; ACP promotion clearing the display content.
