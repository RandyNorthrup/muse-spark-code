## Binding and ownership

The existing lazy `createTeamRunnersRuntime` exposes `createResourceRouting`.
It registers cached approved-route availability, loads the existing window
resource host, and creates one `ResourceRunnerRouter` per conversation. It
uses that host's governor, settings, clock, event stream and durable journal;
it does not start another sampler or discover runners at activation.
`routeChecks` uses this binding through `CheckRoutingDeps.resources` when the
local governor reaches relocate/pause. Normal/throttle preserves ordinary
authorized routing. Disabled/off/headless/light work and absent or revoked
approval retain existing local admission without relocation probes.

CM96C1 must supply these production ports together:

- Cached `hasTarget` reports an active, user-approved SSH check route without
  probing. Approval/configuration changes invalidate the existing resource
  host through `routesChanged`; disposal removes the registration.
- `isHeavy`, live `phase`, and `isApproved` use the scheduler's exact current
  check, repository/snapshot, command and runner grants. The router's shell
  guard runs before ownership, snapshots, health probes or dispatch. No port
  grants new tool authority or permits a model worker on SSH.
- `claim` acquires exclusive attempt ownership. `settle('kept')` releases the
  relocation attempt for the scheduler's ordinary local admission;
  `settle('admitted')` transfers ownership to the existing remote completion
  path; `settle('uncertain')` retains occupancy and forbids a local retry.
  The caller retains the remote run until its existing terminal proof.
- `ask` takes an AbortSignal and uses the existing interactive confirmation.
  `row` installs target, `reason: machineBusy`, level and the provided Keep
  here action before dispatch. `notice` reports once per conversation;
  `traffic` receives each admitted relocation event. All are required ports.
- The existing SSH `sample`/`remote` and local scheduler admission fill
  `CheckRoutingDeps`. The receiver's validated durable start receipt invokes
  `onAdmitted`; output/completion remains owned by its existing transport.
  Existing paid rules stay with the caller; SSH checks introduce no paid call.

Checks share a pending attempt through both remote completion and local
fallback, including pressure recovery; disposal remains closed at every level. Keep here withdraws unanswered Ask and pre-admission dispatch;
after durable admission it cannot cause a duplicate local run. Lost transport,
wrong completion identity and an exception after sending remain uncertain.
Only a proved busy/offline refusal returns to local admission. The receiver
rechecks load, valid core counts and available slots inside its allocation
lock before creating a relocated run. Linux/macOS use the existing POSIX
helper; Windows uses its existing PowerShell helper and job containment.
