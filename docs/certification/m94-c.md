# M94 lane C certification: the pure core (`src/core/tab/`)

Lane C on worktree `m94/c` (HEAD `a7f5537a` = M94 plan + lane 0 strings and
constants). Fakes only: no network, no key, no model call. Every test below
ran as `node node_modules/vitest/vitest.mjs run <files>
--maxWorkers=1 --coverage.enabled=false` on Windows (the rig's `TEMP` was
redirected to a writable sandbox dir; `npx` is broken on this machine, so
the local vitest entry ran directly).

## Files

New, all pure (`vscode` appears in none):

- `src/core/tab/tabContext.ts` — the cursor's line, D73's mode rules
  (Invoke always multi-line), the prefix window anchored to a 0-based
  multiple of `TAB_PREFIX_ANCHOR_LINES`, the unanchored suffix, snippets
  fenced in path order and packed whole within `TAB_CONTEXT_CHARS`.
- `src/core/tab/tabRequest.ts` — the body from `TAB_MODEL_TEXT`
  (instructions + one fenced user message), `stream: true`, `store: false`,
  no tools, no `previous_response_id`, `minimal` effort with no reasoning
  summary, the mode's output cap, `in_memory` retention, and the
  `prompt_cache_key` from `TAB_PROMPT_CACHE_KEY_PREFIX` plus a digest of
  model and instructions only (stable across keystrokes).
- `src/core/tab/tabReply.ts` — wrapper-strip, first-pair tag extraction,
  mode cuts (blank line, line caps, `TAB_MAX_COMPLETION_CHARS` at a line
  boundary first), overlap trim, and the eight refusals.
- `src/core/tab/tabCache.ts` — the `TAB_CACHE_ENTRIES` LRU keyed by the
  document's raw prefix (same key reads and writes) with longest-prefix
  typing-through, plus open-request wait-for matching.
- `src/core/tab/tabScheduler.ts` — debounce (Invoke skips it), the
  `TAB_MAX_IN_FLIGHT` and per-minute caps, replace-while-waiting, and never
  abort: a sent request runs to its end with no abort handle held.
- `src/core/tab/tabSpend.ts` — the worst case (M82's one-token-per-UTF-8-
  byte estimate through `estimateCostUsd`), settlement at reported usage,
  the fit check, and the local calendar day (`tabDayKey`).

Touched:

- `src/shared/constants.ts` — one addition in the Tab region:
  `TAB_REPEATED_LINES = 3`, with a reason comment (D73's number). Nothing
  else added; every other literal the lane needs already existed
  (`MODEL_API_EFFORT_OFF` is the `minimal` floor, `SECONDS_PER_MINUTE` /
  `MILLISECONDS_PER_SECOND` derive the cap window).
- `src/core/backends/modelapi/client.ts` — `isModelApiError` and
  `isMissingApiKeyError` beside the classes, by name and fields, never
  `instanceof` (the Tab bundle crosses a bundle boundary).
- `src/core/backends/modelapi/schemas.ts` — types only:
  `CreateResponseBody['reasoning']['summary']` is now optional. Every
  existing request still sends `summary: 'auto'`; no request's bytes change
  (the only reader of the object, `modelCallHooks.ts`, reads `effort`).

| #   | Finding                                                                    | Fix                                                                                                                                       | Commit     |
| --- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 1   | 3: `tabUserText` filled slots one at a time, so it re-read inserted values | One regex pass over the template's `{name}` slots, with a replacer. A value is never read for slots                                       | `d75713ce` |
| 2   | 4: a settle flushed newer Automatic work while its debounce still ran      | `pendingReady` (debounce elapsed, or Invoke) is kept apart from waiting for capacity. A settle sends only ready work                      | `ba253c5f` |
| 3   | 5: `findOpen` tested every open request against one stream                 | `noteStreamed(id, text)` keeps the stream on its own request. `findOpen(document, prefix, suffix)` tests each request against that stream | `a3694b04` |
| 4   | 2 and the probe: blanket `trim`/`trimEnd` destroyed code whitespace        | `TabFilterContext.cursorLineBefore`; the completion is placed against the cursor (below)                                                  | `c971ff94` |

How item 4 places a completion. Whitespace is kept as the model wrote it,
with these changes:

- **Missing newline.** The cursor's line, trimmed at the end, ends in `{`,
  `(`, `[` or `:`. The suffix's first line is blank. The completion's first
  line starts with a tab, or two spaces or more, and holds code. Then the
  missing newline is added. A lone space (`let total:` then ` number`)
  continues the line, so it gets none.
- **Repeated indentation.** `cursorLineBefore` holds only indentation, and
  the first line starts with that same indentation. Then the first line
  alone drops it.
- **Stray trailing newline.** The cut ends at the first blank line after
  the first line, so it drops a trailing newline and a whitespace-only last
  line. A space or newline that the overlap trim leaves in front of the
  suffix stays.
- **Unchanged.** An empty or whitespace-only completion still drops as
  `empty`. The repeat checks still compare trimmed text.

  - `tabSpend.ts`: `consistent-boolean-name` on the exported
    `tabWithinBudget`, so a rename is an API decision;
  - `tabSpend.test.ts`: `consistent-boolean-name`, and prettier;
  - `tabContext.test.ts`: prettier.

- **The integrator** fills `TabFilterContext.cursorLineBefore` from
  `cursorLine(text, offset).before`. It also calls
  `TabCache.noteStreamed(id, text)` with the whole completion text each
  open request has streamed so far, the text between the tags and not a
  delta.
- **Residual.** A completion with two or more leading newlines is cut to
  nothing by the blank-line rule and drops as `empty`. That is the
  conservative failure. A leading space after a cursor line that already
  ends in a space is kept as the model wrote it.
