## What changed

A Muse Code side chat is read-only at the panel:

- Every `approval/requested` on a side-chat Muse Code session is answered
  with the card's own reject choice (`decision: 'abort'`, the captured wire
  vocabulary), so no card is shown that could approve a write
  (`src/core/agent/approvalRules.ts`: `sideChatRefusalChoice`;
  `src/host/conversation/conversationController.ts`: `refuseSideChatApproval`).
- When the host offers no reject choice, the card is shown so the user can
  still refuse it, and any approving click is refused with the policy reason
  while the card is re-offered (`isApprovingChoice`: decisions starting with
  `approved`; `decideApproval` backstop; retained raw card per approval,
  refreshed on `approvalUpdated`, dropped on resolve / `gone` / session end).
- Refusals resolve labelled `Side Chat` (`UI_TEXT.sideChatResolver`) with
  the reason `UI_TEXT.sideChatWriteRefused`; questions (`userInput`) are
  untouched, so Plan elicitation still works.
- Strings in `src/shared/l10n/en.ts` and all 14 `l10n/ui.*.json` tables
  (`npm run check:l10n`: 0 problems). README side-chat paragraph updated;
  CHANGELOG `[Unreleased]` entry added. No new command, setting or feature:
  no `featureCatalog` row.

Out of scope (belongs to C-M53-4): the ACP agent and other editors keep
their own approval path (`approvalRules.editAutomaticallyChoice` unchanged).
