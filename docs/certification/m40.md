# M40 certification — the panel in VS Code's display languages, part a (PLAN.md M40, D33)

Recorded 2026-09-25.

The owner said "yes" (2026-09-24) to the fourteen languages VS Code ships,
with machine translations disclosed. M40a is the machinery, the English
table and the gate. The panel still reads in English; M40b adds the
translations.

## How the work was split

The lead wrote the shared part first:

- the table (`src/shared/l10n/en.ts`) with templates, plural forms and label
  groups;
- the helpers (`text.ts`: `fill`, `plural`, `templateParts` and the `Intl`
  formatting);
- the checks (`check.ts`) and the language list (`locales.ts`);
- `MODEL_TEXT`, the English kept for the model.

Three agents then worked in parallel on separate files, each adding keys only
in its own marked section of `en.ts`:

- **host and core:** the model text, the sentence templates, the loader
  (`src/host/l10n.ts`) and the table in the webview HTML;
- **webview and shared UI:** templates, plural forms, `Intl`, and
  `installTable.ts`;
- **tooling:** `package.nls.json`, `scripts/check-l10n.mjs`, the harness's
  `--lang` and the pseudo-locale.

The lead then:

- removed the 17 keys no code reads any more;
- turned the sentences that ended in a value into templates;
- moved the last English out of constants.ts: status verbs, onboarding tips,
  dictation reasons, the sign-in terminal's name and Muse Code's exit
  meanings;
- localized dollar amounts;
- fixed the "1000K" edge.

## The accessibility gate in the pseudo-locale

`node scripts/a11y.mjs --lang=pseudo` ran every scenario in the four themes
(216 pages). It found two real problems that English runs had not reached.

- **A dangling `aria-controls`** (WCAG 4.1.2), in `filter` in every theme.
  The `filter` scenario types "eff". That matches an action in English but
  nothing in the pseudo-locale, and the palette's search box kept
  `aria-controls="palette-listbox"` after the list was gone. History's search
  box had the same flaw.
  - The fix: both boxes control a list, and say they are expanded, only
    while one is shown. Unit tests check a search that matches nothing.
  - Drill: `aria-controls` made unconditional again fails
    `Palette.test.tsx` (1 test); restored.
- **A crowded target** (WCAG 2.5.8), in `jump`, one theme, one run. A code
  block's buttons are 17 px tall, and English passes on spacing alone;
  longer labels squeezed that spacing below 24 px.
  - The fix: the buttons are 24 px targets. The `jump` screenshot was
    viewed: the bar is a little taller, with nothing else changed.

After both fixes, the affected scenarios pass in the pseudo-locale in every
theme (`jump`, `tools`, `rewind`, `usage`, `dictation`, `filter`,
`history`: 28 pages, 0 violations).

**Flakes, reported as seen:** two runs had pages without a result.

- One full pseudo run: `usage`, `dictation` and `rewind` in the dark theme.
  A scenario step ran before the element it clicks had rendered.
- One English run of `jump` and `tools`: 4 pages.

Neither came back in the reruns: the next full pseudo run, and three English
runs of those two scenarios. Every full English run of the gate for this
milestone has shown 0 pages without a result.

A later full English run hit the same race: `agents` and `dictation` in the dark
theme found no composer. Scenarios had started on a fixed 400 ms timer. Now
they start once the panel has drawn its surface (the composer, a sign-in or
install gate, or the crash screen), never sooner than 400 ms, and
`whenFound` fails the page by name if none appears. The next full runs were
clean: English and pseudo, 216 pages each, 0 violations, 0 pages without a
result.

## The review of pull request #23

Codex (P2) found that only a plural entry's `other` form was checked for
every slot. A translation's `one`, `few` or `many` could drop `{count}` and
pass both the host's check and the gate, and the strict checks (code spans,
bold markers, English left behind) skipped plural forms.

- **The fix:** every form is now checked like a string against its English
  form, or against `other` for a category English lacks. Russian's `one`
  also covers 21 and 31, so dropping the number there would be wrong, not a
  style choice.
- **Tests:**
  - a Russian `one` without `{count}` fails in both modes;
  - a form with an extra slot fails;
  - a form missing its code span or bold marker fails;
  - a form left in English fails, unless its entry is allowlisted.
- **Drill:** each form compared with itself instead of its English form fails
  4 tests in `l10n.test.ts`. Restored.

## M40b — the fourteen translations

Recorded 2026-09-25.

**How they were made.** Seven agents translated in parallel, two related
languages each: German and Hungarian, French and Italian, Spanish and
Brazilian Portuguese, Russian and Polish, Czech and Turkish, Japanese and
Korean, and Simplified and Traditional Chinese. Each wrote only its
language's `l10n/ui.<language>.json` and `package.nls.<language>.json`, and
reported the values it had kept equal to the English. The lead merged those
reports into `l10n/untranslated.json`, so no two agents wrote the same file.

**What the agents followed:**

- **VS Code's own terms and address in each language.** The Spanish,
  Portuguese, French and Italian agents read Microsoft's VS Code language
  packs.
- **The key names VS Code shows there:** Strg and Umschalt, Maj, MAIUSC,
  Mayús.
- **Settings keep their English titles.** "Allow dangerously skip
  permissions" stays English inside the messages, because VS Code builds a
  setting's title from its id and does not translate it.

**Worth a native speaker's look.** The agents flagged these themselves:

- Hungarian "hookok" and "munkafa".
- Traditional Chinese 認可 for "commit", following VS Code zh-tw.
- A few reworded templates where a literal "Muse wants to {action}" reads
  badly: Chinese, Japanese, Korean, Spanish and Portuguese.

**One gap in the gate, found by the Czech and Polish agents.**
`l10n/untranslated.json` could name only plain strings. "1 agent" is correct
Czech and Polish, the same as English, while the other plural forms are
not. With no way to allowlist one form, both agents had written the awkward
"Agenti: {count}" for every form.

- **The fix:** a plural entry, or a single form such as `agentsCount.one`,
  may now be listed. Both languages then took their natural plurals:
  - Czech: `agent` / `agenti` / `agenta` / `agentů`;
  - Polish: `agent` / `agenci` / `agentów` / `agenta`.
- **Drill:** with plural keys dropped from the listable ones again, the gate
  exits 1 with `l10n/untranslated.json: ui.cs: agentsCount.one: not a string
of the ui table` (and the same for `ui.pl`). Restored.

**The gate:** `l10n: 14 tables, 76 manifest strings, 165 source files; 0
problems`. `vsce ls` lists all fourteen `l10n/ui.*.json` and all fifteen
`package.nls*.json`; `l10n/untranslated.json` is the gate's input and does
not ship.

**Seen:**

- Screenshots in German (`empty`, `usage`, `palette`, `tools`, `modes`,
  `approval`) and in Japanese (`empty`, `usage`, `modes`) were viewed. Long
  German labels wrap without overlap, the numbers are written the language's
  way ("42 % verbraucht", "20,8K"), and the Japanese Modes menu reads
  correctly.
- The README's Languages section shows the German `usage` render.

**The accessibility gate in two translated tables** found one real problem:

- **What it was:** in Dark Modern, the Modes menu's highlighted row showed
  its detail line at 4.41:1 (WCAG 1.4.3). M37 had fixed the palette's
  highlighted row but not the menu's. The longer German and Japanese rows
  put the pointer on a row the English run never highlighted.
- **The fix:** the detail line takes the row's own text colour, as the
  palette's does.
- **After the fix:**
  - `a11y: 216 pages (54 scenarios × 4 themes, in de), 0 rules violated on 0
elements, 0 rules undecided on 0 elements, 8 exempt, 0 pages without a
