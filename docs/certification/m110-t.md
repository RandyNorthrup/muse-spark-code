## Implementation plan and boundaries

Build the local socket client, keyboard controller, bounded view state,
Ink-compatible React views and the linear screen-reader surface against
injected bindings. No node listener, sign-in, credential store, remote route,
QR/SAS pairing, peek or team supervisor belongs to this lane. No model call.

This base (`48250c33`) has neither M104 MHP nor M110 lane-0 schemas, node
service, featureCatalog or Ink. The normalized TUI events are an internal
presentation contract, **not a proposed MHP wire shape**. The socket adapter
requires a binding that validates frozen MHP/node frames before mapping them.
Only tests provide fake wire bindings. An Ink module is injected so this lane
does not change another lane's packaging or install a dependency. The planned
Ink 8 pin and React/Node peer qualification remain a packaging handoff.

New tunables use a TUI-only region of `constants.ts`; new UI strings use
`en.ts` and every translated UI table. No manifest contribution is added,
so the manifest tables need no unused keys. README/CHANGELOG/help-reference
and runtime launcher integration belong to the integration handoff below.

## Implemented behavior

Nine modules under `src/runtime/tui/` supply strict local arguments, a lazy
localized entry, owner-only Unix socket I/O, bounded validated presentation
state, the keyboard controller, React/Ink views, linear output and native
terminal restoration. Tests exercise the entry through a real Unix socket
with fake protocol frames; fake bindings/renderers stay under `test/`.

Chat supports snapshots and deltas. Diff, tasks and status views are reachable
with Tab or linear `/chat`, `/diff`, `/tasks`, `/status` commands. Esc and Ctrl+C
send Stop before any composer, ask or view processing. The full SHA-256
fingerprint and an unexpired setup code are shown; expiry removes the code.
The graphical layout gives each approval its own viewport independently of
chat scroll. Choices appear only when the complete action and paid terms fit
the real dimensions; oversized requests show a refusal with no choices.
Screen-reader/redirected output emits
plain physical lines without Ink, redraws, cursor controls or spinners.
`NO_COLOR`, including an empty value, removes colour props and keeps `+`/`-`.

Tool/vault asks offer explicit once/deny choices; paid asks offer equal
once/always/deny choices and require price plus the shared daily budget.
Tab focuses a fully displayed ask; a subsequent fresh number answers it.
Enter, type-ahead, batched input and bracketed paste never answer an ask.
Redirected input cannot answer asks. Answers preserve the exact id, digest and expiry,
are sent once until settlement, and cannot select the next ask after expiry.
A repeated ask keeps its queue position. Ask changes discard buffered input;
fresh numeric lines without a pending ask are ordinary chat. The node owns approval validity, paid admission and
remembered grants; this surface cannot spend or store a grant itself.

Limits cover incoming/outgoing frames, socket/terminal queues, transcript
characters/entries, asks, tasks, identifiers, setup codes and input. Fatal
UTF-8 decoding, Zod boundaries and control/bidi scrubbing protect output.
The socket and parent must both be owned by the caller and private, with
valid filesystem types. Connect deadlines, abort/closure, failed callback
writes, raw input, listeners and timers are covered by the owned tests.
