## Investigation stop records

The original intercepted HTTPS handler never reached `getResourceHandler`.
Pre-rendering HTML before that callback and registering a scheme factory both
failed readiness, so that path was stopped under common.md. An alternate
loopback asset server also stalled, with and without a resource guard. A plain
browser diagnostic reproduced stalled HTTP even without plugin guards, while
the public IDE HTML loader completed. The alternate server and diagnostic-only
switches were removed. The final page has no network asset path at all; the
shared built entries are folded into native inline bundles. The virtual loader
URL was captured in `native-tab-await.log` / `native-inline-page.log` under this
worktree. Its exact fragment must identify this surface; ordinary/remote files,
queries and network navigation are refused.

The first Tab fixture used `temp:///` and was correctly denied by the real-path
workspace guard. A physical content root fixed that fixture. The next assertion
ran before asynchronous execution completed; the framework's `delay()` waits
for its completion job. No timeout, assertion or gate threshold was weakened.

A stock inline element with an indefinitely open stream caused the framework
completion job to time out. That approach was stopped. The final provider uses
the stock public gray-text element, a finite stream and the public completion
Hide listener; settlement is deferred one EDT turn so acceptance precedes
rejection. No nonextendable interface, override-only getter, deprecated read
action or experimental install listener is used. Native session cleanup keeps
its Tab service reference rather than resolving a service during project
shutdown.
