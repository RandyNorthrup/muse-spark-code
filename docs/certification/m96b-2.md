## Runner implementation and review

- Public admission now requires the Model API backend, acceptEdits and the
  already-validated hard budget. CLI Help and all 14 translations describe
  the working runner; reference and roadmap entries move with it.
- Snapshot: user-owned `acp/<workspaceKey>/team.json` in the agent data
  folder. Preserve Solo. Repository `.muse/team.json` can only lower existing
  caps/concurrency and aggregate worker spending; unsupported review
  requirements refuse. Default follows this run's model/provider.
- `execTeam.js` loads only for the flag; `teamHost.js` loads only for a
  distinct configured engine. Workers reuse the shared fenced engine ports,
  run in-process, and cannot start Muse Code/external/subscription agents.
  Native local pricing uses no key or paid daily reservation, while request
  and concurrency counters still apply.
- Shared exact run ledger covers concurrent requests and retries. Worker
  reserves use the same engine UTF-8 estimate/output ceiling and native price
  policy as the editor. Missing verified cost retains liability; owned unsent
  attempts refund once. Worker settlements cannot replace the orchestrator's
  terminal or release its transcript.
- Concurrency review found incomplete daily-journal intents visible during
  another worker's final synchronous fence. The local journal queue now
  spans publication through dispatch and settlement. Streams remain
  concurrent; cross-process journal intents still refuse. No journal guard
  was removed or weakened.
- Headless team trust authorizes only delegation, merge and file-only worker
  hosts. Ordinary orchestrator shell/hook trust remains the existing policy.
  Worker questions/approvals deny; exhausted-pool cards cancel. Protected
  merge paths deny. Landing is serialized, checks the task branch locally
  with program-free Git, and uses the existing role/path/ref merge fences.
  Landed paths enter M80's unchanged run tree and exact patch flow.
- Lifetime review found disposal returning before worker handoff/state
  persistence. `dispose({ waitForWorkers: true })` drains the whole service
  execution, then the run removes unmerged copies and owned refs. Close also
  waits initialization, preventing a late first-use folder from outliving
  the run. Native worker settlement remains the engine's port; its upstream
  per-attempt correction is not reimplemented here.
- Configured provider credentials join the run's in-memory redactor and
  snapshot scrubber. No key is written into board/copies or passed to Git,
  tools, hooks, launch arguments or child environments.
