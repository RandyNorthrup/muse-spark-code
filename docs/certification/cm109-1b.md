## RVCM1091B guardian finding (lane CM1091BR2, 2026-10-10, rig linuxlt)

Finding: RVCM1091B P2, `src/runtime/vault/posixNative.ts:154` — startup
lock-loss detection misses a guardian killed by a signal before `onLost`
subscribes. A signal exit leaves `exitCode=null`; the replay check only
tested `exitCode !== null`, so a fully-reaped signal death was never
reported and broker startup proceeded without its kernel lock.

Fix: the `onLost` replay also accepts `child.signalCode !== null`. No other
production line changed: `brokerProcess.ts` already subscribes `held.onLost`
before `clearStale` and re-checks the flag in every `assertHeld()`, so the
corrected replay is what refuses the duplicate-broker startup.

Class sweep (part B only; `src/core/vault` and `keyringAnchor.ts` untouched
— part A lane owns them): `brokerProcess.ts:153-159` (late subscribe plus
`assertHeld` re-check, pinned by the startup-refusal test),
`posixNative.ts:102-106,117-118,137` (synchronous subscribes, no await gap),
`vaultInput.ts:97-105` (`signal.aborted` re-checked before subscribing),
`slots/macVaultTransport.ts:18,53-66` and the Windows transport twin
