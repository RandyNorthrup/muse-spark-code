## OS-store slot, before merging part A

`OsStoreVaultSlot` uses only Secret Service on Linux and login Keychain on
macOS. It binds immutable slot identity, refuses overwrites, verifies writes,
serializes removal with wrapping and erases owned/native byte buffers. Native
failures become fixed localized instructions; native exception text is discarded.
No editor surface is enabled by this lane. Touch ID is not offered (lead
M109 decision 10); Linux hardware/screen lock stays in C-M109-2.

Kubuntu native capture: generated 32-byte key, isolated `XDG_DATA_HOME` and
private `dbus-run-session`, unlocked generated keyring. `AsyncEntry.getSecret`
returned `{type: "object", array: true, constructor: "Array", length: 32}`;
the generated key compared equal. Missing entries returned null. The slot
validates both the numeric array and typed-byte shapes and erases the native
return. No generated value was printed or retained.

Receipts: `node test/hosts/vault-os-store.mjs` passed create/read/delete and
absence of key material from the slot record. With an absent D-Bus endpoint,
`node test/hosts/vault-os-store.mjs --unavailable` passed fixed actionable
refusal. The isolated generated keyring folders are removed after testing.
Mac mini receipt is outstanding: the saved connection attempt reports
`Host key verification failed`; no host verification settings were changed.

Unit suite: `npx vitest run test/unit/osStoreVaultSlot.test.ts --maxWorkers=3`,
9 cases passed at repository timeouts. Red drill: bypass immutable-identity
comparison; `refuses swapped immutable identity before reading the OS store`
failed. Restored the source byte-exact with SHA-256 comparison (receipt in
`temp/slot-red-identity.log`). No full quality run: the lane rules reserve that
shared-rig workload for the lead; targeted checks run here with hooks enabled.
