## Implementation

- `pacing.ts`: request and token buckets keyed by provider, endpoint and
  key digest. U12's four exact headers are validated as safe decimal
  integers. The most recently observed snapshot replaces the limits;
  missing or malformed headers cannot erase them. No reset header is
  invented: Meta refill uses lane 0's documented minute constant; a
  captured provider interpreter can supply its own validated window through
  the normalized port. Unobserved
  accounts start at its conservative startup allowance with no invented
  token limit. Concurrent admissions charge synchronously, leave one
  request for foreground, and recheck after waking. Impossible background
  token estimates fail rather than wait forever. Headroom is readable by
  the future resource/account governors without reading a key.
- `client.ts`: taps headers on streamed, ordinary and token-count replies,
  including failures. Tags from subagents, best-of-N, schedules and judge
  select pacing; a team can pass `pacingClass: 'team'`. Pacing adds no wire
  fields and touches neither instructions, tool declarations nor cache
  keys. Foreground bypasses the fan-out queue. 429 pauses queued fan-out;
  the originating request still honors its own Retry-After through the
  existing abortable backoff. Key, consent, Stop and synchronous budget
  admission are checked after a pacing wait.
- 504 joins the existing bounded retry policy before a body is read.
  Jitter, the shared retry counter, body bytes and actual-attempt accounting
  are preserved. An injected `prepareRetry` can retain prior liability and
  reserve the next capped attempt; a failed reservation prevents fetch.
  Paid daily claims and per-call image requests keep the existing 429-only
  policy: no ambiguous billed attempt is silently resent or refunded.
- `readServiceStatus`: public `GET https://api.meta.ai/v1/status`, with
  deadline/Stop and lane 0's response schema. It never reads or sends a key.
  The host parses the full status envelope. The usage row revalidates its
  two consumed captured fields, renders escaped status and service prose,
  cancels on close, and opens that public URL. It imports no transport-schema
  module, avoiding unrelated request/stream schemas in the deferred UI. The report
  facts region accepts a validated status and exports only liveness and
  an allowlisted status word; service prose, dates and unknown model entries
  never enter support facts. Existing facts omit the additive field.
