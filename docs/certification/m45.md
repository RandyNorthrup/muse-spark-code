# M45 certification — session goals (PLAN.md M45, D38)

Recorded 2026-09-25.

Before M45 the panel showed the goal tools' rows (M43) and nothing else:
Muse Code's `goal/*` verbs, its `session/goalChanged` and a resumed
session's goal never reached the panel, and the Model API backend had no
goals at all.

## The live capture

The goal surface is built from what Muse Code 1.3.0 actually sends
(AGENTS.md rule 13), captured on 2026-09-25 with the owner's standing
go-ahead for live checks (no ask, contributor model, empty workspace,
count afterwards):

- **Where:** two new, empty folders, `C:\muse-live-m45` and
  `C:\muse-live-m45-stop`.
- **How:** `muse serve --trust-workspace` driven over MSP by capture
  scripts, approval mode `allowAll`, every notification, ack and error
  written to a JSON lines file. Model `muse-spark-1.3-contributor`.
- **What, in the first folder:** each verb on a session with no goal (no
  model call); an ordinary one-word turn with `goal/set` and `goal/pause`
  sent while it ran; `goal/edit` of the paused goal while idle;
  `session/resume` with `inline` and with `snapshot` history, and
  `session/read`; `goal/resume` while idle (the goal-driving turn, which
  closed the goal with `update_goal`); pause, resume and edit of the
  finished goal; `session/resume` with a snapshot again; `goal/clear`
  twice.
- **What, in the second folder:** `goal/set` while idle, then `turn/cancel`
  (the panel's Stop) of the turn it woke, then `goal/clear`.
- **Cost:** three turns (one ordinary, two goal-driving), **nine model
  attempts**, all on the contributor model, counted from the CLI's trace
  logs (`event="model.attempt.lifecycle" phase="admission"`): seven in
  `cli-3ad5bc45-….log`, two in `cli-f268bbdd-….log`, each identified by
  the capture's own session and run ids.

What the capture showed, and what the extension now does with it:

| `goal/edit` of a paused goal while idle: accepted, the goal stays paused, nothing wakes                                                                                  | The Model API backend follows the same rule                                                                        |

The goal store's status list (active, paused, complete, blocked,
usage_limited, budget_limited), the goal tools' descriptions, `update_goal`'s
"expected complete or blocked", `report_progress`'s 0–100 and non-empty
work, and `create_goal`'s refusals over an unfinished or paused goal were
read from the strings of the Muse Code 1.3.0 binary; the step probe's note
("Progress has not been reported in the last N model calls…") and the goal
turn's cue ("Continue working toward the active session goal.") too.

## What was built

- **Muse Code backend**: `session/goalChanged` mapped (a `null` or absent
  goal clears; `status` and `percentComplete` verbatim; a malformed goal is
  dropped with a log line); `controlGoal` sends `goal/<verb>` with the
  objective only on `set` and `edit`, and turns the two captured refusals
  into `GoalRefusedError`; a resume asks for the snapshot, whose goal is
  read on its own so a goal of another shape never costs the resume.
- **Model API backend** (`src/core/backends/modelapi/goals.ts`): the four
  goal tools with Muse Code's arguments, rules, messages and result shape;
  the goal stored with the session (optional, so older files still read)
  and forked with it; the goal pinned as the last section of the
  instructions while active; the step-probe note after ten model calls
  without progress; tokens counted against a budget (`budget_limited` when
  spent); Stop pausing an active goal; the user's verbs with MSP's rules
  and refusals; a set, edit or resume that leaves the goal active while
  nothing runs starts one visible turn with Muse Code's cue, replayed but
  not shown as the user's message. No turn of its own after a turn, and no
  completion audit: each would be a model call the user did not ask for.
- **The panel**: the goal strip above the task list (objective, status in
  words, percentage, clamped bar, now and next, Pause or Resume, Edit in
  place with the focus given back to Edit when the field closes, Clear);
  `/goal …` in the prompt with the TUI's grammar, sent as a
  command; `/goal` in the palette and the slash list, which leaves
  `/goal ` ready; a notice for each command done, a warning in words for a
  refusal, the live region reading each change of status; the goal kept in
  the webview's saved state.

## Review of PR #31

The review found two Model API goal edges after M45 was integrated:

- A completed reply could spend the goal's token budget and still run the
  function calls it returned, then buy another model round. The loop now
  gives each unrun call a cancelled replay output and ends the turn before
  running a tool or sending another automatic request. A later, separate
  user turn can still ask a question.
- A set, edit or resume accepted during a streaming final reply joined the
  running turn but could be left without a model request that saw the new
  goal. The turn now queues an internal goal cue for its next round. The
  cue is replayed for the model, not shown as a new user message.
