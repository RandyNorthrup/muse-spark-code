## Implemented boundary

- `DevicesView` lives under `src/webview/models/sections/agents/`. It takes
  lane 0's `DevicesPanelPort` and validated state, with explicit injections
  for S's saved/reconciled board bindings, task projections, M95's locally
  resolved price/budget and P/I's qualified QR renderer. No production fake,
  guessed provider field, credential access or fallback scheduler is present.
- The browser entry imports `DevicesApp` lazily only for the explicit
  `data-surface="devices"` document. Ordinary chat is unchanged. An embedded
  section returns nothing with Devices off, no pair or no approved offer;
  explicit setup plainly explains that Devices starts off. Mounting sends
  no ready request, probe, discovery, model call or automatic pairing action.
- Pairing exports selectable/copyable public text, imports invitations and
  strict confirmations, shows the complete peer fingerprint, focuses its
  comparison heading, and requires explicit comparison before confirming.
  A host failure never advances pairing. The QR renderer receives only the
  same public text; text remains available without that optional renderer.
- Device cards show observed status, role/model identity, readiness, payer,
  platform/toolchain, caps, last observation, local approval wait, unresolved
  occupancy and retained spending. Reports, labels and task branch names are
  inert React text, with no remote link opener. Task projections bind the
  device/pair/pool/entry/model, branch and known/estimated/uncertain usage.
- Cap and private-address editors validate before the injected action call.
  Offer selection and nonzero executable capacity are required. The host
  still selects/approves the trusted repository and exact base; the UI sends
  no repository path, shell command, permission grant or paid consent.
  Unsupported hosts disable Offer lanes with the qualified-host reason.
- Resume needs S's actual board id and explicit reconciled readiness, an
  eligible observed status and zero unresolved attempts. There is no Hand
  off anyway, occupancy release or spending refund control. Unreachable
  recovery names supplied listener/interface/endpoint facts and OS/admin
  steps, without interpreting a timeout as firewall proof. Retrying retains
  uncertainty and liability. Unlink explains its offline limits, requires a
  second choice, and restores opener focus on Escape/cancel.
- Incoming UI requests, host replies and browser observations use lane 0's
  strict parsers. Request ids correlate replies. Unexpected host errors become
  a fixed word; browser failures show localized fixed text, retaining the last
  observation. Pending UI actions cannot be superseded. The browser subscribes
  during layout commit and removes its listener/rejects pending promises on
  unmount. No Devices state is persisted in the chat store or webview state.
