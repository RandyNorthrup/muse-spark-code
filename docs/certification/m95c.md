## Implemented contract

- The stable `languageModelChatProviders` contribution and feature-detected
  registration expose only individually selected, current, priced or local
  models with known input/output bounds and a positive daily cap. Defaults
  are an empty machine-scoped opt-in list and a zero machine-scoped cap.
- The Models row asks with rates, the shared cap and the fact that every
  installed extension can spend the provider key. Dismissal keeps the model
  off. Withdrawal stays available after selection or prices change. The host
  validates the visible reference and sets the requested state idempotently.
- The activation shim loads no engine with an empty list. Its first opt-in
  action or native model call loads `editorChat.js`; subsequent calls share
  it. A failed load can retry. The optional browser control has its own lazy
  chunk, accessible loading status and the existing explicit error/retry UI.
  A zero cap withdraws cached registration; cap changes dispose the old
  provider and cancel active callers before registering eligible models.
- Native messages/options are validated before dispatch and mapped onto the
  existing captured `ProviderClient` seam. Text, tool calls/results and
  supported inline images work; unknown parts, system roles, unsupported
  model options and required tool mode fail explicitly. Tool and image
  capability declarations follow the chosen model. Caller-owned tools are
  never executed by this provider. Token counting is an offline conservative
  UTF-8 byte estimate, with no tokenizer or inference charge.
- Confidential or untrusted workspaces refuse requests. Revocation, stale
  models, cancellation, timeout and disposal stop callers. Admission is
  checked again before actual transport dispatch; a dispatched request cannot
  retry and spend another attempt against the same reservation.
- Each dispatched attempt records exactly one M102 `vscodeChat` call with
  model, provider, duration, completion/incomplete/failure/cancellation outcome
  and known usage or retained liability. Unsent requests have no usage record.
  The Usage page reads its separate cap and uncertain ledger even with usage
  history disabled.

## Budget boundary

Reuse M94's exact-USD, atomic per-window daily ledger under a distinct
`editor-chat-spend` directory. Before transport dispatch, reserve the chosen
model's full advertised input/output limits, cold-cache write bound and image
count through its existing price resolver. This can reject a short request
whose final cost would have fit. Concurrent windows share the daily total;
concurrent requests in a window serialize admission. Lowering the cap during
admission refuses dispatch and refunds an unsent reservation. A reservation
keeps its original local day across midnight.

Terminal reported usage settles only when its known price is within the
reservation. Missing terminal usage, unknown settlement, transport retry,
interruption or a failed durable settlement retains liability. A thrown
settlement still produces a failure tally. The bound is conditional on the
configured/captured price and the provider honoring its advertised limits:
the client cannot bound an upstream provider that bills outside those facts.
The ledger covers windows sharing this installation's global storage, not
other profiles, separate installations or other machines. No subscription
pays for these requests.
