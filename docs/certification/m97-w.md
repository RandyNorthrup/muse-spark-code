## Behavior delivered

- **Exact selection/preview.** Checkboxes select findings by id; "Fix all
  safe ones" selects exactly the fixable, non-project-license findings and
  requests the host preview; the preview names the exact eligible ids, the
  only paths a confirm may authorize, and every excluded id with its reason.
  Nothing is pre-authorized by the scan: confirmation posts `confirmLegalFix`
  for exactly the shown `previewId`.
- **Stale evidence refusal.** The preview stores evidence digests, SHA-256
  file hashes, workspace path and mode. Confirm rechecks all five plus
  trust; any mismatch refuses (`staleEvidence`, `workspaceChanged`,
  `workspaceUntrusted`, `planRefusesWrites`, `nothingSelected`). An unknown
  or disposed preview refuses with `previewExpired`; a dropped session
  disposes its previews. A new scan clears the dialog's preview and outcome.
- **Bypass still requires user selection.** An empty selection refuses with
  `nothingSelected` in every mode; the dialog says so before posting.
- **Plan refuses writes.** The dialog disables selection and fix actions in
  Plan mode with the reason; the host refuses regardless of what the panel
  sent.
- **Project-license separation.** A `license` finding without a package is
  the project's own: it cannot enter "safe ones" and joins a preview only
  with the separate confirmation checkbox. Non-fixable findings are
  unselectable; traversal escapes, unreadable files and files past the
  1 MiB guard bound stay out with their reason and are never read outside
  the workspace.
- **Themes / narrow panel.** Theme colors come only from VS Code variables
  with fallbacks; rows wrap anywhere; no fixed widths. Screen-reader status
  regions announce the report, preview and outcome; the modal traps Tab and
  moves focus to the preview/outcome heading once each on arrival.
- **Applier seam.** Applying the authorized paths through the normal edit
  tools is lane B's router via the injected `LegalFixApplier`
  (`src/host/legalFix.ts`). Until it is wired, a guarded confirm refuses
  with `fixUnavailable` rather than reporting an empty success. No fake
  implementation ships in production code.
