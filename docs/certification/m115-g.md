## Admission and transports

`AgentScheduleTools` implements `schedule_prompt`, `schedule_list` and
`schedule_cancel` behind current host capability and charter checks. The
Model API receives function declarations and calls the same validated path
as the MCP adapters. MCP tests use the existing captured envelope through
`handleMcpMessage`, without inventing any Muse Code verb. The generated JSON
declaration is derived from the frozen draft schema, narrowed to prompt
actions and `pinned: false`, and checked against regeneration in the suite.
Runtime validation additionally enforces all refinements the JSON Schema
cannot express. Default Model API declarations remain byte-identical;
`tools.ts` accepts declarations from the lazy engine without importing it.

The creator's effective grant and paid cap are intersected before consent;
the host re-reads identity, charter, lifetime, grant, target, mode, depth and
remembered policy under admission after consent. Policy revisions and a CAS
write prevent an old dialog from replacing a newer revocation or cap edit.
Ask requires a person and refuses immediately unattended, with a transcript
row. Always obeys ten active slots, the fifteen-minute minimum-spacing proof
and a total paid cap. Paused jobs retain slots; ended jobs release slots but
retain their actual daily spend/liability in the ledger (FIXM115G below).
A creator allocation and D78's ledger still
bound spending when schedules are ended or removed. Failed admission returns
its actual typed reason, and storage failures propagate without success.

The host supplies creator marks; the model cannot submit a creator, paid
consent, pin, Bypass or a rescheduling permission. The permission mode is
inherited, and a depth beyond one needs a host-owned permission naming the
creating source schedule. The child carries the boolean required by the
frozen depth schema; it does not grant descendants permission. Expiry and
user pinning share admission, and session/team disposal removes unpinned
jobs before S admits another due fire. Listing and cancellation are confined
to the caller's workspace, orchestrator, session and team. Users retain V's
ability to manage any schedule.

All logic is in the core with injected host ports and both transport
adapters: no `vscode` import, child process, credential, model request or
dependency. UI labels and sentences reuse `UI_TEXT.scheduleV2` at call time;
refusal detail is a stable technical reason after the translated Refused
label. No new English/manifest key or translation is needed.
