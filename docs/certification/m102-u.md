## First piece: host bridges

JCEF and SWT accept a `NativeUsagePort`: a bound JS query / BrowserFunction,
message source, and host persistence. WebView2 takes its bound postMessage and
message source. The companion supplies an `HttpUsagePort` with its real
authenticated loopback request, download and confirmation policy. These are
explicit injected ports, not fake implementations. The shared React page
never needs VS Code, a URL token or fetch. Missing transports fail explicitly.

Every outbound request is checked with the frozen schema. HTTP replies are
checked before delivery; every page checks all incoming native/VS Code replies.
HTTP operations serialize, so a refresh cannot overtake an earlier query.

`--maxWorkers=3 --testTimeout=120000`. ESLint and Prettier pass for these files.

## Page and bootstrap contract

The separate React entry implements all five ranges, validated inclusive
custom dates, four groupings and metrics, refresh, three export requests and
host-confirmed delete requests. Export/delete replies are correlated by their
request id. Superseded query responses cannot replace the selected range.
The page neither fetches history itself nor invents a save path, deletion
count, confirmation grant or remote transport.

The tiles, sortable breakdown and feature tables keep optional counters
unknown. Cost certainty is shown separately, including API-equivalent plan
cost and retained uncertain liability. Input/output plots contain their cache
and reasoning overlays; those counters are not added to total tokens. Six
stable group colours and Other preserve all supplied group totals. Model
detail shows card provenance/date, precise small prices, its trend and the
Models deep link. Attempts and savings remain separate sources.

Limit windows use their reported duration, refresh countdowns once a minute,
become stale after 15 minutes and await a fresh report after expiry. Weekly
windows receive no inferred pace. Warnings contain text and an icon at
75/90/100%; values over 100% retain their actual accessible description.
Raw rate headers remain As reported, with no invented meter. Budget cards
retain Stop, today's raise and uncertain liability and use only a supplied
projection. Empty breakdowns, features, attempts and model trends show text
instead of empty table headers.

Every plot has a figure/caption, summary, keyboard bucket description and
disclosed data table. The plot itself has one tab stop; arrows and Home/End
visit its buckets. CSS uses `--muse-*` tokens with editor/browser fallbacks,
320px reflow, reduced motion and forced-colour support. SVG uses attributes
and stylesheet classes, with no inline styles.

Before loading `dist/webview/usage.js`, the real host supplies:

- `body[data-host-bridge]`: `vscode` (also the default), `http`, `jcef`,
  `webView2` or `swt`.
- For non-VS Code hosts, `window.museUsageHostPorts` with the matching typed
  port. Native ports supply their bound message sender, inbound MessageSource
  and persistence. HTTP supplies a real authenticated loopback RPC and
  persistence; its operations are ordered. JSON native replies are decoded
  and checked before forwarding. WebView2 replies are checked likewise.
- Optionally, `script#muse-usage-l10n[type="application/json"]` containing the
  frozen `{type: "usage/table", locale, table}` envelope. Both shape and locale
  are checked before mount. Runtime table messages update the page and Intl.
  The existing main-table embedded installer runs first.

Missing/unknown transports, malformed messages/tables and render failures
have explicit localized errors. No key, token, API route or child-process
credential is handled by this UI. Companion authentication, CSP, download and
confirmation remain the real S/E host's responsibility.
