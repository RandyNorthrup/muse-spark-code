## Delivered scope (plan §6 "2a — Cascade, `both`, and `auto` → `both`")

`src/core/judge/cascade.ts` (`cascadeJudge`, cascadeJudge):

- Separate source first, then the same-model follow-up below entropy
  `JUDGE_CASCADE_CONFIDENCE` (`shouldCascadeFollowUp`, cascade.ts:86) or
  always for a high-stakes family. Confidences are the actual entropy
  confidences `1 − H(p)/ln N` via `entropyConfidence`, never `|2p−1|`.
- Combination with B's fitted profile weights: each side's distributions
  are calibrated per alternative through `applyCalibration` against an
  exact identity (source, provider, model, version, endpoint, technique,
  family, prompt/criteria versions and the selection-pinned `fitVersion`),
  then blended as a normalized weighted mean with each side's fitted
  `combinationWeight` (`combineCascadeDistributions`, cascade.ts:123).
- Disagreement can only add caution: the blend is convex, so a cautious
  dissent strictly moves caution against the permissive source alone, and
  no question resolves toward one side behind the other's back. The
  cascade emits advisory `JudgeOutcome` values only, never an allow/grant.
- A partial or top-1 result cannot enter the calibrated combiner (refused
  before calibration, mirroring lane D's guards); the answering side is
  reported as it came. A failed or late separate output leaves phase-1
  behaviour (same-only) with the answering source honestly reported; a
  failed same follow-up leaves the separate answer standing. Per-question
  fallback: a question one side cannot combine passes the other side
  through untouched with its own source.
- Each side dispatches at most once per request through its own injected
  `run`, which owns that side's admission claim: one side is never billed
  to the other's claim, and no retry or fan-out hides inside the cascade.
  Combined `muse` costs and usage sum both receipts. The combined label is
  `uncalibrated` with technique `cascade` and source `both`: no
  cascade-level profile exists until M75's held-out paired runs of
  same-only, separate-only and this cascade certify one. The same model
  stays the conversation's model: the cascade reads its answers, never
  reselects it, and the result names only the answering side models.

`src/core/judge/resolve.ts` (`resolveJudgeMode2a`, resolve.ts:224):

- Resolver matrix over `auto|same|separate|both|off`. `auto` becomes
  `both` only with a verified, available separate source and suitable
  profiles (`separateGate`, resolve.ts:208); otherwise it retains
  phase-1 `same` and its readiness default. Explicit modes bypass only
  the automatic ready-rate floor, never consent, confidentiality,
  provenance or admission. Missing readiness fails closed to
  `source-unavailable`; unverified to `source-untested`; missing profiles
  to `profile-missing` (P0's `JUDGE_NO_ANSWER_REASONS` vocabulary).
- `shouldReResolve` (resolve.ts:161) invalidates a cached selection on
  source, model, endpoint, profile, consent, owner, mode, turn and
  confidential changes; the new trigger fields are optional so existing
  callers compile unchanged (a cached selection is no trust proof; the
  host binds the new identities as Z's wiring learns them).
- Compatibility: `resolveJudgeMode`, `JudgeMode`, `JudgeModeReason`,
  `JudgeModeResolution` and the phase-1 fail-closed order are unchanged;
  both entries share one prefix (`failClosedPrefix`, resolve.ts:89), and
  without a separate readiness the 2a entry delegates every phase-1 case
  to the phase-1 entry (proved by test, not by inspection).

No new user-visible strings: reason codes only, surfaced later through
lane 0's strings by lane U. All 14 l10n tables untouched
(`check:l10n` 0 problems).
