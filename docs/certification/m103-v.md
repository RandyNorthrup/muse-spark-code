## What V implements

- `vscodeMakerHost.ts`: the existing `MakerHost` port, native Send once / Reject
  modal, complete target/payload/serial encoding/reset/flash identity and machine
  analysis, oversized payload preview, wall expiry and cancellation, notification
  mapping, independent Stop and physical-switch warning on a failed Stop.
  The engine owns the frozen snapshot, monotonic expiry, replay checks,
  freshly read identity and opaque single-use binding; V returns only the
  echoed UI answer and never implements G4's classifier or latch.
- Canonical outside-workspace host directories, namespaced `workspaceState`
  and `globalState` adapters, and direct SecretStorage delegation. Machine
  registry transactions remain the portable engine's locked file storage.
  Global state is not a competing cross-process registry.
- Six host-owned command handlers: enable/disable hardware, add/remove machine,
  Stop all and explicitly open the local log. Enable gets a native typed reason
  and calls the guard's required audited/persisted latch callback. Commands
  ignore supplied arguments. Registration validates our protocol, confirms
  target/HTTP warning and collects non-OctoPrint keys through a password input;
  they never enter a message, memento, log, child process or tool argument.
  The local key reference is cleared in finally. OctoPrint uses a required
  Read-only Access appkeys callback, never pasted credentials. Removal carries
  the immutable registration UUID for the engine's generation check.
- `makerPreviewPanel.ts`: one reusable tab, separate shared preview page assets,
  cached/replayed validated preview messages, bundle-only resource roots,
  command URIs disabled and existing nonce/default-src-none CSP. Contents do
  not enter HTML. Incoming messages are parsed; only Ready and independent
  Stop are handled, even before readiness. Approval/action/path requests
  cannot become authority. STL requests contain opaque artifact UUIDs.
- `ide/makerTools.ts`: six lazy wrappers (`device_list`, `serial_read`,
  `serial_write`, `machine_status`, `machine_send`, `machine_stop`) gated by
  tool capability, trust and the hardware latch. Invocation rechecks admission;
  serial/send reject unattended use; HTTP observation remains possible.
  Strict argument names and the shared schemas reject approval flags, tokens,
  credentials, endpoints and arbitrary stop payloads. Protected engine callbacks
  own classification, leases, target binding, limits, final write and audit.
  Stop stays usable after revocation/cancellation. Refused/failed results throw;
  unknown-send and missing-audit outcomes survive notification failure with no
  dispatch retry.
- Model-facing descriptions, refusals and Stop text remain English in the
  guarded `MAKER_HOST_MODEL_TEXT` block, even when the native UI is French.
- `makerEntry.ts` installs each caller's display table. `makerPreviewEntry.ts`
  loads only on the first preview, even after the maker host is active. Their
  Node bundles use the existing shared English fallback and mini-parser runtime.
  Three added UI keys have real translations in all fourteen tables. No
  `MakerHost` or maker protocol changes, dependencies or escape hatches.

## Wiring handoff (W/U/R/E)

W binds the callbacks to G4 and the protected P/M engine, supplies the selected
model's capability and top-level attended session state, persists/audits the
hardware reason through workspace storage, and retains all engine binding
objects locally. Bind both preview and MCP Stop to `host.stop`, not a queued action handler.
The engine must check registration generations at removal and reject stale
records. All Stop paths abort the engine's streams before sending fixed stops.

W exposes the command IDs in the manifest, palette and an unused keybinding,
adds the two host bundles to the package allowlist, binds the shared U wizard
and scrubbed explicit log view, and builds `makerPreview.js`/`makerPreview.css`
(the separate page starts with `makerReady`). U/W resolve STL artifact IDs in
host-owned storage; V never accepts a page-supplied path or guesses a mesh wire.
No shared preview page, mesh viewer or real native-dialog interaction is claimed
by this lane. Appkeys HTTP frames are not captured on this trunk: W must supply
that implementation or keep OctoPrint registration unavailable.

The base lacks `src/shared/featureCatalog.ts`, `scripts/gen-reference.mjs` and
`check:reference`. Command/tool facts are in README here; Q-M103V-REFERENCE
assigns the canonical catalogue merge and regeneration to W before exposure.
No replacement catalogue or gate bypass was created.

## Equivalent editor surfaces

This is the required feature mapping, not a claim that R/MHP/E qualification
has run in V. Every operation uses the same portable engine/contract.

| Feature                         | VS Code family / remote extension host (V)                                            | Runtime + ACP + companion (R)                                                                     | Native via MHP (M64/M65)                                       |
| ------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Hardware admission + reason     | Trusted attended native input; workspaceState and required guard latch                | `hardware enable/disable/status`, ACP `/hardware`, shared companion UI; runtime workspace storage | Runtime latch/storage; shared dialog through MHP               |
| Single-use physical approval    | Native modal; exact immutable request; engine retains binding                         | ACP allow_once/reject_once or shared companion dialog; same engine binding                        | Shared dialog/MHP echo; runtime retains binding                |
| Stop + cancellation             | Independent host method, status item and command; preview Stop before Ready           | Client cancel, companion button, CLI `stop-machine`; ACP slash between turns                      | Editor toolbar/command and companion; runtime out-of-band Stop |
| Machine registration/removal    | Shared wizard + native confirmation/password; SecretStorage; generation-bound removal | `machines add/list/remove`, stdin-only credentials, OS store; companion wizard                    | Runtime registry/OS store and shared wizard                    |
| OctoPrint credentials           | Required Read-only Access appkeys callback; no pasted key                             | Same captured appkeys engine flow                                                                 | Runtime engine flow                                            |
| Devices, serial, status/send    | Validated lazy `ide` wrappers over protected engine; per-model tool capability        | In-process Model API tools and runtime loopback MCP on Muse Code                                  | Runtime engine/tools                                           |
| Notices + uncertain send        | Native notices and outcome in tool result even if notice fails                        | ACP updates/companion notices; same outcome and status-before-retry rule                          | Shared notices through MHP                                     |
| Explicit local device log       | Required scrubbed log-view callback; no model/export feed                             | CLI/companion explicit local log                                                                  | Shared view through MHP                                        |
| Read-only payload/STL preview   | Restricted separate tab; opaque artifact UUID                                         | Shared companion preview                                                                          | Shared webview through MHP                                     |
| Host storage/secrets            | Canonical outside-workspace dirs, workspaceState/globalState, SecretStorage           | Per-workspace data dir, portable locked registry, OS credentials                                  | Runtime-owned storage/credentials                              |
| Display language + lazy loading | Caller table in each lazy factory; two lazy Node bundles                              | Caller table in runtime/shared UI bundles                                                         | Runtime/shared UI table                                        |

Ports belong to the engine's machine: local extension hosts use local ports,
Remote-SSH/WSL/containers use the remote's; cloud hosts have offline/simulator
features and only reachable registered machines. ACP clients without a webview
use the loopback companion page. Headless actuation is not enabled by V.
