## Lint memory investigation

Both hosted static-gate logs for PR #138 confirm
`node --max-old-space-size=6144 ... eslint.js . --max-warnings=0` fails with
heap exhaustion, exit 134: Ubuntu job `113017956701`, Windows job
`113017956554`, run `37687198664`. The 6 GiB setting already exists on main;
raising it is not the first remedy.

Sequential local measurements use `/usr/bin/time -v`, Node 22.23.3,
`CI=true`, the complete lint file set and the inherited 6144 MiB heap cap:

| Configuration                                                        | Peak RSS (KiB) | Wall time |                                 Exit |
| -------------------------------------------------------------------- | -------------: | --------- | -----------------------------------: |
| Release pins, original project service                               |      5,518,508 | 4:33.04   |                                    0 |
| Only typescript-eslint changed to 8.71.0                             |      6,596,428 | 15:01.27  |             134 (V8 heap exhaustion) |
| All six updates, immutable programs for the same six projects        |      6,583,200 | 10:41.17  |   134 (SIGABRT / V8 heap exhaustion) |
| Accepted five updates, original project service; initial test helper |      5,367,196 | 11:22.93  | 1 (seven helper lint errors; no OOM) |

The isolated installation changed only the typescript-eslint package family
and its existing nested ignore resolution. The other five direct packages
remained at their release versions. The new strict rule is enabled at error
level, as confirmed by ESLint's effective configuration. The upstream project
service is unchanged except its version; the new rule's
[`hasDeepEnumAssignmentMismatch`](https://github.com/typescript-eslint/typescript-eslint/blob/v8.71.0/packages/eslint-plugin/src/rules/no-unsafe-enum-assignment.ts)
recursively examines generic arguments, numeric index types and object
properties for each assignment, including assignments with no enums.
Its traversal expands and retains TypeScript types. This is the source-level
explanation for the measured regression; no heap snapshot was collected.

All six updates were compared using immutable compiler programs for the same
host, webview, unit, e2e, integration and code-intelligence fixture projects.
The temporary probe changed no rule levels, ignores or file set and also
exhausted the 6 GiB heap. GNU time reports a misleading zero in its exit-status
field when this direct child terminates by signal; its signal-6 record and the
shell/tool's actual 134 are the result, not a pass. Wall times are observational
on the shared rig; unrelated lane work was not stopped.

Chosen fallback: keep `typescript-eslint` and its exact family at 8.70.1;
accept the other five proposed versions. The production ESLint configuration,
heap flag and all existing gates remain unchanged. No rule disable or extra
heap setting ships. Revisit 8.71.0 after an upstream fix bounds the recursive
type walk or a measured, complete configuration repair passes clean CI.

The accepted tree completes lint's whole file set below the release baseline
peak. Its first run reports only seven syntactic errors in the new JavaScript
test helper (missing Node imports, a boolean name and returning array push).
Those are repaired without touching rules; changed-file lint and all five SDK
tests pass afterward. Final clean-clone lint is still required before closure.
A diagnostic-only check of the two expensive conversation/Model API host test
files with 8.71.0's new enum rule disabled finishes in 46.60 s, peak 1,848,708
KiB, exit 0. This control is not a gate receipt or a shipped configuration.

Pre-clone receipts: all five typecheck projects pass; `npm run build` passes
with extension 462.8 KiB / 600 KiB and runtime engine 762.8 KiB / 875 KiB,
including split/global/notices checks. `security:audit` passes with precisely
