## What the milestone rests on

- Muse Code's MSP wire shapes (PLAN.md D11, the live captures of M4–M8):
  the fake CLI serves exactly those shapes, so the SDK's `Connection`, the
  host's zod schemas and `mapNotification` are exercised unchanged.
- Node's spawn rules on Windows: a `.cmd` cannot be spawned without a
  shell, so the fake is a real executable there (`fake-muse/stub.cs`, 40
  lines, compiled at test time) that runs `serve.mjs` under the tests' own
  Node with inherited standard streams.
- The CLI's trace logs: one `cli-<uuid>.log` per `muse serve` process,
  locked while it runs, lines of `event="model.attempt.lifecycle" …
phase="admission"` for each model attempt. **Finding:** the marker string
  recorded after the cost incident (`event="model.attempt.lifecycle"
phase="admission"`, adjacent) never matches a line, because other fields
  sit between them; every "attempt count" made with it, including the one
  in `m12.md`, measured nothing. The drill now matches a line regex and
  reads the log that carries its own session id. `m12.md` carries the
  correction; the `muse init` claim there holds on recount (0 attempts in
  both one-second process logs).

## Process-level drills (the fake CLI, real child process)

| Drill                                           | What happens                                                                                             | Asserted                                                                                                           |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Host dies mid-turn (`die`)                      | The fake exits 1 after `turn/started`.                                                                   | `onExit` fires with `code 1, signal null`; `isRunning` false; the stderr line is logged; `ensureHost` spawns anew. |
| Malformed frame (`malformed`)                   | An `item/delta` without its item id, then a normal reply.                                                | The turn completes with the reply; nothing logged as an error.                                                     |
| Binary will not start (`MUSE_FAKE_START=crash`) | The fake exits 3 before the handshake.                                                                   | `ensureHost` rejects; `isRunning` false; the stderr line is logged.                                                |
| No binary anywhere                              | A missing configured path with `PATH`, `LOCALAPPDATA`, `HOME`, `USERPROFILE` pointed at an empty folder. | `ensureHost` rejects with "not installed"; the machine's real CLI is never found.                                  |
| Cancel (`slow`)                                 | The fake waits for `turn/cancel`.                                                                        | `turnCompleted` with `terminal: 'cancelled'`.                                                                      |

## Security

- The fake CLI runs under the tests' own Node from a temporary directory
  with only the variables the test passes; it never touches the real CLI's
  files, and the "no binary" drill isolates discovery so the real CLI is
  never spawned by accident.
- The live drill uses the CLI's own sign-in exactly as the panel does; the
  pasted Model API key is not involved; the workspace is empty and deleted
  after.
- A rewind reverts through the same review path as a single Revert: a
  file changed since the edit is reported, never overwritten.

## Findings recorded during the milestone

- The attempt-count marker (above); `m12.md` corrected.
- The reminder agents' cost (above).
- Windows: an e2e "missing binary" case must isolate `PATH`, `LOCALAPPDATA`,
  `HOME` and `USERPROFILE`, or discovery finds the machine's real CLI and
  spawns it.
- The C# compiler's `/warnaserror+` compile of the stub is about one second
  and happens once per vitest run.
- The first `v0.3.1` release run failed on the Ubuntu and macOS runners
  (Windows passed): the turn-driving e2e cases timed out. Reproduced under
  WSL Arch Linux only with the full `vitest run --coverage` (never with the
  file alone) and traced to the test harness, not the fake or the SDK: when
  the CLI's response and the turn's notifications arrive in one stdio chunk,
  the `turnCompleted` event is counted before the wait takes its baseline,
  so the wait never ends. The harness now takes the baseline before sending
  or deciding (`start(text)` returns `done`); three full-gate runs under WSL
  and the Windows suite passed. The per-case timeout is 30 s for slower
  runners. The tag was moved to the fixed commit before any release existed.
