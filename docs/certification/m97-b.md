## Lane-boundary decisions

- **Runner injection, unavailable by default.** Every scan path takes an
  injected `LegalScanRunner` (the type lives in lane 0's `src/shared/legal.ts`,
  value-free, so both bundles name it without carrying the scanner). Nothing
  is wired to a real scanner: `extension.ts` builds the runners from
  `dist/legalScan.js` (lane R's build entry), which does not exist yet, so
  every path refuses with the installed `legalScanUnavailable` until lanes
  S/R land. No lane-B commit depends on unmerged lane code.
- **No new `MODEL_TEXT` block.** Tool descriptions and model-facing refusal
  reasons follow the inline-literal precedent of `tools.ts` and
  `codeIntel/definitions.ts`; only the trust refusal on the Model API backend
  uses `MODEL_API_MODEL_TEXT` (that bundle's own block, read there). No
  split-gate change was needed: `npm run build` is lane R's gate to extend.
- **No protocol or schema changes.** Lane 0's `requestLegalScan` /
  `legalScanReport` pair and the input/result schemas are used as defined.
  The host generates `requestId` (`legal-<sequence>`, one scan at a time).
- **No VS Code command contribution.** `/legal` lives in the prompt and the
  in-panel slash palette (like `/review`); no `package.json` command was
  needed. The `skills/` root directory is new: AGENTS.md's layout line said
  the bundled-skills installer lived under `skills/`, which did not exist;
  lane B creates `skills/legal/` as the extension's own skill root. The
  pinned `vendor/high-quality-projects-skill/` package is byte-untouched
  (its suite still passes).
- **The hold reuses M70's class, never a copy.** `src/core/review/planModeHold.ts`
  stays in `dist/review.js` (the split gate forbids it at activation), so the
  controller takes the hold from the scanner bundle's `createHold` factory
  (a required export: a bundle without it would scan a live conversation
  unheld). `takePlanHold` / `dropFailedHold` were extracted from
  `submitReview` so review and legal share every hold rule with zero
  duplication (jscpd threshold is 0); the review path is behavior-identical
  (520 controller + review tests green).
- **A user's mode choice releases the hold, not the scan.** The scan is
  read-only, so it continues unheld with nothing put back; the session going
  stops it through its signal. The restore-failure notice names a review
  (`reviewModeNotRestored`); that wording is M70's, reused for the rare
  failure path rather than duplicated.
- **The Reviewer tool set is untouched.** Adding `legal_scan` there would
  change the exact tool set a live e2e test pins; the deterministic `/legal`
  command does not need it.
- **CHANGELOG under `[Unreleased]`** follows AGENTS.md rule 10 (the D76 plan
  commit set the precedent); the `docs/` evidence record itself is lane I's.
