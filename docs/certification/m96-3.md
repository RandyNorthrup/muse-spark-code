## Design and scope

The lead requires worker cost to settle per attempt through ordinary request
outcomes. `ResponseAttemptGuard.reserveUsage` returns the callback for one
attempt. The host owns it before final admission, marks dispatch adjacent to
transport, and closes it once at `endRequest`. Retry/rebuild preparation
awaits the prior outcome before a new reservation. Valid usage reports
`billed`; a dispatched attempt without valid usage reports `ambiguous`;
refusal or a failure before dispatch reports `released`. A later successful
retry never replaces the earlier ambiguous attempt's full maximum.

The engine port maps those outcomes to the exact service ordinal and awaits
persistence. Final uncertain claims remain counted, labelled estimated, and
are closed rather than left reserved. Explicit Reset can clear completed
liability; open reservations still survive Reset. A revoked admission during
the reservation save removes the never-dispatched claim before returning.
The compaction wrapper preserves the same worker preparation and outcomes.
Cancellation cannot overwrite a proved 429 refusal, and a throwing
pre-fetch callback cannot mark the worker attempt dispatched.
No wire shape changes: this outcome is an internal accounting contract.

Changes stay in the engine accounting files. No dependency, guard widening,
threshold, timeout, hook, credential handling, paid/live call, UI styling,
merge, push or public team activation. No installs.

## CM963NF — native worker new files (2026-10-11, Kubuntu)

The engine's `withWorkerFile`, `fenceWorkerToolIo.writeFile` and
`reserveFile`, and the ACP worker's `acpFsWrite` now share the retained root
grant and a first-use native create factory. Existing writes retain their
opened-handle checks. Missing-file conditional writes refuse before creating
anything. Role/write-path/protected-path policy is checked before preparation
or creation and checked again on the opened file. Missing helpers refuse;
there is no pathname-create fallback. Native output is schema-validated and
bounded to 4,096 bytes with the existing five-second helper deadline.

POSIX operations are included in the existing `muse-created` source and
Darwin helper. Directory components are opened relative to verified handles
without following links. Root/ancestor device/inode identities, kernel handle
names, descriptor ancestry, device and Linux mount identity are checked.
Creation uses exclusive `openat`; its single-link file identity is checked
again after Node opens it. An interleaved parent move at the final native
create is refused, and the helper removes only its own unchanged empty file
through the retained parent. It refuses cleanup of a replacement or changed
inode. Prepared directories can remain after a later refusal; their actual
count reaches the before-create callback.

Reservations retain the exact created handle. Fill checks its identity,
emptiness, role, root and native name before writing binary bytes. Release
removes only that same empty single-link inode. Replacement files, owner
content, hard links and revoked admission are refused without overwriting
owner bytes. Reservation completion closes the descriptor exactly once.

The Windows source implements the same protocol through handle-relative
`NtCreateFile`, exclusive disposition, no reparse traversal and retained
root/component/file handles without `FILE_SHARE_DELETE`. Release disposes
the held file. Windows source and cross-platform tests are supplied here;
**this Linux receipt does not certify Windows execution**. Mac mini, Linux
arm64, independent Grok boundary review and hosted three-OS native builds
remain lead-owned acceptance work. Teams remain hidden pending complete
M96 integration and certification.

### (3) Missing helper and assembly-load failures keep their true reason

Test: `acpFsWrite` with `WORKER_NATIVE_IO` (no `workerNativeOperation`,
no `windowsJob` configured) expects `teamFileHelperMissing`. Two Windows
shapes, both fixed in `src/core/team/workers/workerOps.ts`:

  mapper keeps the sentence it already carries. POSIX path unchanged
  (still helper-missing, now via the typed flag instead of the `ENOENT`
  backstop).

  launcher's existing helper-failed marker already carries the exception

  kinds maps to helper-missing (cause chain kept, idempotent through the

### (4) A file parent is not a link

Test: `acpFsWrite('src/plain/new')` with `src/plain` a regular file.
Expected cannot-create; got the link sentence. Exact path on Windows:
`createWorkerFile` ascends to `src` (`remaining='plain/new'`; Node's

directory. True → new `RefuseReason("parent is not a directory")`, new
`WORKER_REFUSALS` row mapping to `cannotCreate` (as POSIX maps `ENOTDIR`

C change). A junction/symlink parent still answers false (reparse) and
keeps `parent unavailable or linked` (`refusesLink` parent case
unchanged); a truly absent parent fails the probe the same way and keeps
its reason. The `directory && create` line above is untouched, matching
POSIX's `mkdirat`-on-file `directory create failed`. The drift test
(`refusal table matches the helpers it types`) and the launcher
forwarding/mapping tests cover the new row automatically; no new sentence
means no l10n change (14 tables untouched, `check:l10n` must stay 0).
