## Security

- An output document is a read-only virtual document (`muse-output:`)
  holding text the transcript already showed or the CLI's stored output for
  that item; the provider keeps the last twenty in memory and writes nothing
  to disk.
- The warm-up starts the same host the first send would start, with the same
  arguments and environment; no model call is made (`model/list` only).
- The response Copy hands the reply's markdown to the same host clipboard
  path as the code-block Copy.

## Findings recorded during the milestone

- Muse Code 1.3.0 on Windows can answer `approval/decide` with "approval
  decide settlement failed: approval ledger durability fence: background
  task failed: retained acknowledgement fence left records unflushed" after
  the decision took effect; it joins the Windows `session/rename` and
  `session/fork` write failures (M8) as CLI-side faults the panel reports.
- The React compiler lint (`react-hooks/set-state-in-effect`) rejects a
  transcript-follow effect that sets state; the "new below" flag is derived
  from the transcript identity seen at the last scroll instead.
- Claude Code's inline diff expands into an embedded, editable editor; that
  needs Monaco, a third-party package the owner has not authorised, so the
  expand opens VS Code's own diff editor instead.
