## Lane scope and bindings

Implement D95.11 entirely inside `src/core/schedules/events/`: validated
sources, git-ref transitions, confined file-watch notifications, host events,
manual fire, injected plan/network/governor/usage/team/webhook sources,
conditions and history preview, per-trigger debounce/coalescing, permanent
event claims and the bounded, scrubbed, fenced, untrusted data block.

- **S/W:** bind the event engine's `claim` to `ScheduleStoreV2.claim` and
  route its admitted occurrences through S's scheduler and T's composed time
  trigger. Claim precedes buffering/delivery and is never rolled back, so a
  crash may lose a claimed occurrence but cannot replay it. S owns catch-up,
  permanent claims, paused/removed schedules and final settlement.
- **W/editor hosts:** create one source registry per workspace; inject
  trusted local git reads and workspace-confined file watchers. Host finish
  events use stable session/turn/lane/question identities, never provider
  wire frames. The manual source targets only the requested schedule.
- **M113 P/N:** inject the plan reader and validated network/store event
  projections, history and resource ETags. Network permission is checked on
  every poll/history read; no endpoint/parser is invented here.
- **M107/M108/M96/M112/M110:** inject level, threshold, team, answered-question
  and authenticated webhook event ports as their milestones merge. Missing
  bindings return explicit capability/history reasons, never fake success.
- **M84:** reuse the actual export builder to scrub individual event strings
  with mandatory account/path redaction and the caller's local roots. Preserve
  ordinary opaque event identities; hash an identity changed by the scrub so
  distinct secrets cannot collapse into one redaction marker.
- **M109 T/W:** inject the taint marker; the block always has fixed
  `trust: untrusted` and contains no grant, target, tool or executable field.
  W supplies `SCHEDULE_MODEL_TEXT.eventLead` when declaring its guarded bundle
  readers. This lane does not edit another lane's model block/build rules.
- **V/X/M104:** expose the existing `eventSources` and `historyPreview`
  response payloads through the versioned lane-0 channel, equally for native
  bridges, companion, ACP, CLI and later desktop/TUI. No VS Code import.
- **W/HELPREF:** `featureCatalog.ts` is absent on the base. Register event
  sources, unavailable reasons, conditions/history, coalescing and manual
  `schedule fire` in help and shipping docs during W. This lane registers no
  command/setting and reuses the translated lane-0 labels/messages.
