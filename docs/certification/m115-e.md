## Lane scope and bindings

Implement D95.11 entirely inside `src/core/schedules/events/`: validated
sources, git-ref transitions, confined file-watch notifications, host events,
manual fire, injected plan/network/governor/usage/team/webhook sources,
conditions and history preview, per-trigger debounce/coalescing, permanent
event claims and the bounded, scrubbed, fenced, untrusted data block.

- **S/W:** bind the event engine's `claim` to `ScheduleStoreV2.claim` and
  route its admitted occurrences through S's scheduler and T's composed time
  trigger. Claim precedes buffering/delivery and is never rolled back, so a
  crash may lose a claimed occurrence but cannot replay it. S owns catch-up,
  permanent claims, paused/removed schedules and final settlement.
- **W/editor hosts:** create one source registry per workspace; inject
  trusted local git reads and workspace-confined file watchers. Host finish
  events use stable session/turn/lane/question identities, never provider
  wire frames. The manual source targets only the requested schedule.
- **M113 P/N:** inject the plan reader and validated network/store event
  projections, history and resource ETags. Network permission is checked on
  every poll/history read; no endpoint/parser is invented here.
- **M107/M108/M96/M112/M110:** inject level, threshold, team, answered-question
  and authenticated webhook event ports as their milestones merge. Missing
  bindings return explicit capability/history reasons, never fake success.
- **M84:** reuse the actual export builder to scrub individual event strings
  with mandatory account/path redaction and the caller's local roots. Preserve
  ordinary opaque event identities; hash an identity changed by the scrub so
  distinct secrets cannot collapse into one redaction marker.
- **M109 T/W:** inject the taint marker; the block always has fixed
  `trust: untrusted` and contains no grant, target, tool or executable field.
  W supplies `SCHEDULE_MODEL_TEXT.eventLead` when declaring its guarded bundle
  readers. This lane does not edit another lane's model block/build rules.
- **V/X/M104:** expose the existing `eventSources` and `historyPreview`
  response payloads through the versioned lane-0 channel, equally for native
  bridges, companion, ACP, CLI and later desktop/TUI. No VS Code import.
- **W/HELPREF:** `featureCatalog.ts` is absent on the base. Register event
  sources, unavailable reasons, conditions/history, coalescing and manual
  `schedule fire` in help and shipping docs during W. This lane registers no
  command/setting and reuses the translated lane-0 labels/messages.

## Source adapters and final debounce regressions

First checkpoint commit: `a763a3ec1`, hooks on; lint-staged and Gitleaks passed.
The late-drain/history regressions initially failed both named tests (35
others passed). The engine now keeps a matured burst separate from a later
burst even before a drain, and discard clears both. Preview `matchedCount`
counts distinct filtered bursts using the trailing debounce window; its
`events` retain every distinct matching instance, scrubbed, for inspection.
The restored core run passes 38 tests. The three source files pass 34 tests.

Local-git tests create and remove only their own temporary repository. They
read actual branches, tags and packed refs; prove two readers share an event
identity, revisiting a commit has a new identity, and a changed ref/revision
during a read is refused before the next poll retries. One initial fixture
waited on `mktree` stdin; its owned child was terminated and the fixture now
closes stdin. No timeout was changed. No remote or live service is contacted.

File-watch notifications are validated and matched against workspace-relative
globs before admission. The injected watcher must already confine symlink
and junction targets to its workspace. Every callback rechecks capability,
and disposal suppresses late callbacks. Distinct writes to one path have
distinct stable identities. W schedules a debounce wake after enqueue and
binds `drain` and `discard` to S; S rechecks current record/authority before
delivery, and owns event/time composition, catch-up and final settlement.
Coalescing is host-local; permanent event claims are shared across hosts.
Git/plan snapshot sources establish a baseline rather than inventing missed
events. Sources without real retained history explicitly refuse the preview.

All source projections are internal contracts. M113 supplies full resource
event snapshots with resource ETags (not cursor-specific responses), its
network gate and its bounded polling/history policy. The plan projection is
`{ milestoneId, status, certified, revision }` from P's grammar reader. Git's
projection is `{ name, objectId, revision }`; its local implementation reads
no file contents or credentials and uses ENVFENCE's shared child environment
filter. Network replies and each projected event are parsed before use. M110
validates webhook authentication/signatures, body bounds and replay before
its port; E requires its authenticated capability on subscription and every
callback. G/U bind causal run identities/depth and unattended authority; an
event's scalar fields never become authority. Raw projection/schema failures
are not log messages; source callbacks report only a fixed source id.

The new source code uses no new localized key or manifest text: technical
capability codes follow the translated `Unavailable` label, and no-history
uses lane 0's translated message, all read at call time. Shipping commands,
README/CHANGELOG/PLAN/help registration and bundle readers remain W's named
handoff, per the ownership table; this lane does not edit W's files.
