### P2-1 — shared burst ownership and takeover

The engine's complete open/join/consume transition runs inside the injected
`ScheduleEventClaimStore.transact` lock. One open burst per schedule holds
only safe representative data, the first member's stable run id, owner UUID,
trailing window end and count. New unique events inside that window join it
without moving ownership; duplicate members neither count nor extend the
window. Expired bursts remain separately persisted if the next window opens
before a drain. Owner drain commits removal first. A survivor may consume an
abandoned burst at window end plus one debounce interval (30 seconds), under
the same lock, so a returning owner/competing survivor cannot fire again.
`discard` clears open/matured bursts while preserving both receipt sets.

Regressions: `joins the A/a B/b host interleaving into one shared burst`
(now exactly one fire with count 2; before: two fires), `takes over an abandoned
burst after the window plus lease exactly once` (two competing survivors,
no early takeover and no later owner/restart fire), and `retains matured bursts
while a different host opens the next window`. Clients share only committed
fake disk state, with independent cloned transaction values.

### P2-3 — one normalized namespace and legacy replay fence

Every raw key, including one that already starts `evk1:`, becomes `evk1:`
plus SHA-256/base64url over `evk1:` and the UTF-8 byte length followed by `:`
and the raw UTF-8 bytes. Identity is computed before M84 scrubbing; shared
state/model blocks/previews receive the scrubbed payload and normalized key.
The account fixture, its old unprefixed digest and a raw normalized-looking
key now have three distinct identities. Three separate debounce windows each
produce their own fire/run id, proving all three keys remain eligible.
Imported legacy opaque/redacted receipts reject their own raw replays, across new clients, without inserting any new legacy receipts.

Regressions: `separates a scrubbed account key from its raw digest and prefixed
raw keys`, `fires distinct account and digest keys and treats an evk1-looking
raw key as fresh`, and `migrates legacy opaque and scrubbed receipts without
admitting their own replays`. The initial unchanged code failed the interleaving
and namespace regressions (39 passed, 2 failed). The takeover regression was
strengthened to count surviving hosts' output before invoking the original
owner; its deliberate lease/consume breaks fail below.
