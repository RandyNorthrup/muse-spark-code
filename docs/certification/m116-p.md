## REDM116P outcome and serialized-policy redesign (2026-10-06, macmini)

This record supersedes the shell-parser and reservation claims in the earlier
repair above. Work continues from `23897cbc` on `m116/p`. No paid/live model
calls, external network, real pushes, rebases or merges are part of this lane.
The rebase and hook-bypass spellings below run only inside owned, disposable
fixture repositories. Lane commits use the unmodified `.husky/_` hooks.

The security control is the outcome: `beginWork` snapshots all reachable refs
(including detached HEAD) and the configured hook set. `verifyWork` enumerates
new commits reachable from the retained work refs, then runs Git's native
`hook run` for pre-commit and commit-msg on each original tree/message, and
pre-push once on the exact range (including Git's four-field stdin). Commit
verification stages against the first parent; a new root gets an unborn index.
Push verification retains the original HEAD and a clean index. The push set
includes ancestors introduced since the first recorded workspace work, so a
later work baseline cannot hide an earlier unverified commit.
Configured relative wrappers are copied byte-for-byte when absent. Changed
hook bytes/configuration, hook-modified trees/messages/HEAD, failed execution,
denied ordinary tool admission or failed cleanup cannot get a passing receipt.
Temporary directories and the verification worktree are removed. Git must
support native `hook run --to-stdin`; an unavailable runner is a violation,
never a bypass or hook substitution.

Receipts are strict `verification` records with `workId`, `moduleId`, `commit`,
`hookDigest`, `scope` (commit or push), `result` and `at`. A refs/hook-inspection
failure publishes a failure-only work marker; it cannot satisfy a commit or
push receipt. Commit receipts are reusable only for the same commit and hook
set; separate push receipts bind the exact remote, URL and
all local/remote ref/OID tuples. A failed record adds a strike throughout its
module family; a missing receipt blocks push and completion. Receipt admission
re-reads refs and hook definitions, so a new commit or changed hook set cannot
use an earlier receipt. Hook output is scrubbed and returned to the person;
raw output, messages and file contents never enter the journal. Work/lease/
receipt records are mandatory retention evidence. Journal loss still fails
closed; opt-out and escalation clearing still require the actual user's
trusted authority callback.
