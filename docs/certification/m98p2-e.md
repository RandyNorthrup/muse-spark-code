## What shipped

`createByoJudge` is a library. Nothing in the production graph imports it.
`src/runtime/judge/judgeEntry.ts` still builds `dist/judgeP2.js` without this
module, so the production bundles are unchanged. Knip, dpdm, the production
build, localization, and the host-API check were not run: this lane adds no
production import, command, setting, string, or host/Node API.

The library reads an injected M95 `ProviderClient` slice (identity, format,
auth, `currentKeyDigest`), the resolved capability record, the price card,
and D78's `JudgeDailyLedger`. It does not open a second ledger, registry,
key store, or transport. The only network-shaped call is the injected
`ByoRequestPort.complete`. A transport object may also expose `startAgent`;
the runner never calls it.

Technique comes from the captured record agreed with the judge capability.
The provider id is an identity key. The dialect string does not select a
technique. Captured top-k becomes `logprob` with that top-k. Captured top-1
becomes technique `top1` with `requestTopK` 1 for a noul, and a stated call
for a choice or score only when a structured format was captured. A dropped
or refused field states only on that same captured format. Unknown logprobs,
text-only output, and an unknown format list produce no answer. Format
preference is `strict_schema`, then `json_schema`, `forced_tool`, then
`json_object`. The judge capability's `stated` boolean does not invent a
format. `requiresEffortNone` and `minOutputTokens` are copied from the record.

`same` must be the chat provider, model, and endpoint. `separate` stays
labelled separate when the ids coincide and when they differ. A chat, record,
provider, endpoint, confidential-policy, key, price, or consent change drops
the per-instance cache and rebinds after every wait. Confidential separate
work sends nothing. Confidential same work follows the chat model's allow or
refuse policy.

Decoding uses the committed Ollama `/api/chat` body in
`test/unit/fixtures/localJudgeCapture.json` (`qwen3:4b-instruct-2507-q4_K_M`,
singular `logprob`, optional `bytes`). Other formats stay on a strict
normalized seam (`text`, `usage`, `alternatives`) until their own capture
exists. Empty or missing logprobs are a failure. Content text is never a
probability. A plural `logprobs` key is rejected. A multi-character token is
not sliced into an option letter. Top-1 uses the first candidate,
`exp(logprob)`, floor `JUDGE_TOP1_MIN_PROB` (0.8), and `partial: true`. A
short returned top-k is an answer with unseen mass 0 and `partial: true`.
Under the floor the first call is a fallback: its usage is settled, and a
second stated call goes out only when a structured format was captured.

Admission measures the system turn, the user turn, and the full state on
every question (`maxQuestionsPerBatch` is 1; each batch still carries the
state). Context is the minimum of the record limit, the capability window,
and `JUDGE_MAX_STATE_TOKENS`, minus the output floor. The Ollama body, or
the seam when there is no Ollama body, must fit in `JUDGE_MAX_BODY_BYTES`
(64 KiB) or the whole plan is `over-context`. Question ids are not written
into the outbound body. An Ollama body always sends the captured
`think: false` and `stream: false`. Logprob and top-1 add `logprobs: true` and
`top_logprobs`. A stated Ollama body omits those fields. A non-Ollama body
carries the seam fields and no invented vendor keys.

Money uses `reserveRequestUsd` and `settleUsageUsd` on the injected ledger.
A priced call reserves before send and asks consent once for that price
fingerprint against the shared daily budget. Local and plan prices reserve
nothing and do not ask paid consent. An unknown price, an invalid card, a
missing key, a missing ledger on a priced call, a declined or expired
consent binding, and a reservation above the remaining balance dispatch
nothing. Settlement uses the captured usage, which can differ from the
reservation. In the priced fixture, `measureTokens` returns 4, so system
plus user is 8 input tokens and the output floor is 1; the card is 2 USD
per input token and 4 per output token, so the reservation is 20 and the
capture's 30 input / 1 output settles 64. A sent call whose body cannot be
decoded keeps the claim. A reservation that is cancelled or whose consent
expires during the wait settles 0. The key digest is a readiness boolean on
the snapshot. It is not stored, logged, placed in the body, or passed to a
child. Providers with `auth: 'none'` do not call `currentKeyDigest`.

This lane authorized and performed **0 live, 0 paid, and 0 local model
calls**. A missing non-Ollama logprob shape stays on the future row
`L98P2-CAPABILITY` (at most 2 attempts per named model variant) and is not
authorized here.
