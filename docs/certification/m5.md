## What the milestone rests on (verified before code, PLAN.md §6 M5)

- `muse serve` 1.3.0 grants `userShell`, `sessionMcp` and `sessionListStream`
  when `initialize` asks (`scratchpad/probe-caps.ts`, no session).
- `session/start.config.mcpServers.<name>` with `transport: streamableHttp`
  makes the host connect at session start (`scratchpad/probe-mcp.ts`): it
  posts `initialize` (protocol `2025-06-18`, client `tbh 0.1.0`),
  `notifications/initialized` and `tools/list` to the given URL with the
  given `Authorization` header, and its durable log registers the tool as
  `mcp__ide__getDiagnostics` (namespace `mcp__ide`), the very name Claude
  Code's IDE server uses.
- In-workspace file edits are applied by the CLI without prompting (M4,
  D11), so edit review is after the fact; `turn/start.displayText` is the
  transcript's presentation form and never model-visible (MSP tdd SS3.2).
- The Claude Code docs (claude-code-guide agent, 2026-09-22): the composer
  chip shows the file name and the selected line count with an `×`; the
  selected text and path go to the model; excluded / gitignored files share
  their path only; `autosave` saves before Claude reads or writes;
  diagnostics come from `mcp__ide__getDiagnostics` ("the errors and warnings
  in VS Code's Problems panel", optionally scoped to one file); the code
  block buttons and the exact reminder wording are not documented, so the
  `<ide_selection>` / `<ide_opened_file>` wording follows the reminders the
  Claude Code CLI itself injects.

## Live check through the extension's own controller (real turns)

`scratchpad/live-m5.ts` drove `MuseCodeBackendManager` → `ConversationController`
with a recording surface, mode Edit automatically, a real `IdeMcpServer`
serving one fake diagnostic, and an `EditReview` whose diff opener records
the rebuilt "before" text (workspace `C:\muse-live-ws`, real tokens;
`live-m5.log`, `live-m5-edit.log`). The Meta API answered 503 to most model
calls during the run, so the turns took minutes of the CLI's own retries.

- **Editor context** (`greet.ts` line 2 selected, chip on): prompt "What
  does the selected line do? One sentence, no tools." → `turn/start` carried
  the typed text, the `<ide_selection>` part with the selected line, and
  `displayText` → reply "It returns a greeting string interpolating the
  given `name`." with **no tool calls**: the model answered from the
  selection alone.
- **Diagnostics**: prompt "Call the getDiagnostics tool of the ide MCP
  server…" → `approvalRequested` (an MCP tool call is gated like any
  unmatched tool in a prompting mode; the script chose `allow_once`) →
  `itemStarted toolCall mcp__ide__getDiagnostics args={}` → our loopback
  server answered → `itemCompleted … out="greet.ts:2:10: warning: Template
literal could be a plain string (fake diagnostic for the live check)
[live-check]"` → the reply quoted that line verbatim. The row is labelled
  `Diagnostics` (the catalog name `mcp__ide__getDiagnostics` was added to
  `TOOL_LABELS` from this run, as was the `search` tool the model used on
  the edit turn, `{glob, output_mode, pattern}`, labelled `Search` with its
  pattern).
- **Edit review** (`live-m5-edit2.log`, after the path fix): prompt "Edit
  notes.md: replace "first line" with "second line"…" → the model ran
  `search {glob, output_mode, pattern}`, a four-stage PowerShell line
  (`approvalRequested` stage 0 → `approvalUpdated` stages 1, 2, 3 and stage
  3 **again** — pipelines count as stages, and the repeat is the M4 finding
  once more; the script's naive handler answered twice and got "already
  resolved", which the locked card avoids), `read_file`, then `edit_file
{find, path, replace}` → `itemCompleted` with the patch → reply "done";
  the file read `# Notes\n\nsecond line\n`. The script then sent
  `openEditDiff` for that item: the controller fetched the stored patch
  (`item/readOutput`), `EditReview` rebuilt the pre-edit text and asked for
  `vscode.diff("muse-edit:/<itemId>/notes.md", "C:\muse-live-ws\notes.md",
"notes.md (Muse edit)")` with the staged original `# Notes\n\nfirst line\n`.
  `revertEdit` then wrote that text back: the file on disk read
  `# Notes\n\nfirst line\n` again and the transcript got "Reverted
  notes.md.". The first attempt (`live-m5-edit.log`) had refused the path;
  see Findings.

## Security

- The IDE tool server binds `127.0.0.1` on an ephemeral port, requires a
  32-byte bearer token minted per extension host (compared in constant
  time, never logged, never written to disk), answers only `POST /mcp`, caps
  the body at 1 MiB, and exposes one read-only tool.
- Edit review resolves every patch path against the workspace root and
  refuses anything that escapes it; reverts go through the workspace file
  API and created files go to the trash, never a hard delete.
- Editor context never leaves the host except as the turn part the user
  chose to send (the chip is on and not dismissed); the selected text is
  clipped and withheld for files outside the workspace index.

## Findings recorded during the milestone

- **The patch document names files with the Windows extended-length
  prefix**: the live edit turn's stored patch carried
  `"path":"\\?\C:\muse-live-ws\notes.md"`, not the `notes.md` the M4 fixture
  assumed, and the first review attempt refused it as "outside the
  workspace" (`path.relative` sees `\\?\C:\` and `C:\` as different roots).
  `EditReview` now strips `\\?\` (and `\\?\UNC\`) before resolving, takes its
  path rules from the platform so the Windows case is unit-tested on every
  OS, and the live turn was re-run to confirm (below).

- The MCP tool catalog `muse serve` writes for our server names the tool
  `mcp__ide__getDiagnostics` (`namespace: mcp__ide`), so prompts and skills
  written for Claude Code's IDE tool address ours unchanged.
- The Meta model API returned HTTP 503 for every model call during the
  first live run (the CLI's durable log: "opening meta model stream attempt
  n/10", retry every 60 s, `error_kind: server`, `http_status: 503`); no
  `turn/retryScheduled` notification reached the client for those provider
  retries, so the panel showed the spinner only. Recorded as an observation,
  not a fix: the retry notice the transcript renders is driven by
  `turn/retryScheduled`, which the host did not send here.
