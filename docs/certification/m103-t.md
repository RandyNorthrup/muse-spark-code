## Thonny API evidence (read, not guessed)

`thonny-5.0.0-py3-none-any.whl` was downloaded from PyPI and its sources
inspected read-only (the wheel was deleted afterwards; it never entered
the repository). Findings, each cited in the code:

- Plugins are modules under `thonnycontrib.__path__` exposing
  `load_plugin()` (`thonny/workbench.py`, `_load_plugins`).
- `thonny.get_workbench()`, `thonny.get_runner()` (may be `None`)
  (`thonny/__init__.py`).
- `workbench.add_command(command_id, menu_name, command_label, handler,
tester=None, ..., image=None, caption=None, include_in_toolbar=False,
...)`; the `tools` menu exists; `image=None` is safe; a toolbar button
  needs only `caption`.
- `runner.send_command(InlineCommand(name, **fields))` is async and shows
  no UI; backend `InlineResponse` events arrive on the workbench bus and
  match by `response.command_id == cmd["id"]`.
- **Correction to the research citation:** `send_command_and_wait(cmd,
dialog_title)` (5.0.0, two arguments) pops a modal `InlineCommandDialog`
  per call — it is not a silent programmatic call. The bridge never uses
  it; it sends with `send_command` and matches `InlineResponse` itself,
  so no per-action Tk dialog double-prompts the user.
- Backend `read_file` takes `path` and answers `content_bytes` + `path`;
  `write_file` additionally requires `content_bytes` and
  `make_shebang_scripts_executable` (`thonny/backend.py`). The bridge
  sends both fields.

The whole package imports without Thonny installed (`thonny` is imported
lazily only); `test_package_import_needs_no_thonny` pins that.

## Reuse and scope decisions

- No new npm dependency; no new Python dependency (standard library
  only). `thonny` itself is the host and provides its own package.
- Runtime commands reuse the plan's names: `muse-spark-code-acp panel`
  (D84) to start, `muse-spark-code-acp stop-machine` (D83.16) for the
  out-of-band stop.
- MIT license text is byte-identical to the repository `LICENSE`.
- Workflows follow `release.yml` conventions (SHA-pinned actions,
  `persist-credentials: false`, secret-gated publish, `environment`).
- Owner rulings (2026-10-04): this lane has no paid surface and no model
  choice, so there is nothing to gate — enhancements/paid/single-model
  behaviour is unchanged by the plugin. Recorded here so the question is
  visibly considered, not overlooked.
- **Strings:** no keys were added to `src/shared/l10n/en.ts`, the 14
  `l10n/ui.*.json` tables or `package.nls*.json`. Those tables carry
  strings the TypeScript UI reads; the plugin's two menu labels live in
  the Python package, which cannot read them. Adding unread TS keys
  would be dead code (rule 6), and `check-l10n` fails _unused_ manifest
  keys, so `package.nls*.json` must stay untouched while lane W owns
  `package.json`. `node scripts/check-l10n.mjs` reports 0 problems on the
  finished tree (see gates below).

## Cross-lane interfaces (proposed by T, to be frozen by R/P/I)

The runtime and engine lanes build in parallel, so these are explicit
injected seams with fakes in the tests — not guesses baked into
production code. Each is versioned, strictly checked, and documented in
`protocol.py` and the plugin `README.md`.

| #   | Seam             | T's proposal                                                                                                                                                                    | Freezing lane |
| --- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| 1   | Start argv       | `muse-spark-code-acp panel` (D84's name)                                                                                                                                        | R             |
| 2   | Announcements    | stdout lines `MUSE_SPARK_COMPANION_URL <url>`, `MUSE_SPARK_COMPANION_LAUNCH <code>`, `MUSE_SPARK_PROVIDER <host> <port> <token>`; other output ignored                          | R             |
| 3   | Provider channel | newline-delimited JSON v1 (`hello`/`welcome`, `device_request`/`device_response`); approval echo (`request_id` + `digest`) mandatory; TCP loopback + token transport, swappable | R/P           |
| 4   | Device ops       | `read` → `read_file{path}`; `write` → `write_file{path, content_bytes, make_shebang_scripts_executable:false}`; `info` sends nothing                                            | P/I           |
| 5   | Stop             | `muse-spark-code-acp stop-machine` subprocess, never gated                                                                                                                      | R             |

Until lanes R/P freeze these, the plugin connects only to endpoints its
own started runtime announces, over loopback, with a per-launch token —
so a changed schema fails closed (version refusal, auth refusal) rather
than misbehaving.

## FIXM103T — RVM103T corrections (2026-10-05, Windows 11)

The rig brief overrides the original full-quality/merge instruction: run
owned checks directly here, commit with hooks, never merge/rebase/push.
No dependency, paid/model call, board or publication. Python testing uses
the already-installed pytest 9.0.2 in the reviewer's isolated OS-temp
Thonny 4.1.7 environment (Python 3.14); it is read/executed only.

First piece fixes findings 1, 2, 3, 6, 9, 10 and 11. Dispatch and settlement
share an RLock, including synchronous runner sends. Detach and wait timeout
settle requests; the pump skips settled/deadline-expired work. Write
approval echoes require an exact byte digest, opaque runner/proxy identity
and finite UTC expiry. The `info` reply advertises that identity; the runtime
must bind it at approval time. Every write rechecks all three immediately
before dispatch, and the production seam also checks the target before
calling the captured runner. Labels are never treated as device identity.
Empty bytes are valid. The strengthened fields remain a T proposal awaiting
R/P freeze; no installed-runtime interoperability claim is made.

The provider announcement and connector both require literal `127.0.0.1`,
before any bearer is sent. Handshake refusal fields and integer version
types are validated. Successful handshakes clear the socket timeout;
closing wakes idle receive and cancels queued work. Browser false/exception
results become CompanionError, which Open reports.
