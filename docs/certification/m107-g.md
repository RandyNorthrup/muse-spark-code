## Scope and policy

Only G's new `src/core/resources/{governor,queue,events}.ts`, its owning
tests and this record change. Construction/import starts no timer, probe,
process or network operation. `start()` belongs at the first governed
spawn; sampling is serial, five seconds after the preceding sample settles,
and concurrent refresh calls share one promise. Disposal cancels timers
and discards an in-flight result without ending running work.

CPU entry takes thirty seconds; memory entry requires two consecutive
known readings. Critical CPU takes sixty seconds at 97%; available memory
below half the size-capped floor goes directly to pause, including during
dwell. GPU/disk use the CPU's thirty-second sustained window when their
threshold is set; unset metrics neither trip nor block recovery. This is
the explicit choice for D87's otherwise unspecified optional entry window,
using existing constants, not a new setting. Linux pressure remains a
reported reading, not an invented threshold.

Unknown readings break sustained/recovery evidence, trip nothing and never
clear a level. A known overloaded metric can still escalate while another
metric is unknown. Escalation takes sixty seconds with current overload;
without an approved target it skips relocate. Relocation off does not even
call the target port. Recovery needs every enabled reading below its
ten-point band (free memory above floor plus 0.5 GiB) for sixty seconds.
It descends one available level per window. Automatic changes hold each
level for at least sixty seconds after the first pressure transition,
including normal after recovery; critical, override and disable bypass it.

Resume now holds normal for fifteen minutes despite critical readings;
renewal cancels the previous expiry. Expiry requests a fresh reading,
rather than deciding from a cached sample. Explicit disabled settings
restore normal immediately and cancel the override. Machine-setting
validation is the existing lane-0 schema, not a workspace reader here.

The governor publishes no additional capacity at normal (`null`), one
background item per kind at throttle/relocate, zero at pause. Existing
caller caps still apply. The queue orders lower scheduler priorities first
and FIFO within each kind/priority; other kinds can progress independently.
It reserves synchronously before resolving admission, closing the interval
before a child is registered. Registry occupancy and outstanding permits
both block throttle admission, with unknown occupancy treated as busy.
No running work is stopped when the capacity shrinks.

Foreground work bypasses throttle/relocate occupancy. At pause its handle
provides Run now and an independent twenty-second deadline; an unavailable
registry cannot block that deadline. Cancel/abort and disposal reject
queued admissions immediately and cancel their timers. Cancelling a
previously admitted request never releases its permit. Only the caller's
observed retirement or failed-spawn cleanup releases it, idempotently.
A same-kind child which would wait on its active background parent's
slot is refused explicitly; a parent is never released to make room.

Events are validated by the strict shared schema before delivery, contain
only the shared numerical/enumerated fields, give each observer a separate
copy and isolate observer errors through an injected diagnostic sink.
Status and queue counts are detached snapshots. Pause/defer events name
only kind and (for deferral) class; status carries aggregate queue counts.
Neither includes process/session identity, paths or command strings.
There are no casts, lint suppressions, new dependencies or production fakes.

## Named integration handoffs

- **G–T occupancy / C1 lifetime:** bind `ResourceRunningWork.backgroundCount`
  to T's registered background trees by kind; return null when unavailable,
  and call `queue.wake()` when registry occupancy changes. Retain an
  admission permit from before spawn through proved retirement, release
  on failed spawn, and never release for cancellation/age/missing PID alone.
- **G–C2 child slots:** pass scheduler priority and a local parent permit
  for delegated same-kind work. Preserve M96c's existing slot preflight and
  child-capacity rule before admission; this queue is an additional limit,
  never authority to widen scheduler slots or retire a parent.
- **G–R targets/events:** bind `hasRelocationTarget` to currently approved
  paired-device/runner availability under M100/M96c. This governor dispatches
  nothing, guesses no wire shape and grants no relocation authority. R
  publishes the existing `relocated` variant only after its own admission.
- **G–A priorities:** consume level transitions through `ResourceEvents`;
  preserve T's per-action membership proof and A's reversibility rules.
- **G–U/H surfaces:** compose `governor.status(queue.counts())`, subscribe
  to events, and attach a queued admission's `ready`, `runNow` and `cancel`
  to its existing visible row. Render lane 0's translated resource strings;
  deduplicate pause notices per conversation there. Core diagnostic errors
  are not user-facing labels. Stop/tree kill, approvals and paid consent
  stay outside `request()`; it accepts only governed spawn kinds/classes.
- **G–J history / C2 hints:** consume schema-bounded events/status for
  records and hint publication. Identity never enters either payload.
- **G–W delivery:** lazy `dist/resourceGovernor.js`, spawner binding,
  manifest/NLS contributions, README/CHANGELOG/PLAN, editor/runtime docs,
  registry/help entries, bundle/split maps and the joined full quality gate
  remain W's owned files. This base has no featureCatalog; integration must
  list Show resources, Resume work now, `/resources`, CLI resources and the
  resource settings there. No command or setting is independently exposed
  by G. Every editor/runtime binds this same portable core.
