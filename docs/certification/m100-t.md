## Address and frame boundary

Addresses use lane 0's private literal schema plus Node's IP syntax check.
Chosen binds must belong to an actual local interface. Every hostname lookup
checks all answers, rejects empty/oversized/mixed-public answers and loopback
substitution, then hands TLS a checked literal. Mapped IPv6, metadata,
wildcards, URLs, zones and public destinations are refused. Manual literal
entry needs no discovery or DNS. These are connection checks, never attempt
retirement or liability settlement.

The authored version-1 transport is newline-delimited UTF-8 JSON over TLS.
It caps bytes before concatenation, UTF-8 decoding, JSON and zod; rejects
invalid UTF-8, duplicate keys (including escaped spellings) and excessive
nesting; validates complete strict envelopes and bounds the ready queue.
Outgoing frames also have schema and UTF-8 byte checks. Unknown versions use
the fixed `incompatible` reason; peer input/errors are never reflected.
No upstream Muse/provider wire shape was added. The nesting stack uses the
existing 32-frame resource ceiling; no new tunable or shared constant edit.

## Mutual TLS and authenticated channels

`DeviceTransport` uses Node built-ins, TLS 1.3 only, the exact confirmed peer
certificate as its dedicated CA and a separate SHA-256 DER leaf pin on both
ends. Saved public certificates must match their stored fingerprints and
verify their own signatures; the local private key must match. Corrupt material
fails with a fixed reason before listening/dialing. Mutual authentication and
the current pair state precede every application callback. TLS tickets are
disabled, resumed sessions are refused and the server's session lookup returns
no session. A real captured-ticket positive control first proves resumption
works without these defenses; the guarded listener refuses that bypass.

Listeners bind only the explicit present private/loopback interface and nonzero
port, with no wildcard or fallback. DNS is resolved afresh and the dial uses
only its checked literal, with the chosen source interface. Raw Node TCP/TLS
receives no proxy agent, forwarded environment, upstream credentials or child
process. The proxy test sets HTTP/HTTPS/ALL proxy and Node proxy opt-in against
an owned interception listener and proves it receives no request.

Window limits include unfinished handshakes: 16 listeners, 16 total sockets,
2 sockets per pair. DNS/TCP/TLS/initial-offer setup has one absolute 10-second
deadline; native incoming TLS has the same deadline and failed handshakes are
destroyed. Pending DNS setup is cancellable on unlink, and slots release once
on failure/close. Unlink destroys only that pair's listener and pending/live
sockets. No refusal, deadline or disconnect retires an attempt or settles debt.

After mutual TLS, the receiver's `connected` port sends actual current `offers`.
The source learns the current receiver incarnation from that first paired,
validated offer instead of trusting a cached incarnation. All coalesced
envelopes must match before readiness, and the incarnation cannot change within
the connection. The source cannot send while it is unbound. Restart regression:
a source remembering R1 connects to pinned R2, then sends a reconciliation
envelope rooted at R2 containing the unchanged R1 attempt owner. E still owns
reconciliation, durable admission, settlement and retained liabilities.

Channels cap bytes and queues before parser/admission, serialize handlers,
recheck revocation for each queued request and outgoing frame, and bound the
outgoing writable buffer. Incomplete frames have an absolute 10-second
deadline, including a check before parse when the timer callback was delayed;
trickling bytes cannot extend it. Idle sockets close after 30 seconds. Errors
and incompatible versions use fixed protocol reasons; peer text is never
logged/reflected. Test-only identities are fresh in-memory P-256/X.509
certificates built with Node crypto; no fixture key/file or OpenSSL dependency
is shipped. The CA-signed child tests prove a valid certificate chain is
insufficient without the exact leaf pin.

## Optional discovery policy

Construction performs no I/O. `start` does nothing unless discovery is enabled
and a paired receiver is offering; both states are re-read for traffic and
announcements. The injected DNS-SD adapter receives the chosen interface only.
Advertisements have exactly three fields: a rotating random 128-bit opaque
service id, port and authored protocol version. No account, OS hostname,
repository, model, credentials or stable device identity is carried.

Packet bytes and per-window rate are capped before the adapter's decoder;
strict zod validation and private sender validation precede retaining at most
16 address hints. Hints expire after 30 seconds. They cannot replace a saved
pair/pin or automatically route work. Rotation, revocation, stop and generation
checks prevent stale callbacks or delayed opens from reviving discovery or
closing a newer session. The required reviewed mDNS runtime binding remains an
explicit I handoff; T does not ship a guessed or fake implementation.

## Integration handoffs

- **P pairing:** inject confirmed, durable per-pair certificates/private key,
  exact fingerprints, stable pair id and the channel's receiver incarnation.
  Re-read `isActive`/`isOffered` from current local state. `revoke(pairId)`
  closes that pair's listener and sockets; keys never reach a child or wire.
- **E receiver:** bind the channel's receive/disconnected port to actual
  receiver admission and durable disconnect handling. Authentication is not
  an execution/paid grant; disconnect never settles work or frees liability.
  The receiver's connected port must announce actual current offers; a source
  waits for those offers and learns the current incarnation while preserving
  historical attempt owners inside reconciliation envelopes.
- **I discovery dependency:** lane 0 selected no mDNS implementation and the
  brief prohibits adding a dependency not named by the plan. Bind the explicit
  injected `DeviceMdnsPort` to a reviewed lazy DNS-SD implementation. It must
  bind only the chosen interface, decode only admitted bounded packets,
  advertise the rotating opaque service id/port/version only, withdraw on
  close, and expose no proxy, credentials, hostname or additional TXT fields.
  There is no fake/default production implementation or claimed live mDNS
  qualification in T. Manual TLS works independently of that binding.
- **I product:** lazy `dist/devices.js` inclusion and `DEVICE_MODEL_TEXT`
  reader registration, manifest/help/README/CHANGELOG/security/privacy and
  delivered-feature claims remain I-owned. No new command/setting or visible
  ordinary-chat feature is registered here. Carry equivalent unsupported-host
  reasons to ACP/headless and other editors under D80.
- **I rigs/floor:** Node 20.18.3 TLS passed above; installed four-device tests, routed
  multicast-blocked/manual success, default/denied OS firewall outcomes and
  true missing-route cases need installed-host evidence. Local loopback
  refusal does not certify an OS firewall policy or remote retirement.

### Listener lifecycle: P2-1 and P2-2

Startup races `listening`, `error`, `close` and explicit revocation, with its
own 10-second timer. Close/unlink rejects with the named `revoked` error;
bind errors/deadlines use `blocked-or-unreachable`. Startup handlers, timer
and pending cancellation are removed on settlement. Listener disposal,
errors and failed-start cleanup check the exact server occupying the pair's
slot, so repeated cleanup of A cannot revoke its replacement B.
