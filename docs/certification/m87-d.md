## Delivered

- `TodoPanel` starts expanded. Its keyboard-accessible header names progress,
  controls its list with `aria-controls`, and reflects `aria-expanded`.
  Collapsing leaves the current task on one ellipsized line. An optional
  callback exposes **Open in a tab**; lane W owns its chat wiring.
- `TasksPanel` implements lane P's `TasksTabPort`, opens beside the editor,
  caches updates, and resends the current list and ended state on every
  `tasksReady`. It reuses the existing HTML/CSP, disables command URIs, and
  registers no serializer. Ending a conversation freezes its cached view.
- `TasksApp` mounts only for `data-surface="tasks"`, validates host messages,
  and has no composer or conversation store. The tasks-only strict schema
  rejects chat commands and extra action fields.
- `museSpark.openTasks` is registered for the active conversation. Its
  manifest title is translated in all 15 manifest tables.
- Window movement is offered only after `getCommands(true)` includes
  `workbench.action.moveEditorToNewWindow`; the host reveals the tasks tab
  before executing it. A disposed tab's late lookup cannot change its
  replacement. This is a built-in command ID, not a stable VS Code API.
  The generated host API record tracks `getCommands`, `executeCommand`,
  the tasks adapter, webview options and manifest contribution count;
  the generator does not enumerate command ID values.
- README documents window limits and lack of whole-window restoration.
  CHANGELOG, CONTRIBUTING, AGENTS and PLAN move with the implementation.
