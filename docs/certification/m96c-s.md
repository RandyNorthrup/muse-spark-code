## Scope and acceptance

Lane S supplies the window-owned board, selection, child reservations, retirement policy,
stall recovery, review flow and the scheduler region of `teamPool.ts`. All production seams
are interfaces with injected dependencies; there is no fake backend or process proof.
Imports and constructors start no timers, workers, prompts or network calls.

| 4: critical path, score/fit, aging, starvation, transitive inheritance and weighted fair share                              | `criticalPath.ts`, `pick.ts`; `teamSchedulerPick.test.ts`                           |

The stall checkpoint test uses a real temporary Git branch and verifies the committed
edited blob. The retirement test launches a real direct child with a detached descendant
that writes five seconds later: the child's observed exit and cancellation acknowledgement
do not release the reservation. Its unproved container stays unproved even after the write.
Other retirement tests use normalized evidence to exercise the policy, including Windows
job and Linux cgroup outcomes; they do not certify native containment on those platforms.

Review results survive a refused rework admission or a failed queue enqueue, so retrying
delivery does not charge for another review. A new retired rework attempt counts as a new
bounded round even when it leaves the branch head unchanged. Fractional learned durations
retain the critical-path normalization, and a zero-duration board keeps a finite score.

## Integration contracts for the other lanes

- **A / accounting:** supply canonical model identities, ordered entries, `poolFit`
  (`0.9 ** placesAfterFirstWithHeadroom`), remaining daily tokens, estimates, live headroom,
  learned minute estimates after the plan's observation minimum, conversation weights and
  eligible-younger-start history. `BoardContext.countAttempt` must atomically count every
  initial, child, rework and reassigned attempt under tasks-per-turn and every cap/budget.
  `halveAgentCap` applies the shared 503 ceiling; it does not preempt a running worker.
- **K / lifetime and journal:** provide evidence only for launches owned by this window,
  with the actual direct-child exit and container proof for every descendant. No PID poll,
  cross-window hint or protocol cancellation acknowledgement is proof. `changed` and
  `delay` honor their abort signals; launch/restart callbacks resolve on the actual outcome.
  `start` admits a launch promptly; worker initialization and completion are separate
  events. It rechecks current attempt/trust immediately before creating a worker and must
  never create one after its attempt retired. Process spacing is recorded after launch
  admission resolves, so delayed admission cannot compress two actual starts.
  `markUncertain` blocks the task; quarantine keeps its copy unavailable. Host restart
  admission must stay quiescent while the confirmed worker list is being ended.
  Restore the board and recover its retained slot liabilities only after K's journal
  ownership/takeover procedure; a foreign journal is read-only until its required decision.
  `restore` itself always pauses and marks nonretired attempts interrupted.
- **C / leases and Q / copies:** `lease` reserves synchronously and remains held until
  retirement. Supply lease/merge waits to inheritance and use the combined wait graph at
  child admission. `canQuarantine` refuses handoff for an in-place writer. A handoff keeps
  the old uncertain slot, reserves another slot and rechecks exclusive resources after
  quarantine; `prepareReplacement` performs final atomic admission, a fresh copy from the
  immutable checkpoint and same-task lease transfer. It returns false on any refusal.
  A new attempt refreshes from integration; a running copy is never changed.
- **B / authorization and paid policy:** `authorize`, stall `consent`/`reassign` and review
  `admit` enforce the named delegate card, current workspace trust, all admission limits,
  the paid feature gate, the existing three-choice price popup and the shared daily paid
  ledger. Apply the 2026-10-04 owner ruling: enhancements on for the chosen setup, and
  consent once before the first charge; an unnamed key entry asks again. Scheduler S
  provides no alternative approval or paid path.
- **T2 / tools:** submit a complete delegate batch atomically; reserve child slots while
  the parent is running before accepting delegation, and roll back graph/slots together
  on refusal. Children use the reserved entry's slot, never their parent's. Release an
  unstarted child's reservation when its delegation is cancelled. Render `BoardRefusal`
  codes/edges through the existing translated strings. `reschedule` only changes queued
  or ready tasks and never launches work. Accept state/report events only when
  `applyEvent` returns true; its usage callback also charges valid late usage.
- **Q / review and landing:** review `admit` atomically reserves all requested lanes and
  authorizes their charges. `run` returns normalized `{head, groups}` only after each
  reviewer has retired; the flow waits for every result before releasing admission.
  `record` persists the whole head and round count in the task/journal. `rework` receives
  every finding and actual failed command, re-admits a new attempt and calls
  `TaskBoard.prepareNext`. The third failing round returns `redesign`. An `enqueue` with
  `isReviewed=false` must still show the required not-reviewed landing card, including
  Bypass; no reviewer is not permission to land. Landing validates that exact reviewed
  head and all Q admission identities again.
- **X2 / wiring:** construct one scheduler only for an admitted multi-model team and
  wire readiness, retirement, lease-release and recovered-limit events to `wake`.
  Call `startSweep` explicitly and dispose it with `stopSweep`. The scheduler files are
  not yet reachable from the production bundle at this lane base; X2 adds them to the
  lazy `dist/team.js` graph and remeasures its budget. Full quality, golden single-model
  frames, editor integration and live/native multi-platform certification remain with
  their assigned owners. Lane S runs the permitted scoped checks and makes no claim that
  those milestone-wide gates passed.

No new wire shape from Muse Code or the Model API is parsed here. Events use 0c's schemas;
retirement facts, checks, and review groups are explicitly normalized adapter inputs.
No new localization key, dependency, lint escape hatch or unverified cast was added.
