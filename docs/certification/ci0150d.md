## The rest of the class, in the same pass

A script read the full CI log for every test that ran 3 s or longer on any
hosted runner and checked it for a deadline. It flagged 29; 21 of those already
had one (`REAL_GIT_TIMEOUT_MS`, `REAL_LANDING_TIMEOUT_MS`,
`REAL_MERGE_BATCH_TIMEOUT_MS`, a literal `180_000`, or the 60 s
`PROCESS_SUITE` describe option, which the script could not see). Four of the
other eight are the hosted failures above; the remaining four each got a named per-case deadline: `HANDOFF_REFUSALS_TIMEOUT_MS`
and `FULL_REFERENCE_SEARCH_TIMEOUT_MS` (20 s, measured 4.7 s),
`LEGAL_CAP_SCAN_TIMEOUT_MS` and `COLD_CLI_TIMEOUT_MS` (15 s, measured 3.5 s and
3.1 s).

A first draft also put 20 s on three `actionRunExec.test.ts` cases and 60 s on
three `actionApply.test.ts` cases. Both suites already run under
`PROCESS_SUITE` (60 s), so the 20 s values tightened them and failed on this
host at 20 s. Both files were reverted unchanged.

No assertion, fixture, case or production path changed. Every deadline is
registered in PLAN.md §8 with its measurement and a removal path.

## Drill

Removing the bearer-header line from `publicMainFiles` made
`sends a job token to the GitHub API inventory only, never to an image host`
fail on kubuntu (`expected undefined to deeply equal { authorization: 'Bearer
job-token' }`, 1 failed / 39 passed, exit 1). Restored byte for byte; 40 of 40
pass.

## Second pass (run 37680755821)

The next full run failed on a lint rule in the badge change (`unicorn/consistent-conditional-object-spread`; I had not run lint on the script) and on three cases that were under 3 s in the first log: ollamaCodec's stream cap (5.2 s, macOS), handoffDialog's lazy dialog wait (macOS) and a companion browser case (Windows). A sweep at 2 s over both full runs found the cause on macOS: hosted runners have 3 vCPUs and the config ran four workers plus V8 coverage, so timings swung between runs. `vitest.config.ts` now sizes macOS workers as cores minus one (two on hosted, at most four on rigs). The four heaviest cases without a deadline got named ones (PLAN.md §8). The handoff dialog already pre-warms its lazy surfaces; it failed on CPU starvation, which the worker change addresses. All touched files pass ESLint with `--max-warnings=0`.
