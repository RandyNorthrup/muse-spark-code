## Integration contract for lanes B and D

- Import `startCompanionServer` from `src/runtime/companion/server.ts`.
  Inject actual input/output zod schemas, `post(message, browserSessionId,
signal)`, and `subscribe(browserSessionId, emit) -> unsubscribe`. The runtime
  owns controller/session selection, pending approval identities and paid consent;
  it must honor the abort signal. No method table or fake controller is shipped.
- Supply positive integer limits from the shared constants region: body/event
  bytes, request/idle timeouts, launch/cookie lifetimes, and total pending codes
  plus cookies. The server validates these before opening a socket.
- Supply an exact URL-path map of packaged assets and `renderPage(nonce)`.
  Put that nonce on every script. This callback receives no launch code,
  cookie, credential-store reference or API key. Asset URLs never become paths
  read from the filesystem. Only authenticated requests receive the real UI.
- `url` is the credential-free root. `launchUrl()` issues a fresh URL with
  `#k=<code>`; send it over the trusted editor pipe/launcher only. Anonymous
  bootstrap removes the fragment before POSTing `{code}` to `/session` with
  `Content-Type: application/json` and `X-Muse-Panel: 1`. The response sets the
  cookie; the browser reloads `/` with the cookie.
- UI sends schema-defined JSON to `POST /post` with that custom header.
  Browser SSE uses **`POST /events`**, the same headers and body `{}`, and
  consumes its `ReadableStream`. Native `GET /events` requires exact Origin.
  Captured Chrome behavior: same-origin EventSource omits Origin, so it is
  intentionally refused by the required strict policy. POST SSE preserves
  that policy and works in a real browser. Lane D must use streaming fetch,
  not EventSource, for its bridge.
- `close()` is idempotent; `closed` resolves after shutdown. Pass the runtime
  AbortSignal. A second window gets a fresh code, and one cookie owns one SSE
  connection. Reconnecting after disconnect releases the old subscription.
- For native bearer endpoints, import `createTokenFile` and `TokenWindowsAcl`
  from `src/runtime/tokenFile.ts`. M98's owner must migrate its judge imports
  and remove its duplicate module during integration; this lane never edits
  the judge owner's files.

## Documentation and residual boundaries

Lane J owns README, CHANGELOG and PLAN. Its integration entry should describe
the companion transport and shared owner-only token files, with the POST SSE
contract above; it must retain Preview/Planned status until editor evidence
exists. This lane adds no user-visible strings, commands or settings, so no
translation table or manifest entry changes.

The handler and packaged renderer are trusted runtime dependencies. Transport
cannot protect a key a caller deliberately puts in its permitted message text;
the runtime must keep the OS store outside those dependencies. Same-user process
inspection remains outside the boundary, as in §3.8. HTTP cookies are host-scoped,
not port-scoped: another loopback service visited in the same browser can receive
them. The exact-origin/custom-header policy prevents cross-origin browser
dispatch, but this is not a claim against a local process that has stolen a live
cookie and can forge HTTP headers. No stronger multi-user/browser-cookie claim
is certified by this lane.

SSE frame exposed one further defect: Node's normal `write(false)` closed a fast
stream even though the frame was below the configured cap. The named test
`keeps a fast stream alive after a large valid frame crosses the Node high-water mark`
failed before correction and passed after it. The final implementation limits
**frame bytes plus current writable queue bytes**, allowing ordinary backpressure
and disconnecting before additional bytes would exceed that bound.
