## Integration contract for lanes B and D

- Import `startCompanionServer` from `src/runtime/companion/server.ts`.
  Inject actual input/output zod schemas, `post(message, browserSessionId,
signal)`, and `subscribe(browserSessionId, emit) -> unsubscribe`. The runtime
  owns controller/session selection, pending approval identities and paid consent;
  it must honor the abort signal. No method table or fake controller is shipped.
- Supply positive integer limits from the shared constants region: body/event
  bytes, request/idle timeouts, launch/bearer lifetimes, and total pending codes
  plus bearer sessions. The server validates these before opening a socket.
- Supply an exact URL-path map of packaged assets and `renderPage(nonce)`.
  Put that nonce on every script. This callback receives no launch code,
  bearer, credential-store reference or API key. Asset URLs never become paths
  read from the filesystem. Only authenticated requests receive the real UI.
- `url` is the credential-free root. `launchUrl()` issues a fresh URL with
  `#k=<code>`; send it over the trusted editor pipe/launcher only. Every new
  tab starts the bootstrap even if other tabs are already open. Bootstrap
  removes the fragment before POSTing `{code}` to `/session` with
  `Content-Type: application/json` and `X-Muse-Panel: 1`, with cookies omitted.
  The successful response carries a fresh `Authorization: Bearer <id>` header
  and the trusted renderer's HTML. It sets no cookie. The header's format is
  checked before use; HTML is trusted packaged output, not a JSON protocol.
- Bootstrap keeps the bearer only in a fetch closure, installs that window's
  `fetch`, then fetches packaged script/stylesheet bundles with Authorization
  and installs them inline under the original nonce CSP. The renderer must
  supply self-contained bundles; other protected resources must also load
  through fetch (images can use permitted blob URLs, fonts can use FontFace
  with fetched bytes). Native script/link/img/font requests cannot attach a
  bearer. No asset guard is widened and no credential enters rendered HTML.
- UI sends schema-defined JSON to `POST /post` with the custom header.
  Browser SSE uses **`POST /events`**, the same headers and body `{}`, and
  consumes its `ReadableStream`. The per-window fetch supplies Authorization
  on every request, refuses other origins and omits cookies.
  Native GET `/events` still requires exact Origin plus Authorization.
  Lane D must use streaming fetch, never EventSource or a token URL.
- `close()` is idempotent; `closed` resolves after shutdown. Pass the runtime
  AbortSignal. Each window has its own bearer and SSE subscription. Different
  runtimes cannot overwrite credentials. Tokens expire and all codes/tokens
  are revoked at shutdown, including idle exit; disconnect releases the
  subscription. Reload requires a fresh editor launch link, because tokens
  are not persisted. Rejected/failed launches show translated focused alert
  with editor reopen guidance and no unhandled rejection.
- For native bearer endpoints, import `createTokenFile` and `TokenWindowsAcl`
  from `src/runtime/tokenFile.ts`. M98's owner must migrate its judge imports
  and remove its duplicate module during integration; this lane never edits
  the judge owner's files.

## Documentation and residual boundaries

FIXM104C updates the threat model here and in the research note, PLAN and
CHANGELOG. One recovery string is translated in English and all 14 tables.

The handler and packaged renderer are trusted runtime dependencies. Transport
cannot protect a key a caller deliberately puts in permitted message text;
the runtime must keep the OS store outside those dependencies. **Other local
users and services on other ports are in scope.** Their HTTP listeners never
receive cookies or bearers from the companion page, and forged Host/Origin
headers alone cannot authorize replay. Same-user process inspection remains
outside the boundary: those processes can inspect memory and read owner-only
token files. This does not exclude other local users or other-port services.
