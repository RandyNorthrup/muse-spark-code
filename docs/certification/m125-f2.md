# M125 F2 — B2 check core: closure, baseline, snapshot, allow-list

Status: core built and proven; inert until certification. F2 covers
D107 §9.5's capture, closure and snapshot core only: the command
grammar, the definition closure (scripts, fields, configs, pinned
files), the owner baseline over real git, the frozen snapshot copy
with its reader, and the strace-verified syscall allow-list. No run
path, native helper change, approval wiring or setting enables B2:
nothing in the product calls this core. Model attempts: **0**. No
paid call, live model attempt, credential read, network use or new
dependency.

## Scope

- The grammar (`parseB2Command`) admits the four check shapes with no
  option (`npm test`, `npm run <script>`, `pnpm <script>`,
  `pnpm run <script>`) and path filters after `--` only; anything
  else (other commands, scripts, options, escaping filters, shells
  the walker does not model) is refused with a named reason.
- The closure (`collectB2Closure`) walks the entry script with its
  pre/post hooks and nested `npm run` references, over the D121 walk
  bound, with a cycle readout; the digest (`digestB2Closure`)
  normalises scripts, fields, configs and pinned files in sorted
  order. The walk is pure over ports: no file, process or network
  touch of its own.
- Config keys (`checkB2ConfigKeys`, `npmrcKeys`,
  `pnpmWorkspaceKeys`, `resolveB2Manager`) admit only keys that name
  no program, file or code; yarn and pnpmfile repositories are
  excluded; links landing in the workspace are refused.
- The baseline (`B2Baselines`, `compareB2Closures`) records the
  closure at the owner's commit over real git and compares the live
  tree to it, naming the first difference (script, package.json
  field, config, pinned file).
- The snapshot (`copyB2Snapshot`) freezes the workspace minus `.git`
  under the §9.5 budgets (files, bytes, time), copying files, links
  and modes and leaving specials out; the reader
  (`openB2SnapshotReader`) is traversal-guarded and never follows
  links out.
- The allow-list (`JUDGE_FAST_B2_SYSCALLS_X86_64`, 193 calls) is the
  design §9.5 set verified against the installed kernel headers plus
  the five the capture observed outside it (below). On arm64, 26 of
  the 193 have no number in the installed asm-generic table (each
  superseded there except x86-only `arch_prctl`), so 167 — against
  the design's 28. That delta stays an open question for the lead.

## Capture (F2-d)

Four checks ran under `strace -f -c` on linuxlt (x86_64, kernel
6.17.0-12, strace 6.16, bubblewrap 0.11.0, node v24.21.0) from a
private TMPDIR fixture (`b2-fixture`: one source file, one
vitest test, real `node_modules` with vitest 5.0.3, eslint, tsc
and prettier):

- `npm test` — vitest run, 11,846 calls, 1488 errors (probing).
- `npm run lint` — eslint, `npm run typecheck` — tsc, `npm run
format` — prettier check.

The four runs observed 81 distinct calls in union. Five were
outside the design list and went in through the counted-receipt
process, each observed in all four runs: `clone3` (node worker
spawn), `io_uring_setup` and `io_uring_enter` (libuv's ring),
`socket` and `bind` (npm's `networkInterfaces` probe, which B2
discards on the filter event). All five exist on arm64, so the
capture changes no arm64 count. Re-diff after the fix:
OBSERVED-NOT-IN-LIST NONE. The `exit_group` quirk: strace `-c`
never shows it (non-returning); it was already listed and is
unaffected.

A full B2 confined run trace needs a root-owned-/usr rig (this
rig id-maps system files to nobody, as in F1); it rides with
lane V's receipt.
