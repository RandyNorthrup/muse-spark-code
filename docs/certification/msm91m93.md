## What was unfinished, and what this lane did

M91 and M93 both shipped on main, but four exports stood callerless,
tagged `@unwired` by TESTCUT-fin2. Two were this milestone's
built-but-unconnected code and are now connected; two stay tagged, with
reasons below.

### Connected: the Elicitation hook seam (M91 D70)

The plan promises (archived M91 event table): an `Elicitation` hook where a
project hook may decline and a user hook may answer (schema-validated), and
`ElicitationResult` observation where a project hook sees field names and
the action only. Lane E removed the payload builders as unused, lane M built
the seam interface plus every consumer (`runElicitation`,
`finishElicitation`) but left the default as ALLOW — so with hooks
configured, no Elicitation hook ever ran, while the README already claimed
"Elicitation and ElicitationResult hooks run through the host seam".

- `src/core/backends/modelapi/extensionHooks.ts`: new `elicitationFields`
  (server, bounded message, field names, required names); removed the
  `@unwired M91` tags on `elicitationResultFields` and `teammateIdleFields`.
- `src/core/backends/modelapi/mcp/elicitation.ts`: `ElicitationResultInput`
  gains optional `values` (accepted answer, user scope only); new pure
  `elicitationVerdictFromDispatch(policy, personal)` mapping the two
  scope-grouped dispatches onto the verdict (policy refusal declines first,
  then user refusal, then user answer; a non-record user answer declines
  rather than guessing; otherwise proceed).
- `src/core/backends/modelapi/ModelApiHost.ts`: new
  `defaultElicitationSeam`/`fireDefaultElicitation`/
  `fireDefaultElicitationResult` (policy hooks `project`+`managed` first,
  then `user`; matcher is the server name; no turn, so contexts drop and
  messages surface as notices); both elicitation call sites now fall back to
  it instead of ALLOW; `finishElicitation` forwards accepted content as
  `values`. `fireExtensionHooks` gains a trailing optional `onlySources`
  filter (default: all hooks, every existing caller unchanged).
- `src/core/backends/modelapi/ModelApiHost.ts` (`keepIdleChild`):
  `TeammateIdle` now fires through `teammateIdleFields` (same bytes as the
  inline literal it replaces). Best-of-N's copy stays inline on purpose:
  that module must stay out of the lazy hook bundle (D6), as its comment says.

Refusal maps to `decline` (the noticed refusal); `cancel` stays the caller's
own stop/timeout/concurrent-form path, because the hook protocol carries a
single refusal. Only an explicitly user-scoped hook answers or sees values;
managed hooks run in the policy group (decline only, no values).

### Stays `@unwired`, deliberately

- `runPluginHook` (`pluginHost.ts`): one plugin call outside any session.
  Every plugin hook runs inside a session's `PluginSession` (see
  `foreignHooksEntry.ts`); no outside-session entry point is promised by
  the plan. Wiring it would invent surface. It is also not exported from
  `pluginHooksEntry.ts`, so no bundle carries it.
- `buildProblemReportDraft` (`problemReport.ts`): the sync builder. Lane P's
  original; both callers (`reportProblemHandler.ts`,
  `reportCommand.ts`) now use the async vault version, which already covers
  the no-vault case (`vaultScrub === undefined`). Kept as planned surface
  through knip's sanctioned `@unwired` tag.

### Noted limitation (not changed)

Exact hook matchers accept `[A-Za-z0-9_|]` only (`MATCH_EXACT`), so a
hyphenated MCP server name cannot be selected by an `Elicitation` matcher;
a matcherless hook still runs for every server. Pre-existing lane-E design,
out of this lane's scope.

## Real-life steps (for the lead's run)

1. On the Model API backend, in a trusted workspace with
   `museSpark.modelApiHooks` on, write `.muse/spark-hooks.json`:
   `{"hooks": {"Elicitation": [{"hooks": [{"type": "command",
"command": "/path/to/decline.sh"}]}]}}` with `decline.sh` printing a
   reason to stderr and exiting 2.
2. Trigger any MCP `elicitation/create` (any MCP server that prompts).
   Expect: no form; a notice "A hook declined this request from
   \<server\>: \<reason\>"; the server receives a decline.
3. Replace with a user `spark-hooks.json` hook printing
   `{"answer": {"<field>": "<value>"}}`. Expect: no form; a notice that a
   hook answered; the server receives the values (schema-checked).
4. `TeammateIdle`: start a Best-of-N run or team delegates with a
   `TeammateIdle` hook; when a task idles with siblings running, the hook
   receives `{name, siblings_running}` on stdin.
5. M93 (unchanged, regression only): `Muse Spark: Report a Problem` with no
   chat open builds the scrubbed draft; Copy/Save/issue-URL equal the preview.
