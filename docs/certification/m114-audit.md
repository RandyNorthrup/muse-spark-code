# M114-A before-state design audit

Base `6c048ed33` (lane 0 plus review fixes), Kubuntu, 2026-10-06. This is the
audit that P1/P2/C execute before polishing. No production component, token,
theme fixture, setting, consent policy or host interface changes in lane A.

Read with [D94 and M114](../../PLAN.md#d94--design-language-and-polish-m114-2026-10-06),
[the frozen token contract](../../design/tokens/README.md),
[lane 0 certification](m114-0.md) and the desktop research §13. The research’s
older 280 ms slow motion and `--muse-*` proposal are superseded by the frozen
240 ms `--ms-*` contract. The owner’s 2026-10-04 defaults and ask-once paid
rulings remain; this audit recommends no backend/provider restrictions or
changes to spending admission. Single-model users retain current behaviour.

## Findings that determine the polish pass

**All 65 render inputs are graded** (60 component files, App, TasksApp, main,
and the separate What’s New page script). The remaining 32 files under
`src/webview/` are classified below: none is silently excluded. Component rows
include shared/nested renderers: ToolBodies includes memory/goal/schedule/web/
image/workflow; Transcript includes user/assistant/queued/error/notice, time,
citations, plan actions and folded steps; Usage includes account/subscription/
tokens/paid/Tab/insights; AgentMap includes nodes/details/results/background
tasks/workflows; Git includes hold/commit/PR/checks. Every exported icon is
captured in the test-only icon gallery. Delegating wrappers inherit grades
through the actual child, rather than being claimed to have independent UI.

The critical fixes are the stacked narrow approvals and unequal approval/
rejection emphasis, enabled placeholder and focus contrast in the supplied
third-party themes, missing pressed styles, 1 px/inset or absent focus rings,
missing explicit HC elevation/border binding, and motion outside the new token
contract. The generated tokens themselves pass; a token palette passing AA
does not make each captured host theme or component pass.

## Grading and evidence

`P` = partial migration/coverage; `F` = a concrete failure against D94;
`I` = inherited, no independently painted surface/state; `—` = not applicable.
There is no overall “pass” awarded to an unpolished component. Each row has
nine dimensions: colour, radius, elevation, motion, focus, states, high contrast,
accessibility and typography/spacing. Raw colours are already removed by lane
0, but direct `--vscode-*` reads still need the shared semantic role mapping.
Noninteractive text has no pressed/disabled state; active-descendant options
retain their owner’s focus and do not gain extra Tab stops.

The [machine-readable audit](m114-audit.json) stores each grade, selector,
CSS declaration with source line, exact host-role mapping, concrete fix,
source SHA-256 and scene. CSS matching is source evidence, not a claimed
computed cascade. The [before receipts](/home/randy/archive/m114-a-before-17d7/manifest.json) record
actual browser styles and rendered class/tag inventory beside each PNG.
The [capture index](/home/randy/archive/m114-a-before-17d7/index.md) links all six themes at 320 and
690 px for every representative scene. Several components share a scene;
this is a screenshot of the actual composition, not a fabricated isolated UI.

State work applies to the whole control, not just its SVG. `--ms-hover` is
the list-hover role; icon controls retain `--ms-toolbar-hover`; primary
buttons use accent/on-accent and the pressed/hover accent role; secondary
buttons use secondary-surface/text/hover. Use selected/on-selection together.
No control is blurred: add translucency only behind an overlay/popover;
keep gooey pills opaque with no shadow or filter, including disabled notes.
