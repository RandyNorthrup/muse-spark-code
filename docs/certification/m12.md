## What the milestone rests on

- VS Code's configuration scopes: a `scope: machine` setting takes its
  value from user settings only; a workspace value is ignored and the
  Settings editor says so. Proved live in the integration test below, not
  assumed.
- VS Code's `WebviewPanelSerializer` contract: `onWebviewPanel:<viewType>`
  activation, `registerWebviewPanelSerializer`, and the object the webview
  last passed to `setState` handed back on reload.
- VS Code's built-in context keys `activeWebviewPanelId` and `focusedView`
  for the keybinding `when` clauses (no custom key to maintain), and the
  walkthrough completion events `onView:`, `onCommand:` and `onContext:`.
- `muse init` (Muse Code 1.3.0): scaffolds `AGENTS.md` from a heuristic
  reading of the directory, no model call. Checked by running it for real
  through the command (below) with the CLI's trace logs counted before and
  after: 0 `model.attempt.lifecycle` admissions on both sides. **Correction
  (M13, the same evening):** that count used a marker that never matches
  (the two fields are not adjacent on the line), so it measured nothing.
  Recounted with a line regex against the two `muse init` process logs
  (`cli-e614c363…`, `cli-ffa27063…`, one second each): 0 attempts, which
  is what the claim said, by luck rather than by measurement.

## Security

- The six machine-scoped settings are the ones that choose what executes
  (`museBinaryPath`, `environmentVariables`, `shellSandbox`), what is billed
  (`backend`) and how much is approved (`initialPermissionMode`,
  `allowDangerouslySkipPermissions`); no repository can set them any more.
- `muse init` runs only in a trusted workspace, in the workspace root, from
  the resolved CLI binary, with a 30-second timeout and no shell; the pasted
  Model API key is never in its environment (`runProcess` passes none).
- The environment section carries git metadata only (branch, a count,
  commit subjects), never file contents; a failing `git` leaves the section
  at "not a repository".
- The webview state holds one session id, nothing else; anything else found
  there restores an empty panel.

## Findings recorded during the milestone

- `clear()` never told the webview the session was gone: the webview's
  `sessionId` stayed set after "New conversation", which would have resumed
  the old session after a reload. It now re-posts `sessionInfo`.
- Walkthrough tabs are labelled "Welcome" by VS Code, not by the
  walkthrough's title; the integration test matches either.
- The `muse init` template line "Generated by `muse init`" is replaced by
  "Generated by Muse Spark Code" when the extension writes the file, and
  the detection lines become hints, so the file never claims a detection
  that did not happen.
