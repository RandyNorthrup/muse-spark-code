## RVM107W1C: pull model for Show resources

2026-10-08. Codex review RVM107W1C of `8af2be222..1a843f16f` found four more
P2s in the open-intent lifecycle:

- document generations did not identify the document that sent `ready`;
- Show bound its target after asynchronous work and had no ordering;
- an in-flight Show continued after disposal;
- a failed conversation opening left an open behind.

This was the fourth round on the mechanism, so the lead replaced the push
with a pull model. **0 model attempts.**

**Design.** Each chat document's chip mints its own random nonce when its
chunk first runs (`ResourceSurface.tsx`, `documentNonce`). On mount the chip
sends `resourcePull {nonce}`. Show binds its target synchronously, before any
await: the chat in view, or the id of the surface `startConversation` opens.
It also takes a monotonically increasing `seq`, and records
`pending = {surfaceId, seq}`; the latest Show wins. After each await, Show
continues only while the adapter is alive and its `seq` is still the latest.
A failed opening withdraws its own `seq` only.

The host offers `resourceOpen {seq, nonce}` only to the document that named
itself: the chip's pull, or the chat in view's last pull when Show finishes.
Only that document's `resourceOpenAck {seq, nonce}` spends the open, and an
unacknowledged open stays pending. A reload marks the current nonce stale, so
its queued pulls and acks are ignored, and the new document pulls again.
Disposal clears `pending` and ignores everything after. The generation
bookkeeping is removed.

`resourcePull`, `resourceOpenAck` and `resourceOpen` are strict, with a
1–64-character nonce and an integer `seq` ≥ 1.

One deviation from the brief: the nonce is **not** in `ready`. Adding it
there (with the eager port logic) measured 751,624 bytes, 213 bytes over
FIXDIET1's 751,411-byte line. The chip's pull on mount names the document
instead. A ready document always receives the latest status, which mounts
the chip, which pulls. So every ready document with a status pulls, and the
host never infers which document is speaking. **Corrected by RVM107W1D:**
that last claim was wrong. The host still decided which nonce was current
from the order messages arrived in. The RVM107W1D section replaces this
design with ids the host issues.

## RVM107W1D: host-issued document identity and one Show operation

2026-10-08. Codex review RVM107W1D of `1a843f16f..f2708deeb` found five P2s
in Show resources' open handshake. This was the fifth round on the
mechanism, so the lead redesigned it rather than patching it. **0 model
attempts.**

**Why the two earlier designs failed.** Both let the host _infer_ which
document was speaking.

- **Document generations** (RVM107W1B, `fb0332b1c`): the host counted a
  generation on each Reload. That number never went into the HTML and was
  never echoed back, so every `ready` marked the newest generation ready. A
  queued `ready` from the replaced document counted as the new one
  (RVM107W1C P2-1).
- **Pull model with webview nonces** (RVM107W1C, `e2118f64b`): the chip
  minted its own nonce, so the host learned a document's identity only
  from its messages. It had to infer "current" from arrival order.
  - A stale set held only nonces the host had already heard, so a replaced
    document's late first pull was promoted (RVM107W1D P2-1).
  - An ack could register its own nonce (P2-2).
  - Show also started the conversation opening before its awaits and
    awaited it only later. A superseded or disposed Show left it unobserved
    (P2-3), and an off governor still opened a blank chat (P2-5).
  - Show's continuation check did not cover its target's removal (P2-4).

**Design.**

- **Host-issued identity.** `configureWebview` names every document it
  builds: `createNonce()` goes into `<body data-document-id>`
  (`WEBVIEW_DOCUMENT_ATTRIBUTE`, `html.ts`), and the surface exposes it as
  `ChatSurface.documentId`. Reload builds a new document with a new id, and
  the old one is no longer current from that instant.
- **The chip only echoes.** `ResourceSurface.tsx` reads
  `document.body.dataset['documentId']`. It reads through `dataset` so
  chat startup carries no copy of the attribute name; importing the
  constant measured +25 startup bytes. The chip pulls and acks under that id
  and opens only for an offer naming it. It never mints one, and with no
  id it never pulls.
- **The window validates against the record and never promotes**
  (`resourceWindow.ts`).
  - `pull` is accepted only when its nonce equals that webview's current
    `documentId`. It then records which document listens.
  - An offer goes only to a listening document that is still current, and
    records `offeredTo`.
  - `acknowledge` spends the open only for the current id, the pending
    surface, the pending seq, and `offeredTo` equal to that id.
  - Any other message is ignored, so arrival order decides nothing. The
    `onDocumentReplaced` hook and `surfaceReset` are removed.
- **One Show operation.** Each Show is a `ShowOperation`: its seq, an
  `AbortController`, and its bound target. The target is the chat in view
  when Show ran, or the new conversation's surface id once it opens.
  - A newer Show aborts the older one and withdraws its open. Removing the
    target (registry `onRemoved`, which the panel and view adapters'
    `onDidDispose` fires) and `dispose()` also abort it.
  - Every await is followed by an abort check, and no reveal, open or offer
    happens after one.
  - A failure withdraws only its own seq, and `finally` clears only its own
    operation.
- **Check before acting.** Show loads the host and reads the status first.
  An off governor shows the existing "governor is off" message with Open
  settings and never opens or focuses a conversation. The conversation
  opening starts after the check and is awaited in the same tick, so its
  rejection always reaches Show's caller (the command's log). A sidebar
  that already pulled before the focus is offered the open once the focus
  resolves.

User-visible strings, the chip, a11y and the scenes are unchanged.

**Design choices** (PLAN left them open; each keeps governed admission, the
activation budget and all editors equal):

1. One facade per process, configured by the command that needs it. A flag
   or consent given after the first governed use applies at the next
   settings sync or sample; it is never refused and never silently dropped.
2. The shared governor is the runtime host's alone. Safe points, created-root
   cleanup on pressure and transport results therefore follow the one
   governor, as in the VS Code window, where before the launch host's own
   governor was idle at normal.
3. Attested settlements are kept only while the process records (the agent's
   consent); one-shot and headless processes keep none.
4. Local session correlation through AsyncLocalStorage: a turn's governed
   spawns notify that session. Nothing enters a resource event, status or
   record; headless's in-process client drops those chunks (only account
   notices surface there), so its answer text is unchanged.
5. A failed load of the launches is retried by the next spawn, not cached.
