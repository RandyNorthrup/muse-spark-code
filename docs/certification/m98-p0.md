## Delivered seams

- `JudgeRuntime` in `engine.ts` is a request-only injected interface:
  `judge(request: JudgeRequest, signal: AbortSignal): Promise<JudgeOutcome>`.
  Assembly supplies the actual implementation, including current source,
  owner/consent binding, redaction and per-attempt durable admission. P0
  creates no backend, transport, key store, ledger, scheduler or fallback.
  Its imports of the request/outcome are type-only. The existing engine
  predicate emits exactly the same implementation and stays schema-free.
- `judgeOutcomeSchema` distinguishes `answered` from an explicit
  `no-answer` with a bounded reason code. Success requires 1–64 answers;
  the existing result schema still requires matching `muse` ids. A refusal
  rejects arbitrary content/extra fields. This wrapper does not alter
  phase-1's existing result schema or its callers.
- `judgeCapabilitySchema` identifies one source/provider/model/version/
  endpoint and a named capture. It distinguishes top-k (positive integer
  k), top-1, refused, dropped and unknown logprobs, alongside stated,
  SystemOne, cache, forced-reasoning and positive-integer context/output
  limits. This is an internal record supplied by the capture-owning source
  lanes, not a new parser for any uncaptured provider response.
- `judgeProfileIdentitySchema` binds source/provider/model/version/endpoint,
  technique, family, prompt, criteria and fit versions. Every binding is
  required/nonempty; top-1 is excluded. B owns fitting, evaluation and exact
  identity matching; these fields alone do not certify a calibrated model.
- `muse` accepts SystemOne, sampling, contrastive, cascade and embedding
  technique values, optional `profileId` and nonnegative
  `uncertainCostUsd`. Existing Jev request/answer schemas are unchanged;
  phase-2 metadata stays in the sibling. Log summaries retain uncertainty
  cost and exclude private profile ids, state, questions and answers.
- Shared refusal codes cover off/consent/source/readiness/profile,
  untested/unverified/confidential/capability, context/budget/price,
  cancellation/timeout/failure. Sources still implement their own verified
  refusal conditions; codes are not permission or locality proof.

## Settings, text and unchanged defaults

`museSpark.judge.engine` now accepts `auto|same|separate|both|off`, retaining
`auto` and machine scope. `museSpark.judge.separate` is the source/model
identifier, machine-scoped, default empty. The settings reader validates it
and keeps it out of the webview snapshot. It stores no key and performs no
selection or discovery. The phase-1 resolver is untouched: `auto` remains
`same`, and phase-2 explicit values cannot dispatch until A/Z deliver their
resolver and runtime. Existing single-model defaults and all request builders,
MSP adapters, paid activation/consent and approval paths are untouched.

The auto description now requires verification, calibration and measurement
before both sources join; mere configuration no longer promises activation.
New separate/both/selection descriptions and six source/status/no-answer UI
keys have real translations in all 14 languages. The existing ask-once
first-charge template, `{price}`, `{budget}` and free-to-paid re-consent text
are unchanged. Paid activation stays excluded, including for the new modes.
No source is enabled, downloaded or contacted by P0.

Named phase-2 tunables: cascade and embedding entropy bars `0.8`, isotonic
minimum `200` independent labels, CLI default paid cap `0`, sampling
eligibility ceiling `$0.001` per question. The latter is a conservative
provisional eligibility cap, not a measured price or spending permission;
D/Z must still use uncached worst-case prices, captured eligibility, consent
and the existing ledger before any dispatch. No algorithm or adoption claim
is made from these constants. No new model-facing wording/block is needed
by this passive seam; future lazy blocks and their split readers require Z's
build/split integration rather than an unguarded object here.
