# M103A3 — JSON diagnostics in Arduino IDE

Mac mini, branch `m103/a3`, base `33a9c3ee`. No live model attempts, paid calls,
credential reads, device opening/actuation, push, merge or rebase. The brief
assigns full quality/coverage to the lead and forbids an aggregate lane run.

The adapter detects a missing native report by behavior on each JSON document,
never by host name or installed-provider identity. It parses JSON/JSONC with
UTF-16 positions and uses existing Muse permission-setting schemas for editor
settings. A DiagnosticCollection publishes the result so the verification loop
and diagnostics tool read the same API. Native reports/held errors take
precedence; a late native report withdraws our entries. Cleanup removes owned
entries and disposes subscriptions. Confinement, changed-file, unsaved-text,
read-admission and cancellation checks remain in effect.

`dist/verifyEditor.js` defers the whole adapter until a diagnostics or formatting
request; its factory installs the caller's language table. Redaction is provided
by the caller, sharing the existing activation redactor rather than adding its
4 KiB implementation to this small lazy bundle. The 25 KiB new artifact budget
follows D6; every existing cap remains unchanged. The pure parser can serve
other host adapters; broader language-service parity remains D84/M104.

All 58 focused tests in jsonDiagnostics, verifyEditorBundle and verifyEditor pass.
Final real-host counts, package receipts, scoped gates and byte-exact drills are
recorded below. Arduino's absent TypeScript cases remain explicit
capability expectations rather than claims of semantic parity.

The feature-reference files/script named by the current common rules are absent
on this A2-based branch; no placeholder catalog or generator is invented. README,
CHANGELOG and PLAN record the feature here. No new command, setting or script.
