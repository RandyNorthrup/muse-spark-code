  owner to `ModelApiBackendManager` and `ModelApiHost`. The original pool
  chooses; the registry writer builds the selected account's guarded client.
  Every send checks the payer digest and credential revision, separately from
  the unchanged conversation/run and daily budget identities.
- ACP `/accounts use` and session selection use that same pool per session.
  Busy/stale adoption refuses. Muse Code has no Meta account picker.
- Stored-key native Meta headless requests bind account admission even with
  no pool flag; `--account-pool` permits swaps, while unflagged runs stop at
  their caps. CI stdin keys never select or pool stored accounts.
- Independent durable claim names prevent lost reservations. Exact receipts
  settle on the original account; nonsends refund; unknown sends retain
  liability. Pending counters survive resets; the send sets its actual day.
  Append-only vendor blocks retain group identity after account removal and
  concurrent resets. Corrupt, linked or oversized claim files refuse with
  fixed error text. No label, prompt, endpoint, credential or key digest goes
  into this account journal.
- Credential writes validate before mutation, advance a random metadata
  revision and invalidate held clients. Replaced accounts get a new paid
  binding; held revoked answers neither grant nor dispatch. Runtime metadata
  has a synchronous final read, so another process's edits are fenced too.
  Meta's origin/product/policy mapping is fixed rather than user-overridable.
- Paid worker admission uses the original question under the selected payer.
  Best-of-N passes its question through the installed runner/manager; legacy
  schedules carry their original question. Native replay crosses accounts
  only as visible text. Cold-cache liability is reserved before admission.
