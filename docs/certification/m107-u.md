## Surface implementation and named integration bindings

The shared chip renders all four levels, preserving unknown versus zero.
The popover shows CPU, memory use and available memory against their actual
thresholds, including lane 0's size-capped free-memory floor. GPU/disk rows
appear only when configured. It shows aggregate waiting kinds/classes/counts
and the override expiry using the installed language's Intl helpers. Resume,
Settings and Show resources call the supplied host port directly. Escape,
Close and action completion restore focus to the chip; focus leaving closes
it, and another modal makes it inert. Only level text enters its live region.

The App accepts `ResourceSurfaceLoader`, created with
`createResourceSurfaceLoader(port, load)` outside render. Its React lazy
component loads only when mounted; connecting/absent-resource Apps load no
surface, and unmounting an unresolved load cannot reopen it. Source snapshots
must retain object identity between notifications. The component validates
with `resourceStatusSchema` before displaying any fields. The heartbeat
portal is scoped to its own App, follows the working row's retirement without
remounting the surface/subscription, and returns to the composer's mount.
A companion page uses the same component and port without a heartbeat.

`ResourceTaskRow` is the delivered row for M96c V/R. It shows waiting, the
pending target/reason, Run now only for an injected foreground queued handle,
and Move to/Keep here only for checks or queued workers with an injected
target. Other kinds and running workers never get relocation controls.
Receiver admission removes controls and retains a completed-move row.
The UI never asserts retirement, grants an offer, sends a task, publishes a
relocation event, changes a process or spends money itself.
