## Implementation and boundaries

- `WindowsVaultSlot` implements lane 0's `VaultSlotPort`, with authenticated
  slot identity and generation metadata supplied by C and a helper transport
  injected by B/W. The shape matches the shared macOS adapter; no fake or
  credential migration lives in production code.
- DPAPI uses `CurrentUser`, with entropy bound to the vault id, slot id and
  tier. Only the wrapped 32-byte vault key belongs in C's owner-only slot
  file. DPAPI availability is probed in the current session; no network-logon
  guarantee follows from replacing Credential Manager.
- PCP uses a current-user, non-exportable RSA-2048 decryption key, and
  OAEP-SHA-256. No software provider fallback. Creation refuses overwrite;
  key properties are checked again when opening. ECC is reported only from
  `NCryptIsAlgSupported` for `ECDSA_P256`, never inferred from RSA support.
- Presence creates a PCP key with `ForceHighProtection`. Each unwrap also
  asks Hello to sign a fresh random challenge bound to the identity and exact
  named use, in a separate helper process with its own visible window.
  Native and Node verification accept actual valid PSS/SHA-256 or
  PKCS1/SHA-256 padding; the public key is pinned in the authenticated slot.
  Signatures never derive a wrapping key. Closing the window, cancellation,
  unavailable Hello, a changed challenge/use/key, or a bad signature refuses
  use. No cached PCP prompt is treated as fresh presence.
- The helper uses Windows' runtime WinRT metadata and reflection, without
  requiring an SDK or provisioned application to compile. An OS refusal
  stays a refusal; compilation alone makes no Hello support claim.
- Binary framing is a big-endian 32-bit JSON header length, a bounded strict
  metadata header, then exactly 32 raw bytes for wrap input/unwrap output.
  Every TypeScript header is validated with zod; the native receiver validates
  exact fields, types, identities, lengths and EOF before acting. No secret
  is an argument, environment variable, JSON field or diagnostic.
- Both launcher and compiler use empty environments and hidden consoles.
  The compiler uses M27's atomic rename and scratch cleanup within a fresh
  private directory; process-local identities and launch verification now
  replace filename-only caching. The helper transport is bounded, cancellable, discards stderr,
  and erases its received chunks. Owned Node buffers are unpooled and zeroed
  on success and failure. Native key arrays are cleared in `finally`; this
  does not claim OS memory zeroization or protection from same-user debuggers.
- `windowsVaultScreenLock` waits for WTS session-lock notification. B supplies
  lifetime cancellation and treats a validated `locked: true` notification
  as a lock; an invalid notification or failed subscription cannot pretend
  to report a lock. This wait is not subject to the approval deadline.
- Banner facts reuse lane 0's translated warning keys at call time. No new
  UI or manifest strings, commands, settings or npm dependencies were added.
