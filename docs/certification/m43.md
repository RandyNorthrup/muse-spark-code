# M43 certification — a row for every tool Muse Code runs (PLAN.md M43, D36)

Recorded 2026-09-25.

Before M43 the panel knew a dozen tool names. Muse Code's memory, goal,
schedule, web search and background-work tools showed their raw names and
their JSON results, a command Muse Code moved to the background read
"Interrupted" once its turn ended, and a picture the agent read was a line
of text.

## The live capture

The rows are built from what Muse Code 1.3.0 actually sends (AGENTS.md rule
13), captured on 2026-09-25 with the owner's standing go-ahead for live
checks (no ask, contributor model, empty workspace, count afterwards):

- **Where:** an empty folder, `C:\muse-live-m43`, holding only a 2×2 PNG.
- **How:** `muse serve --trust-workspace` driven over MSP by a capture
  script, approval mode `allowAll`, every notification written to a JSON
  lines file. Model `muse-spark-1.3-contributor`.
- **Six turns**, each asking for one tool family: memory (add, read, edit),
  goal (create, get, report progress, complete), schedule (one-shot create,
  list, delete), web search, background work (a `Start-Sleep` backgrounded,
  then stopped), and reading the PNG.
- **Cost:** 38 model attempts, all on the contributor model, counted from
  the CLI's trace log (`event="model.attempt.lifecycle" phase="admission"`,
  the capture's own `cli-dbdc652d-….log`).

What the capture showed, and what the rows now do with it:

| Tool family                                                 | What Muse Code sends                                                                                                                                                        | The row                                                                                                                   |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `add_memory`, `read_memory`, `edit_memory`                  | Arguments `path`, `scope` (`personal_project` by default), `content` or `old_str`/`new_str`; a JSON result, `content` on a read                                             | The note (or the text read back), where it lives, an edit as removed and added lines; the path beside the label           |
| `create_goal`, `get_goal`, `update_goal`, `report_progress` | A JSON result `{ goal: { objective, status, percent_complete, current_work, next_work, tokens_used, token_budget } }`; `session/goalChanged` beside it                      | The objective, the status in words (an unknown one as it came), a progress bar, now and next, tokens against any budget   |
| `cron_create`, `cron_list`, `cron_delete`                   | Arguments `cron`, `prompt`, `recurring`; `cron_list` answers `{ jobs: [{ id, cron, prompt, recurring, next_fire_at_ms, fire_count }] }`; the others text                    | Each prompt, its schedule, once or repeating, the next run as a local date, how often it ran                              |
| `web_search`                                                | Argument `query`; a JSON result `{ query, results: [{ url, title, snippet }] }`                                                                                             | The results as links opened through the host, with snippets. The Model API backend's search rows now carry the same shape |
| `powershell` backgrounded, `work_stop`                      | The shell call stays `inProgress`; its result is JSON with `execution_state: "background_running"`, `work_id` and `output`; no `background` flag                            | What the command printed, "Running in the background", the background badge, and no "Interrupted" at the turn's end       |
| `read_file` of an image                                     | Text only ("Read image file … as model-visible image output"); the image the model saw is in the durable session log, not on the live stream (`modelVisibleContent` absent) | The picture itself, read by the host from the workspace path, opened in VS Code's image viewer on click                   |

Every other name in the CLI's tool list (the workflow, code, artifact,
monitor, session-messaging, reminder and patch tools) now has a label, an
MCP server's tool reads "tool (server)", and a tool with no view of its own
shows its arguments and result as indented JSON.

## The picture a row shows

The webview asks the host (`readToolImage`) once the row is open and the
call has completed; the host (`src/core/toolImages.ts`) answers with a data
URI or the reason it will not:

- only `.png`, `.jpg`, `.jpeg`, `.gif` and `.webp` names;
- only inside the workspace, with the same link check the Model API's file
  tools use (`confineWorkspacePath`, D24): a link that leads out is refused;
- no larger than an attachment may be (`MAX_IMAGE_BYTES`);
- nothing is read for a refused path.

The pictures are held in the webview's state only while the conversation is
shown; they are never saved with it.

## The review of PR #29

Codex found four gaps, all fixed:

- **`modelVisibleContent` read leniently (P1).** Its shape comes from MSP
  1.3.0's schema, but it was never seen on the wire, and a strict parser
  would have discarded a whole item or history over it. Each element is now
  checked on its own and anything that differs is passed over.
- **Snippets kept on the Model API (P2).** Its search rows carried title and
  URL only; Meta's `snippet` now reaches the row as Muse Code's does.
- **Background runs need the whole envelope (P2).** A command that printed
  JSON with an `execution_state` was taken for a background run; the
  captured `work_id` is now required too.
- **An unreadable `cron_list` shows its text (P2).** It read "No scheduled
  prompts"; only a valid empty list does now.

## Translations

The 52 new strings are in all fourteen languages, made by seven agents in
parallel, two languages each. The gate found one thing: the English
"Ran once" had no `{count}`, which Russian's `one` form (21, 31, …) cannot
drop, so the English became "Ran {count} time" and every language's `one`
form names the number.
