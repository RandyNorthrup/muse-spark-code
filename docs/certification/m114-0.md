paths, the native role list and the A/P1/P2/C/D/N/F/S handoffs. The visual matrix
is `test/harness/visual-matrix.json`: six themes, 320/690 px, six interaction
states, a fixed component/state/theme/width golden path and the complete current
React component inventory plus Tasks and What’s New. A owns the grades; S owns
the comparison/update runner and goldens, including the one-pixel drill.

The old danger fallback misses AA on raised dark backgrounds. The standalone
semantic danger role is stronger; the existing red fallback remains a separate
legacy token, while VS Code mappings still take the host theme’s colours.
Extending the checks to every host-role fallback exposed weak standalone error
and warning backgrounds, link hover and progress colours. Error/warning surfaces
now have separate opaque mode values, and link hover/progress use stronger roles.
The coverage guard also caught an unpaired control border before completion.
`check:tokens` checks 89 declared pairs (356 mode comparisons) and rejects any
colour without a checked use or an explicit decorative classification. Eleven
decorative effects, logo/gradient stops and disabled roles are classified in
the source; none claims text contrast. The host’s
actual colours remain subject to the harness accessibility checks and A’s
state audit; this does not certify arbitrary third-party/user themes as AA.

The extended host map is generated separately from the startup token CSS so
unused editor mappings do not enter today’s panel. TH and TD get every resolved
mode and token in `consumers.json`. No desktop/native/TUI binding is fabricated.
