## Design and launch contract

No M96 K cgroup launcher exists on this base. `launchLinuxResourceTree` is the
portable Linux launch seam for C1/C2/W and every editor/ACP/headless caller.
It detects cgroup v2 and the systemd user manager without root, or a writable
subtree already containing the harness. An explicit delegated root remains a
trusted caller dependency, never a workspace/model setting. It creates a
fresh UUID child cgroup per workload. An initial shell waits for GO; membership,
exact launch birth and registry admission precede every workload instruction.
The workload keeps its stdin/stdout/stderr, cwd and explicitly supplied env;
no environment is inherited by default. OS probes inherit no credential variables.

A real probe showed EACCES when migrating a login-session child into a user
manager scope: Linux requires migration authority at the common ancestor.
The manager path therefore starts both gate and keeper _inside_ its delegated
`systemd-run --user --scope --property=Delegate=yes` scope, and lets only
the workload gate move itself into the private child cgroup. The gate writes
its own $$, never a host-selected PID. systemd-run uses
--expand-environment=no to preserve shell dollars and literal workload args. The keeper holds a separate
control pipe (fd 3, closed before workload exec); workload stdin EOF cannot
release it. On verified completion the child cgroup is removed, its registry
entry retired and the keeper released. systemd then removes its outer scope.
No machine/user settings, root rights or security policy are changed.

Cgroup readers accept only canonical descendants of the trusted root under
this user's slice. Their current kernel membership supplies the entire tree:
no ancestry anchor, retained PID/birth witness or current root is needed after
launch. CPU is the cgroup's lifetime `cpu.stat`; its recursive cgroup.procs supplies
the members whose `/proc` resident pages contribute RSS, excluding cache rather than equating
`memory.current` with RSS. Missing lifetime counters are unknown. This remains
an adjacent-read sample, not an atomic memory snapshot.

`registry.kill` dispatches the Linux kernel-contained action port. SIGKILL
writes `cgroup.kill`; an unsupported kernel (ENOENT/EOPNOTSUPP), or requested
SIGTERM, freezes, waits for `frozen 1`, recursively enumerates `cgroup.procs`,
checks current containment and signals each member, then thaws in finally.
Permission/I/O failures do not select a permissive fallback. Both paths wait
for `populated 0`, with a 5 s deadline and 10 ms poll, before removing nested
cgroups child-first. Unknown, malformed, timed-out or retired actions return
refused and retain the scope. Harness/invalid PIDs are refused before dispatch.
Cgroup kill's `done` is an exit receipt, with an empty per-PID result list;
legacy group kill's `done` remains an admitted-signal result. Consumers must
retain that distinction; Darwin and Windows APIs/native sources are unchanged.

## No-delegation residual

Group fallback reads `pid_max` and `CLK_TCK`, refuses admission below
`LINUX_PID_IDENTITY_MIN_PID_MAX = 4,194,304` or on unavailable units/bounds,
and rechecks the bound and current observed identity/membership before every
signal. Kubuntu reads **pid_max 4,194,304, CLK_TCK 100 Hz**, a **10 ms** birth
bucket (generally 1/CLK_TCK seconds). The bound is a checked assumption, not a
proof that tick identities are unique: namespace occupancy, allocator wrap
and process churn are not bounded here. Same-tick PID aliasing remains possible
in undelegated groups. No native same-tick reuse was forced or observed.

The final read-to-signal race remains for individual POSIX signals and the
specified freeze fallback; `cgroup.kill` avoids numerical PID signalling.
An unobserved group fork/reparent edge remains unavailable. PLAN §9 records
these residuals explicitly. C1/C2/W must use this launch seam for every governed
Linux tree and wire the planned lazy governor bundle. This base has no such
all-spawn integration, so current bundle sizes are not integrated M107 claims.
