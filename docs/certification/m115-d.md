## Core delivery

`src/core/schedules/delivery.ts` implements `ScheduleHostPort`. Steer reaches
a running turn and starts a turn when idle; only an explicit no-input steer
refusal allows fallback. Interrupt uses the session's public Stop and waits
for the aborted turn to unwind before sending. Queue retains a withdrawable
run handle; default delivery owns a withdrawable entry in the backend queue after the
user's already-queued turns, with Skip retained through asynchronous admission
(FIXM115D below). New-conversation delivery asks
for a fresh target. Closed targets open in the background or settle as
missed, and catch-up is Run once or Skip for S's selected latest occurrence.
The run context must match the admitted schedule's authority; both are
parsed/copied before asynchronous delivery. Every final record preserves
run identity, occurrence, refusals, cost certainty and retained liability.
External settlements must match the original run/target/event. Unavailable
board/report bindings refuse explicitly before any model submission.

## Background targets and backend adapter

`src/host/schedules/backgroundTarget.ts` borrows an existing live target or
resumes a closed conversation through its actual `AgentHost`. Concurrent
background leases share one resume; the last release detaches the transcript
and disposes the background session. Failed resumes are evicted for retry.
Fresh delivery starts a new backend session for every fire, names it with the
schedule and localized occurrence, and uses the schedule's mode rather than
the interactive host's default. Where backend rename is unavailable, the
published history title still carries the name. The injected publisher receives
history and the background notice without selecting a panel.

`ScheduleAgentSession` binds U's required message context before send, steer
and queue. It tracks normalized backend events, handles completion before the
send acknowledgment, reparents queued handles by user-message identity, and
withdraws only the exact backend message. An aborted hold or closed session
wakes idle waiters. Interrupt calls the actual `AgentSession.cancel`, which
retains the existing Stop cleanup of partly-decided approvals. Delivery also
rechecks workspace ownership after U's admission wait and after Stop unwinds.

The Stop integration test runs the real `MuseCodeHost` against the in-memory

### Queue and lifecycle repairs

- **P2-1:** When-idle is an entry in the actual target session's queue, not
  wait-then-send. `queueWhenIdle` is a local delivery-adapter operation over
  the existing `sendTurn`; no frozen lane-0 contract or provider shape changes.
  Its abort signal is checked in the context submitter's dispatch callback,
  after asynchronous admission. Only that exact pre-dispatch abort can prove
  no input was sent. Skip survives admission and acknowledgement waits,
  withdraws the exact run's queued message, and leaves the user's turn alone.
  A repeated Skip shares the withdrawal attempt. Withdrawal failures propagate
  without fabricating a settlement; U still owns all refusal/cost facts.
  Duplicate delivery cleanup compares hold identity and cannot remove the
  first fire's Skip handle.
- **P2-2:** The controller's predicate is extracted unchanged into
  `src/shared/agentEvents.ts`; both controller and background adapter call
  that one function. This minimal shared extraction and controller delegation
  are necessary to obey the lead's explicit instruction to share it. No
  event schema or unrelated controller region changes. Known child sessions
  come from actual subagent rows, including resumed history; forwarded child
  starts/completions cannot replace the parent steer target or wake waiters.
- **P2-3:** Busy means a parent turn or any non-idle session status. Resumed
  status is initialized from the loaded record. Compaction Interrupt calls
  the real public Stop; its idle wait stays pending until actual idle.
  When-idle queues behind compaction, and Skip removes only that queued entry,
  leaving the summary running.
- **P2-4:** A pooled lookup acquires a lease only after a synchronous check
  that its entry is current and open. Open retries a retired lookup; release
  deletes the key only when the map still points at that exact entry. Tests
  cover the review's deterministic microtask race and an old host lease
