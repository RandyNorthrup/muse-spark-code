## Integration on `feature/m94-tab` (lanes C and L wired, 2026-10-04)

Recorded after the merges of P, C, L, H and U (`215f4004`). The lead's brief:
wire H's seams to the real C and L modules and adapt anything that assumed
Tab off by default to the owner's ask-once ruling.

### What changed

- **Seams removed.** `unwiredEngine`, `unwiredSpend` and `unwiredConsent` are
  gone. The bundle builds the engine and the spend gate itself
  (`createTabServices` in `tabEntry.ts`, a sixth entry `isTabBundle` checks)
  from what activation hands it: the key client's stream, the ledger folder
  (`TAB_LEDGER_DIR`, global storage's `tab-spend`) and a per-window id.
  Activation keeps the question (`paid.consent.allows({ feature: 'tab', … })`)
  and the tally (`PaidUsage.addTabRequest` / `addTabUsage`).
- **Engine** (`src/core/tab/tabEngine.ts`, new, pure): the typing-through
  cache first, then the scheduler (Automatic debounced, Invoke at once); a
  replaced or cancelled waiting trigger is answered with no suggestion and
  zero usage. The request is lane C's body; the client gets one HTTP attempt
  (`retriesUsed: MODEL_API_MAX_RETRIES`), since the reservation prices one
  (RVM94LC's integration note). The suggestion is published as soon as a
  complete tag pair has streamed; `usage` settles when the stream ends and
  rejects when it reports none (the reservation then stands, M82).
- **Spend gate** (`src/host/tab/tabSpendGate.ts`, new) over lane L's ledger:
  `reserve` returns a `TabReservation` carrying its own worst case, and
  `settle(reservation, usage)` replaces exactly that one. The status bar's
  total is the last one the ledger answered, refreshed after each change.
- **Provider:** the window is lane C's `contextWindow` (anchored prefix,
  bounded suffix), redacted before pricing; the worst case is priced on the
  instructions plus the one user message actually sent (was: the whole
  file). A token cancelled before sending releases its reservation (was: kept
  with nothing to settle it). The snapshot carries the model, the cursor
  line's text before the cursor (lane C's whitespace normalisation), the line
  above, the lines below and the token's state for the debounce.
- **Ask once, no turn-on modal (owner 2026-10-04).** `PaidFeatureGate` gains
  `asksOnFirstUse` (`tab` in `createPaidFeatures`): the gate's review and
  palette Turn on never show Tab's price confirmation; the acceptance follows
  the setting silently, so turning Tab off still voids its "always" grants.
  The first request's D48 question (lane L's wording: rates, budget, training
  note) is the only consent, and nothing is sent before it. Lane L's two
  paidHost tests that drove the old turn-on modal now assert this flow.
- **Pre-existing test faults fixed.** `tabBundle.test.ts` failed 7 of its
  tests at the H merge (`c484309f`, slot m94int-hbase): the activation harness
  returned a spread copy, so `settingOn` never reached `isTabSettingOn`, and
  the entry test left `registerInlineCompletionItemProvider` returning
  undefined. `test/integration/tab.test.ts` never called `tab.refresh()`, so
  no provider registered; it now does, and runs the real engine and ledger
  with a faked key-client stream.
