# M91-G: golden "hooks off" requests

Recorded on branch `feature/m91-hooks-parity`, from the lane-0 tree
(`84e83b8f`). PLAN.md M91 acceptance 14g, SoL-Pi rule 7: with hooks off,
every request the Model API backend sends must stay byte-identical to what
it sent before M91. This lane's fixtures are the baseline every later M91
lane compares against, so they were captured before any lane changed
request building.

## What

`test/unit/modelApiGoldenRequests.test.ts` drives the real `ModelApiHost`
against the fake Model API (`test/unit/helpers/fakeModelApi.ts`) with hooks
explicitly OFF (`isHooksEnabled: () => false`), over the shared deterministic
harness (`fakeModelApiHostDeps`: counting ids, a clock from a fixed start,
in-memory workspace at `/ws`, no memory store, no MCP, nothing paid except
where the scenario needs it). Observation packing stays ON: it is not a
hook, and scenario 4 watches it work.

For each scenario the test serializes every `POST /responses` body the fake
receives — stable JSON with keys sorted at every level — and asserts it
equals `test/fixtures/golden-requests/<scenario>.json` byte for byte.

## Scenarios

| Fixture                     | Requests | What it covers                                                                |
| --------------------------- | -------- | ----------------------------------------------------------------------------- |
| `01-plain-turn.json`        | 1        | A plain one-turn reply: model, instructions, input, full tool list, cache key |
| `02-tool-call.json`         | 2        | One `read_file` call and its result echoed in the next request's input        |
| `03-edit-then-run.json`     | 2        | `edit_file` with `then_run` (`echo then` ran through the shell fake)          |
| `04-packed-output.json`     | 4        | A 400-line `read_file` result sent whole twice, then as a placeholder         |
| `05-manual-compaction.json` | 3        | A turn, the manual compaction (`tools: []`, summary prompt), the turn after   |
| `06-subagent-child.json`    | 3        | Parent spawn call, the child turn (task marker in input), parent follow-up    |
| `07-skills-and-rules.json`  | 1        | `AGENTS.md` rules and the skill catalogue in the instructions                 |

## Normalisations (only real nondeterminism, each with its reason)

- **Wire item ids** (`function_call`/`reasoning`/`message`/`web_search_call`
  `id` fields → `<item-id>`/`<reasoning-id>`/`<message-id>`/`<search-id>`).
  The fake numbers every streamed item from a module-global counter and the
  host replays those ids in later request inputs; they name nothing the test
  chose. Scripted call ids (`c1`, `e1`, `spawn1`) stay: a lane that renamed
  or dropped a call must fail loudly.
- **Nothing else.** The harness clock fixes the instructions' `today` at
  `1970-01-01`; `prompt_cache_key` is a digest of model+instructions+tools
  and is deterministic, so it is kept byte-exact on purpose. No temporary
  path, wall-clock timestamp or random marker reaches these bodies
  (pack markers are per recall _response_; there is no checkpoint shadow
  repository without the verify dep). A second consecutive run diffed clean
  with no further normalisation. If a later lane puts a timestamp or path on
  the wire, the byte comparison fails first and the list above grows only
  with a documented reason.

## Regenerate mode

`MUSE_SPARK_UPDATE_GOLDEN_REQUESTS=1` (read the way the eval probes read
`MUSE_EVAL_PROBE`) rewrites the fixtures instead of comparing. It is never
on by default, and it throws under CI (`CI` set), so a pipeline can never
silently re-baseline.
