## OAuth issuer (P2)

The new regressions “RVM109L0 P2 issuer: OAuth contracts preserve complete
HTTPS issuer identifiers” and “RVM109L0 P2 issuer: OAuth digests distinguish
tenants and exact issuer spellings” failed on the original code (25 other
tests passed). With the fix, all 27 passed. Uses, bindings and private material
now share a distinct URL schema. The raw identifier survives parsing, and
different paths, trailing slashes, case, explicit default ports and encoded
spellings stay distinct in the digest. HTTP, query/fragment delimiters
(including empty ones), credentials, whitespace, backslashes and invalid URLs
are refused. Origin and fill guards are unchanged.

No vault JSON Schema existed on this base. The committed issuer schema is
generated from `vaultIssuerSchema` with `z.toJSONSchema`, with an explicit URI
format annotation (Zod's exporter drops the URL format when a regex is added)
and the HTTPS/authority/path pattern; a contract regression checks drift.
Wave-1 O/B obligations are in `m109-contract-handoff.md`.

This piece passes all five `npm run typecheck` projects, changed-TypeScript
ESLint and Prettier. The restored contract/digest files pass 28 tests,
including the JSON Schema drift regression. Five issuer drills fail as
expected: each of the three OAuth fields changed back to an origin, removal
of the URL pattern, and mutation of the committed JSON Schema annotation.

The final issuer pass also accepts HTTPS scheme case without rewriting the
identifier. Adding `HTTPS://...` to the preservation/digest fixtures first
failed both named regressions; the lowercase-only pattern was corrected and
the same pattern was deliberately restored for a sixth issuer red drill.

Red-drill receipts are in [m109-l0-drills.json](m109-l0-drills.json). The
drill harness snapshots the source bytes, mutates one guard, runs the whole
owned files, restores in `finally` and compares SHA-256. Every recorded
runtime mutation must exit 1 with a named RVM109L0 regression failure; the
two compiler mutations must exit 2 with owned fixture diagnostics. No test is
skipped or filtered.

## Broker authorization (P2) and owned snapshots (P3)

On the original broker/fake code, the new automatic-ticket contract regression
failed because `authority` was rejected, the host ownership regression failed
because the foreign peer received `true`, and the pre-await snapshot regression
failed because requester, nested role, command, environment names and taint
all reflected caller mutation. The other 34 tests passed in that batch.

`VaultAuthorizationResult` now gives request consumers approval, ticket or
denial. `VaultApprovalResult` gives answer consumers ticket or denial. The
port and response parser reuse those schemas. Tickets carry a strict mode,
named-grant or UI-user authority. This is an internal project protocol with
no external wire guess or enabled runtime. Always/session policy enforcement,
audit persistence and ticket redemption remain B's work; the automatic
outcomes in the regression are scripted through the typed port, not claimed
as a fake policy implementation. The fake UI answer supplies the full bound
single-use ticket, consumes a valid Deny and refuses replay and expiry.

Pending fake requester/use/taint are deep-copied before the first await,
metadata is copied at minting, and returned approvals are independent. The
tests mutate original nested inputs during the await, mutate the host after
minting, mutate returned cards, and mutate the store's list metadata.

`vault-authorization-result-v1.schema.json` is generated from the same Zod
boundary; a regression checks drift. The artifact is generated contract
data, not additional implementation or a policy engine. Existing exec JSON
Schemas need no change for these internal contracts. The wave-1 handoff
documents result branching, authority/audit mapping, automatic operation ids,
private ticket delivery, schema generation and runtime enforcement duties.
