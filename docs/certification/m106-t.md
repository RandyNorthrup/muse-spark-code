## Delivered mechanism

- Harness declarations accept the injected effective session choice in
  `ToolDefinitionOptions.shouldUseStrictTools`. All declarations, including
  recall, browser checks, image tools, goals, memory, subagents, checks and
  code intelligence, use FIXM101P2's existing `withStrictTools` rewrite.
  Full-option Linux, Darwin and Windows declarations are tested. The caller
  resolves setting AND model support; an absent effective choice stays off.
- Responses encoding accepts `ResponsesEncodeOptions.shouldUseStrictTools`.
  Explicit false keeps canonical non-strict bytes even on a capable model.
  True cannot override a selected record's false/unknown. The existing
  selected-model resolver remains authoritative over preset quirks.
- MCP conversion preflights the original schema with the same rewrite.
  A schema already fitted with losses, outside the strict subset, missing,
  or replaced stays non-strict. References and metadata outside M101's
  subset remain conservative fallbacks rather than claiming that an
  inlined/trimmed schema establishes lossless support.
- A symbol on an unconvertible declaration preserves that evidence through
  object copying without adding a JSON/wire field. The rewrite skips it;
  harness schema errors still throw. Nullable-argument restoration also
  skips it, so the server receives unchanged non-strict arguments.
- One technical fallback note joins the converter's existing `notes`.
  The existing MCP pool logs one line naming server and tool when offering
  it. Repeated strict request construction logs nothing further and reveals
  no schema contents. A real pool over a fake transport proves this.
- U9's valid declaration round-trips through conversion and Responses
  encoding. Its exact captured 400 goes through the real client, retaining
  the message/type and null code semantics, with one attempt and no retry.
  Source: [lane-0 capture receipt](m106-captures.md), run
  `2026-10-06T00-30-19-038Z`, sequences 35/36, two source attempts (one
  refused); the standalone HTTPS probe has no recorded repository workspace.
  This lane makes zero inference attempts. No argument delta is invented.

## Named integration handoffs

**M106T-SESSION-BINDING (lane W).** Register the machine-scoped
`museSpark.modelApiStrictTools` setting, default on, using lane 0's
[translated manifest descriptions](../research/m106-manifest-strings.json).
Snapshot the user's choice for the session, and combine it with the selected
record's `supportsStrictTools === true` before ModelApiHost's prompt/cache
construction, reviewer declarations and optional-null restoration. The
existing `withStrictTools(tools, effective)` boolean is the injected seam;
`ToolDefinitionOptions.shouldUseStrictTools` accepts the same effective value.
Responses options take the session choice as an additional narrowing gate;
they cannot undo an already rewritten prefix. Do not turn it off only after
cache-key generation. Bind the same choice in the portable ACP/headless
factories; no VS Code-only enablement. ModelApiHost, factory/settings files
and registration belong to other lanes and were not edited here.

capabilities, not `m95/caprec`'s evidence-bearing record. Map only resolved
strict support to that existing boolean, preserving unknown as off and
selected-model false over preset support. U9 qualifies its captured Meta
model; non-Meta rows need their own counted capture before enabled records.
No new resolver or speculative wire dialect is introduced.
