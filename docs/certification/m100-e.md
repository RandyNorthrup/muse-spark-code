## Implemented behavior

`src/core/devices/attemptJournal.ts` implements bounded, owner-only,
nonsync durable records, separate from runtime folders and pairing/logout.
Explicit first provisioning creates a retained sibling marker; recovery opens
existing state and never provisions an empty substitute. Missing, corrupt,
noncanonical, unknown, oversized or abandoned-stage state refuses work.
The selected parent must already exist. Loss of it is not permission to
reinitialize; I must preserve the initialized storage namespace.

Every mutation rereads and validates state under the required exclusive M96
owner lease. POSIX directories/files are 0700/0600, with owner, native file
identity, hardlink, symlink and ancestor checks. Readable system ancestors
are allowed only when another user cannot replace the path; root's sticky
OS temporary ancestor is allowed for tests. Windows requires real private
ACL, safe-ancestor and durability bindings. There is no Windows success
fallback. Temporary sibling creation, file flush, atomic replacement and
directory flush precede success. Failed persistence latches storage failure;
no raw filesystem/path error is reflected in protocol responses.

Canonical SHA-256 hashes validated dispatches independently of property
insertion order. Attempt IDs cannot be reused with a different original
pair/incarnation/board/task tuple or payload. Admission is idempotent;
launch intent can occur once, before running. Revisions, owner, payload and
settlement IDs remain bound. Nonterminal transitions cannot reduce occupancy
or retained liability. Distinct attempts cannot reuse a settlement ID.
Unresolved, full-result, tombstone and byte ceilings stop admission; no
unresolved record or permanent tombstone ages out.

Source intent can be written before transport send. `settleSource` records
an authenticated terminal reconciliation only for a source intent; it cannot
turn receiver-owned unresolved work into a terminal record. Exact duplicates
return prior evidence, while stale or altered terminal claims refuse. Source
and receiver journals use separate persistent namespaces. Source settlement
is bookkeeping, not authority to release a receiver's leases or transfer
spending grants. Source acknowledgement binds the original tuple, payload
and settlement ID. Full results compact only after durable acknowledgement
and its retention period, atomically replaced with permanent tombstones.

`src/host/devices/deviceReceiver.ts` implements lane 0's
`DeviceExecutionPort` and T's receiver-side `receive` adapter. It parses
frames again, binds the authenticated channel/pair/current incarnation, and
accepts only dispatch, reconcile, cancel and acknowledgement requests. Peer
outcomes/check reports cannot retire work. Replies preserve request IDs.
Historical reconciliation/tombstones retain the original attempt identity
inside the new authenticated channel envelope.

Admission uses P's current grant intersection, receiver-local policy and
ordinary approval, then M96's atomic reservation. Durable admission and
launch intent both finish before the sole `start` call. The local executor
gets mandatory ordinary-action and paid-use boundaries. Paid use checks
local gate/consent and the local model/tariff/key binding again after the
popup; no peer consent or credential is expressible. Existing receiver-local
remembered paid grants remain the existing consent implementation's decision.
Checks use a local check ID and need no model startup in this adapter.

Disconnect stops admission immediately, asks live owners to pause, and
requires reconciliation plus explicit Resume. Cancellation never writes a
terminal outcome or releases a reservation. Complete local retirement is a
required owner promise covering engine/request settlement and all admitted
tools/descendants. Only then does the receiver durably record retirement
before releasing execution occupancy. Retained paid liability stays in the
local ledger. Failed/unproved retirement and failed terminal writes stay
blocked; no timer, endpoint, parent exit, PID or user assertion releases work.

On restart M96 first retains saved occupancy/copies/liability. Old unresolved
attempts become uncertain under their original identity, without adoption or
launch. Old terminal outcomes and artifacts remain available through the new
incarnation; cleanup replay returns their tombstones. Ordinary chat has no
imports of either new implementation; I owns the eventual lazy entry.

## Owning proofs and integration limits

The tests use real temporary filesystem persistence, fake local execution
owners and forbidden-call/launch spies. A real Node parent spawns a detached
child and exits; occupancy remains held while the unproved child survives.
The test kills only its freshly spawned child for cleanup and never treats
that PID or the parent's exit as retirement evidence. Each child starts with
an empty inherited environment. No model/provider network operation runs.

This proves E's adapter ordering, replay/refusal and required-port behavior.
It does not prove M96's absent native worker/check/process owner, real
Windows ACLs, another OS account's access, or installed four-device/floor
qualification. Wrong-owner samples, actual POSIX permissions, unsafe
ancestors, file/directory substitution and hardlinks exercise isolation;
the accepted same-user/root residual remains PLAN §9's
**M100-LOCAL-ACCOUNT**. Atomic writes and schemas do not authenticate a
malicious same-user process.

Mandatory named handoffs, with no production fake/default implementation:

- **E-M96-OWNER:** bind `AttemptJournalOwner.assertOwner` to an exclusive
  lifetime lease for the journal namespace. Another window, abandoned owner,
  endpoint/PID/time guess or lost namespace cannot authorize takeover/reset.
- **E-M96-EXECUTION:** bind `DeviceReceiverExecution.retain/admit` to real
  worker/check, local-load, process, child-capacity, write-set/resource and
  isolated-copy admission. `admit` reserves without starting; `start` returns
  launch confirmation and calls the supplied boundaries. Its retirement
  promise requires all admitted requests/tools/descendants to settle. Release
  execution occupancy only after durable terminal evidence; preserve M82/D78
  uncertain financial liability. No scheduler, machine coordinator or remote
  lease-release implementation is introduced here.
- **E-M96-M95-POLICY:** bind current grant, local mode/trust/role/tools,
  protected paths, confidentiality policy, ordinary approval and paid binding
  to existing local authorities. Use the selected model's local capability,
  credential and tariff records for every provider; wire capability claims
  cannot widen them. `paidGate` and `paidConsent` are required local ports to
  the existing gate and three-choice price/daily-budget modal, not peer tokens.
- **E-P-T:** supply current durable P grants and T's authenticated channel;
  connect receive/disconnect to E. Trust loss, unlink and narrowed offers
  immediately block boundaries, with local cancellation/retirement rules.
  A failed send retains the recorded outcome for retry/reconciliation.
- **E-S-SOURCE:** source board waits for `sourceIntent` before send, durably
  records verified terminal reconciliation through `settleSource` before
  acknowledgement/credit, and deduplicates its own routing/tally effects by
  original attempt/revision/settlement. Unknown evidence retains source
  occupancy/debt and never permits reassignment. Bind its separate source
  namespace; do not open it as the executing receiver's journal.
- **E-G-ARTIFACTS:** only the local owner supplies a retirement manifest.
  Historical reconciliation retains it exactly. G validates repository,
  expected base/head/tree, quarantine and artifact bytes before source use;
  a reported remote pass never authorizes merge.
- **E-I-STORAGE:** provision persistent nonsync per-user namespaces outside
  runtime and pairing state; bind and qualify Windows private ACLs,
  safe-ancestor checks and replacement/directory durability through
  `AttemptJournalProtection`. Actual other-user, OS/floor and four-rig tests
  remain required. There is no automatic recovery migration or empty reset.
- **E-I-PRODUCT:** wire `dist/devices.js`, measure its joined budget, register
  `DEVICE_MODEL_TEXT` readers/split checks, regenerate/review host API, and
  run all unchanged aggregate gates. Carry receiver/source recovery and
  approval/cost behavior into README, PRIVACY, SECURITY and feature catalog
  when those commands/features are actually registered. Local desktop hosts
  alone are D80's supported receiver scope; ACP/headless and JetBrains,
  Visual Studio, Eclipse, Zed, Xcode, Neovim/Emacs/Sublime must retain the
  unsupported-host reason until execution/key-location qualification.
