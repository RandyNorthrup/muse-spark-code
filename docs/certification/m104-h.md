## Neovim

`hosts/neovim/lua/muse/init.lua` supplies `MusePanel`, `MuseStop` and a
CodeCompanion ACP adapter factory. An unpaired launch uses the authored
`panel --companion` CLI route; a fresh ACP `/panel` fragment link opens the
existing session. The runtime/page own code redemption, per-window bearer
tokens, authenticated fetch streaming, MHP, UI and paid consent. The shim
does not parse a guessed runtime stdout shape, make HTTP requests, store
URLs, expose raw stderr or use cookies. Default launch still depends on
lanes B/C/D's composed runtime, absent on this baseline.

Companion and browser argv launches strip every `*_API_KEY` and the existing
six named credential variables, case-insensitively. CodeCompanion v19.25.0
inherits its environment; the adapter factory overrides those credential
variables with empty values. Its source was installed only in ignored
`temp/` to verify the adapter and `last_chat():stop()` and adapter identity APIs. The factory
must be recreated if the editor's environment gains new credentials.
Late termination callbacks cannot clear a newly launched companion.

Installed Neovim **0.12.5** and StyLua **2.5.2** locally in ignored `temp/`;
no global installation or machine settings changed. `nvim --headless -u
NONE -l hosts/neovim/test/check.lua`: **11/11 named checks pass**, including
a real sanitized child. StyLua check passes. All tests are offline.
