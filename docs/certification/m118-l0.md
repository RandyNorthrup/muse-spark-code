## Integration limits

This lane does not register commands, implement storage IO/variable expansion,
render share files or dispatch a destination. P/C/X own those adapters and their
end-to-end UI/host checks. The confirmation token must be bound by the host to
its exact stored preview bytes; a parsed webview message is not authorization.
Path normalisation and current registered-secret values are injected ports,
not a new detector/store. JSON front matter is deliberately a strict YAML
subset, not a generic YAML parser. Copy to my prompts retains the workspace
original and preserves untrusted status; no network sync is implied.

Contract exports have schema/test consumers until the implementation lanes land;
PLAN §7 records the bounded deferral without changing Knip. Before merging P/C/X,
verify actual production consumers and remove unused contracts. Node lazy
consumers of `_default` must extend the real shared validation runtime and drill
its existing split guard; this lane's schemas are unbundled. The feature catalog
and reference scripts mentioned in the shared brief do not exist on this base;
P/C/X must update that parallel feature when their commands actually register.
Full integrated quality, coverage/a11y/editor/native checks remain with the
lead/implementation lanes as expressly required by the rig brief. No guard,
threshold, cap or hook is weakened.
