# M95 lane O — Ollama codec (2026-10-05)

Recorded 2026-10-05 on branch `m95/o`, from `feature/m95-byo-providers` at

## What landed

- **`src/core/backends/modelapi/codecs/ollama.ts`** — the native
  `/api/chat` codec as pure functions (no clock, no random id, fixed key
  order, D74 SoL-Pi invariant 1):
  - `encodeOllamaRequest(body, { model, numCtx, think? })` → `{ path:
'/api/chat', body }`, the exact native request bytes. `num_ctx` (the
    panel's stored per-model context, lane P's `ProviderEntry.numCtx`) and
    `num_predict` (the quirks' output-cap parameter) go in `options`;
    `think` is injected or derived from the effort tier
    (`thinkForEffort`). `tool_choice` omitted, empty tool lists never
    sent, `web_search` tools and past `web_search_call` items dropped
    (acceptance 11), Meta-only fields never sent. History function calls
    replay with arguments as objects; results carry `tool_name` from the
    call map; same-provider thinking replays as `thinking`, foreign
    reasoning is dropped. PDFs and tool-result pictures throw an explicit
    error instead of running on shortened input.
  - `readOllamaLines(chunks)` — the NDJSON reader: blank keep-alive lines
    skipped, chunks split anywhere including inside multi-byte characters.
  - `decodeOllamaStream(chunks, { model, status })` — native lines to
    canonical `StreamEvent`s ending in one canonical `ResponseObject`:
    text deltas, `thinking` to reasoning items (the raw text also packed
    into `encrypted_content` as an opaque string only this codec replays),
    whole and fragmented tool calls keyed by index, usage from the final
    line (`prompt_eval_count`, `prompt_eval_cached_count`, `eval_count`;
    invalid counts leave usage unknown), `done_reason` to
    completed/incomplete/failed, mid-stream `{"error"}` lines to
    `ModelApiError`, and a stream closing without a final line fails
    instead of hiding a truncation.
  - `parseOllamaError(status, body, statusText)` — the `{"error": "…"}`
    envelope to `ModelApiError`, status preserved, 429 keeping the
    `HTTP 429:` reason (D74).
- **Tests**: `test/unit/ollamaCodec.test.ts`, 22 tests — exact-byte
  goldens (first turn, tool loop with thinking replay, image, empty-tools
  with `think: false`), prefix stability across a growing session,
  NDJSON chunk splits, text/thinking/parallel-tool usage decode, invalid
  usage, keep-alives, mid-stream and malformed errors, truncation,
  `done_reason` mapping, reasoning replay same-provider vs foreign,
  error parsing, effort mapping, explicit refusals.
- **No new strings.** The codec's errors are wire-level English literals,
  as `client.ts`'s are; lane 0 owns `en.ts` and the 14 tables and its
  record says no lane should invent `UI_TEXT` names, so this lane touches
  none of those files. `node scripts/check-l10n.mjs` reports 0 problems
  (unchanged).

## Temporary seam (lanes T and I not merged)

Lane T's `WireCodec`/`transport.ts`/`ndjson.ts` and lane I's host
integration do not exist yet, so the codec is plain functions over
explicit inputs: the caller injects `model`, `numCtx` and `think`, and
reads `StreamEvent`s off `decodeOllamaStream`. Lane T adapts these to
`WireCodec.encode/decode/parseError` without changing them. No fake
implementation anywhere in production code.
