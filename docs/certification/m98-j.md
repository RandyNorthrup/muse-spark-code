## What this lane owns

New `src/core/judge/{judge,math,techniques,prompt,resolve,entries}.ts`
(backend-agnostic; no `vscode` import) and new `test/unit/judge*.test.ts`
(65 tests). Behaviour, per the lanes table:

- `math.ts`: the entropy confidence `1 − H(p)/ln N` (0.329 on the probe's
  tev1 distribution, as recorded in `m98-research.md`), logprob
  renormalization over distinct alternatives (case and leading-space
  variants counted once; the RVM98 pair renormalizes to 0.143, not the
  0.40 complement), the residual mass.
- `techniques.ts`: binary-from-top-1 with its floor and stated fallback
  (the RVM98 counterexample at 0.60 under a 0.80 floor falls back), top-1
  excluded from choice/score, the stated-confidence parser (zod; a missing
  field is a failure, never certainty), per-capability technique selection.
- `prompt.ts`: the state-first prompt builder, batching (questions split,
  never the state), the over-context refusal with its reason code, question
  ids never sent.
- `resolve.ts`: the phase-1 mode resolver (`auto` is `same`; unknown
  settings, declined/unasked paid consent, an unavailable source and a
  measured ready rate under the floor fail closed to `off` with a reason
  code), and the re-resolve triggers (setting, provider, consent,
  confidential flag only).
- `entries.ts`: the exact-action entry store (sha256 key over backend,
  session, turn, tool and canonical arguments), pending/ready/failed
  states, discard rules, and the synchronous latch read, which consumes
  the entry so a late result is never readable after its fence.
- `judge.ts`: the shared types and the answer assembly (our confidence
  always computed by us; the backend's value kept untouched as
  `vendorConfidence`; phase-1 labels only "uncalibrated" and
  "approximate (top-1)").

## Deliberate seams for the parallel lanes

Lane 0 owns `src/core/judge/schema.ts`, the `JUDGE_*` limits in
`src/shared/constants.ts`, `PAID_FEATURES`, `museSpark.judge.engine` and
all judge strings. This lane touches none of those files. The seams:

- Limits arrive as parameters: the top-1 floor, `JUDGE_MIN_READY_RATE`,
  the context-token ceiling, `maxQuestionsPerBatch`, costs.
- `prompt.ts` takes all model-facing wording as an injected
  `JudgePromptWording` (it lives in `MODEL_TEXT`, not here) and the token
  counter as an injected function (lane S measures with the model's own
  counter).
- `techniques.ts` reads a `ModelJudgeCapability`, not a provider name;
  lane S fills it from the captured capability records.
- `resolve.ts` and `entries.ts` return reason codes, not user text; lane U
  says them through lane 0's strings.
- No user-visible string was added by this lane, so `en.ts`, the 14
  `l10n/ui.*.json` and `package.nls*.json` are untouched and
  `node scripts/check-l10n.mjs` reports 0 problems.

`CHANGELOG.md` is lane D's file and is left for lane D.
