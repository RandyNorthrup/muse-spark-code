## Native implementation

`native/darwin/VaultKey.swift` accepts one bounded length-prefixed JSON header
and, for wrap only, exactly 32 private input bytes. Output uses the same framing;
unwrap returns exactly 32 private bytes after its public header. There is no key
in argv, environment, a plaintext file, an error or stderr. Errors are fixed
protocol codes; buffers are erased on exit as a best effort, without a memory
zeroization guarantee for Foundation/CryptoKit copies.

The login-Keychain slot stores a random AES wrapping key as a generic-password
item under its own service/account, with `SecAccessCreate` trusting this signed
helper. `SecItemAdd` never replaces a duplicate. AES-256-GCM authenticates the
format domain, vault id, slot id and tier. The Keychain query explicitly selects
the file-based login Keychain, never the default system or data-protection store.
The deprecated legacy API is deliberate under D89/Q-M109; no warning is disabled.

The SE slot generates its P-256 key inside the enclave, keeps only its opaque
device-bound blob, and wraps through ephemeral ECDH, HKDF-SHA-256 and AES-GCM.
Both silent and `userPresence` modes compile. Each unwrap creates a fresh
`LAContext`, disables Touch ID reuse, names the exact use, and invalidates it.
The shipping certification flag remains false; no input, flag, environment or
setting can turn it on. The separate test capture calls the native functions
with an explicit certification input and is never built into the helper.

`build.sh` builds/signs/verifies both architectures into
`dist/native/darwin/muse-vault`. CI's native-build region runs `check-vault.sh`
and uploads `muse-vault-darwin`. W owns downloading/packaging that artifact.

## Shared runtime adapter

`src/runtime/vault/slots/macVaultSlot.ts` implements lane 0's `VaultSlotPort`
behind an injected `MacVaultTransport`; there is no fake implementation in
production. It validates and owns C's context before any native side effect,
binds provider/tier/reference and container identity before unwrap, requires
both physical availability and certification for SE operations, and snapshots
private bytes before awaiting. It returns an owned unpooled Buffer that the
final consumer erases. It never caches a presence result or an unwrapped key.

`macVaultProtocol.ts` checks both directions with strict Zod schemas, canonical
base64, exact crypto lengths and bounded framing. It wipes private input and
output buffers on success and failure and suppresses untrusted diagnostic text.
`macVaultTransport.ts` executes the injected absolute packaged helper path with
empty argv and environment, binary pipes, a bounded output, a 120-second maximum,
and cancellation. Errors, exit failures, cancellation and oversized output kill
the helper. It discards/wipes stderr and output chunks; no host log is used.

`macVaultProtectionFacts` distinguishes the API probe from certified/available
protection and reads the existing translated tier warnings at runtime. No new
UI/NLS key, command, setting or npm dependency is introduced.

## FIXM109PM review repair — P3 (2026-10-06)

The native reader now installs failure cleanup before reading private input.
Every private read chunk is erased after copying; the accumulated partial
buffer is erased on EOF or a thrown read. A successfully read key transfers
ownership to `runVaultHelper` only after trailing-input validation succeeds.
The one-byte trailing buffer and a complete key on a subsequent read failure
are erased too. Keychain-returned bytes are erased on failed status/length
validation; wrapping and unwrapped buffers share the same explicit eraser.
This remains best-effort erasure of buffers the helper owns, not a guarantee
for incidental Foundation/CryptoKit copies or allocator storage.

The pure native suite calls the actual reader/eraser with generated material:
empty input, **31 private bytes + EOF**, complete input, 33-byte rejection, a
read failure while accumulating and a read failure after the complete key.
The 31-byte case proves `invalidRequest` and erasure of both its read chunk
and its accumulated private buffer. Every observed erasure also checks the
bytes became zero. The real signed helper's protocol suite includes the same
31-byte EOF request and requires an empty private tail on `invalidRequest`.
No test creates a Keychain item or triggers authentication.

Nine further red drills remove partial-buffer, chunk, completed-key, trailing
or rejected-Keychain-result cleanup, make the eraser do nothing, or break a
successful ownership handoff. Each fails its named native assertion; all sources
restore byte-exact. The combined sixteen-drill receipt is
[m109-p-review-drills.json](m109-p-review-drills.json). P2 native hashes record
its first commit `4bc80416`; P3 hashes record the final cleanup source.
The first reader-handoff mutation did not fail: Swift's Data copy-on-write
preserved the returned bytes. The successful-read assertion now also checks
that only the consumed read chunk is erased before ownership passes to the
caller; both handoff mutations were rerun and fail. Neither review finding is
deferred in P's owned implementation.

**Named residual P-mac/owner-certification:** this rig is an Intel Mac mini
