## Policy and approval piece

- Registered requester identity, ceiling, role, workspace, session and task
  are immutable snapshots. The trusted launcher verifies registrations;
  frame claims alone confer nothing.
- Ask every time, exact-use session answers, Always with a matching scoped
  grant, Never, disclosure opt-in, provenance taint and unattended flags
  are enforced. Every grant field narrows access. Hooks never prompt.
- Requests and one-use tickets are minted by the broker, with canonical
  digest, nonce, deadline and epoch. Only an authenticated host UI answers.
  Actual use is checked again at redemption; callers and returned cards
  cannot mutate the broker's snapshot.
- Per-use OS presence is uncached. A lock while presence is pending closes
  the lifetime, erases the held/source keys and denies a late result.
- Revocation closes active lifetimes and terminates processes through the
  route's pinned process port; an unsuccessful termination is explicitly
  audited as unrecallable. First-party fallback refuses all agent uses.
- Grant use counts are reserved when minting a ticket, through C's atomic
  transaction. An unused/failed ticket does not refund that reservation.

## Native channel investigation

A finite standalone probe showed `getpeereid` and `LOCAL_PEERPID` returning
the actual uid/pid. Passing a Node Socket object as child stdio stopped
bidirectional replies. Waiting for exit/stdout rather than `close`, and
buffering pre-authentication bytes, did not repair that stream-transfer
path; its interrupted diagnostic runs are not green receipts. That path was
stopped, rather than repeatedly rewritten.

The replacement inherits a numeric descriptor from an explicit
`VaultSocketDescriptorPort`. A finite two-endpoint native probe completes
the exchange; the native channel suite then passed 17 cases, with its one
remaining epoch assertion correctly exposing fs.watchFile's initial
missing-file notification (epoch 0). The test now awaits a positive changed
epoch. The descriptor must belong to the accepted socket; it is never read
from a frame. Tests use a structurally validated, test-only Node `_handle.fd`
seam. Production requires W/P's native descriptor binding.

## Integration handoffs

- **B-C-store:** `VaultBrokerRepository.open` binds C's unlock/store; grants,
  atomic count reservation and revocation use C's authenticated single writer.
- **B-C-audit:** `VaultAuditAnchorPort.transaction/read/write` binds C's
  generation/slot checkpoint. A writer failure or unmatched disk/head is
  fail-closed, never silently repaired.
- **B-P-slot:** `VaultUnlockPort` binds slot selection/unwrap, fresh per-use
  presence over the exact challenge/use, and screen-lock signals.
- **B-P-epoch:** the shared `VaultLockEpoch` directory is the same for every
  editor and protocol version.
- **B-P-peer:** Unix descriptor ownership and process start/image identity;
  Windows owner-only, remote-refusing named-pipe creation plus
  GetNamedPipeClientProcessId/SID/start/image verification. The Windows
  verifier is tested through its port here; actual Windows capture remains
  an integration requirement.
- **B-T-scrub:** bind the real scrub service before persisted targets or
  requester text; no identity or silent fake scrubber is installed.
- **B-S/X/L/O-dispatch:** the channel calls the injected route only after
  successful redemption; its lifetime closes/terminates the pinned process.
- **B-H/U-host:** separate management/private-read and requester connections;
  UI answers must originate only in the authenticated UI registry. Host and
  runtime clients share the core wire implementation.
- **B-M-credentials:** inject the vault SecretStore/read adapter into existing
  CredentialStore/AuthCommandDeps. The legacy entry flow remains untouched
  until C/P/M are integrated; values still enter through password UI/stdin.
- **B-W-runtime:** build/register the lazy host client and separate

  above dependencies. No global install or npm dependency is added.
- **B-W-docs:** CHANGELOG/README/security/privacy/editor references and the
