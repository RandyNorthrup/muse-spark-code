### Ownership and settlement changes

Plaintext erasure is part of `state.ts`'s synchronous transition. Cleanup wipes
each known source, temporary or installed key, private buffer and item field
before removing its ownership entry. The unwrap source is wiped immediately
after copying it into the owned key. Cleanup effects carry only store/writer
close work, with separate effects for those resources. The runner isolates each
effect, including lifetime close, from exceptions; a throwing failure notice
cannot stop later effects either. No callback runs between the reducer's wipe
and removal of ownership.

An active admission becomes redeemable for material only after its redemption
audit succeeds. A failed redemption audit removes the admission and ticket
authority in that step and closes/terminates the lifetime. Finish closes the
lifetime and retires all material operations for that ticket synchronously,
including a read whose result has not arrived. Final release also requires the
current redeemed admission, its ticket object, registration and generation.
Already returned owned plaintext is erased immediately; a still-running read's
result is erased when its obsolete tagged completion arrives, without release.

Terminal outcomes are recorded on the operation before termination I/O and on
the audit entry when the terminal transition is reached. Only an operation with
a recorded terminal outcome is exempt from invalidation: expiry cannot turn
it into its own audit waiter, and its completion emits one terminal audit.
A new Finish after disposal still rejects. Retiring unwrap/open/writer/read/release
work settles its caller and removes its serialized queue position immediately;
late completion has no operation owner and can dispose only its own result.

## REDM109B — synchronous state-machine redesign (2026-10-06)

### Architecture and invariants

`state.ts` contains the synchronous `step(state, event) -> { state, effects }`
reducer. It copies state containers and operation records, accepts requests,
timer events and tagged completions, and emits I/O without running it. The small
runner in `broker.ts` executes effects and returns their tagged results. Neither
an effect nor an obsolete helper changes broker state directly. Synchronous
cleanup and lifetime-close effects run before callbacks and I/O from that step.

- Registration capabilities use object identity plus an incarnation. A connection
  captures the registration tokens present when accepted, before identification.
  Authentication cannot attach a later replacement token. Requests carry that
  capability, and delayed close cancels only its own connection/incarnation.
- Completion admission checks operation id/phase, registration capability,
  connection identity and unlock generation. A late result can only dispose the
  resources returned by that effect. One reducer-owned unlock operation publishes
  the key, store and writer; concurrent unlock callers await that publication.
- Plaintext stays in the broker's buffer table under operation/generation ownership.
  Private transport receives a synchronous send callback rather than a returned
  independent plaintext buffer. `runVaultRelease` checks current generation,
  incarnation, lifetimes, item/grant expiry and approval deadline in the same tick
  as destination invocation. The private write and buffer wipe finish in that
  tick. Lock advances the generation and emits every wipe/close immediately;
  its safety barrier does not wait for settlement.
- Every audit effect captures an isolated writer and row version before scrub I/O.
  The terminal decision supersedes pending work in the reducer. The writer checks
  that version immediately before its synchronous physical commit. Writer sessions
  have distinct handles and keys and never reopen. A closed/obsolete queued append
  cannot commit; an already committed row finishes its authenticated anchor under
  the shared transaction before the terminal row. Rotation follows exact native
  file identity, including a second live writer whose descriptor names the old file.
- Operation cleanup frees its own temporary key, source buffer, item, store,
  writer and use lifetime. Audit paging reads the installed writer through a
  tagged effect. Ordinary stale completions cannot close installed
  resources. Terminal cleanup can settle its original liability after a fresh
  unlock, without altering current authority. Epoch and grant writes invoke the
  reducer-owned authorization fence immediately before physical commit.
- Failed epoch persistence still reports failure with the local barrier applied.
  Bounded cleanup or audit settlement timeout rejects Lock and retains the scoped
  terminal liability; it never reports an empty success. A retained writer can
  finish only its terminal rows, then closes. Audit rows contain outcomes and
  generated identities/digests, never material values. Disclosure remains person-only;
  the source-generated schemas and their drift checks are unchanged.

The deleted implementation includes `broker/queue.ts` (`VaultBrokerQueue`),
`validate`, `current`, `management`, promise-based authorization ownership,
post-await returned validators, and the channel's awaited independent private-read
copy. The unused asynchronous file-append function/port is removed as well;
audit has only the synchronous owned-descriptor commit path. The historical
`m109-b-round2-awaits.md` is not an active proof artifact.
Synchronous predicates and commit fences are part of reducer/effect admission,
not async broker methods that resume and act on shared newer state.
