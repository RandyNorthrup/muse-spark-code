### Architecture and invariants

`state.ts` contains the synchronous `step(state, event) -> { state, effects }`
reducer. It copies state containers and operation records, accepts requests,
timer events and tagged completions, and emits I/O without running it. The small
runner in `broker.ts` executes effects and returns their tagged results. Neither
an effect nor an obsolete helper changes broker state directly. Synchronous
cleanup and lifetime-close effects run before callbacks and I/O from that step.

- Registration capabilities use object identity plus an incarnation. A connection
  captures the registration tokens present when accepted, before identification.
  Authentication cannot attach a later replacement token. Requests carry that
  capability, and delayed close cancels only its own connection/incarnation.
- Completion admission checks operation id/phase, registration capability,
  connection identity and unlock generation. A late result can only dispose the
  resources returned by that effect. One reducer-owned unlock operation publishes
  the key, store and writer; concurrent unlock callers await that publication.
- Plaintext stays in the broker's buffer table under operation/generation ownership.
  Private transport receives a synchronous send callback rather than a returned
  independent plaintext buffer. `runVaultRelease` checks current generation,
  incarnation, lifetimes, item/grant expiry and approval deadline in the same tick
  as destination invocation. The private write and buffer wipe finish in that
  tick. Lock advances the generation and emits every wipe/close immediately;
  its safety barrier does not wait for settlement.
- Every audit effect captures an isolated writer and row version before scrub I/O.
  The terminal decision supersedes pending work in the reducer. The writer checks
  that version immediately before its synchronous physical commit. Writer sessions
  have distinct handles and keys and never reopen. A closed/obsolete queued append
  cannot commit; an already committed row finishes its authenticated anchor under
  the shared transaction before the terminal row. Rotation follows exact native
  file identity, including a second live writer whose descriptor names the old file.
- Operation cleanup frees its own temporary key, source buffer, item, store,
  writer and use lifetime. Audit paging reads the installed writer through a
  tagged effect. Ordinary stale completions cannot close installed
  resources. Terminal cleanup can settle its original liability after a fresh
  unlock, without altering current authority. Epoch and grant writes invoke the
  reducer-owned authorization fence immediately before physical commit.
- Failed epoch persistence still reports failure with the local barrier applied.
  Bounded cleanup or audit settlement timeout rejects Lock and retains the scoped
  terminal liability; it never reports an empty success. A retained writer can
  finish only its terminal rows, then closes. Audit rows contain outcomes and
  generated identities/digests, never material values. Disclosure remains person-only;
  the source-generated schemas and their drift checks are unchanged.

The deleted implementation includes `broker/queue.ts` (`VaultBrokerQueue`),
`validate`, `current`, `management`, promise-based authorization ownership,
post-await returned validators, and the channel's awaited independent private-read
copy. The unused asynchronous file-append function/port is removed as well;
audit has only the synchronous owned-descriptor commit path. The historical
`m109-b-round2-awaits.md` is not an active proof artifact.
Synchronous predicates and commit fences are part of reducer/effect admission,
not async broker methods that resume and act on shared newer state.

### Deterministic scheduler

The scheduler executes the production reducer and final release runner. I/O
results are generated and snapshotted at dispatch; it enumerates every ready
completion choice recursively, including effects created by prior completions.
It asserts generation/incarnation ownership, cleanup ownership, terminal finality,
and the immediate Lock barrier after every event; destination callbacks count
writes before checking material, so a forbidden zero-byte send still fails.
The smaller sets are exhaustive. Larger sets add four status/epoch operations
and use seed `109003` (100 rounds per scenario); failures print seed, scenario,
round and completion-choice path. This is finite scenario exploration, not a
claim of proof over arbitrary programs or all operating-system schedules.

## Policy and approval piece

- Registered requester identity, ceiling, role, workspace, session and task
  are immutable snapshots. The trusted launcher verifies registrations;
  frame claims alone confer nothing.
- Ask every time, exact-use session answers, Always with a matching scoped
  grant, Never, disclosure opt-in, provenance taint and unattended flags
  are enforced. Every grant field narrows access. Hooks never prompt.
- Requests and one-use tickets are minted by the broker, with canonical
  digest, nonce, deadline and epoch. Only an authenticated host UI answers.
  Actual use is checked again at redemption; callers and returned cards
  cannot mutate the broker's snapshot.
- Per-use OS presence is uncached. A lock while presence is pending closes
  the lifetime, erases the held/source keys and denies a late result.
- Revocation closes active lifetimes and terminates processes through the
  route's pinned process port; an unsuccessful termination is explicitly
  audited as unrecallable. First-party fallback refuses all agent uses.
- Grant use counts are reserved when minting a ticket, through C's atomic
  transaction. An unused/failed ticket does not refund that reservation.

## FIXM109B — RVM109B repair (2026-10-06)

All five P1 and four P2 findings in RVM109B are fixed. No review finding is
accepted as a residual or deferred. This supersedes the earlier disclosure
exception and the earlier lifecycle claims above. The work remains an unbound
broker lane; the existing integration handoffs remain required.

Authorization transactions still use the single broker queue. Its synchronous
invalidation entry preempts suspended transactions: lock, revocation and
requester exit remove authority and wipe material before awaiting cleanup.
Every authorization operation captures a local generation at entry in addition
to the persisted epoch. A lock makes that generation terminal even if epoch I/O
fails. The shared validator returns a synchronous check that each continuation
invokes immediately before committing authority or releasing bytes; this closes
the promise gap between an asynchronous validation result and its caller.
It checks generation/locking, the approval/ticket deadline, item expiry,
registration, metadata identity and live grant coverage. Unlock uses the same
validator while owning its temporary source/key/store from acquisition.

Revocation marks the grant unusable locally before repository removal, closes
and wipes all affected uses synchronously, then settles every termination and
audit operation. A termination rejection is recorded as unrecallable and does
not skip later uses. The common affected-requester scan is scoped to the grant's
item. Lock and requester exit record terminal denials for approvals and unused
tickets while the audit is still open. Private socket closure supplies an abort
signal, rejects the waiting read promptly, wipes material awaiting presence,
and erases a store read that returns after cancellation.
