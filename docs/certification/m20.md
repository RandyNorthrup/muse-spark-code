# M20 certification — rewind across subagents (PLAN.md D23)

Recorded 2026-09-23 on Windows 11 (Node 24.20.0, VS Code 1.138.0). A reader
on Facebook asked how "Rewind code to here" handles overlapping files when
several subagents edited them in one run. Reading the code for the answer
found the gap: since M18 a subagent's rows live in its own transcript, and
`editsAfter` only scanned the conversation's, so a delegated run's edits
stayed on disk after a rewind, without a word. The fix orders every edit by
the arrival number it completed at, across the conversation and its agents,
and unwinds them all in reverse.

## Findings recorded during the milestone

- A child's edit rows carry the same `patchRef` as the parent's: they are the
  same `toolCall` items through the same mapping, only routed by `turnId`.
- Ordering by transcript position was already wrong in principle for the
  conversation alone (a backgrounded tool can complete after a later row);
  the completion number fixes that as a side effect.
- No screen changed; the rewind menu looks as it did (`rewind` scenario,
  M13), so no new harness scenario.
