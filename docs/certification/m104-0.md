## Semantics for adapter and runtime lanes

The snapshot includes transport and semantic conventions: one UTF-8 JSON-RPC object per stdio line; no batches; zero-based UTF-16 positions; explicit empty params; null for absent storage or cancellation results. Requests and notifications have distinct id rules. Lifecycle is mandatory; a missing optional group selects its declared fallback. A host advertises a group only if it implements every method and notification in that group.

The injected implementations must enforce lifecycle, negotiated direction/capabilities, selected version, response-id correlation and cancellation. Editors must validate expected versions and invalid/overlapping ranges before side effects, refuse dirty-buffer overwrites, and group an atomic edit in one undo transaction. Those behaviors need the adapters and the lane I conformance scenarios; this skeleton does not claim to implement them.

No secrets method exists. UI input cannot request a password; terminal/create accepts only LANG, LC_ALL, TERM and COLORTERM overrides. auth/github returns authentication status only: no GitHub token or Model API key crosses MHP; the runtime implementation must use the researched gh credential-store route for authenticated GitHub operations. Settings values must be checked against the existing manifest schema before persistence. The runtime owns paid consent and the ledger; UI choices are opaque ids. The owner’s enhancements-on and first-charge consent rulings are preserved for the implementation lanes.

No UI-visible strings, manifest commands, settings, dependencies, casts or lint suppressions were added. Feature names and errors are technical identifiers. No other lane’s existing file was edited: only new files and the MHP constants block.

### Contract and handoff

- `src/shared/hostApi/panel.ts` authors a separate strict `kind: panel`
  envelope with `mhp: 1.1`, opaque surface, direction, safe positive seq and
  the existing shared payload schemas. Main protocol schemas and What's New's
  schema are exported without changing their definitions. Tasks and What's
  New retain their existing vocabularies; usage and maker declare their kind
  and use the main protocol. No second panel vocabulary is introduced.
- Pure admission validates registered surface kind, readiness, direction,
  contiguous per-surface/per-direction sequence, and original serialized
  UTF-8 bytes (16 MiB cap). Unknown surfaces produce a typed `panelError`
  and no delivery. Rejected frames do not advance a sequence or enqueue.
- Separate `kind: surface` notifications declare opened, ready, reloaded,
  hidden and closed. Binding is immutable: one surface/session/kind. Reload
  carries the existing state request, retains sequence and replays once
  after ready; What's New's null request means render its existing HTML.
  Closing requires the exact queued drop count, with `MHP_PANEL_DROPPED`
  warning when nonzero. Actual queues, warning emission and state replay
  remain lane B/C/native implementation requirements, not implemented here.
- `MuseEmbeddedHost` specifies `window.museHost.postMessage`, onMessage,
  getState and setState with JSON-only saved UI state. Posting is synchronous
  with no delivery acknowledgment; remote refusals use typed panelError
  frames. The snapshot exports payload/callback/state schemas and mappings
  for JBCefJSQuery, WebView2, BrowserFunction and companion POST/SSE.
- `framing.ts` parses one bounded UTF-8 NDJSON object (LF or CRLF), multiplexing
  frozen calls/results/failures/notifications and the new carrier kinds.
  A pending method selects result validation; runtime request-id correlation
  and contextual admission follow parsing. Panel frames require negotiated
  1.1.0. Backpressure budgets are 32 MiB and 128 pending messages, including
  service traffic; queue-budget schema rejects excess before enqueue. Writer
  pause/drain behavior and companion disconnect reopening are documented.
- `mhp-v1.1.schema.json` / `.lock.json` export and freeze the additive
  contract. `scripts/mhp-schema.mjs` verifies both locks and snapshots; it
  never silently rewrites a lock. The supported minor range is
  `mhp/1.0.0..1.1.x`. `selectMhpVersion` selects the latest implemented
  version in an explicit minor-range offer; legacy wide v1 offers retain
  1.0.0 and a v1-only host receives only frozen v1.
  Initialize's 1.1 result adds the selected version; every v1 call, error,
  capability and other result schema remains identical.
- `docs/ide-compatibility/host-api-panel-1.1.md` is the handoff contract;
  README documents the successfully run exporter commands, CHANGELOG records
  the authored contract, and PLAN records lane 0's status. No runtime or
  browser bridge implementation, native qualification or other lane's code
  was added. F1–F56 qualification remains unchanged.
