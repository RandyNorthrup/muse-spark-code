## Semantics for adapter and runtime lanes

The snapshot includes transport and semantic conventions: one UTF-8 JSON-RPC object per stdio line; no batches; zero-based UTF-16 positions; explicit empty params; null for absent storage or cancellation results. Requests and notifications have distinct id rules. Lifecycle is mandatory; a missing optional group selects its declared fallback. A host advertises a group only if it implements every method and notification in that group.

The injected implementations must enforce lifecycle, negotiated direction/capabilities, selected version, response-id correlation and cancellation. Editors must validate expected versions and invalid/overlapping ranges before side effects, refuse dirty-buffer overwrites, and group an atomic edit in one undo transaction. Those behaviors need the adapters and the lane I conformance scenarios; this skeleton does not claim to implement them.

No secrets method exists. UI input cannot request a password; terminal/create accepts only LANG, LC_ALL, TERM and COLORTERM overrides. auth/github returns authentication status only: no GitHub token or Model API key crosses MHP; the runtime uses the researched gh credential-store route for authenticated GitHub operations. Settings values must be checked against the existing manifest schema before persistence. The runtime owns paid consent and the ledger; UI choices are opaque ids. The owner’s enhancements-on and first-charge consent rulings are preserved for the implementation lanes.

No UI-visible strings, commands, settings, dependencies, casts or lint suppressions were added. Feature names and errors are technical identifiers. No other lane’s existing file was edited: only new files and the MHP constants block.
