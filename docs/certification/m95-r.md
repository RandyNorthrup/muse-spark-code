## Integration handoff

`ResponsesWireCodec` is an explicit injected seam while lane T's shared
`WireCodec`/`ProviderClient` and lane P's presets are absent from this
branch. It identifies `format: 'responses'`, offers
`encodeRequest(CreateResponseBody)` and
`decodeStream(AsyncIterable<Uint8Array>, sink?)`; the optional sink reports
valid xAI settlement once. There is no production fake adapter.

Lane T supplies auth/error redaction, cancellation/stall handling and the
planned frame/argument/item/total-stream size caps around the shared SSE
reader. Lane I consumes the retained cache-write field and settlement sink,
closes budgets after a decode/usage failure, and filters reasoning when
switching provider/model. Lane W wires this codec into the lazy
`dist/providers.js` entry, updates shared documentation and runs the full
quality gate. None of those other lanes' owned files was changed here.
