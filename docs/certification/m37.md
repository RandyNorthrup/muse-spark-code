# M37 certification — the accessibility gate (PLAN.md M37, D32)

Recorded 2026-09-24.

## The gate

`npm run test:a11y` (`scripts/a11y.mjs`) opens every harness scenario in
headless Chrome, once per VS Code default theme, and runs axe-core 4.13.0
against WCAG 2.0, 2.1 and 2.2 at levels A and AA. It exits 1 on any
violation, on any page that wrote no result, and when the bundle or Chrome
is missing. It runs after `quality:gates` has built the production bundle
(in `npm run quality` and `quality:ci`), so it checks the bundle that
ships. In CI it is its own step on Linux and Windows.

- **Themes:** `test/harness/themes/{light,dark,hc-dark,hc-light}.json`,
  captured from VS Code 1.139.0 by `scripts/capture-themes.mjs` (Default
  Light Modern, Default Dark Modern, Default High Contrast, Default High
  Contrast Light). The light capture matches the values the harness used
  to hard-code (`#3b3b3b` text, `#f8f8f8` sidebar, `#005fb8` button), which
  checks the capture against something known.
- **The harness:** `?theme=<kind>` applies a capture: the variables it
  sets, `initial` for the ones the theme leaves unset (so the stylesheet's
  fallback applies, as in a real webview), and the webview body classes.
  `?axe=1` runs axe 5 s after the scenario has played and writes the
  result into a hidden `<pre id="axe-result">`, which the script reads
  from Chrome's `--dump-dom`.
- **The exemption:** a `target-size` finding is reported as exempt, not
  failed, when every element axe relates to it sits in a `.popover`,
  `[role="menu"]` or `[role="dialog"]` that does not hold the target and
  overlaps it on screen (D32: WCAG 2.5.8 does not apply to targets
  obscured by content the user displayed). Each is printed on every run.
  The first version asked only that the related elements be inside such
  an element; see the review below.
- **Undecided results:** what axe could not decide by itself
  ("incomplete") fails too. The exceptions are contrast checks on text it
  could not see where it looked (covered by an opened menu or dialog, or
  scrolled out of the transcript's view) and on glyph-only content, which
  are counted and printed. The first version dropped all of them
  silently; see the review below.

## What the first run found, and the fixes

The first full run found four rules violated, in some themes only. Each
was fixed in the code, not suppressed:

| Rule                          | Where                                                                                                                                                                         | Fix                                                                                                                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `color-contrast`              | Diff line numbers (3.0 to 4.48:1 on the tinted rows); a failed tool's reason in Light Modern's error colour (3.15:1); the grey detail on a selected row (Dark Modern, 4.41:1) | The text colour for all three. The failure keeps the error colour as a 2 px bar beside the reason, which needs 3:1 (1.4.11)                                                                                      |
| `nested-interactive`          | The effort dots inside the palette's Effort row; the archive button inside each History row                                                                                   | Both are for the mouse only and hidden from assistive technology. The Effort row already took Left and Right. A History row now takes Delete (`aria-keyshortcuts`, `aria-description` says Archive or Unarchive) |
| `scrollable-region-focusable` | The palette's and History's scrolling list                                                                                                                                    | Each list is a Tab stop. The dialogs close only when the focus leaves them (they used to close when the filter box lost it), and Escape works from the list                                                      |
| `target-size`                 | Radio and checkbox answers in a question card                                                                                                                                 | Each answer row is at least 24 px tall, the input centred in it                                                                                                                                                  |

The tool-row chevron also gained a 24 px box. The gate does not need it:
with or without it, the chevron passes by the spacing rule everywhere but
the `rewind` scenario, where an open menu covers it and it is exempt. It
was kept as a larger click target.

Result after the fixes:

```
a11y: 208 pages (52 scenarios × 4 themes), 0 rules violated on 0 elements, 8 exempt, 0 pages without a result
```

The 8 exempt elements are two tool-row chevrons in `rewind`, in each
theme, under the open rewind menu.
