## Implementation and authority

`src/webview/maker/` contains separate lazy approval, Stop, device/serial,
machine registration and log views. `makerEntry.ts` is the small eager loader;
it preserves incoming messages during import and installs the receiver before
announcing `makerReady`. The chat receiver demultiplexes the maker namespace;
the lazy store parses it with the existing maker host schema. Unrelated
malformed chat traffic still reaches its existing failure reporter.

The UI returns the engine's exact approval id, digest and target. It removes
the pending request before posting the answer, rejects dismissal, expiry and
admission revocation, and ignores replay/closed requests. It offers only Send
once and Reject. The tests consume the answer through the real MakerApproval
port with its opaque single-use target binding; wrong id, digest, target and
expiry do not start the fake action. No engine classifier or hardware guard
was implemented in this lane. `src/core/maker/ports.ts` is unchanged.

Stop bypasses trust, hardware enable and attended admission. It is present
inside each modal and has a working fallback while the Stop chunk is pending.
Its modal slot stays at the top when the document scrolls. The separate
preview page's Stop works before geometry and after a WebGL failure. The
host's independent Stop path remains required while a surface is absent.

Serial controls default DTR/RTS off, show the reset warning and send a precise
port snapshot, baud, duration and exact hexadecimal bytes as an intent.
Registration sends no key or registration generation. Limits are optional
with the existing explicit status/Stop-only warning; incomplete, reversed and
nonfinite travel limits fail the existing schema. Plain HTTP needs the
explicit warning checkbox, which resets when the endpoint changes. Logs open
only on the user's request, display uncertain outcomes, escape payload text,
and have no persistence, automatic export or approval grant.

## Independent preview and additive protocol

The original `makerPreview` message supplies artifact metadata, not geometry.
The additive `makerMesh` variant supplies a host-owned UUID and complete,
finite triangle positions: at most 100,000 triangles, absolute coordinates
at most 1,000,000, and a multiple of nine components. Its UUID must equal
the UUID in the host-rendered page. Extra URL/path fields and wrong versions
are rejected. This is a local host/surface contract, not an invented service
or MSP frame; it adds no captured backend parser.

The first production experiment pulled the full browser English fallback
through constants.ts and produced a 152.1 KiB page, failing the 25 KiB cap.
The schema now lives in `makerProtocolPreview.ts` and is re-exported unchanged
by `makerProtocol.ts`; import-free preview constants follow the existing
browser constants pattern. The page uses that narrow projection of the same
protocol. Its in-house WebGL renderer releases buffers/programs/shaders on
replacement, failure and disposal. Keyboard-accessible HTML controls rotate,
zoom and reset. No React, English table, host/core implementation, file reader
or URL loader enters this page. Driver errors never become displayed text.

The real VSIX file-list test first failed because the new page was omitted
from the explicit allowlist. `.vscodeignore` now includes exactly its built
script and CSS, and the same regression passes. Host-rendered HTML and CSP
remain with W. README documents the HTML/bridge contract, including Stop.
