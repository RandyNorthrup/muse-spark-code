# M97 lane R — headless `legal` command and packaging (D76)

Lane R owns the reserved headless scan command in `src/runtime/**`, the lazy
build/package wiring for its code, and the optional public-registry reader.
The scanner itself (`src/core/legal/**`) is lane S's parallel work; this lane
calls it only through lane 0's contract (`src/shared/legal.ts`) behind the
explicit `LegalScanner` interface in `src/runtime/legal/legalScanner.ts`.
No backend, no auth, no model call, no paid call is involved anywhere here.

Machine for everything below: the macmini rig (`/Users/randy/lanes/m97r`).

## What shipped

- `muse-spark-code-acp legal [--format text|json] [--out <file>] [--registry]`
  (`src/runtime/legal/legalArgs.ts`, wired in `src/runtime/cliArgs.ts` as a
  reserved top-level command beside `exec`/`scan-secrets`, run in
  `src/runtime/main.ts`'s headless branch with no backend or sign-in).
- Exit codes (D76): 0 is a complete scan with no blockers, 1 a complete scan
  with `blocker`/`should-fix` findings, 2 incomplete coverage, bad input or
  an operational failure. Advice alone exits 0.
- stdout carries only the rendered report (or nothing with `--out`); every
  other word goes to stderr in the display language.
- The registry reader (`src/runtime/legal/legalRegistry.ts`) runs only with
  `--registry`, asks only `registry.npmjs.org` and `pypi.org` over HTTPS with
  no credentials, one bounded request per package@version, at most
  `LEGAL_REGISTRY_MAX_QUERIES` requests, each cut at
  `LEGAL_REGISTRY_RESPONSE_MAX_BYTES` within `LEGAL_REGISTRY_TIMEOUT_MS`.
  Every query (hosts, exact URLs, bytes) is disclosed in the report; anything
  unanswered stays unknown.
- The scanner loads lazily as `dist/legalScan.js` beside the running bundle
  and its result is validated against lane 0's `legalScanResultSchema`
  before use. Until that bundle ships the command honestly reports
  incomplete coverage (exit 2).
- Strings: the command's lines in `en.ts` plus all 14 tables (short, real
  translations by this lane); command syntax stays English under
  `l10n/untranslated.json`, as `execUsage`/`execScanUsage` do.
- Split gate (`scripts/check-bundle-split.mjs`): `src/runtime/legal/**` must
  be in `dist/acp.js` and absent from `dist/extension.js`/`dist/modelApi.js`;
  when `src/core/legal/**` lands, the same check refuses it in activation.

## Deviations from D76's letter (design intent kept)

- D76 sketches `exec legal-scan --json`; the lane brief orders a reserved
  top-level `legal` with `--format`. This lane implements the brief: `legal`
  never reaches prompt parsing either, and `--help` lists it.
- D76's "1 = complete/blockers" does not name `should-fix` alone. Advice
  alone must not fail CI, so `should-fix` alone exits 1 with the blockers;
  only advice (or nothing) exits 0. Recorded here, not in code comments.
- The JSON surface is `{ result, registry }`: `result` is exactly lane 0's
  contract (the tests validate it with lane 0's own schema); `registry` is
  this lane's disclosure section. Findings are never rewritten with
  registry data; enrichment stays additive beside the scanner's facts.

Fixtures in `test/unit/fixtures/legalRegistry/`: the npm version document
verbatim (1,728 bytes) and PyPI's verbatim `info` object (the parser reads
only `info.*`, so the envelope is rebuilt around it in the fake). The
abbreviated npm metadata (`Accept: application/vnd.npm.install-v1+json`)
was captured too and carries NO license field, so the reader queries the
per-version document instead. A legacy object license (`{type}`) is not
parsed: no live shape was captured for it, so an object license stays
unknown rather than guessed.

Sandbox note: this rig's network sandbox allows egress (the captures above)
but refuses listening sockets (`listen` EPERM, verified 2026-10-04). The
registry fake therefore lives at the fetch seam production injects (real
`Response` streams, real URLs, real aborts) instead of on a loopback
socket; the tests never touch the network.
