## Designed boundary

`src/shared/devices.ts` defines this product's own protocol version 1. This
is an authored exchange, not a captured Muse/provider/external-agent frame.
No upstream wire schema is added. All objects are strict; unknown fields or
versions fail rather than being stripped. Wire failure reasons are fixed
words, never peer error text. Offers carry canonical provider/model identity
and capability/availability summaries only, never provider definitions,
endpoints, credentials, environment, local paths or executable commands.
Canonical identity does not confer capability, price or credential authority:
the receiver resolves it through its own M95 registry and current policy.

Opaque 128-bit ids separate device, pair, repository, grant, pool, entry,
receiver incarnation, board, task, attempt, request, artifact and settlement.
Model identity alone never identifies an execution/auth owner. A receiver
incarnation belongs to one explicitly selected window; it is not a PID,
timestamp, machine singleton or process-liveness proof. Routes bind pair,
device, receiver incarnation, pool, entry and canonical model. This leaves
M107 relocation, M108 placement, M109 slots and M110 nodes able to compose
their own policy against stable ids; they must reconcile the original owner
before relocation and must version any new wire fields. Their plan/interfaces
are absent on this base, so no guessed implementation is introduced.

`DEVICE_LIMITS` names every transport, invitation, artifact, queue, journal
and retention ceiling. It does not implement pre-parse transport caps or
atomic admission. Counts are finite nonnegative integers, prices finite USD,
Git ids are consistent SHA-1 or SHA-256, and planned writes are bounded
relative paths. G still checks actual objects/modes/confinement in quarantine.
Only own-branch/read-only lanes and locally named check ids are expressible.
Remote in-place, Bypass, shell commands, paid tokens and merge refs are absent.

## Pairing and transport review before any listener

**Dependency choice:** use Node's built-in `crypto`, `X509Certificate` and
`tls`, on the extension's Node 20.18.3 floor and current host. No npm package,
global tool or cryptographic primitive is added. Certificate generation uses
P-256 (`prime256v1`) and SHA-256/ECDSA supplied by Node/OpenSSL. P emits only
a fixed, bounded DER X.509 v3 profile, then reparses and verifies it with
`X509Certificate`; it does not implement elliptic-curve/signature mathematics
or a general ASN.1 parser. The design probe implements that profile in tests
only, to make the choice reviewable rather than leaving a fake factory in
production. P owns production generation, malformed-profile tests and floor
qualification before opening a listener.

Profile: random positive minimally encoded serial, opaque fixed subject/CN
without hostname/account/path, identical issuer, P-256 SPKI, SHA-256/ECDSA,
critical `basicConstraints` CA=true/pathLen=0, critical keyUsage
digitalSignature/keyCertSign, EKU serverAuth/clientAuth. Use bounded validity
and validate dates and the exact profile; no caller-supplied extensions. A
certificate is used directly as a per-pair trust anchor. This CA bit does
**not** permit descendants: both ends require the exact leaf DER SHA-256 pin,
self-signature and matching stored private key, in addition to TLS chain
verification. Changing/reissuing the certificate requires re-pairing.
Certificate lifetime is separate from the five-minute invitation lifetime;
clock errors fail visibly, never disable certificate verification.

Each pair has its own locally generated key and dedicated TLS context/port.
There is no SNI-driven identity selection, default context for unknown pairs,
shared device private key, multi-peer trust store or ambient root CA list.
This resolves multiple per-pair identities without trusting an unauthenticated
selector. The chosen literal loopback/RFC1918/ULA interface and exact port are
part of the invitation and local setup. A port collision fails setup and
requires a fresh invitation; it never falls back to wildcard/another port.
Pair/connection/global limits bound all listeners. Unlink affects only that
pair and removes its key, trust and sockets.

Offline flow: both devices generate public invitations, compare the other
screen's full fingerprint, then export/import signed confirmations. P uses
a domain-separated canonical transcript including the ordered invitations,
both certificate fingerprints, endpoints, issue/expiry times and invitation
ids. The pair id derives from that transcript; both signatures bind the same
transcript and explicit local confirmation. Reject equal/reflected identities,
old/expired/reused invitations, altered transcript, future timestamps beyond
the clock-skew bound and unverified signature/possession. Persist both
confirmations before declaring the pair usable. An invitation or screenshot
alone cannot authorize a listener or execution. After pairing, the separate
local **Offer lanes** action and repository grant enable that pair's listener.
There is no unauthenticated network bootstrap or numeric-code key derivation.

TLS settings: min=max TLSv1.3, requestCert=true and rejectUnauthorized=true
on the server, rejectUnauthorized=true on the client, only the exact peer
certificate in `ca`. Client `checkServerIdentity` replaces hostname matching
with the exact saved DER pin, never chain validation. At server
`secureConnection`, check `authorized`, exact peer DER, current pair grant and
`isSessionReused` before installing application handlers. Disable tickets
with `SSL_OP_NO_TICKET`, reject resumeSession lookup, supply no client session,
and reject a reused session on either end. TLS 1.3 has no early-data path here.
Recheck revocation/grant revision on every request, including an existing
connection. A authenticated socket is not an execution grant.

T must apply byte/connection/queue/handshake/frame deadlines before JSON or
zod, count UTF-8 bytes rather than JS characters, limit chunk decoded bytes,
and stop before allocating an advertised huge body. JSON duplicate keys need
rejection before ordinary JSON.parse loses them. Literal invitation addresses
are syntax/private-scope checked in the contract. T additionally verifies the
chosen local interface, rechecks every resolved discovery/manual-host address,
rejects mapped IPv6, public/metadata/mixed answers, proxies and redirects, and
connects to the checked literal. Private scope supplies no trust. Any discovery
advertisement contains only a rotating opaque service id, port and version;
it supplies no identity authority. mDNS stays off by default.

The contract also excludes the known IPv6 instance-metadata ULA
`fd00:ec2::254` after numeric expansion, including uppercase, padded and
alternate compressed forms. T still checks destinations and local interface
ownership before connecting; accepting ULA syntax alone would miss this case.

QR is an encoding of the same bounded public invitation/confirmation, with
copyable text always available. No QR/mDNS library is installed in lane 0:
those lazy implementation choices require I/P/T's exact pin, peer-range,
audit and notice receipts before integration. No numeric PAKE is selected.
No production QR/discovery support or dependency audit is claimed.

## Durable ownership, retirement and settlement review

Durable ordering: **source intent → receiver admission → receiver launch
intent → spawn → receiver-observed retirement → terminal result/settlement →
source acknowledgement**. Hash canonical validated dispatch data; compare
both attempt tuple and payload digest on every retry. Changed payload refuses.
Outcome revisions are monotonic per attempt: reject stale/reordered revisions
before applying status or usage. Repeated equal revisions must have the same
canonical digest; they cannot re-credit a settlement. Admission/reservation
and launch intent are persisted before spawn, under
the receiver's own atomic M96 capacity/write/resource acquisition. A failed
write/fsync stops admission; it never recreates an empty success journal.

E/P storage: owner-only nonsync files in host storage, separate from sockets
and runtime folders. Each state transition uses a temporary sibling file,
file flush, atomic same-volume replacement and parent-directory durability
where supported; establish the platform-specific durability contract before
launch. A per-window serial writer plus M96 owner leases prevents concurrent
lost updates. Torn/corrupt/unknown state fails closed and preserves existing
copies/debt. Recovery must never infer no launch from a missing record;
launch-intent without proved outcome stays quarantined/uncertain, including
after reboot, logout or folder loss. A new receiver incarnation does not adopt
or replay an old attempt.

Keep unresolved records indefinitely, up to 128 admissions and a 16 MiB
journal ceiling; exhaustion blocks new work. Full terminal results retain
at most 4,096 records for 30 days after durable source acknowledgement.
Before deleting a terminal result, durably write a compact permanent
tombstone (attempt tuple, payload/result digests, outcome revision, terminal
state and usage including the settlement id and retained liability). A wire
tombstone returns this compact data after full-result cleanup, rather than
relaunching or manufacturing an empty result. Tombstones
have no TTL; their 65,536-record/16 MiB bound stops admission when exhausted,
never deletes replay evidence. No settlement can credit twice after lost
reply/restart/cleanup. Acknowledgement is not retirement. Deleting/re-pairing
trust cannot delete unresolved records or make liabilities disappear.

Receiver retirement is established only by the actual local M96 execution
owner: engine/request settlement, all admitted tools and descendant processes,
and the held resources are observed settled. A reported remote result is a
claim used in reconciliation, never a remote PID/endpoint/time oracle or a
lease-release call. Parent exit, timeout, socket closure, cancel response,
start-time sample and a user's assertion cannot prove this. Receiver
uncertainty keeps its occupancy; source uncertainty keeps routing reservations
and attributed liabilities. A forged peer check report cannot authorize a
merge. Permanent loss can remain unresolved indefinitely.

Disconnect detection closes admission on both ends and pauses at the next
controlled boundary; admitted work may still finish/spend. Reconnect
reconciles paged durable outcomes first. Only explicit **Resume queue** plus
current receiver-local permission/paid consent allows new work. No automatic
redispatch, ownership transfer, distributed Hand off anyway, global budget,
machine-wide cap or exactly-once network guarantee is introduced.

## Adversarial review and retained limits

| Attack/failure                                                    | Reviewed control and remaining obligation                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Copied QR, MITM, reflection, unilateral confirmation              | Public invitation is insufficient; both offline signed confirmations, exact pins and private-key possession. P must prove freshness/replay/reflection. Socially approving the wrong fingerprint remains a user risk.                                                                     |
| CA-signed child, wrong pair, stale socket/ticket                  | Dedicated per-pair context; no ambient roots; exact leaf pin plus verification; no resumption; request-time revocation. T must exercise unlink on a live connection.                                                                                                                     |
| DNS/mDNS/proxy/interface substitution                             | Scope-checked literal and pinned identity; all answers checked before connection; chosen interface only. T owns rebinding/proxy/flood drills.                                                                                                                                            |
| Firewall deny or missing route                                    | Blocked or unreachable names listener/interface/port and OS/admin recovery. No timeout-based diagnosis or firewall changes; retries retain old attempts/debt.                                                                                                                            |
| Authenticated malicious receiver                                  | Strict task-only API, receiver policy intersection and local keys; G quarantines bounded bundles; source alone reviews/checks/merges. A trusted receiver can retain code or forge its own reports; honest-receiver durability remains an assumption.                                     |
| Approval/cost laundering                                          | Pairing and sender mode cannot widen receiver trust/tools/protected paths. Receiver's three-choice paid modal shows current model price and shared `museSpark.paidDailyBudgetUsd`, asks before the first charge and honors its own remembered grant. No consent or key crosses the wire. |
| Lost acknowledgement, disk full, corrupt journal, surviving child | Durable prelaunch ordering, retained occupancy/debt, permanent tombstones; no timer/manual release. E must exercise crash boundaries and actual process retirement.                                                                                                                      |
| Huge frame/bundle or secret in peer output                        | Contract resource caps plus T pre-parse byte caps; G expansion/object/path checks. Bound and scrub task/report data on both sides; never treat text as tool authority or automatically open peer links. Scrubbing cannot promise to detect all secrets in approved source.               |

Review conclusion: the specified trust/ownership design has no identified
unresolved authority path after the controls above. This is lane 0's own
security review, not an independent runtime penetration test or an approval
of another lane's implementation. No listener may ship before P/T/E prove
their controls and the lead accepts the joined implementation. Node 20.18.3,
four-device/floor/OS permission and installed-host drills remain integration
obligations; this rig currently runs Node 24.21.0.

  only the Devices region and injected bridge; protocol exports its types only
  so ordinary chat/Node wire do not initialize device schemas. The dedicated
  parsers return fixed failure words. The M95 panel merges it by
  meaning. No provider definitions or fake model registry are added here.
- **M96-execution/E:** `DeviceExecutionPort` binds real M96 admission,
  retirement and durable journal; no fallback production implementation.
- **M107–M110:** stable device/pair/pool/entry plus incarnation and attempt
  tuple are the composition boundary. Relocation must not change an unresolved
  owner's identity or release its liabilities; device slots remain local.

  never activation/Model API/ACP/webview. I owns the reader/split/build edits
  and must guard its sentinels before that object can pass the product build.

  README and feature catalog/reference generation. Locale labels supplied by
  lane 0 must be registered together with their `%key%` manifest uses: adding
  unused package.nls keys alone correctly fails the localization gate.
  `m100-manifest-strings.json` supplies exact English/all-14 translations for
  `museSpark.pairDevice`, machine-scoped `museSpark.devices` (default false),

  strings in each package.nls table together with the package.json uses.

- **Editors:** all schemas and the bridge/port use no vscode/Node/DOM imports.
