## Detection and catalogue

The read-only Node adapter enumerates at most 256 directory entries (including
ignored entries and directories), with a depth cap of 4, and sniffs at most
8192 bytes per regular file. It skips links, device files, dependency and
build directories. It never sniffs sdkconfig, settings.toml or secrets.yaml.
The detector repeats the name and byte guards on injected adapters and
rejects unsafe shell paths before reading. Markers select 18 project kinds;
CIRCUITPY roots and printer configs carry explicit safety facts.

`detectOnPi` reads the OS-owned `/proc/device-tree/model` only on Linux;
vcgencmd runs only after a Raspberry Pi identity and executable presence
check, at fixed `/usr/bin/vcgencmd` or `/opt/vc/bin/vcgencmd`. Only
get_throttled and measure_temp are sent. Each process has an empty inherited
environment, a 2000 ms cap and an 8192-byte output cap. Failed or absent
optional probes omit their facts; throttle bits are retained whole.

`loadSkills` accepts injected `makerSkillIds`. Bundled maker_* skills are
absent without those detected ids; user/project skills retain their existing
precedence. The marker-free catalogue and rendered Model API instruction
bytes are compared against the base catalogue. No request wire shape changed.

## Contract for the integration lanes

Lane I's full MakerHost port is absent on this base. Lane D uses explicit
injected interfaces, never production fake implementations. ProjectDetectIo
has bounded files/read operations; PiDetectIo has readModel/isExecutable/run.
The shared Node implementations work in an extension host, ACP or headless.
Host lanes V/R and wiring lane W must call the lazy detector and pass its
skillIds to loadSkills; they own session routing and the dist/maker.js entry.
No VS Code import, host adapter, wire capture parser or physical action is
introduced by this lane. End-to-end editor wiring is an integration item,
not claimed as certified here.

The recommendation ids are maker_firmware, maker_micropython,
maker_raspberry_pi, maker_printers, maker_cnc, maker_ros2, maker_kicad,
maker_cad and maker_simulation. Lane S's shipped ids must agree with this
contract. Existing muse_gadgets remains unchanged.
