## Detection and catalogue

The read-only Node adapter enumerates at most 256 directory entries (including
ignored entries and directories), with a depth cap of 4, and sniffs at most
8192 bytes per regular file. It skips links, device files, dependency and
build directories. It never sniffs sdkconfig, settings.toml or secrets.yaml.
The detector repeats the name and byte guards on injected adapters and
rejects unsafe shell paths before reading. Markers select 18 project kinds;
CIRCUITPY roots and printer configs carry explicit safety facts.

`detectOnPi` reads the OS-owned `/proc/device-tree/model` only on Linux;
vcgencmd runs only after a Raspberry Pi identity and executable presence
check, at fixed `/usr/bin/vcgencmd` or `/opt/vc/bin/vcgencmd`. Only
get_throttled and measure_temp are sent. Each process has an empty inherited
environment, a 2000 ms cap and an 8192-byte output cap. Failed or absent
optional probes omit their facts; throttle bits are retained whole.

`loadSkills` accepts injected `makerSkillIds`. Bundled maker_* skills are
absent without those detected ids; user/project skills retain their existing
precedence. The marker-free catalogue and rendered Model API instruction
bytes are compared against the base catalogue. No request wire shape changed.

## Contract for the integration lanes

Lane I's full MakerHost port is absent on this base. Lane D uses explicit
injected interfaces, never production fake implementations. ProjectDetectIo
has bounded files/read operations; PiDetectIo has readModel/isExecutable/run.
The shared Node implementations work in an extension host, ACP or headless.
Host lanes V/R and wiring lane W must call the lazy detector and pass its
skillIds to loadSkills; they own session routing and the dist/maker.js entry.
No VS Code import, host adapter, wire capture parser or physical action is
introduced by this lane. End-to-end editor wiring is an integration item,
not claimed as certified here.

The recommendation ids are maker_firmware, maker_micropython,
maker_raspberry_pi, maker_printers, maker_cnc, maker_ros2, maker_kicad,
maker_cad and maker_simulation. Lane S's shipped ids must agree with this
contract. Existing muse_gadgets remains unchanged.

## Presets and the host event

`checkPresets` offers at most 32 unique presets from at most 256 markers.
All generated shell arguments are quoted for the host platform; unsafe,
escaped and absolute paths are rejected. Windows commands work with Windows
PowerShell 5.1. Suggestions are not executed and no setting is written.
Arduino and Zephyr require a user-selected target. ESP-IDF QEMU and Klipper
checks require a user-provided finite harness instead of guessed paths or
success output. Config-only Marlin detection has no fabricated build check.
Python checks parse the AST without importing the program, executing it or
writing bytecode. G-code uses a typed offline-analyser preset rather than an
invented CLI. Wokwi needs explicit cloud opt-in and a user-chosen expected
result, carries a finite deadline and a privacy notice, and reads no token.
Build/check commands still use the ordinary M68 check permission path when
accepted by a host; the maker guard remains the other lanes' responsibility.

`detectAndOfferMakerPresets` is the shared entrypoint. Its injected
MakerDetectHost projects the planned MakerHost's isTrusted/notify operations.
It checks trust before reading and again before emitting. Marker-free,
non-Pi workspaces emit nothing. The strict presetsOffered event includes
kinds, skillIds, presets, CIRCUITPY/config safety notices and optional OS Pi
facts. `presetOffers.ts` is a Node-free schema module: a browser-platform
esbuild bundle succeeds without Node shims. Lane I can compose the schema
into its makerProtocol union. Panel/ACP/headless tests exercise this same
injected seam; they are not editor end-to-end receipts.

Host lanes V/R/W must render offers, let the user choose checks, enforce the
existing list/name limits when persisting them, and pass detected skillIds
into loadSkills through their workspace-context wiring. Multiple file-level
checks can share a display name and need a user-selected unique name at that
point. Lane S/R owns matching bundled skill ids and the Muse Code installer
catalogue. Lane W owns lazy dist/maker.js packaging and the host API record.
No new public command, setting, dependency, manifest string, wire parser or
model prompt is added. Nine UI keys have real translations in all 14 tables,
in a separate maker-detect region of en.ts, and are read at runtime.
