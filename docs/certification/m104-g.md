## Frozen-contract blocker E02

The frozen MHP 1.1 export admits `surfaces/open` with `kind: "whatsNew"`. Its carrier permits only the existing outward `openLink(index)`, `tryIt(index)` and `hideOnUpdate(isHidden)` actions; there is no inward payload vocabulary. The lifecycle documentation requests a fresh HTML render for `stateRequest: null`, but no editor-service method or carrier delivers that HTML and the corresponding allow-listed links/tries to a native host. The current renderer (`src/host/whatsNew/whatsNewHtml.ts`) takes runtime-owned releases, update range, installed locale and the persisted show-on-update setting. Guessing defaults or duplicating a static release list would misroute click indices and display the wrong persisted setting.

Native `surfaces` is not advertised and What's New requests fail explicitly. Lane G cannot complete native What's New without a lead-approved render-transfer seam owned by lane 0/B/D. No schema or shared file was changed. Companion rendering remains the declared `surfaces` fallback, pending B/C integration. E02 is a blocker, not an approved parity exception.

## Bootstrap metadata integration question

`initialize` is explicitly runtime-to-host in both frozen exports. The plugin accepts that request, selects 1.1 only for a bounded compatible offer, intersects capabilities and rejects duplicate initialization. No host-to-runtime exception is shipped. Its required request fields include native host identity/version, installed language, theme, folders and trust, while its result carries only version/capabilities. A fresh stdio runtime cannot discover the editor's installed language, theme or product identity through the declared launcher or the other methods. Lane B/0 needs an agreed bootstrap route; no guessed environment variable or launcher flag was added. Native rendering itself reads the installed Eclipse language and colors. Workspace folders and trust can be queried after negotiation.

## Implementation and verification

The plugin uses the exported JSON Schema at build/runtime, strict duplicate-key JSON decoding and startup vocabulary checking. MHP uses one bounded NDJSON writer, bounded raw-line decoding, correlated validated results, negotiation and request cancellation. The aggregate budget is 16 MiB per frame, 32 MiB/128 pending deliveries across service, lifecycle and browser queues.

Surface bindings are immutable and sequenced in each direction. Admission validates readiness, direction, sequence and the bound payload vocabulary before advancing; rejected enqueue does not consume sequence. Reload retains JSON state and requests controller replay once. Close purges pending messages, reports counts and clears saved state.

Eclipse buffers provide versioned UTF-16 selection and reads, dirty/stale edit refusal and prevalidated edits in one native undo transaction. Tab completion paints ghost text in the native editor and accepts the current suggestion with one undo. Workspace trust starts false. Native problem markers feed diagnostics. Runtime child environments strip credential names; stderr is drained without logging provider/account text.

The additional editor interruption test proves that cancelled queued UI work cannot apply later; numeric IDs such as `1` and `1.0` share cancellation/duplicate identity. Automatic typing/caret completion, all translated properties characters, JSON-only saved state and packaged lazy assets are also exercised.

The last 4.38 verification exposed the byte-at-a-time raw reader missing its existing two-second rejection deadline under rig load (`temp/m104-g-reader-red.xml`). The reader now appends bounded chunk spans instead of synchronizing on every byte. The deadline, frame cap and test assertions are unchanged; the restored full 4.38 run passes. D59 proves the replacement pre-append cap check still fires.

SWT explicitly requests Edge on Windows and WebKit elsewhere, checking the actual engine. Asset extraction uses the bundle state directory; pages have nonce CSP, exact-document navigation, blocked popups/context menus and the native embedded bridge. Real WebKit requires starting page modules after BrowserFunction installation and allowing its private `swt://browserfunction` transport. Windows devtools suppression through supported SWT APIs remains unqualified; keyboard/context-menu suppression alone is not proof of `AreDevToolsEnabled=false`.
