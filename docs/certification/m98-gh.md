a production fake, permissive result, new ledger or automatic source.

The complete native JSON state is bounded and redacted before source
initialization. Unknown additions survive, while known tool/event fields
and M91's required/schema/scalar/JSON-transform fields are validated.
Payload model selectors remain state: only G's explicit CLI model/provider
context selects inference. No transcript, workspace file, credential store,
ACP agent or chat backend is opened. One inherited deadline covers stdin,
initialization, admission, execution and the final output fence; late work,
closed/stalled pipes and malformed borrowed outcomes cannot succeed.

A complete aligned risk result at `JUDGE_ADVISORY_THRESHOLD` or above emits
only M91's validated ask/message/context shape. A safe result emits nothing
and exits 0. Partial, unavailable, refused or failed results emit no verdict
and retain the declared CLI exit 4. Invalid input/configuration exits 2
with fixed localized words. No allow, deny, rewritten tool input, guessed
neutral field, automatic provider switch or raw private error is generated.

For `claude`/`vscode`, the existing M91 Local/Copilot `vscode` flavor supplies
the nested Claude output shape. Other formats retain their actual table
events and aliases. Cline uses its existing `cappedContext` custom rule;
Windsurf stdout, Kiro tool stdout, Cursor `beforeReadFile`/`stop` and Copilot
`permissionRequest` cannot carry a caution without another decision, so
they refuse **before source resolution or any billable admission**.

The exit-4 conflict above remains a delivery blocker, not a supported
no-op claim: Gemini treats exit >=2 as blocking, and Copilot pre-tool rows
interpret nonzero exits as a veto. Malformed input can also veto there via

CLI policy; GH does not silently adopt it. G/Z must resolve this before
registering affected native events. README/CHANGELOG/PLAN and any needed
