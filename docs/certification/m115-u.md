## Implementation plan and integration bindings

- Implement the frozen grant matcher, using existing conservative shell
  parsing and canonical workspace confinement. Protected paths, physical
  actions and `requiresAsking` refuse regardless of a rule or mode.
- Keep unattended authority per queued/running turn, never as a session-wide
  flag. Backend entry points take a run object with validated context and
  injected grant/audit/question/paid dependencies. Scheduled input alone
  carries the fixed model note; request instructions and tool definitions
  retain their ordinary prefix.
- Grant editing and revocation use revisioned compare-and-swap. An injected
  authority transaction stores the audit and the authority mutation together;
  S/W bind that transaction to durable storage. No production fake store.
- Schedule-scoped paid consent names the model's verified price, cadence,
  extras, schedule cap and shared daily budget. Only explicit Always persists;
  Once is supplied to one run, Deny supplies no authority. Changed identity
  requires interactive renewal; unattended fires never ask. Reserve against
  both durable ledgers before dispatch, retain uncertain liability, and never
  raise either budget through a runtime modal.
- M112 is absent: inject immediate `deferQuestions` retaining the original
  question for later answers. M103/M109/M107 are absent: inject tool safety,
  schedule requester/admission and live authority validity through the run
  object. W binds these actual services, not permissive placeholders.
- D/W/X bind scheduled backend entry points to `ScheduleSessionPort` and the
  v2 channel. M52's v1 UI remains until V/W replace it; v2 entry points do not
  use its per-run confirmation modal. W owns the fixed `SCHEDULE_MODEL_TEXT`
  block and bundle reader registration. This lane requires that block through
  injection. HELPREF is absent; W adds grants, audit/revocation, immediate
  refusals and per-schedule consent/caps to the catalogue and shipping docs.
- Core ports work identically for VS Code, ACP, CLI, companion and native
  bridges. OS entries, delivery settlement and UI registration belong to X,
  D/S and V/W respectively.

## Final findings and gate-fire evidence

- A native rename originally authorized only its target path; the regression
  failed by observing an actual second-file write with a target-only grant.
  The dispatcher now checks and matches all canonical files in the final plan,
  including the no-card Accept Edits path. Both the narrow rejection and broad
  grant's actual writes are exercised. Live revocation is rechecked at the
  native shell/write/check entry after adapter waits.
- A delayed scheduled approval failure originally cancelled the next ordinary
  turn after the scheduled turn had completed. The regression reproduced that
  actual MSP cancellation. Both approval/question failure handlers now stop
  only the run that still owns the session (`MuseCodeHost.stopScheduledRun`);
  the new guard's red mutation reproduces the cancellation again. Prompt
  ownership survives turn completion until the prompt itself settles, so a
  newly attached panel cannot replay an approval awaiting an audit or a
  question awaiting the registry. Both late-listener regressions failed
  before the ownership fix; its two red mutations fail again.
- A grant audit failure now records a refusal row and denies, including an
  audit-time revocation. Grant creation and its audit are one revision-zero
  transaction. Duplicate creation and stale changes refuse.
- Repeated wildcard segments use bounded scanning rather than constructing a
  backtracking regular expression. Unicode filenames use grapheme segments.
- Two money mutations first survived because another guard rejected the same
  request (the base feature gate, and an already-full cap). The independent
  extra-gate and changed-body-model tests now isolate those guards; both
  mutations fail at their intended named tests. No gate was weakened.
- Duplicate detection first found five clones in test setup. The final tests
  reuse the existing `fakeMcpSource` and local captured-command/wait helpers.
  The later late-listener cases also share completion and event-capture helpers;
  the zero-clone gate passes without ignores or threshold changes.
- Host-API inventory first caught one extra `node:crypto` import. The schedule
  identifier now uses the existing SHA-256 `fingerprint` helper, preserving
  exactly the same ledger name. No other lane's generated record was edited.

**64 guard mutations** each exit 1 at their named regression, restore original
