### `session/delete` is gone in 1.4.4

`MuseCodeHost.deleteSession` and the lifecycle reader port (M106 S, lane W)
send `session/delete` and wait for `session/deleteCompleted`. Neither is
wired in production (`features.lifecycle` is never set and nothing calls
`deleteSession`), so no user-visible path breaks. Recorded in PLAN D26: it
must not be wired for 1.4.4 hosts. Removing the dormant port is a product
decision outside this lane.

## ACP SDK 1.5.1 → 1.7.0: what changed

Release notes (GitHub releases, read 2026-10-09): v1.6.0 (2026-10-01)
moves the schemas to ACP v1.24.1 and v2.0.0-alpha.7; v1.6.1 types
`AgentProtocolRouter.connect().closed` as always present (#265); v1.7.0
checks the extensible-union values a v2 caller builds (#268). The published
`dist` was diffed against 1.5.1.

| Change                                                                                                                                             | Touches us?                                                                       |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `PROTOCOL_VERSION`                                                                                                                                 | Unchanged: 1 (stable), 2 (v2)                                                     |
| `connection.js`, `stream.js`, `stream-limits.js`, `line-buffer.js`, `jsonrpc.js`                                                                   | Byte-identical: the 32 MiB `ndJsonStream` default and our override are unaffected |
| `ClientApp`'s constructor router (`client-session-update-router`, 1.7.0 `dist/acp.js:878-888`)                                                     | Unchanged: both reflection seams still find it                                    |
| New `SessionUpdate` variants `subagent_update`, `session_message`, `session_message_chunk`; `StateUpdate`; optional `ClientCapabilities.subagents` | Additive. No exhaustive switch here; our agent never emits them                   |
| Unstable MCP-over-ACP rework: `mcp/connect`/`mcp/disconnect` removed, `MessageMcp*` take `serverId`/`requestId`                                    | Not used                                                                          |
| `onConnect` documentation; v2 union checks                                                                                                         | Not used (no `onConnect`, `AcpServer` or `sdk/v2` import)                         |
| `AgentContext`, `RequestError`, elicitation, session config options, permission, `ContentBlock`, `AuthMethod`, `McpServer`, notices                | Unchanged shapes                                                                  |

No required method or field was added to anything the repository uses, and
no protocol behaviour changed, so 1.7.0 is in. The adaptation is wording
only: `execClient.ts`'s seam comment, the 32 MiB comment in
`constants.ts`, PLAN D3 (a new row and note), Q61 and a §8 re-check note.

New in 1.6/1.7, worth adopting later (not built):

- `subagent_update` with `ClientCapabilities.subagents`: show Muse subagents
  to ACP editors as child sessions with title, description and state.
- `StateUpdate` (running, idle, requires_action) and its guards: per-child
  activity.
- `session_message` / `session_message_chunk`: parent and child session
  transcripts.
- `SubagentSessionCapabilities.cancel`: cancel a child's work without ending
  the session.
- Stateless `mcp/message` with `serverId`/`requestId`, if MCP-over-ACP is
  ever used.
