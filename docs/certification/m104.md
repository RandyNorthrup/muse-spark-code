Both JVM hosts retain descendant identities (pid plus start instant) at
construction, every 10 ms and before shutdown. Eclipse's `RuntimeProcess`
continues tracking during the bounded graceful stop, discovers descendants
from surviving recorded parents after root death, and checks each identity
again before signalling. Window teardown snapshots before cleanup and always

identities. JetBrains also captures synchronously at construction, snapshots
before closing stderr, and serializes snapshots. The observed-ancestry discovery
window in PLAN §9 applies to both: a child that detaches/reparents between
observations can remain unseen; Eclipse has no process-group/job containment.

The frozen MHP schema supplies every numeric error code to
`scripts/mhp-errors.mjs`. One shared alias list covers capability-unavailable,
dirty-document and invalid/overlapping ranges. Generated Java constants and a
Kotlin object replace both handwritten allowlists/maps. Both preserve recognized
technical messages and numeric codes; unrecognized exception text becomes fixed
`MHP_INTERNAL_ERROR`. `npm run check:mhp` checks both generated files byte for
byte without changing the schema or either version lock. Gradle compiles the
production Java mapper alongside Kotlin for executable parity over every schema
entry and alias; each host's dispatcher also receives those thrown errors and
asserts the resulting wire frames.
