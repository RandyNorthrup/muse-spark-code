## Time engine and integration bindings

The pure core now computes once, elapsed intervals, anchored civil-day
cadences, weekdays, weekly sets and five-field cron in the stored IANA zone.
`Intl.DateTimeFormat` supplies Gregorian civil parts and offsets. Gap fires
collapse to the first valid minute; folds resolve to the first occurrence.
Times are sorted and duplicate instants coalesced. Tests cover Los Angeles,
Berlin and Sydney through both transitions, Lord Howe's half-hour transitions,
and Apia's full skipped date. Sparse cron has no seven-day search horizon;
impossible Gregorian dates return no occurrence before starting a search.
Malformed cron and unsupported instants fail explicitly.

- `nextTimeFire(trigger, zone, afterMs, beforeMs?)` is strictly after the
  cursor and strictly before the optional end. Interval `anchorMs` remains
  the reference occurrence, including a migrated outstanding fire.
- `nextScheduleTime(plan, afterMs, eventAtMs?)` applies the current run
  count/end and computes one fire for a matched event. Without the event
  it stays unarmed. A composed interval is one delay from the event; a
  calendar kind selects its first fire strictly after it. E owns matching,
  filtering, scrubbing, event identity and claims; no event text reaches
  this engine.
- `previewScheduleTimes` projects up to five successful runs using that same
  calculator, including the date/run-count intersection. A once trigger
  or one matched event previews at most one fire.
- `scheduleTimeOccurrences` is lazy and retains no backlog. Recovery walks
  dates once with one formatter instead of rebuilding a search per minute.
  `missedScheduleTimes` counts `(afterMs, throughMs]`, chooses the newest
  original occurrence for Run once, or skips overdue occurrences for Skip.
  An occurrence exactly at the observation remains on time. Intervals count
  a million missed occurrences arithmetically. Skipped occurrences do not
  consume the remaining run count. S owns permanent claims, durable cursors,
  final settlement, counter updates and recovery-window detection.
- `readScheduleClock` accepts the lane-0 host clock port and a previous
  snapshot. Its virtual epoch advances by monotonic elapsed time, preserving
  fractional readings; wall corrections only change `jumpMs`. A host with
  a suspend-inclusive clock passes no extra sleep duration. A host whose
  monotonic clock pauses must inject measured `suspendedMs`; never guess it
  from the wall delta. S/X must bind a real measurement or suspend-inclusive
  clock. Initialize the snapshot for each armed interval/event delay; do not
  reuse an older global virtual epoch for a newly observed event or schedule.
- `scheduleTimeAtClock` supplies the calculator's plan, clock-domain `nowMs`
  and display/wake offset. Wall kinds use wall time. Interval kinds (including
  event delays) use the virtual epoch, but absolute end dates are converted
  into it so a forward correction cannot extend the wall deadline. Fractional
  boundaries round to preserve the exact allowed integer instants. S/V/X use
  the logical occurrence for the permanent run id and add `wallOffsetMs`
  only for display/wake times; never re-anchor a trigger or claim on a clock
  correction. Keep durable cursors monotonic across backward wall changes.
- `parseScheduleLoop` is V/X's unregistered core adapter. It calls the
  unchanged M52 grammar, keeps list/cancel, the ten-minute default and the
  seven-day default end. Under the FIXM115T compatibility ruling, all
  `m`/`h`/`d` inputs use M52's elapsed intervals with the creation instant's
  seconds and milliseconds intact. A seven-day first fire equals the
  deadline and is refused, including across daylight-saving transitions.
  Explicit `daily` triggers still use civil days; other schedules have only
  their explicit end conditions.

S/V/X/W binding uses this same core in every editor, ACP and the runtime;
there is no VS Code import, process spawn, provider call or hidden paid path.
U retains unattended approval/question/physical-action refusals and paid caps.
W's shipping handoff is the README/CHANGELOG/help entry for time kinds,
stored zones, DST, preview, ends, missed policies and extended `/loop`, plus
its lazy bundle binding. No unsupported CLI/editor command is documented as
already registered here. `featureCatalog.ts` and `check:reference` are absent
on this base; add those entries during W/HELPREF integration.

failure, and restored exactly. No test-name filter, skip or timeout change.

transition day and 1,767 ms for an autumn day on Kubuntu. Its counts were
already correct (1,380 and 1,440 respectively). The shared lazy traversal
preserves those counts and avoids restarting the date search for each fire;
the owning suite covers both days. Afterward the same benchmark measured
76 ms and 60 ms respectively, with identical counts. These are observations,
not a new timing gate; worst-case calendar recovery remains linear in the
number of matching occurrences. Scratch scripts/bundles stay in ignored
`temp/`; no benchmark fixture ships in production.
