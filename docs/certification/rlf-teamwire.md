## What this lane wired and built

- **Merge planner binding (M96).** The merge flow plans before the card:
  `runMergeFlow` calls `api.merges.plan` first (`teamMergeFlow.ts:214`),
  so unsafe paths and moved refs refuse before any decision card, and the
  card lists the planner's files and protected paths. The engine port
  plans over real git through `planTeamMerge` (`teamEnginePorts.ts`,
  `312cfad23`). Proof: `teamMergePlan.test.ts` (real git),
  `teamHostService.test.ts` ("plans before the merge card").
- **Team MCP server (M96 lane T / C-M96-4's server half).** A Muse Code
  orchestrator conversation gets its own `team` MCP endpoint:
  `TeamHostBinding.teamMcp` (`teamHostBinding.ts:139`) mints an endpoint
  only with a stored runnable team (single-model otherwise), serves the
  five tools over real HTTP to its own conversation, refuses other
  tokens, and keeps durable `command_id` answers per conversation
  (`museSpark.team.commandRecords`, `teamConversation.ts`) so retries
  answer once. Wired at `extension.ts` (`teamMcp: teamHost.teamMcp`,
  lazy `loadTeamMcp`); `conversationController.ts` consumes
  `modeForNewConversation()` / `endpointForConversation()`
  (`0e63efa62`). Proof: `teamMcpWiring.test.ts` (real HTTP).
- **Finding 5: preserve on every merge failure (M96b).**
  `preserveFailedMerge` (`execTeamRecovery.ts:559`) holds a failed
  merge's head as `refs/heads/agents-hold/<role>/<task>` in the person's
  repository, records the hold in the run ledger, and keeps the work in
  place when the hold cannot be created — it never destroys the work.
  New sentences in English and all 14 tables (`bf915f865`; `check:l10n`
  0 problems). Proof: `execTeamSweep.test.ts` (real git).
- **Cross-process file lease (M96b).** Every cleanup-ledger write runs
  under one folder file lease (`withExecLedgerLease`,
  `execLedgerLeaseEntry.ts:46`), loaded lazily as its own bundle so
  `execTeam` keeps its budget (`e40d03290`, `9dd4aef31`). Concurrent
  records under contention lose no update. Proof: the lease cases in
  `execTeamSweep.test.ts` (two real holders).
- **P2-11 artifact journal (M96b).** Pre-creation tombstones: the ledger
  names the hold ref before the fetch creates it
  (`execTeamRecovery.ts:569`), so a kill between the two never leaves an
  unrecorded ref; ledger writes sync the file and its directory, so a
  completion record survives a kill. Proof: the tombstone case in
  `execTeamSweep.test.ts` (`5d4f6f789`), whose scratch repositories now
  resolve their real path as git prints it (`helpers/teamGit.ts`).
