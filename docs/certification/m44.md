# M44 certification — images on both backends, and image edits (PLAN.md M44, D37)

Recorded 2026-09-25.

The owner asked for images on each backend. Muse Code 1.3.0's own image
tool is switched off in `muse serve`, so on the Muse Code backend the
extension now makes images itself, with the stored Model API key, through
the `ide` tool server every Muse Code session loads. Both backends also
gain image edits.

No live check: there has been no Model API key on this machine since
2026-09-22, so every path is certified against the fake Model API
(`test/unit/helpers/fakeModelApi.ts`, which now answers `/images/edits`
too) and fake file I/O. Meta's edit endpoint was read from its
documentation: a JSON body with the sources as data URLs, answered like a
generation, at the same price (dev.meta.ai/docs/api-reference/images/
edit-image, read 2026-09-25).

## What changed

| Area               | Behaviour                                                                                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| One image pipeline | `prepareImageCall` checks everything before the question (arguments; the output path confined, a `.png`, not taken; each source confined, a PNG, JPEG or WebP, present, at most 10 MB); `runImageCall` rechecks the gate, reserves the file, buys, checks the PNG, writes                  |
| `edit_image`       | Offered with `generate_image` while image generation is on; 1–4 sources; `POST /images/edits` with the sources inline; the result is a new file, the sources untouched                                                                                                                     |
| The card           | An edit's card says "make the edited image" and names the images it starts from                                                                                                                                                                                                            |
| Muse Code images   | The `ide` server lists `generateImage` and `editImage` only while image generation is on and a key is stored, the list read per request; each call is checked, then confirmed in a modal (path, prompt, sources, price, billed to the key, not the subscription), then bought with the key |
| Marked paid        | `mcp__ide__generateImage` and `mcp__ide__editImage` rows carry `paid` from the moment the item is read (`toSnapshot`)                                                                                                                                                                      |
| Key presence       | The paid state carries `isKeyStored`, read from the secret store at start and after every sign-in change; `usablePaidFeatures` gives the palette toggles, the composer badge and Account & usage the key's images and voice on Muse Code                                                   |
| Muse Voice         | The microphone's paid engine on Muse Code too while a key is stored                                                                                                                                                                                                                        |
| Image rows         | The prompt, an edit's sources and the result, then the picture (M43's preview), instead of the arguments as JSON                                                                                                                                                                           |
| A flake            | The e2e turn test waits for the idle status that follows `turnCompleted` instead of assuming it arrived (the M43 gate hit it once)                                                                                                                                                         |

The key never leaves the extension host: the `ide` server's tools use their
own Model API client over the secret store, and `muse serve` is still never
given it (D1).

## The review of PR #30

Codex found one gap (P2): after a window used paid web search on the Model
API backend and then moved to Muse Code with a key, Account & usage listed
only images and voice but its total still counted the searches. The dialog
now lists every feature the backend can use and every one this window has
used (`listedPaidFeatures`), so the total is the sum of the rows shown.
