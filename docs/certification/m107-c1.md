## C1 behavior and ownership

One shared `dist/resourceAdmission.js` installs the window's inspected global
settings without importing the governor or starting a probe. First admission
loads `dist/resourceGovernor.js`; its process singleton owns G's queue/events,
S's machine sampler, and T's native tree registrations. The split guard rejects
the governor from activation, Model API and ACP. Every Node cohort uses the
same external admission shim, including browser and agent-import bundles.
The governor contains metrics, no UI text; the existing English-fallback
requirements continue to apply to every existing bundle. Shared validation
exports the pinned mini `_default` API used by the machine settings.

Reservations include logical best-of-N, subagent and scheduled work. Child
processes inherit background class through AsyncLocalStorage. A tool moved to
background changes to `backgroundTask`. Unknown membership/usage counts are
null, never zero. Root exit marks work ended; only positive whole-tree
retirement releases it. An SDK exit before delayed identity registration also
stays occupied. Late registration cannot resurrect a retired ticket.
Foreground work runs immediately at throttle and within G's 20-second bound
at pause; Stop/cancel, approvals and paid popups remain outside admission.
No priority/rate action, relocation or governor kill is introduced.

Windows shells/hooks and SDK launches create a fresh named job with a trusted
idle holder outside that job. Native testing proved the last root handle can
close while an orphan continues: an absent job name alone is insufficient.
The holder waits for empty job membership after root completion. A crashed
holder, unclean exit or read failure keeps admission unknown. Duplicate names
are refused. Governed PowerShell join failure exits before any payload runs;
unconfigured legacy join behavior is preserved. MCP/Git/voice/plugin/browser
use the existing suspended-before-resume launcher with its job name derived
from the private control pipe. Chromium's binary FD 3/4 pipes are duplicated
into the explicit handle list and CRT startup table; native bytes 00/01/02/ff
round-trip and the child is proved inside the named job.

The SDK exposes no public PID. Its POSIX wrapper writes only its own PID to
an OS-private file, removed in finally; T validates Linux parent PID and
process-group identity. The installed SDK's actual spawn implementation
(`@muse-code/sdk` pin 1.3.0,
`dist/src/connection/spawn.js`, detached POSIX branch) was inspected locally;
no dependency or SDK file was modified. No Muse Code/Model API frame or field
was invented; no live model capture was needed for this launch-only change.

All actual spawns recheck their existing workspace/owner/cancel fences after
admission/preparation. Model API children revalidate their paid task grant;
schedules keep their confirmation/key-digest checks. Existing paid policy,
credentials and permission decisions are unchanged. Voice's synchronous
interface receives buffered pipes immediately; cancellation while queued emits
its existing signal result and starts no helper.
