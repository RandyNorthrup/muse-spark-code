## What the row shows (PLAN.md D73 acceptance 16)

`TabRow` in `src/webview/components/UsageDialog.tsx` builds on lane 0's
hook (`paidUseText`'s `tab` case, the tally fields, the six
`usagePaidTab*` strings) and reads only `PaidState`:

- state from `paidRowState`: `off`, `on`, or `on, allowed always in this
workspace` (D48);
- request count (`tabRequests`), tokens and cached tokens (`tabTokens`,
  `tabCachedTokens`), the reported token estimate (`tabCostUsd`, reported
  costs only, as lane 0's `paidCostUsd` counts it);
- `Today:` and `This window:` from the tally's reported cost, and
  `Daily budget:` from `TAB_DAILY_BUDGET_DEFAULT_USD` ($1.00, Q-M94c).
- requests with no reported usage yet reuse the generic
  `usagePaidSubagentUnknown` note, as the reviewer/best-of-N rows do.

While Tab is off and has never run in this window, the row renders
`Tab completions (off)` with the budget only: no `0 Tab requests`,
no `$0.00` lines that would read as use. Real history stays visible
after Tab is turned off. Tab on with no requests yet shows honest
zeros under the `(on)` state.

## Known limits (for the joining lanes)

- `Today` equals this window's reported cost: the dialog only knows this
  window's tally. A cross-window day total (lane L's ledger read) arrives
  with a later lane; the two strings already support distinct values.
- The snooze is the status bar's state (lane H owns it): `PaidState`
  carries on/off/always only, so the dialog cannot name `snoozed`.
- The budget is the `$1.00` default: the user's configured
  `tabDailyBudgetUsd` does not reach the dialog on this lane.
