## Runtime carrier and composition

`panel --stdio` and `panel --companion` are implemented as experimental MHP
1.1 carriers. A real `RuntimeConversation` calls A's
`composeConversationDeps(host, ports)` and creates the shared
`ConversationController` from the existing lazy conversation bundle. The
registry owns the actual prepared backend session and every admitted surface
resolves its immutable session/view binding through that registry. Runtime
settings and storage hydrate before composition; admitted settings updates
refresh the controller's settings reader. ACP injects its own resource-not-found
error factory into the now SDK-independent registry; its existing wire errors
remain unchanged.

Negotiation refuses v1-only ranges. Native requests are schema-validated and
correlated, with 30-second deadlines, abort propagation and fixed diagnostic
words. Unknown results and invalid correlated results terminate with exit 1.
Initialization is abortable and does not publish after closure. CLI trust is refused when the native host reports an untrusted workspace; granting trust needs a fresh carrier initialization. Shutdown waits
for its result write callback, with a five-second bound. Invalid UTF-8 and an
incomplete final NDJSON line fail. Normal EOF and explicit shutdown return 0.

Delivery accounts for queued/unfinished output and pending service metadata,
at most 128 messages and 32 MiB, with a 16 MiB per-frame bound. A false Node
write result pauses until drain without resending. Input dispatch is ordered
per surface. Reload preserves both sequence counters and dispatches one state
request after ready. Closed IDs are tombstoned; lifetime binding metadata is
also bounded by 128 bindings/32 MiB. Disconnect drops unfinished deliveries
exactly once. Drop logs report counts, never payloads or private paths. Delivered document/selection snapshots have a separate 32 MiB retained-data budget and at most 128 documents; replacement/close releases their prior byte accounting. A new oversized-snapshot process test fails before the guard and passes after it.

The fake CLI's deliberate process death exposed dead SDK timers after cleanup.
Concurrent registry/backend closure was tried and reverted: cancel/stop must
settle before live backend closure. On an already stopped host, close the dead
handles first so controller disposal cannot send `task/stopAll` to them.
After owned cleanup, the standalone panel command flushes stdout/stderr with
a five-second bound and exits with the carrier's status. This narrowly scoped
process-exit suppression is recorded in PLAN §8. Its fatal-status mutation
fails the process suite; the successful tests require natural command exit
before their fixture's failure-only SIGKILL cleanup.

The registry's final close also awaits releases already draining after host exit and attempts every remaining controller even if an earlier release fails. Both new tests fail before the fix (`temp/registry-close-red.log`), pass after it, and fail under independent removal drills. Fresh `controllerRegistry`, `runtimePanelPorts`, `acpAgent` regression run: **105 passed** (`temp/registry-ports-acp-final.log`).
