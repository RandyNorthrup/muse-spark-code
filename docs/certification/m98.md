# Phase 2 redesign (M98P2R)

Lane `M98P2R`, branch `m98/p2-redesign`, base `a46bece6d` (`refs/rigs/kubuntu/m98/p2-fix`), Windows 11 host, 2026-10-08. Fakes and fixtures only: zero live, paid, local-model or network calls; no credential was created or requested.

## Why the previous rounds failed

Three rounds (W, P2B, P2F) patched symptoms of one missing object. Each fix added another place that read the binding: resolution read it, `worstCaseUsd` re-read it, `admitPaid` re-read it, and the runtime read it again and re-resolved the mode. Every new check compared a different snapshot, so a receipt landing between resolution and dispatch (auto → both) or a tariff refresh (embedding $0.0002 → $0.20) still dispatched past the admitted cap. The "production binding" was a gap reporter: the host's `sources` callback was always `{}`, the CLI used a clientless twin constructor written to dodge the duplication gate, and a configured id produced a side-less runtime that replaced the working phase-1 judge, sent nothing and showed no caution. Technique matching used two guessing helpers that disagreed with `chooseByoTechnique`. The evidence root convention appended a second `judge`, and a test pinned that duplication. Every lane's tests used injected fixture bindings, so none ever exercised the real production construction.

## Design

1. **One immutable plan per run** (`src/core/judge/plan.ts`). `planJudgeRun` reads the binding once and freezes the mode, the dispatched sides (endpoint, model, technique, profile identity, tariff), the embedding route with a copied source and its tariff and consent epoch, the receipt that decided `auto`, `isPaid` and the whole run's `worstCaseUsd`. `createJudgeRuntime` exposes `plan(input)` and `run(plan)`. `run` never reads the binding: an abort or a changed surface trigger identity (`triggers`, read once into the plan) only cancels. The CLI's `resolveSource(options, signal, request)` builds the request's plan. Its price, `admitPaid` and dispatch all read that plan (`src/runtime/judge/assembly.ts`), and the embedding admission refuses a claim above the planned tariff.
2. **One production side-factory port** (`src/core/judge/sides.ts`, exclusive to `dist/judgeSources.js`). The window (`src/host/judge/judgeBinding.ts` via `separatePorts`) and the CLI/ACP/MCP (`src/runtime/judge/cliBinding.ts` from `src/runtime/main.ts`) build the separate source here.
   - **C, SystemOne (built).** `openrouter-jev:typesafe/jev-1.13` (any captured preset/model pair) becomes lane C's `createSystemOneJudge` over M95's origin-bound stored record, a pinned-origin `fetch` POST with `redirect: 'error'`, and the D78 ledger (window) or the run cap (CLI). It is explicit-only: `auto` reads it as unverified. It asks the D48 popup first with its ceiling and recipient (`paidConfirmJudgeSystemOne`) and reserves the route's captured per-request ceiling, because the service bills its own prompt above the body.
   - **Every other id names its gap.** `key`, `capture` (E), `install` (J) and `unknown` appear in the status line (`JudgeStatus.separateGap`, all 14 tables).
   - **No side-less runtime.** A plan with no request-level side runs the window's own phase-1 same-model judge (`dispatch: 'phase1'`).
3. **One technique selector** (`judgeSideTechnique`). It uses `chooseByoTechnique` over a bring-your-own record, or the SystemOne wire. Anything else has no technique, so no profile is read and nothing qualifies. Sides carry the technique (`JudgeCascadeSide.technique`), and lookup and qualification both read it. The guessing helpers `servableTechnique` and `phase2SideTechnique` are deleted.
4. **One evidence-root convention** (`phase2EvidenceFile`). It writes `<root>/<kind>/<slug>.json`, where root is `<globalStorage>/judge` or `<config>/muse/judge`. The slug is a 96-character readable prefix, `--`, then 32 hex characters of SHA-256 over the complete identity.
5. **One binding policy.** `createPhase2Binding` serves every surface; the CLI reaches it through `dist/judgeP2.js`. The entry twin `createEntryClientlessBinding` is deleted.
6. **Explicit `separate`** needs a verified, permitted source and consent, not fitted profiles. This is the setting's documented contract; B fits only `logprob`/`stated` (`calibration/schema.ts:143`), so a SystemOne side could never be profiled. `both` and automatic `both` keep requiring both sides' profiles.
