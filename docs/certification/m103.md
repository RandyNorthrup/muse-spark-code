Root cause: guard5 made `hardwareContext.ts` the single owner of the
hardware evidence rule. The shell imports only `hasHardwareEvidence` from
it, but the module's detection code imports `MAKER_DETECT_MAX_*` from
`src/shared/constants.ts`, and esbuild cannot drop that file's unused
`64 * 1024`-style declarations, templates and `String.raw` constants. Both
entries therefore carried the same ~4.3 KB of constants they never read
(plus the re-exported browser-check table). The hardware context itself is
not duplicated beyond `hasHardwareEvidence` (233 B in the shell).

Fix (`scripts/lib/hardwareGuardSplit.mjs`, the existing hardware-only
`hardwareConstantTables` plugin; no source module, rule, guard or check
moved):

- `constants.ts`, `browserCheckConstants.ts` and `makerPreviewConstants.ts`
  resolve with `sideEffects: false` in the two hardware builds (all three
  contain only `export` declarations). The shell reads none of them, so they
  leave it; the guard keeps only what it reads.
- Integer-literal products (`export const X = 64 * 1024`) are folded to the
  same number in that build's copy of `constants.ts`, as the plugin already
  marks `new Set(` pure, so unused ones tree-shake. 79 declarations; each
  folded value was checked equal to the JavaScript product.
- New split-gate row (`scripts/check-bundle-split.mjs`): `dist/hardwareShell.js`
  must not carry `constants.ts` or `browserCheckConstants.ts`.

All other bundles are built by other plugin lists and are unchanged; every
row of the size gate is `ok`, split gate exit 0.

Smoke on the built bundles (`node`, from `dist/`): shell
`hardwareAction('arduino-cli upload -p /dev/ttyACM0 sketch', 'bash', {isMakerEnabled:true})`
→ `program`, `ls` → `undefined`, `isHardwareWorkspace({})` → `false`;
guard loads with its 26 exports; folded `MAKER_DETECT_MAX_BYTES` reads 8192.
