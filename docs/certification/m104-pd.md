## Checkpoint 3 — queue, reload, theme and correlation boundaries

F12/F15/F46/F47/F48 host components now enforce 16 MiB per-frame and 32 MiB
aggregate UTF-8 admission, preserve validated in-flight responses during reload,
and serialize reload against outgoing messages. Closed relays refuse reload.
Editor path identity normalizes Windows separators/case/dot segments while
virtual RDT monikers remain unmatched, preserving close-event teardown.
Native status IDs distinguish numeric from string IDs and equate JSON numeric
notations; disposal closes both real WPF windows.

The native page bootstrap maps MHP theme names/tokens to the shared CSS names.
Four production scripts execute before and after DOM ready in an isolated Node
fixture. Schema-invalid metadata and CSS injection fail before script creation.
These are executed-script components, not installed WebView2 theme receipts.
Runtime theme-refresh integration remains requested from A/C.

A new controlled cancellation race first failed on the unchanged peer: a valid
reply received while the cancellation notification was still writing could
leave a stale retired ID that accepted a duplicate. The peer now validates and
consumes that reply once, for both success and failure, before or after retirement.
An unrelated request completes; repeated and unknown IDs still fail.

The native suite contains 48 tests, zero skipped. Sixteen additional controls
failed their targeted tests, with byte-exact restoration: UTF-8 admission,
aggregate bytes, queue recycling, reload in-flight delivery, closed reload,
status ID types/numeric notation, Windows path normalization, URI validation,
virtual monikers, rooted identity, theme DOM application/schema/CSS validation, cancelled ID
retirement and repeated pending replies. The first reload control also triggered
the compiler's unused-field gate; it was corrected to exercise behavior without
weakening that gate. The fixture uses the existing threading package's async
