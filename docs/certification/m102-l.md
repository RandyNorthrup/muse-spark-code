## What was delivered

- `l10n/usage.<lang>.json` for all 14 locales: every one of the 184 frozen
  English keys translated (194 leaf strings), with exactly the plural
  categories `Intl.PluralRules` gives each language (`other` only for
  `zh-cn/zh-tw/ja/ko`; `one/other` for `de/tr/hu`; `one/many/other` for
  `fr/es/pt-br/it`; `one/few/many/other` for `ru/pl/cs`).
- Shared vocabulary is reused verbatim from the shipped `l10n/ui.*.json`
  (title, provider, model, cancel/close/export, request counts, window labels,
  feature names such as `Best-of-N`, `Hook`, `Tab`-completion), so the usage
  page agrees with the panel. Where the main table keeps English for a genuine
  term, the usage table keeps it too and allowlists it below.
- `l10n/untranslated.json` gains the `usage` section: `*` holds `chartBucket`
  (a slots-only template, identical in every language); per-locale entries hold
  only values whose correct translation is byte-identical to English —
  technical terms kept as loanwords (`Hook` in 8 locales, `Worker` in 7,
  `Subagent`/`Reviewer`/`Editor`/`Name` in German, `Model` in `tr/pl/cs`,
  `Plan` in `es/tr/pl`, `Tokens`/`Local` in `es/pt-br`), same-spelling French
  words (`Conversation`, `Images`, `Catalogue`, `Date`), and Italian's
  invariable `recordCount.one`. Provider names (`Meta`, `Tab`, `Muse Code`),
  unit symbols (`JSON`, `CSV`, `p50`) and the `museSpark.paidDailyBudgetUsd`
  setting id stay inline inside otherwise translated sentences, so no entry is
  needed for them.
- `scripts/pseudo-l10n.mjs` + `scripts/lib/harnessLang.mjs`: the pseudo pass
  now writes `test/harness/l10n/usage.pseudo.json` beside `ui.pseudo.json`
  (both git-ignored) from `USAGE_EN`, honouring the `usage` `*` exceptions.
  `scripts/lib/l10nSource.mjs` additionally exports `USAGE_EN` for the scripts
  that need it. `prepareLang` callers (`harness-shots`, `a11y`, `readme-shots`)
  are unaffected; only `pseudo-l10n.mjs` consumes the (now plural) return.
- `test/unit/usageL10nTables.test.mjs`: the durable lane guard — all 14 real
  tables strictly checked with the real `untranslated.json` section, the
  section itself validated, and the locale count pinned at 14.

## Sandbox notes (for the lead)

- `npx --no-install husky` fails here (npm cache URL error); hooks were
  already present via `core.hooksPath=.husky/_` and demonstrably ran on every
  commit below (lint-staged prettier/eslint, gitleaks: no leaks).
- The shell starts node with a UNC (`\\?\`) cwd, which breaks esbuild's path
  handling and vitest's root detection. Workarounds used: `process.chdir` to
  a drive-letter path, vitest `--root` with a clean path, `TEMP`/`TMP`
  redirected into `temp/`. The esbuild _service_ cannot read directories here
  at all, so `scripts/check-l10n.mjs`, `scripts/pseudo-l10n.mjs` and the
  fixture-based `usageL10nGate.test.mjs` cannot execute in this sandbox; the
  checks above run the same shipped logic (`tableProblems`, `USAGE_EN`,
  `TABLE_LOCALES`, the real exception sets, the real `writePseudoTable` with
  only its esbuild bundling stubbed) over the same files. Rerun the real gate
  on an unsandboxed rig.
