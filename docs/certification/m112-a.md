## Implemented in A

- `src/acp/questionDeferral.ts`: the agent's injected clock and form lifecycle;
  default 60 seconds, 0 never, 1–9 clamped to 10 and maximum 3600; cooperative
  withdrawal after a successful deferral; early answers and invalid/declined
  forms; late validated form answers; stable, non-reused question numbers;
  one notice per successful open transition; safe Stop/close/settlement paths.
  Registration freezes arrival time; a replay retains its saved deadline;
  a slow registration cannot reset the minute or race the deferral write.
  Coalesced requests show one form and use the registry's grouped reply port.
- `src/acp/agent.ts`: reserved `/questions` and `/answer <n> <text>` announced
  alongside skills, also when skill listing fails. Local commands work while
  a prompt is running without starting another model turn. Valid late answers
  steer the current prompt; idle answers and proven refused steers go through
  the durable queue port before the next ordinary prompt. Uncertain admission
  is never retried. Queue loading is inside prompt preparation, so Stop there
  cannot accidentally start a turn afterwards. Question diagnostics are fixed
  words, never a form, question, answer, exception message or stack. The registry
  loads before replay listeners attach. Resumed turns use the actual loaded
  active-turn id; their completion also withdraws forms. Release is rechecked
  after awaiting start, and a failed state write cannot prevent Stop.
  A failed queue acknowledgement reports fixed text and retains the started
  turn's identity so it can still be stopped.
- `src/acp/questions.ts`: local command parsing and the no-form deferral
  description. Existing zod validation of client form answers remains the
  boundary before use; no new ACP/MSP wire shape was invented.
- `src/runtime/cliArgs.ts`: `--questions-defer-after <seconds>`, default 60,
  strict integer/range validation and clamping. Exec refuses this interactive
  flag. Serve options carry the normalized value for the runtime binding.
- The English runtime usage and all fourteen real translations include the
  new flag. Lane-0 strings supply the new notices and command descriptions;
  no unused manifest strings were added (U owns the manifest artifact).
- README's Questions section, ACP and CI guides, CONTRIBUTING, AGENTS.md's
  layout, CHANGELOG and the editor matrix describe the behavior and distinguish
  implemented adapters from outstanding integration and installed-editor runs.

The explicit `questions: 'decline'` policy creates no registry, form or clock,
and preserves immediate headless decline. It is a policy, not a fake registry.
The other choice is a **required injected factory**; there is no production
no-op, optional backend-method fallback or fake implementation.

## Integration handoff: Q and the runtime launcher

Lane Q's registry and store adapters are absent on this base. A defines the
small consuming interface `AcpQuestionRegistry` and its factory in
`src/acp/questionDeferral.ts`; the lead binds it after Q merges. This is
required work before shipping, not a claim of disk-persistence certification.

The factory gets the actual `AgentSession`, the same `QuestionClock` that A
uses, and the session-scoped `deliver` callback. Bind these methods to Q:

| Method                              | Required binding                                                                                                                                                                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `load`                              | Load owner-only, zod-validated state for this session before adoption succeeds. Reject corruption/read failure; never fabricate an empty success.                                                                                                         |
| `register(event, timing)`           | Register/coalesce the request without a second clock. Return the canonical record and keep an existing arrival/deadline on replay. Resolve a missing timing turn id from the actual session/ledger; never guess a handle.                                 |
| `defer(id)`                         | Settle through required `AgentSession.deferQuestions`, persist the open state, and return true only for a new open transition. An existing settlement returns false; failures must not announce success.                                                  |
| `replyWaiting(id, reply)`           | Answer, clarify or cancel every still-waiting request coalesced into this card; never deliver a model user message for an early form reply.                                                                                                               |
| `list`                              | Return this session's current records. Q owns normalization, coalescing, 20-open bound and terminal retirement. A filters the open set for the local list.                                                                                                |
| `answer(id, reply)`                 | Validate stored question/answer ownership and values, format Q's bounded English late-answer text, mark before delivery, restore only on proven `notTaken`; an exception/uncertainty never permits a retry. Approvals/modes/rules are unreachable.        |
| `settled` / `turnEnded`             | Apply actual backend outcomes, leave an interrupted/failed waiting question open, cancel a stopped waiting question; do not relabel user clarification as deferral.                                                                                       |
| `queue(message)`                    | Persist idle/refused-steer answers in owner-only per-session storage before returning `taken`. The stored message is removed with its session and excluded from logs, exports and report text.                                                            |
| `queuedParts` / `acknowledgeQueued` | Lease the precise saved prefix for one submission; acknowledgement retires only that prefix on `taken` or `uncertain`, never answers queued concurrently after the lease. Preserve it after proven `notTaken`. Runtime cleanup must drain pending writes. |
| `dispose`                           | Detach the held registry and retain its durable state; do not delete the session's records. Runtime cleanup must drain pending writes, including any waiting-to-open transition required on reload.                                                       |

Named launcher bindings (outside A's file regions):

3. Q binds both backend `deferQuestions` methods and the ordinary full-session

   a test-only shim for the old full fake, while new M112 tests use lane 0's
   `ScriptedQuestionSession`. Remove that shim when Q updates the common fake.
4. Scheduled/unattended producers select immediate deferral (including
   setting 0); best-of-N/worktrees/evaluation retain their existing decline/
   clarification. The schedule binding and its fake cases belong to Q/lead.

Actual persistence, coalescing, security of the disk queue and restoration
