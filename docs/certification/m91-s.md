# M91 lane S: the shell keeps its directory between calls

Scope: PLAN.md M91 step 4 "Lane S" and acceptance item 9, D70, and the
binding lead decisions in `m91-lane-common.md` (SoL-Pi rules, the side-file
read-back). A `cd` in one shell call of a Model API session carries into the
next call of the same session; a new session starts at the workspace root;
a directory outside the workspace roots resets to the root with a note.
Worktree `mx-m91s`, branch `m91/s`.

## What was built

- The host wraps the user's command after admission with a trailer
  (`shellDirectoryTrailer` in `tools.ts`) reporting the call's sequence and
  the final directory (`pwd`, `(Get-Location).Path` on Windows) to the
  session's side file (`<tmp>/muse-spark-shell/<session>.<object>.cwd`).
  The trailer restores the command's own exit (bash keeps `$?`; PowerShell
  saves `$?`/`$LASTEXITCODE` first: probed, a failing cmdlet exits 1 and a
  succeeding trailer after it exits 0) and writes a file, never a stream, so
  output is unpolluted.
- `ModelApiSession` reads the report back (never the output), validates the
  canonical directory (`realPath` both sides, links resolved, D24) against
  the workspace root, and keeps it or resets with
  `UI_TEXT.shellDirectoryReset`. A result off the root carries
  `UI_TEXT.shellDirectory` (`In {path}`, workspace-relative) at its tail in
  both `output` and `visibleOutput` (the panel's tool row); a result at the
  root carries nothing, so no earlier request bytes change (SoL-Pi rule 1).
- The declared tool description and JSON schema are untouched (pinned by an
  exact-match test). Approval cards, session rules and hook payloads see the
  user's own command: the wrap happens after admission. `then_run` and
  `run_checks` run through `runCommand` at the workspace root, untrailered.
- Machine-scoped `museSpark.modelApiShellKeepsDirectory`, default on (the
  owner's 2026-10-04 ruling). No new UI table strings were needed: lane 0
  already added `shellDirectory`/`shellDirectoryReset` to en.ts and all 14
  tables. The setting's manifest text is in `package.nls.json` and all 14
  `package.nls.<lang>.json` with real translations.
- M75 records the setting: the eval driver pins `shellKeepsDirectory` off,
  matching the recorded baseline, which predates the setting (PLAN.md M75
  decision). Pinning it on broke `evalDriver.test.ts`'s exact-command
  assertion (`node -v` arrives wrapped); rather than rewrite M75's test, the
  lane keeps eval conditions identical to the baseline. The shipped default
  stays on; turning it on for eval needs a fresh baseline run.

## Tests

`test/unit/modelApiShellDirectory.test.ts`: 29 tests. Trailer format on
bash/PowerShell incl. hostile quoting and drive letters; report parsing incl.
stale sequences and embedded newlines; the declaration byte-stability guard;
carry-over within and across turns (model request bytes and panel row);
silence at the root; new sessions at the root; escapes (`..`, absolute
outside, symlink out, UNC, other drive, bare `cd` home, drive-relative);
failed `cd`; `exit` before the trailer; setting off (`false` and absent) as
today's behaviour; `then_run` at the root untrailered; one real-shell
end-to-end test on the current platform (real `cd`, real escape, `exit 3`
code preserved, no trailer bytes in output). The emulated shell reads the
real trailer format, so a format drift fails loudly.

## Red drills

Each drill breaks one guard in source, runs the lane file (filtered as
noted), and restores the exact lines (verbatim re-application; the final
diff holds only the feature hunks, and the full file is green again after).

- G1 confinement: `if (!isBelow(relative, p))` to `if (false)`.
  `-t 'resets to the root'`: 7 failed, 22 skipped. Escapes kept:
  `/etc`, `/`, `/outside`, `/home/tester` as next cwds; win32 tails
  `In //server/share/`, `In D:/other`. Restored.
- G2 root silence: root branch returns `In .`.
  `-t 'adds nothing at the root'`: 1 failed
  (`[exit code 0]\nIn .` vs `[exit code 0]`). Restored.
- G3 trailer presence: `__m91status` to `__m91statuz`.
  `-t 'carries a cd into the next call'`: 1 failed
  (cwds `[/ws, /ws]` vs `[/ws, /ws/sub]`). Restored.
- G4 setting gate: `!== true` to `!== false`.
  `-t 'the setting off'`: the explicit-false row failed
  (cwds `[/ws, /ws/sub]` vs `[/ws, /ws]`). Restored.
- G5 declaration: `workspace root` to `workspace` in the tool description.
  `-t 'byte-stable'`: 1 failed (`toContainEqual`). Restored.
- G6 `then_run` pin: `runCommand` cwd to `keptShellDir ?? root`.
  `-t 'then_run at the root'`: 1 failed (then_run cwd `/ws/sub`
  vs `/ws`). Restored.
- G7 missing report: keep-previous to reset-to-root.
  `-t 'exits before the trailer'`: 1 failed
  (cwds `[.., /ws]` vs `[.., /ws/sub]`). Restored.
- G8 canonicalization: `realPath` both sides to identity.
  `-t 'through a link'`: 1 failed (kept `/ws/linked`). Restored.
- G9 unconditional trailer: bash `;` to `&&`.
  `-t 'tracks the directory even when the command fails'`: 1 failed
  (no `In sub` tail after `exit code 1`). This drill also caught and fixed
  an emulation bug: the test double's `(\S+)` swallowed a following `;`
  into the target (now `[^\s;&|]+`), and it honours `&&` skip semantics.
  Source restored to `;`; the emulation keeps both understandings.
