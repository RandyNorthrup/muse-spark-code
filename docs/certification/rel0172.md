### One test followed the release

`test/unit/cx1r2Truth.test.ts` required the shipped What's New notes to
contain "Correction (2026-10-10)". What's New ships the two newest releases
in full (`FULL_NOTES_RELEASES`); in 0.17.1 those were 0.17.1 and 0.17.0, and
0.17.0 carries a correction. In 0.17.2 they are 0.17.2 and 0.17.1, neither
corrected, so the sentence is no longer in the shipped notes and the case
failed. Nothing false ships: the three corrected releases' notes are not in
the content at all, and `CHANGELOG.md`, which the page links, keeps all three
corrections (the case before it still counts three).

The case now encodes each corrected release (0.15.0, 0.16.0, 0.17.0) through
the same round trip and requires its correction, so the rule holds whenever
one of them is shown, and it keeps every "must not contain" check on the
shipped two.

### A check the footer scene lost (known; not fixed in 0.17.2)

The capture applies hover, focus and pressed to the first control visible in
a scene's screen. In `whats-new-footer`, the page scrolled to its end, that
was the footer's first link with 0.17.1's notes, and 0.17.1's review used
those frames to see the focus ring on **Full Changelog on GitHub** clear of
**README on GitHub** in six themes.

The fixture's last screen holds controls above the footer, so the states
land on them instead: at 320 px on the code block (the 24 frames whose
target changed from `a` to `pre`: default, hover, focus and pressed in six
themes), at 690 px on the written-out link in a paragraph (the same tag, so
no row flags it; seen in the frames). In this baseline the footer links are
drawn in their default state only.

It cannot hide a regression in 0.17.2: 0.17.1's baseline exercised the
check, and the code it checks is unchanged since
(`git diff 4d28a4f84 HEAD -- src` names two files, both under
`src/core/providers`).

The fix belongs in the capture, not in the notes: the footer scene takes its
state target from the footer itself, whatever the notes end with, and a test
pins it. It moves that scene's hover, focus and pressed frames, so it is
rendered with the release train's baseline. The lead's ruling: no second
render for 0.17.2.
