# The Windows vault and Windows test truth on the 0.19.0 tree (lane WINLEGAL, 2026-10-20)

Run on `thispc` (Windows 11 Pro 10.0.26200, Node 24.20.0, Windows PowerShell 5.1)
in the `fix/0190-winlegal` worktree. The vault is on by default
(`museSpark.vault.enabled` defaults to `true`), and on Windows it could not
start: every suite below was red before its fix and is green after it.

## The machine

This PC's `%TEMP%` grants Modify to `CodexSandboxUsers` and to an unresolved
SID, and `C:\Users\Randy\Coding` grants read to `CodexSandboxUsers` and
`MuseSandboxUsers`. The vault guard and the media private root rightly refuse
folders other principals can reach, so the vault and media suites ran with
`TEMP`/`TMP` pointed at a folder under the profile that inherits only
SYSTEM, Administrators and the user (`C:\Users\Randy\mx-vtmp`, removed
afterwards). Hosted Windows runners have ordinary grants. With this PC's own
`%TEMP%` the private-root suites fail with the product's refusal ("The private
media root is not owner-only"), which is the correct answer for that folder.

## Tests that were wrong about the product, corrected

- windowsPipeHelperStart: the job helpers are prepared in the hook (their first-use compile is a build, not the case under test).
- writerCrashPosix: the stage argument shifted the helper path into the stage slot when no stage was given; the slot is always filled. Its children configure the governor as the broker does.
- windowsPipeRelayChild, windowsBrokerClient: the governor configured as the broker and the extension host configure it; the broker client stages the job-helper sources the package ships and ends the broker it started before removing its folder (Windows cannot delete a running program).
- jobCreateAtomic: compiles with the real program runner.
- mediaConvert: converts with the product's own bindings (`conversionBindings` with a real private root), which Windows requires.
- pluginImport: scans with this machine's platform (it reads real files planted here).
- vaultExecSpawn: a read-only folder on Windows is a real denial of new entries (`denyWrites`, icacls `(WD,AD)`), as mode 0555 is on POSIX.
- recordingLatest: the scripted `run` answers for PowerShell and icacls are gone with the seam itself; the Videos folder is compared with the registry's own value, the lockdown is read back with icacls (one `OWNER RIGHTS:(OI)(CI)(F)` grant), and the failure paths use a system root without the tools, on every platform.
- legalBuildEvidence: the shared build call extracted (duplication 0).
