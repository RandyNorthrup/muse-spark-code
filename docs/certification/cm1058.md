# CM1058 round 3 — certification for review RVCM1058B (lane CM1058R3)

Worktree `/Users/randy/lanes/CM1058R2`, branch `c/m105-8`. Every finding
(P1/P2/P3) is fixed against the lead's three rules; no residuals.

Rules as built:

- RULE 1 — a file in use is never deleted. "In use" is the ledger's
  durable `pinned` set under the cross-process file lease, written by the
  request bracket (media `beginRequest`/`prepare`/mid-turn `upload`,
  drained by the turn's end) — never one window's snapshot.
- RULE 2 — nothing destructive runs after cancel. The listing signal
  threads `read → accountReport → retryPending/cleanup → removeEntry`,
  and every destructive step checks it immediately before dispatch; the
  ledger records the delete intent first and the next read retries it.
- RULE 3 — the expiry sweep is the only thing that deletes orphans, at
  the promised time: one clock unit everywhere (provider `expiresAt`
  seconds vs the millisecond clock) and a release deletes only the files
  its own sync left without a session.

## Incident during the lane (kept out of the diff)

First version of finding 8 imported `isModelApiError` from
`modelapi/client` into `host/backend/storeErrors.ts`. That edge drags the
client graph into the sessions chunk: 8 unrelated `deferredBundles`
suites failed with `modelApi.js ↔ modelApiSessions.js` load-time
`Maximum call stack size exceeded` (dpdm reports no source cycle — this
is a chunk-boundary cycle). Fixed by making the provider check
structural and local in `storeErrors.ts` (mirrors
`transport.isModelApiError`'s shape; parity pinned by
`storeErrors.test.ts`). Lesson: a helper shared by lazy chunks must not
import the client graph. All 120 `deferredBundles` tests pass, and
`npm run build` (tokens, esbuild, size, split, host-globals, notices)
exits 0.
