# M102 lane E — editor adapters

Rig: Kubuntu, 2026-10-05. Base: `7e55c5fb` (`m102/0`). Lane E only.
No push, merge, rebase, credential access, live/model attempt or paid call.
Hooks resolve through this worktree's `.husky/_`; pre-commit exists.

## Delivered adapters

- One Usage & cost tab per VS Code window, through `buildWebviewHtml`, with
  scripts enabled, command URIs disabled and only `dist/webview` as a resource
  root. Incoming and outgoing messages use the frozen lane-0 zod parsers.
  Service operations are ordered and failures use fixed words rather than
  raw service errors. Closing the document releases its connection.
- VS Code save and counted delete dialogs; remote save-dialog URIs work through
  `workspace.fs`. A dismissed dialog or closed tab cannot authorize a write.
  Settings, the history folder, safe HTTPS console links and model-price
  navigation reach their editor adapters. History changes target global settings.
- `museSpark.openUsagePage` is registered, the controller accepts both the
  dedicated message and the host action, and the palette supplies Usage & cost
  and `/usage page`. Existing `/usage` continues to open Account & usage.
- ACP `/usage`, `/usage page` and `/usage open` use the shared reader and
  `usageText` renderer. They never start a model turn. The command stays
  available if skills fail; a colliding skill cannot shadow it. A client with
  URL elicitation gets that request; other clients, and failed elicitations,
  get a Markdown link. Cancellation while reading produces no late reply/link.
- CLI `usage [summary|daily|models|limits|export]` accepts `--range`, `--by`,
  `--from`, `--to`, `--json`, `--csv` and `--out`; `usage open` uses the
  companion and a fixed OS opener; `usage serve --stdio` carries validated
  page messages. Text, CSV and versioned JSON use the service, with no adapter
  aggregation or invented zero for unknown cost/tokens. Malformed flags exit 2.
- Runtime credential removal precedes these routes. The OS opener uses the
  existing bounded `runProgram`, shell-free, with only a checked loopback URL;
  opener errors cannot log its private fragment.

The page/service/table/journal contracts, frozen English table and all
translations are untouched. No dependency, cast, suppression, ignore, threshold
or global/user-machine setting was added. Production seams have explicit types
and injected dependencies; unavailable modules/actions fail explicitly.

## Cross-lane interface and integration work

The plan fixes message schemas but not the service bundle's factory API. Lane E
therefore supplies `UsageAccess`, `UsagePagePorts`, `UsagePageConnection` and
`UsageAccessDeps` in `src/runtime/usage/usageAdapter.ts`, rather than a fake
service or an import of an absent implementation.

- Lane S's `dist/usageService.js` must export
  `createUsageAccess(deps): UsageAccess` and re-export `runUsageCommand` from
  `src/runtime/usage/usageCli.ts`. The same `read`, `usageText`, `export` and
  `connect` operations serve VSIX, ACP, CLI and native hosts. `historySettings`
  supplies VS Code's live enabled/retention values; standalone service settings
  remain the service's own responsibility.
- Lane S's `dist/usageCompanion.js` must export
  `openUsageCompanion({usage, assetsFolder, locale})`, returning `{url, close,
closed}`. `url` is `http://127.0.0.1:<port>/#<64 hex characters>`; `closed`
  resolves on idle shutdown too. Failed starts are retried and an idle server's
  URL is evicted. No token is logged or persisted by this adapter.
- Lane U/integration must route the new `PaletteAction` `openUsagePage` in
  `src/webview/App.tsx` to `{type:'openUsagePage'}`. The Account & usage button
  belongs to U. This lane did not edit U's chat/action code.
- Lane W must register the command/manifest keys and settings, build
  `usagePanelEntry.ts` to `dist/usagePanel.js`, and register S/U's other new
  entries, bundle budgets/split checks, notices and host API record. Node usage
  bundles need `custom` and `partialRecord` added to the shared validation
  entry; importing the frozen page/journal schemas otherwise exposes that
  existing split gate failure. No gate was weakened.
- Native plugins can inject chooser/confirmation/settings/model actions through
  `UsageCliPorts.pagePorts`. The bare stdio route refuses those host actions
  until an adapter supplies them; it never writes a file or grants deletion on
  a page-supplied approval. The frozen page protocol carries no reverse host
  dialog request/answer. M64/M65/integration must supply that transport for full
  native export/delete equivalence. The companion page remains their interim
  route, as D82 specifies.
- README, CHANGELOG, PLAN, privacy/security/ACP guides and host-matrix docs
  belong to W. They were left to that owner. Full quality is reserved for the
  lead by the rig/shared brief, overriding the general AGENTS gate rule.

Every editor matrix route is represented: VSIX family and remote hosts use the
same tab; ACP clients use summary/elicitation/link; native JCEF/WebView2/SWT
hosts use the stdio service plus injected ports; CLI/headless use text/export;
Jupyter/RStudio use the companion. Browser-only hosts without a runtime retain
D60 phase G's deferral. UI, server, real provider aggregation and visual/editor
receipts require the other lanes; no complete M102 certification is claimed.
