# CAPAUDIT — multi-vendor capability audit

Date: 2026-10-05. Worktree: C:/Users/Randy/Coding/mx-capaudit. Branch: rv/capaudit. Audited HEAD: 415cf3f752d73533557384947de834074691a31e.

## Result and scope

The owner's rule requires model-specific enablement, not a Meta-shaped request with a different model name. This snapshot does not yet provide that end-to-end: M95's provider dispatch, catalogue consumption and final host/runtime wiring remain unfinished. PLAN.md:13885-13952 explicitly identifies this intermediate integration; it is not an undisclosed regression or proof that the remaining lanes were abandoned.

Two independently confirmed implementation defects deserve correction before dispatch is enabled:

- The Anthropic encoder sends adaptive thinking and effort to Haiku 4.5 even though the captured model record explicitly refuses those capabilities.
- The price-card settlement cannot distinguish five-minute from one-hour cache writes, although the decoder preserves that distinction and reservation reads the one-hour price.

The wider integration gaps affect model selection, limits, reasoning replay, media, paid operations, hooks and the judge. Several algorithms are already provider-neutral; they should remain available on capable BYO models. Features such as structured output and logprob judging must not disappear because Muse Spark lacks their particular wire capability.

This audit was read-only. Only this report was written. No checkout, fetch, install, source edit, gate mutation, commit or push; no new inference, paid call or credential access. Public documentation GETs were used for three narrow API checks. No full quality run, as review-common.md explicitly prohibits it. These findings do not certify a release.

M95's committed captures prove selected model routes, not every model at a vendor: docs/certification/m95-captures.md records 46 historical inference attempts, 44 billed. Azure, Ollama, LM Studio, vLLM, llama.cpp and custom presets have wireCapture false in this HEAD; listedPresets correctly excludes them. Azure deployment names must resolve to the model family, not become a capability heuristic.

The supplementary catalogue contains 669 tool-capable models across 13 providers. Every retained provider has vision, reasoning and cache-price entries, but individual models differ. For example, OpenAI has 42 vision entries out of 44 retained models; Groq has 2 out of 7; Z.ai has 6 out of 18. A price for cached input is not proof of a cache hit, supported TTL or breakpoint policy.

The captured Anthropic models list is richer than the shared four booleans. ## Findings by review class

### Concurrency and lifecycle pass

**F1 — P2, concurrency/lifecycle, latent: replay has no producing identity.** src/core/backends/modelapi/ModelApiHost.ts:521, :9203; sessionStore.ts:265; codecs/responses.ts:148. Defect: changing the model retains unowned native reasoning and forwards it through the Responses codec.

Scenario: an Anthropic/OpenRouter reasoning envelope or an encrypted item from another model remains in replay; switch to an OpenAI/xAI Responses model; the next encoder forwards that item unchanged. The receiving API can refuse the turn rather than preserving usable text/tool history. Resume/fork retain the same identity gap. Confirmed by reading the wrapper, persisted schema, setter and encoder; no live switch run. This is an integration blocker, not a claim that the current Meta-only dispatcher already performs the cross-provider switch.

Fix: store producing configured provider/model identity on replay entries and apply captured native replay policy before encoding. Invalidate old request factories/capability snapshots and rebind budgets/consent after switches. Do not blanket-delete ordinary conversation history.
