# M83d: refuse, do not mask (RV83d and mr83)

**Superseded history:** D64 and [M83e](m83e.md) replace this design and its
credential-masking/refusal claims. Evidence below applies only to its named
historical source snapshots.

**Status 2026-10-02 (round 4): implemented with scoped evidence; lead
certification pending.** The lead decided on 2026-10-01 that the import
refuses items that may hold a credential instead of masking them: four
review rounds (RV83, RV83b, RV83c, RV83d) each found a spelling that hid a
value from span masking. This record covers that redesign, the other RV83d
and mr83 findings, and the join with `origin/main`. Full quality, a fresh
review, the native VS Code import UI, other platforms and M76 runtime
admission remain lead-owned. Earlier records (`m83.md`, `m83b.md`) describe
the masker as history.

## The decision as built

`src/core/import/importMask.ts` (`maskText`, `maskArgs`, `maskUrl` and their
span logic) and its test are removed. `src/core/import/importCredentials.ts`
exports `credentialCue(texts)`, which reads all of an item's texts as one,
and `maskValues`, kept for the structured `env` and header values of an
admitted MCP server (masked whole, names kept, as every review found sound).

### What an item is, and what is read

| Item          | Texts read                                                                                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MCP server    | its name, the names of the fields left out, `command`, every `args` entry, every `env` entry as `NAME=value`, every header as `Name: value`, `url`, Codex's copied tool names |
| Hook          | event, matcher, `command`, `statusMessage`                                                                                                                                    |
| Command       | its file's name parts, its skill id, the whole file, the generated `SKILL.md`                                                                                                 |
| Agent         | its file's name parts, its id, the whole file (written as is)                                                                                                                 |
| Project rules | the whole file, and the section made of it (its heading names the path)                                                                                                       |

An item's label (a server's name, a hook's `event (matcher)`, a file id or
path) is shown as `(name not shown: it may hold a credential)` when the
label itself holds a cue. A user rules file and a project MCP server, which
are never offered, keep their refusal reasons; their labels are checked the
same way.

### The three spellings

1. As written: Unicode NFKC, every format character (`\p{Cf}`: zero-width
   spaces and joiners, soft hyphen, BOM, bidi controls) removed, and 50
   Cyrillic and Greek look-alikes read as their Latin letters.
2. As a shell, a JSON reader or a URL decoder joins it: `\`, `^` or a
   backtick before a line break removed (shell, cmd and PowerShell
   continuations); JSON and JavaScript escapes (`\u0074`, `\u{74}`, `\x74`,
   octal `\164`, `\n`, `\"`, …) decoded, an unknown one kept as written so
   a Windows path's folders do not join; runs of percent escapes decoded as
   UTF-8 (byte by byte when not); numeric HTML entities decoded; every quote
   mark (straight, typographic, guillemets) removed; then spelling 1 again
   on the result.
3. Spelling 2 with every character but letters, digits, whitespace, `-`,
   `=` and `:` removed, so a name split by other punctuation reads whole
   (`**to**ken:`, `--to\ken`, `to"k"en`). The dash stays so a flag stays a
   flag.

"Join lines": a name, its separator and its value may each be on their own
line, since every separator and value check allows any whitespace,
line breaks included, between them (`password:` then the value below it).
A separate line-joining replace was written first and removed: no test
could fail without it, because the checks already span lines.
"Lowercase": names are matched case-insensitively; token shapes keep their
case (`AKIA`, `eyJ`).

### The cues

Checked in this order across all three spellings; the first decides the
kind the preview names.

- **token**: GitHub (`gh[oprsu]_`, `github_pat_`), GitLab (`glpat-`),
  OpenAI and Anthropic (`sk-`), Slack (`xox?-`), AWS (`AKIA`, `ASIA`),
  Google (`AIza`), Stripe (`[prs]k_live_`, `_test_`), npm (`npm_`), Hugging
  Face (`hf_`), Meta's Model API key (both of the log redactor's shapes), a
  JSON Web Token's start (`eyJ`), a PEM private key header, Slack and
  Discord webhook URLs. The log redactor's own `Basic` pattern is not
  reused: it matches prose such as "basic examples".
- **url**: user-info, `//something@`, with or without a scheme.
- **name**: a run of letters, digits, `_`, `.` and `-` holding a credential
  word (`token` but not `tokenizer`; `secret`; `passw`; `passphrase`;
  `pwd`; `api_key` in any joining; `auth` but not `author`, `authenticate`
  or `authorized`, though `Authorization`; `bearer`; `credential`;
  `private_key`; `access_key`; `signature`; `cookie`; `session_id`;
  `sessid`; `jwt`; a `_KEY`/`.key`/`KEY` ending), or exactly `pw` or `otp`,
  followed by closing quote marks, `=` or `:` (not `==` or `::`) and a
  value; such a name starting with `-` (a flag) followed by whitespace and
  a value that is not another flag; any name ending in `key`, or exactly
  `sig`, `code` or `pass`, followed by `=` and a value; `Bearer` and a
  value; `Basic` and an encoded value (one with a digit, `+`, `/`, `=` or
  an inner capital); `-u` or `--user` followed by `name:password`. A name
  cue right after a query's `?`, `&` or `;` (whitespace apart) is named
  **url** instead.
- **opaque**: in spellings 1 and 2, a run of 32 or more
  (`AGENT_IMPORT_OPAQUE_RUN_MIN_CHARS`) of `[A-Za-z0-9+=_-]` that is hex
  with a digit and a letter, or has a digit and both letter cases. `/` is
  left out of the run (it joins a path's folders), and spelling 3 is not
  read (it joins ordinary words). A random 32-character base64 key lacks a
  digit or a case about once in 230 tries; hex, never in practice.

An MCP server's dedicated URL is also refused (**url**) when it has
user-info, a query or a fragment, whatever their names, and is unsupported
when it does not parse. A server is refused whole when any of its texts
holds a cue (RV83d's "an MCP server whose env/args hold one is refused
whole").

### What the user sees

- The picker lists a refused entry checked, its detail `… · may hold a
credential (<kind>): copy it yourself`, so the preview always lists it.
- The preview has a section **Not imported: may hold a credential — copy it
  yourself** with one line per entry: its label, kind, tool and scope, and
  the cue's kind in words. Never the value.
- Nothing of a refused entry is planned, written, appended or copied; the
  counts list it under "Not imported".
- The log line: `N entr(ies) may hold a credential and are not imported
(<kinds>)`. Never a label or a value.
- The preview's introduction says so, and that MCP servers' environment and
  header values are masked. Eight new strings and the changed introduction
  are in `en.ts` and all 14 tables, translated; `npm run check:l10n`: 0
  problems.

## False positives

The decision accepts false positives; the cue list was tuned so ordinary
prose mostly passes, without loosening any reported case.

- **200 open-source rule files** (40 each of `CLAUDE.md`, `AGENTS.md`,
  `.cursorrules`, `copilot-instructions.md` and `.cursor/rules/*.mdc`,
  found by GitHub code search on 2026-10-01 and kept only in the lane's
  scratchpad, not in the repository): **25 refused (12.5%)**. Eight of them
  hold a key, a password or a placeholder for one (`OPENAI_API_KEY=sk-...`,
  `password: "123456"`, `"connection_string": "postgresql://user:pass@…"`,
  `HA_TOKEN=your_long_lived_access_token`, real-looking `ClientSecret`
  values and a PEM key). The other 17 are prose or code: `**Auth**: Basic
auth…`, `**Secrets & Security:** …`, `Map format tokens: …`, `const
tokens = …`, `let approxTokens = …`, `const string cacheKey = …`,
  `CAP_TOKENS = 600`, `contains_secrets: true`,
  `rbac.authorization.k8s.io/clusterroles: …` (joined by spelling 3), and
  three whose cue appears only across several lines.
- Before tuning, 35 of the 200 (17.5%) refused. The changes, each kept only
  where no reported case depended on it: `==`/`::` are not separators;
  `authenticate`, `authorized` and `tokenizer` are English, not names;
  `pass` and camelCase `…Key` count only with `=`; a flag's value is not
  another flag; `/` does not join an opaque run; an unknown backslash
  escape is kept (Windows paths).
- **This repository's corpus**, the test `refuses no more ordinary rules
documents than the stated budget` in `test/unit/importCredentials.test.ts`:
  12 rules-like files whole, `README.md` section by section (28) and 12
  typical rule texts written for the test. 4 of 52 refuse (7.7%):
  `AGENTS.md` (`SecretStorage: it is the store`), and three README
  sections: the import's own (it quotes `GITHUB_TOKEN=` and
  `Authorization:`), Troubleshooting (a bold `META_API_KEY` label, then a colon and prose) and
  Screenshots (an image's alt text ending `tokens">` joined by spelling 3
  to `<sub>Subagents:`). The budget is 15%; the 12 written texts must all
  pass.

## Findings

### RV83d #1–#4 (P1): credentials through multi-line values, continuations, joined names, escaped or Unicode names, query whitespace

Closed by the redesign: every input the review quotes is a refusal test.
`test/unit/helpers/credentialLeaks.ts` holds every reported input of RV83,
RV83b, RV83c, RV83d and mr83 (47) and eleven further spellings of the same
classes (a shell-escaped flag, a percent-encoded name, an HTML-entity name,
a Markdown-split name, a zero-width space, full-width letters, a Cyrillic
look-alike, cmd and PowerShell continuations, curl's `-u`, a folded YAML
value): 58 in all. Tests:

- `importCredentials.test.ts`: `refuses %s as text, as separate arguments
and inside a shell argument`, for each of the 58.
- `agentImportCommands.test.ts`: `refuses every reported credential leak in
MCP arguments, hooks, commands and rules`: each input as an MCP argument
  (`sh -c`), a hook command, a personal command and a Cursor rules file
  (232 entries); every one is listed in the credential section, nothing is
  copied, no personal file is written, `AGENTS.md` holds exactly the
  ordinary rules file, and no secret is in the preview, the picker, the
  clipboard, the notifications or the log.
- `refuses an MCP server and rules whose URL query holds a credential…`
  (RV83's original input) and `refuses every entry holding a secret…` check
  the picker detail, the preview lines, the counts and the log line.
- `agentImport.test.ts`: `refuses each one whole, names its cue and keeps
none of its text` covers each kind at the scan, a hidden server name and
  a hidden hook matcher.
- `importConvert.test.ts`: servers with a credential flag, env name, env
  value token, command, `Authorization` header, URL query, user-info or
  fragment are refused whole with their cue; hooks with a credential in the
  matcher or status line too.

### RV83d #5 (P1): imports attributed to a running turn

`asUserEdit` is still on main, so every successful publication is noted the
same way: `ImportApplyOptions.notePublished` runs after a create or append
returns written, inside the lease; the host wires it to
`checkpoints.noteUserSave` (`src/extension.ts`), as `asUserEdit` does for

the order (`write`, then `user`) and `notes only a file the import actually
wrote as the user’s`.

### RV83d #6 (P2): the folder change during the final root lookup

`isRootCurrent` rechecks, after its awaited `identifyRoot`, that the
window's first folder is still the one it identified; the clipboard's
synchronous guard refuses a hooks copy unless the window's first folder is
still the planned one (`isLiveRoot`). Tests: `copies no project hooks when
the folder changes during the final identity lookup` (the reviewer's
third-lookup injection), `copies no project hooks when the folder changes
during the final path check` (the last await before the guard), `writes no
project file when the folder changes during the identity lookup before
it`.

### RV83d #7 (P2): masking cut the generated YAML's closing quote

Moot: nothing is masked after serializing. A description with a cue is
refused at the scan (`agentImport.test.ts`, `keys` command:
`description: token=…`). `importConvert.test.ts` `writes front matter the
skill reader takes, its scalars closed` parses an ordinary generated
`SKILL.md` with the production reader (`parseSkillFile`) and checks every
scalar is a closed YAML single-quoted scalar. The installed `yaml` 2.9.1
reader is not a listed dependency (knip's unlisted-dependency gate fails an

parses (`{"name":"review","description":"Keyboard shortcuts for reviewing
code","argument-hint":"[file]"}`), and round 3's output is rejected with
`Missing closing 'quote`.

### RV83d #8 (P2): `fenced` overflowed on 128,000 backtick runs

`fenced` now finds the longest run in a `for … of` loop with `Math.max` of
two values (M84 makes the same change; the text is
`let longest = 0` / `for (const [run] of text.matchAll(BACKTICK_RUN))` /
`longest = Math.max(longest, run.length)`). Tests: `transcriptMarkdown.test.ts`
`fences a text of 128,000 backtick runs, longer than its longest`, and
`agentImportCommands.test.ts` `previews an admitted MCP argument of 128,000
backtick runs`.

## Linear time

`credentialCue` builds each spelling with linear replaces and scans each
with one pass over its name runs (a separator check reads only the
whitespace after its own run), one token-shape search, one user-info search
and one pass over opaque runs. `importCredentials.test.ts` `reads %s in
linear time` runs 19 adversarial inputs (escapes without digits, percent
marks, entity starts, continuations, one name of many credential words,
many credential words without values, flags without values, quote marks or
spaces after a credential word, query marks, URL marks, JWT near-misses, a
URL path of dots, an unterminated key header, `basic` words, `-u` flags,
colons after short names, `key` words, long runs without digits) at 64,000,
128,000 and 512,000 characters, each within 1 s per 64,000 characters.

The slowest at 512,000 characters on Kubuntu (2026-10-02): backslash
escapes without digits 221 ms, `-u` flags 206 ms, percent marks 182 ms,
colons after short names 161 ms, `key` words 145 ms, URL marks 131 ms.
