## CM971-R3 — licence-text matcher redesign (2026-10-10, host lane, macmini tests)

Third review round (RVCM971B: 1 P1 + 7 P2 + 1 P3, the same class as
RVCM971), so the lead ruled a redesign rather than another patch. Branch
`c/m97-1-r3` from `8e74f2d23`. Host work: one single-project `tsc`,

### What the matcher is now

- **SPDX templates, SPDX guidelines.** `src/core/legal/licenseTemplates.ts`
  parses the official `<<var>>`/`<<beginOptional>>` templates and walks
  them against the text (backtracking over a compiled program, dead states
  memoized). Equivalences are exactly the guidelines': case, whitespace,
  quote and dash styles, `©`/`(c)`, `http`/`https`, comment markers and
  comment-box edges, separator lines, and the SPDX equivalent-words list.
  Every other fixed token must be present in order, and nothing may follow
  the template's end (text after the end is a difference, never
  "extraneous").
- **Variables hold only what they stand for.** A variable must match its
  SPDX `match` pattern _and_ its role: `copyright` variables accept only
  copyright-notice lines (markers, years, a name-shaped holder, contacts,
  "All rights reserved"); `bullet` variables only list markers; every
  other open wildcard only a name (capitalised words, initials, numbers,
  contacts, a lone handle, a closed set of particles; a period only after
  an initial or a corporate abbreviation or closing the name). A
  terminator (`. ! ? ;` and their CJK/Arabic/Devanagari forms) inside a
  name, lowercase prose, a script without letter case, a capitalised word
  after an abbreviation, or three capitals-only words in a row outside the
  variable's own wording is never that shape. Closed alternations
  (`Software|Materials`) need only their pattern. The old copyright-line
  predicates, condition-word list, hashes and phrase lists are gone.
- **Exact or differs.** Exact needs a full alignment; only templates whose
  required words are all present are walked (a necessary condition).
  Otherwise the closest template (Dice share ≥ 0.8) is reported as
  "differs from the SPDX `<id>` template at “span”, where the template
  continues “…”" (m200) or "“span” is not part of it" (m201), with the
  span as the finding's excerpt. Licence files that stay heuristic keep
  m084 and the m110 human-review reason.
- **GPL variant from the project's grant only.** Template keys for the GPL
  family are the version stem. `-only`/`-or-later` comes from manifests,
  the README declaration, project source `SPDX-License-Identifier` headers
  (`projectHeaderGrants`), GNU "any later version" notices in those
  headers, and a trailing `+` (`grantIdOf`); with no grant it stays
  `-only`. Header coverage accepts the project's own variant for a bare or
  `+` header.
- **Inexactness survives everywhere.** The dependency loop checks every
  licence file a dependency carries or names (`licenseTextFile` from the
  Cargo `license-file` and Go vendored readers, `SEE LICENSE IN`, Python
  `License-File:`); vendored licences below the root that are not exact
  add m117/m199 and `requiresReview` (→ m110).
- **Fail closed on data.** `readPinnedLegalData` (the only new file read,
  in `workspace.ts`, read-only, no final link, bounded) loads each pinned
  file; its SHA-256 must equal `provenance.json` or the template is left
  out and named (m205, plus m110).
- **Freshness per bundle, from the build itself.**
  `scripts/lib/compiledSources.mjs` is the last plugin of every production
  bundle: it reads each source once, records the SHA-256 of those bytes and
  hands the same bytes to esbuild; transforming plugins read through
  `readCompiledSource` so their inputs are recorded the same way; a file
  read twice with different bytes in one run is recorded as conflicting
  and gets no hash. `dist/meta-hashes/<bundle>.json` is record version 2;
  outputs are hashed from the files esbuild just wrote, and an output
  whose size disagrees with the metafile is left unrecorded. The scanner
  keeps each bundle's record separate (`BundleEvidence`): every listed
  input must match its hash (m206), every listed output must exist and
  match (m204), a bundle without inputs or outputs proves nothing (m035),
  two records disagreeing about one input fail (m203), and an absolute or
  parent-escaping input or output is named (m202) instead of being treated
  as a constant. Version-1 records (hashes re-read after the build) are
  refused. The bounded scan view now forwards the native reader's
  admitted-byte digests, so a byte-order-marked input hashes the same
  bytes as the build.

### Scan scope (lead ruling 2026-10-10): a workspace scan judges what it distributes

**Decision (lead, 2026-10-10)**, recorded in PLAN M97: this is a product
rule for every user's workspace, not a special case for this repository.

1. **Order and budget.** `createLegalSnapshot` admits, before the walk and
   outside the directory-entry budget: `dist/meta/*.json`,
   `dist/meta-hashes/*.json`, every workspace file a metafile lists, and the
   `package.json`, licence, copying and notice files of each installed
   package a bundle takes files from. The walk then skips `.git` and
   `node_modules` as expected (no incomplete reason) and the budget applies
   to the rest. Distribution comes from the build records (or the package
   files list when there are none); an input that contributes no bytes to
   any output (`bytesInOutput: 0`) does not ship.
2. **Shipped vs not.** With distribution known, the readers, project
   licence, header and attribution checks see the distributed workspace:
   root files, shipped files and the shipped packages' admitted files. A
   dependency's licence texts and declarations count only when it ships;
   otherwise its declaration findings are advice and a differing or
   unrecognized text is named in one informational line (m207). A
   dependency the bundles never took in does not ship (with build records,
   production scope no longer makes it "unknown"). Root files the package
   carries beside its bundles (a notice file not excluded by
   `.vscodeignore`) count as shipped notices. The npm reader's aggregate
   "lock entries without licence" note is gone: each shipping dependency
   without licence data is named by the dependency reader (m022). The
   dependency bound is its own (`LEGAL_DEPENDENCIES_MAX` 10,000) and the
   text budget covers a distributed workspace's sources (64 MB).
3. **Expected entries.** `.git` and `node_modules` (including `.bin`
   links) are skipped and documented, never reasons; notes from inside
   dependencies that do not ship are never produced because those trees are
   not walked. The unused `.git` reason (m141) and npm note (m174) strings
   are removed.
4. **SPDX guidelines.** Quote marks of every style and Markdown emphasis
   (`*AS IS*`, `_…_`) carry no terms; a list item's bullet or number at a
   line start is ignored; titles and copyright-notice lines outside the
   template's slot (up to three at either edge) are ignored when they pass
   the notice check; an optional appendix may be given from its applied
   notice (`Copyright … Licensed under the Apache License …` after `END OF
TERMS AND CONDITIONS`); a notice may name the work first (`Portions
Copyright …`, `pngjs original work Copyright …`: closed lead-in words plus
