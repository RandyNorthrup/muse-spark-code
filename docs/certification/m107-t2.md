## Native identity and exited state

universal binary, package route and ad-hoc signature already ship. No sibling
binary or dependency is needed. `proc-identity <pid…>` dispatches before the
responsibility relay, audio, microphone or Speech setup. It reads only

## Registered action API and LSP entry points

The additive surface is:

```ts
registry.signal(ticket, member, signal: 'SIGTERM' | 'SIGKILL'):
  Promise<'done' | 'gone' | 'identity-changed' | 'refused'>
registry.kill(ticket, signal = 'SIGKILL'):
  Promise<{ status: ResourceActionResult;
    members: readonly { identity: ResourceProcessIdentity;
      result: ResourceActionResult }[] }>
```

Construct `ResourceTreeRegistry` with `LinuxResourceTreeReader(deps)`,
`MacResourceTreeReader({ helperPath })`, or
`WindowsResourceTreeReader({ assemblyPath, systemRoot })`. The Mac path is
its trusted host's installed `muse-dictate`; the Windows path is M27's
source-digested compiled assembly. Acquire `reader.identity(child.pid)` at
trusted launch and `registry.register(ticket)` before admitting actions.
LSP calls `registry.signal(ticket, exactMember, 'SIGTERM')` for cancellation
and `registry.kill(ticket)` for forced tree stop. Refresh `registry.members`
while parent edges exist to enroll detached descendants. Retire with
`registry.unregister(ticket)` when the whole tree completes, not merely when
the root exits. Lane A can continue using the unchanged `contains` seam;
its priority/CPU controls are untouched.

Signal rejects forged/unregistered/retired tickets, the harness PID, invalid
identities and unsupported ports. It supplies canonical copies and a current
registration-epoch callback. POSIX reads the native identity once more and
invokes synchronous kill directly, without an intervening await. Windows
opens the named job, holds one process handle, checks creation/live state/job
membership and calls `TerminateProcess` on that handle, closing both handles
in finally. SIGTERM and SIGKILL both terminate on Windows. No T2 action uses
an unchecked PID, negative PID/group kill, or `TerminateJobObject`.

Tree kill validates the entire fresh identity snapshot before sending any
signal, visits the original root last and returns each member's result.
Unknown enumeration refuses. Previously observed departed identities remain
in the action snapshot, allowing honest gone/changed results rather than
silently omitting them. A successful send means **admitted signal**, not an
exit receipt. Per-member refusal dominates the summary, then changed birth,
then done, otherwise gone. Consumers must retain and interpret the detailed
results; the existing `members` empty-array API is not an exit proof.

## Enrollment and native lifecycle receipts

Linux group and Darwin scans walk the full numeric parent table. New detached
members need a fresh parent birth and a fresh matching child-parent edge;
recorded exact births survive setsid and reparenting. Recycled PIDs never
inherit old authority: new birth enrollment requires a proven current ancestry
edge (or native cgroup/job containment). A live recorded descendant can witness
a tree whose original root PID now names a different birth, including a proven
descendant reusing that PID. It cannot confer authority on unrelated processes
in the reused old group. CPU history retains exited members' observed totals.
Inaccessible Mac rows that could belong to the tree make kill enumeration
unknown. Registration independently proves the root through targeted native
inspection even when global accounting is unavailable; its initial descendant
scan remains optional, and unknown tree enumeration still refuses kill.

The production signed Swift helper is built in each native suite's private
fixture using the unchanged universal build/package route. This removes reliance
on preexisting ignored binaries. Setup uses the brief's 120,000 ms native
build deadline; the newly added setup initially exceeded Vitest's default
10-second hook deadline once. No existing test timeout/config was changed. Native Mac tests use only local processes:

- unreaped child zombie, plus an enrolled root subsequently held zombie;
- 32 sequential fast process births and stale identity action attempts;
- setsid child, its setsid grandchild, intermediate exit, root exit, retained
  grandchild membership and verified tree kill.

The PID churn test attempts reuse but did not force/observe actual numerical
PID reuse on this Mac. Deterministic seams exercise reused births/root PIDs.
No unobserved double fork is claimed: a child that forks and reparents wholly
between observations has no recoverable user-space ancestry. Native cgroups
and Windows jobs can supply containment instead. OS-wide snapshots are not
atomic; accounting remains a lower bound. Native root/zombie tests initially
encountered refused global snapshots: root registration now uses a targeted
native proof, and the zombie kill test waits for a fresh available snapshot
within a bounded poll. Portable tests separately require unknown snapshots
to refuse, and no refusal is treated as completion.

Linux has no existing pidfd binding. This brief permits adjacent final `/proc`
read and synchronous kill, so no new native dependency was introduced. Both
POSIX implementations have a residual read-to-signal race, unlike Windows'
same-handle action. Windows signal already dispatched cannot be revoked by a
later JavaScript unregister; its actual native result is preserved.
