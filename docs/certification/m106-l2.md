## Repeat guard and cancellation

The guard canonicalizes JSON object keys and whitespace, preserves array
order and tracks consecutive complete results. It resets after a changed
argument/result, another call, a new user turn or steering. Invalid/deep
arguments still reach the tool's normal validation path. Identical calls
within one batch are serial, so a later call cannot outrun the guard.

The third proven unchanged call returns lane 0's fixed English model note
without executing the tool. The fourth is also paired with that note and
ends the turn with the installed-language stuck notice. A text read's proof
uses the exact confined source's fresh bytes and canonical path; changed
proofs or denied paths take the normal admission path instead.
Both proof operations failing leaves legitimate repeats runnable.

**D86.5 interpretation / open owner question for PLAN §3.** Two identical
past results cannot prove an arbitrary shell, MCP, clock-dependent query,
paid call or hook-dependent read's next result. Blind pre-execution
suppression would violate the owner's invariant that a changed result is
never blocked. An optional clarification was requested; no answer arrived,
so the conservative interpretation was used. Native successful text reads
without hooks have the fresh proof above. Other tools keep running unless
the trusted host supplies ModelApiHostDeps.repeatResultWitness: observed
binds a witness to the actual complete result, current freshly proves that
same result. Untrusted server hints never supply this proof. This is an
explicit interface with an injected dependency, not a fake implementation.
The lead must resolve/record the general-tool interpretation; this lane does
not claim blanket pre-execution suppression for unprovable results.

Cancelled parallel results are discarded before replay/media settlement,
and their speculative seen-file fingerprints are forgotten. The test then
attempts an overwrite and proves that a fresh read is still required.
Foreground shell cancellation retains the existing message and lifecycle.
The scheduler passes its execution kind explicitly to settlement; a timing
fake and red drills prove this flag reaches the real loop.
