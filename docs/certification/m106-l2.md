## Scheduling and output

- Only the fixed native read set and the host-owned diagnostics reader may
  overlap, at most four. No server readOnlyHint authorizes concurrency.
  PreToolUse is serial; execution overlaps; media admission, replay and
  PostToolUse settle in call order. Asking/blocked reads, edits, shell and
  arbitrary MCP tools are barriers. then_run uses its existing serial path.
- Both generated scheduler batches and a real fake-HTTP multi-read turn with
  observation packing produce serial replay/request bytes. Existing M91/M98
  request goldens are retained; no rebaseline or live M75 pair is needed.
- The selected model's injected output.maxTokens is fixed per model in a
  session. Budget reservation clamps that cap, including limits below the
  legacy cap. Missing capability binding retains 32,768, without inferring
  support from a model name.
- max_output_tokens incomplete replies get one continuation, then the
  translated notice. Partial text stays in replay; every function call in
  an incomplete reply receives an error and never executes. Other reasons
  do not continue. Continuation is admitted/reserved through the ordinary
  request path, with an explicit off arm.

The full host regression suite exposed the legacy foreground-shell Stop
message being overwritten at settlement. Parallel read cancellation is now
separate from serial shell settlement, preserving the original shell words.
The first stop-tail drill revealed only the serial barrier was tested; a
read-group stop case was added, and that same mutation then failed.
