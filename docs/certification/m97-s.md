## Review and scope

Kept the pinned SPDX identifier/exception artifacts and provenance, expression
parser, injected snapshot API, project/header readers, all eight ecosystem
readers, distribution/compatibility checks and local fixtures. Removed the
broad unused public re-export list. The public entry exposes the scanner,
bounded workspace admission, versions/provenance and snapshot/error types.
No other lane's production files or gate configuration were changed.

The recovered SPDX changes normalized whitespace. All four identifier arrays
match the installed pinned packages exactly, including their upstream hashes.
Provenance retains the upstream SHA-256 and records normalized-file SHA-256
and modification notice. No matching corpus/license text was copied.

Regression fixtures first failed in all twelve cases: nested npm versions and
conflicts; unsupported npm locks; Python lock resolution/version mismatch;
Cargo unresolved ranges/path ownership; Go vendored transitives; Gradle
transitives/static gaps; NuGet transitives/project separation; Composer dev
transitives/conflicts; standalone gemspec/static gaps; nested SPDX choices and
WITH; missing copyright suppressing SPDX conflict; path-count/path-size bounds.
Each was corrected without running the corresponding package manager/build.

The initial no-capability assertion checked its diagnostic label, not source.
It now checks executable source and imports. String/comment/regex evidence is
data; template interpolations remain executable. The filesystem adapter is
explicitly read-only and gets separate identity, link, byte-budget and
cancellation tests. Enumeration and bytes are bounded using lane-0 limits;
no symlink is admitted, and each read verifies its sampled native identity.
