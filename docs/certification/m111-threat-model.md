- **Drills run real code only.** Where a drill says "fake" (a fake bus, a
  fake action, a logging DNS fake, a fake device), it names a disposable
  test input inside a disposable VM or QEMU run — a test bus-policy
  drop-in, a canary unit, a logging resolver, a canary device endpoint —
  exercised against the real helper, shell and installer code. It never
  licenses a stand-in for our own modules, a provider, the CLI, the editor
  API or a store; a lane whose drill cannot run that way withdraws the
  claim instead of keeping it on a stand-in.
- **Numeric bounds are person-settable safety defaults.** The rate and
  resource values (D46, D83, D95) keep Stop, Lock and the safety services
  alive under a hostile `run`. Implementation lanes expose the
  machine-resource values as settings the person can change (the standing
  limits rule: only a provider's limit or a value the person set binds),
  keeping the safety reservations in D95; changing a shipped default still
  needs the lead, as D95 states.

RVM111TM2) and accepted as the baseline before any greeter, lock, portal,

## The threat table

Lanes: IG admin access, ID installer daemon, IA unattended install, IU
installer flow, IB boot menu and live medium, IM images, SS session and
recovery, CP compositor, SH1 bar, SH2 overlays and services, SY system
bridge, PT portals and AppArmor, WB workbench, WP preview tabs, WN sharing,
WG agents' preview tools, AX accessibility, OB observability, PE companion,
QA test rig, GT GUI or TUI. "Drill" is a test to be written; "break" is what
removing the guard must show (a red test). E*n* and O*n* are the decisions at
the end.

**Drill method (every row).** A guard with independent backstops is tested in
two tiers. Tier 1: a fixture where the guard under test is the only layer
between the probe and its effect; the other layers are deliberately absent
and named in the test; a positive control shows the probe's effect lands
when the guard is removed. Tier 2: the full profile in a QEMU VM, whose
break names the whole mutation set that must be removed to turn it red.
Device drills use a real extra virtio disk or device in the VM, never a
regular file. A string test never stands in for a flow (D52).

### D. The `run` action and the never-allowed list

The never-allowed list (D91.25) cannot be enforced by reading an arbitrary
root argv: `cp`, `tee`, `install`, `find -exec`, `awk 'BEGIN{system()}'`,
`tar --to-command`, `git -c core.pager`, `vim`, `env`, `busybox` and any
interpreter reach the same files. **The list holds for `run` only if `run`
executes in a confined unit whose mount, capability, process and network
limits make the listed paths, devices, identities and processes
unreachable.** An argv check stays as a fast, explainable refusal, never as
the guard. E3: `run` is confined; unrestricted root exists only as the warned
sudo opt-in (D52). Writes are not the only concern: the list also forbids
**reading** the vault's and the Secret Service's files, and root with
`CAP_DAC_OVERRIDE` reads anything that is merely mode 0600, so secrets are
hidden by mount, not by permission.

### E. Persistence (writable `/etc` and `/var`)

`/usr` is verity-protected and changes only by signed bundles (D90.24). The
OS1 base has one root partition holding `/etc` (`os/repart/10-root.conf`,
currently `ReadOnly=yes`) and one `/var` partition, both separate from the
A/B `/usr` slots. The desktop's writable `/etc` (overlay or otherwise), its
reset behaviour and OS4's policy are design work. A slot change switches
`/usr` and may switch the kernel, initrd and UKI with it; it does not revert
`/etc` or `/var`. RAUC does not itself define what `/etc` and `/var` share.
D91.25's "which roll back and reset" holds for factory reset, not for a slot
rollback (O8, E7).

## Accepted risks (the owner's choices)

- **Always allow is the admin default** on the owner's own box (D91.25,
  D89.6's amended exception). An untainted but wrong root action runs. The
  audit shows it; reset may undo it; a slot rollback does not undo `/etc` or
  `/var` (§E).
- **The taint ask stays** for admin actions that follow untrusted content
  (owner, 2026-10-06), including content of unknown provenance (D79, E4).
- **Plain NOPASSWD sudo is an opt-in** under Advanced. It removes every
  guard in this document except sudo's own log, which root can erase (D52).
- **Secure Boot keys are the owner's** and off by default (Q-M110 item 6):
  anyone at the keyboard can boot other media (D38, D56, D66).
- **Same-uid processes can read the Secret Service** (D89.2's label).
- **The keyboard monitor is our plugin** until Hyprland ships it (D63).
- **Electron's Chromium can trail Chrome's security fixes by days** (D57).
- **A compromised node or broker can mint admin requests** until Lock admin,
  through the fixed client only (D16, D76).

Stated limits (not choices, but not solvable here): the mirror cannot prove
that a compromised writer logged everything (D85); a `run` with any internet
egress could reach cloud-relayed devices (D81, O7).
