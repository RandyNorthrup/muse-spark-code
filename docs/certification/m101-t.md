## Golden bytes

- No committed golden pins request text bytes, so turning items off is
  byte-identical by construction: item 8 rides the existing
  `completed`-only path; item 15 leaves `output` elided
  (`wholeShellOutput` is sent only `when packing !== undefined`);
  item 20's schema addition is additive/unread; search caps and read
  offsets touch output, not requests; observation-pack changes touch what
  rides `function_call_output` text, which heuristics never see.
- Fix that changes live bytes (recorded on purpose): `edit_file`'s tool
  definition gains the `edits` array property (description + JSON-schema
  fragment) sent to the model on every backend on every turn. Old bytes:
  `…apply multiple edits (search and replace)</description>` with no
  `edits` property; new bytes: the same plus
  `"edits":{"type":"array","description":"Multiple exact replacements,
applied atomically: either every item replaces its first match or none
of them run."…}`. Additive only: no existing property changed, so the
  cache-stable prefix lane's pinned head is untouched — the integrator's
  full gate confirms.
- `read_file`'s `offset` semantics flip for past-end (2xx→4xx) and `next`
  is new output: both touch tool _output_, never request bytes; rows and
  the visible shell text are unchanged, so no golden re-baseline needed.
