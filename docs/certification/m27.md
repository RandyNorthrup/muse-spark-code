# M27 certification — the tree kill's orphans (PLAN.md D25, M27)

Recorded 2026-09-23 on Windows 11 (Node 24.20.0).

## How it was found

The 0.6.0 release gate failed three times in a row in `toolIo.test.ts`'s
teardown: removing its temporary folder raised `EBUSY` while every test
passed. Retrying the removal for three seconds (M24) did not help, so the
hold was not transient. A run with the tree kill and the shell runner
logging to a file, and the teardown listing the processes created in the
last minutes, showed it:

- the timed-out shell (`Start-Process … ping …; Start-Sleep 30`) was
  spawned at 00:11:50.837, its 500 ms timeout started `taskkill /T /F`;
- `taskkill` reported killing the console host and the shell (00:11:52.090)
  and nothing else;
- a `PING.EXE` whose parent was that shell, created at 00:11:51.928 (during
  the kill), was still running at the teardown, its working directory the
  test folder.

One orphan of an earlier run (a ping from the same test, 16:18) was still
there at 17:00, suspended: PowerShell had been killed between creating it
and letting it run. It was a test process and was ended by hand.

Idle, the same kill never missed (`scratchpad/probe-taskkill-race.mjs`, 29
kill delays from 100 ms to 1.5 s, with and without CPU load, and
`scratchpad/probe-spawn-loop.mjs`, a shell starting pings in a loop); the
parallel coverage run hit it on every kill.

## Built

- `killTree` (`src/host/processTree.ts`) is async. On Windows it waits for
  the shell to exit after `taskkill /T /F`, then reads the process table
  (Windows PowerShell under `%SystemRoot%`, its own `PSModulePath`,
  `Get-CimInstance Win32_Process -Filter 'ParentProcessId=…'`, one row per
  process with its FILETIME creation time) and kills each orphan's tree.
  The next round asks after the orphans' own children, three rounds at
  most; what it cannot do (read the table, kill a process, see an end) it
  logs.
- A child counts only if it was created after the shell started and no
  later than its parent's death as seen here, so a later holder of a dead
  parent's id is never touched, and nor is an earlier one.
- `runCommand` (`src/host/backend/toolIo.ts`) answers a killed command only
  once the kill, sweep included, is done.
- `removeFolder` (`test/unit/helpers/temporaryFolders.ts`) keeps its short
  retries for scanners; its comment no longer claims the hold was
  transient.
