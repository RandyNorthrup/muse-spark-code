## What was built

- **Address rule** (`src/core/browser/browserPolicy.ts`). Loopback is
  `localhost`, 127.0.0.0/8 or `[::1]` as the WHATWG URL parser writes the
  host (`127.1`, `0x7f.0.0.1` and `2130706433` are `127.0.0.1`). A name is
  never looked up: `app.localhost`, `localhost.`, `lvh.me` or a name in
  `/etc/hosts` is beyond loopback until widened. The model's URL must be
  `http:`/`https:` with a plain host (letters, digits, dots and hyphens, or
  an IP address) and no user name or password; anything else is refused
  before any card. The setting's entries obey the same plain-host rule,
  since each also goes into Chrome's proxy bypass list, where `*`, `;` or
  `<` would mean more.
- **Launch** (`browserLaunch.ts`, `BROWSER_LAUNCH_FLAGS`). The system Chrome
  or Edge from its well-known places, then absolute PATH entries only (D24).
  `--headless --remote-debugging-pipe`, a fresh `--user-data-dir` under the
  OS temporary folder, `--password-store=basic --use-mock-keychain` (a new
  profile would otherwise ask the user's keyring or keychain), no
  extensions, sync, updates or background networking,
  `--proxy-server=http://127.0.0.1:9` with
  `--proxy-bypass-list=<-loopback>;localhost;127.0.0.1/8;[::1];<allowed hosts>`,
  and `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`. No flag
  names a port.
- **Run** (`browserRun.ts`, `cdpPipe.ts`). `Fetch.enable` on the browser's
  own session, before the page exists, pauses every request of every
  target; each is continued only if http(s)/ws(s) to loopback or an allowed
  host, else failed with `BlockedByClient` and listed as blocked. On the
  page session: console errors and exceptions, failed requests (network
  errors, and HTTP 400 or more), WebSockets beyond loopback listed as
  blocked. A response, a redirect or a WebSocket handshake from beyond the
  allowed hosts stops the check at once with nothing from the page
  (`leaked`). Up to 8 click/type steps, each `Runtime.evaluate` of a fixed
  script with the selector and text as JSON data. Screenshot checked as a
  PNG within `MAX_IMAGE_BYTES` and measured. Bounds: 60 s per check, 15 s
  for the load (then the page as it stands), 1 s after each step, 3 s for
  the browser to exit when asked and again when killed; 20 entries of each
  kind, 500 characters each; 32 MiB per CDP message.
- **Lifetime.** A check that ends by itself sends `Browser.close`, then
  kills the browser if it is still there; a deadline, a Stop, a leak or a
  dead pipe kills it at once with everything it started
  (`processTree.killTree`: its process group on POSIX, taskkill and the
  orphan sweep on Windows). The window closing aborts every check under way
  (`BrowserChecks.dispose`). The profile is removed afterwards (with retries
  for Windows' held files); a profile that cannot be removed is logged.
- **Model API** (`browser_check`). Offered in a trusted workspace when the
  window has the check, not in a side chat. A `network` tool judged per
  host (`host:port`): Manual and Auto ask, "Always allow in this session"
  covers that host, Bypass runs, Plan refuses, Restricted Mode refuses. A
  host beyond loopback and the setting gets a card (subject
  `browserCheckWiden`) even in Bypass unless the user chose "Always allow"
  for it on one in this session (`PermissionEngine.isAllowedForSession`).
  Trust and the mode are asked again after the card and after the check.
  The screenshot travels like `read_file`'s images (D47): a user message
  after the round, lead `The screenshot the browser check took of <url>:`;
  `VisibleFile` now carries its own lead and not-delivered lines.
- **Muse Code** (`mcp__ide__browserCheck`). Listed only while the workspace
  is trusted and `museSpark.sandboxNetwork` is not `restricted`; open-world,
  not read-only; the extension's modal before every call (one per URL at a
  time), naming a host beyond loopback, which only then is widened for that
  check; the offer checked again after the modal and after the run; Muse
  Code's stop aborts the check. Text only (AGENTS.md rule 13).
- **Bundle.** `dist/browserCheck.js` (`browserCheckEntry.ts`), loaded on the
  first check through the checkpoint store's loader pattern; the split gate
  keeps the runner, pipe, launch and process code out of
  `dist/extension.js`, `dist/modelApi.js` and `dist/acp.js`.

## Residual risk

- An administrator's proxy policy outranks the command line: there a
  WebSocket or preconnect beyond loopback could leave through that proxy.
  HTTP requests stay failed by Fetch, and a WebSocket answer from beyond
  stops the check before anything from the page is returned.
- Console errors and failed requests of frames in other processes and of
  workers are not listed (their requests are still gated and blocked ones
  listed).
- A window that dies mid-check leaves its profile folder in the OS
  temporary folder; the browser exits with its pipe.
- Muse Code's image content waits for a live capture (AGENTS.md rule 13).
