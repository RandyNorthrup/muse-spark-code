# M91 lane P: foreign hook-format adapters, round 3 (contract-first redesign)

## Input shape for lane I (read first)

No breaking change. Every round-2 entry point keeps its inputs:
`build<Vendor>Stdin(event, payload, options?)` and
`parse<Vendor>Result(event, exitCode, stdout, stderr, options?)`. Additions:

- A generic entry for the import record:
  `buildForeignStdin(format, museEvent, payload, options)` and
  `parseForeignResult(format, museEvent, exitCode, stdout, stderr, options)`,
  with `options = { sourceEvent, flavor, failClosed, workspaceRoot, platform,
pathPattern, input }`. `sourceEvent` is the vendor event exactly as the
  imported config spelled it (Cursor `beforeShellExecution`, Copilot
  `preToolUse` versus `PreToolUse`, Kiro `PostFileSave`). `flavor` is `copilot`
  (default) or `vscode` for Copilot. Kiro's `trigger` option is kept as an alias
  of `sourceEvent`.
- The parse side now takes `options.input`, the Muse payload the answer belongs
  to. Two documented rules need it: Cursor `subagentStop` consumes
  `followup_message` only when `status` is `completed` (CH:1038), and Cursor
  `updated_mcp_tool_output` applies to MCP tools only (CH:919). Without
  `input`, neither is applied (the conservative outcome).
- A stdin refusal from a blocking row includes `blockOperation: true`. Lane W
  must refuse the guarded operation before execution; treating this as a hook
  failure and executing anyway is forbidden. Gemini's supported native inputs
  are shell command/description, read path/range, write path/content (saved
  example), and pattern-only search. MCP objects stay unchanged. Uncaptured
  edit arguments and incompatible recursive glob calls are refused.
- `confineHookCwd(cwd, workspaceRoot, platform)` is exported for lane W/I: the
  hook DEFINITION's relative `cwd` (vsc/hooks-reference.md:61), confined
  exactly as round 2 did.
- `ForeignHookAnswer` extends `HookAnswer` with `allowedToolNames` (Gemini
  BeforeToolSelection) and `replacement` (`{ target: 'toolResult' |
'subagentResponse', value }`, a documented output replacement W applies
  before packing, D70).

## Why round 3 is a redesign

RVM91P found 16 defects and RVM91P2 found 9 more after a module-per-vendor
rework. By the owner's rule a third round redesigns. Each vendor contract is now
a typed declarative table under `hookFormats/contracts/` (cursor, copilot with
its `vscode` rows in vscode.ts, windsurf, gemini, kiro). Every row is one vendor
event: Muse event, vendor name and aliases, flavor, `default` or `explicit`
selection, the Muse tool classes it translates, a vendor tool-name map, stdin
field builders (named transforms in transforms.ts), and a result spec (exit-code
routing, failClosed, stdout mode, strict zod schema, and a rule list: veto, ask,
context, message, updatedInput, replacement). Every row cites its saved source
(`cite.input`, `cite.output`). `engine.ts` is the only interpreter. Vendor code
the table cannot express is limited to three named, documented functions: Kiro's
bounded path scope (`gate`), Gemini's tool-selection restriction (`custom`), and
the Windsurf/Cursor `editsArray` transform.

## Engine invariants (property suite over every row)

`test/unit/hookFormatsContracts.test.ts` runs each invariant over all 83 rows (cursor 18, copilot 24 CLI + 8 vscode, windsurf 11, gemini 11, kiro 11):

1. Every row builds from a complete payload, emits its required fields and
   cites a saved source.
2. Rows are unique; default rows told apart only by tool class share one result
   spec, so a parse without the tool cannot pick a weaker rule.
3. Each required field, when missing, refuses the build (nothing is guessed).
4. Every veto rule blocks with an unsupported sibling field, with and without
   failClosed: a documented deny never becomes failed or allow.
5. Every block exit code (and Gemini's >= 2) blocks.
6. No row, for exits 0/1/2/3/null and allow/ask/garbage outputs, produces
   `approvalDecision` or `permissionDecision` allow.
7. failClosed upgrades failures exactly on rows that declare it and changes
   nothing elsewhere; in a vendor that honours it, every blocking row declares it.
8. Schema and type errors follow the row (block, fail or ignore); Copilot's
   unparseable output and Gemini's plain text are lenient as captured/documented.
9. No adapter source constructs a RegExp at run time (Kiro uses the bounded
   matcher; the child-deadline test proves `^(a+)+$`), and 1 MiB outputs parse
   in bounded time on every row.
10. Every absolute-path and cwd field refuses drive-relative, `C:`, UNC, device
    and drive-less rooted Windows forms; contained-cwd fields refuse a cwd
    outside the workspace.

`hookFormatsFixtures.test.ts`: every documented event is a row or refused on
purpose (Cursor subagentStart, Tab hooks, Copilot userPromptTransformed, Windsurf
transcript variant); every emitted stdin key is one the source shows, with the
documented JSON type; all 38 JSON doc outputs parse to the documented answer;
every captured Gemini event has a row. Every Gemini JSON capture is checked,
including exact nested tool arguments for translated tools; incompatible
list_directory/glob calls explicitly refuse with `blockOperation: true`.

## What is proven, and what is not

Proven here, by fake-only unit suites on a rig: emitted top-level keys and JSON
types against saved examples/captures, documented output answers, and the
engine invariants over every row. The expanded Gemini checks compare supported
nested tool inputs exactly with each capture and assert explicit refusal for
incompatible tools. These checks do not certify every vendor's nested argument
schema or arbitrary data-dependent guard. The saved Gemini filter-tools.js runs
verbatim; the secret-scanner test reads its selectors/expression from the saved
Bash script (the separate verbatim execution receipt is below).

Not proven here (lane W, the lead's integration gates):

- Dispatcher wiring: admission of imported commands, passing `sourceEvent`,
  `flavor`, `failClosed`, `workspaceRoot` and `input`, applying `replacement`
  before ObservationPack packing, admitting `allowedToolNames` at call time
  (never by editing the tool list), approval-card display, request-byte golden
  tests with hooks off.
- Timeout versus crash: the parser sees `exitCode: null` for both and treats it
  as a crash. Copilot says timeouts always fail open (C:854); W must route a
  timeout without the fail-closed crash rule.
- Physical containment: cwd and path checks are lexical; W realpath-confines
  links and junctions before spawning.
- Gemini model events need Gemini's own `llm_request`/`llm_response` objects
  (captured shape: `captured/gemini/BeforeModel.json`, `AfterModel*.json`).
  Muse's bounded summaries are refused; W decides whether to build that shape.
- Native Windows dispatch: win32 path semantics are tested through the explicit
  `platform: 'win32'` API on Linux, not on a Windows host.
