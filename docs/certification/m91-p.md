## What was built

One adapter per foreign format — gemini, cursor, copilot (CLI/cloud and VS
Code payloads), windsurf, kiro — each translating our hook event + payload
into that agent's documented stdin shape, and mapping its stdout/exit code
back onto the existing `HookAnswer` type (`hooks.ts`, the M51 contract).
Pure module, no I/O: the caller runs the foreign command under the hook
limits and feeds the result back into the parse function.

Contract source: `docs/certification/m91-research.md` (the per-format rows:
event names, tool maps, exit codes, decision fields, timeouts in ms vs s),
corroborated against each vendor's current hooks documentation before
writing. Per the round 2 lead decision the vendor docs stand in for a wire
capture. Guard rules, exactly as specified:

- Cursor: invalid JSON from permission hooks blocks (even without
  `failClosed`); a `failClosed` entry blocks on crash, non-zero exit or
  missing JSON; exit 2 denies; `ask` forces a card; `followup_message` on
  Stop/SubagentStop blocks.
- Copilot: preToolUse/permissionRequest errors (non-zero exit, crash,
  invalid JSON) deny; `cwd` sent only relative and confined to the
  workspace; `env` always refused; `userPromptTransformed` refused.
- Kiro: only exit 2 blocks; success stdout is injected as bounded context;
  file triggers apply their path regex inside the adapter before running
  (skip when outside scope); Manual triggers and agent actions refused
  (agent actions become prompt/agent handlers in lane H).
- Gemini: BeforeModel/AfterModel refused (their fields modify the
  request/response); block and observation kept; timeouts convert ms to s,
  rounded up, capped at 600 (`geminiTimeoutMsToSeconds`, for lane I).
- Windsurf: exit codes only (stdout ignored); exit 2 blocks on pre events
  and fails the WorktreeCreate attempt; anything else fails open;
  `_with_transcript` refused.
- Everywhere: an adapter parse failure is a failure, never allow; a foreign
  "allow" maps to completed with no `approvalDecision` and no
  `permissionDecision` — it never skips an approval card.

Kept events per format are listed in the module header. Refused concepts
stay refused with a reason (Gemini model events, Cursor subagentStart/Tab/
workspaceOpen, Copilot userPromptTransformed, Kiro Manual, unknown tools or
missing required stdin fields).

## Red drills

Both broke exactly one guard, failed exactly the intended tests, and were
restored byte-exact: the SHA-256 of each file before the drill equalled the
SHA-256 after its restore (verified at the time; later lint/type edits
changed both files again, followed by a final green run).

1. Cursor invalid JSON fails open: returned `{ status: 'completed' }` for
   invalid JSON on PreToolUse. Result: 1 failed, 67 passed (the
   "blocks on invalid JSON from permission hooks" test).
2. Allow skips the card: returned `approvalDecision: 'allow'` on Gemini
   approve. Result: 1 failed, 67 passed (the "never turns approve into an
   approval grant" test).

## Open questions (for the lead, not decided here)

- Kiro CLI documents that any non-2 exit blocks the tool, while the lane
  contract says only exit 2 blocks (Kiro IDE triggers). The adapter follows
  the lane contract; flag if CLI-sourced hooks need the stricter rule.
- Copilot mirrors document timeouts as fail-open while preToolUse errors
  are fail-closed; timeouts never reach the adapter (dispatch handles them),
  so lane W should confirm what a Copilot preToolUse timeout does.
- `AdapterEvent` (Muse + extension events) is exported from `hookFormats.ts`
  for the build/parse signatures; lane E may want to own that union name
  long-term.
- No new constants or strings were needed: reasons follow the inline
  technical-reason precedent in `hooks.ts`, and bounds reuse
  `HOOK_TOOL_OUTPUT_PREVIEW_CHARS`, `HOOK_MATCHER_VALUE_MAX_CHARS`,
  `HOOK_MAX_TIMEOUT_SECONDS` and `MILLISECONDS_PER_SECOND`.
