### Finding 1: an English refusal in a localized line

Three sites gave a refused command `MODEL_TEXT.agentToolNotOffered` as its
`detail`. Where that detail is shown decides the fix:

- **`then_run` (no shell tool).** The line under the edit is
  `thenRunOutcomeText`, built from `UI_TEXT`, which appends `detail`
  verbatim. With the German table installed it read the German "not run:
  refused" followed by the English sentence. Real. The skipped outcome
  now carries `visibleDetail: UI_TEXT.agentToolNotOffered` for the row; the
  model's text still uses `detail` (`MODEL_TEXT`). A hook's or the user's
  own words have no `visibleDetail` and are shown as they are.
- **Check edits / Run checks rows.** The detail reaches the row's body
  (`visibleOutput`, which `VerifyBody` shows as "the check's output, as the
  model read it") and `verifySummary.checks[].detail`. Every sentence of

  `checkNotRun`, `checkSkipRefused`, `verifyAccessRefused`), and README's
  "What stays in English" lists text sent to the model. The localized part

  no UI or export renders a check's `detail`. Putting `UI_TEXT` there would
  put the user's language into the model's note, so these sites keep

  lines are translated. `runVerifyCommand`'s own guard cannot be reached

### S2: spawn admission is one ordered pipeline (findings 2 and 4)

Finding 2: an exact retry (same role, objective, agent and `command_id`) ran
the catalogue and tool admission first, so a retry after image generation
was turned off failed although its child existed. Finding 4: trust withdrawn
or a confidential workspace turned on during the contributor question still
reached the paid-use popup before the refusal.

`decideAndRunSpawn` owns the order:

1. the mode (`verdictWithHook`; Plan refuses a retry too), then
   `existingSpawn`: an exact retry returns the existing child's id and state;
   another task under the id is refused;
2. `admitNewSpawn`, which awaits nothing: worktree isolation, the
   64-child limit, `spawnAgentOf` (Restricted Mode, the catalogue),
   `agentToolAllowlist`, then `childTaskGate` (paid subagents, a
   budget-limited goal, the price, a contributor model in a confidential
   workspace);
3. `consentToChildTask`: `newChildGrant` (the key's read), then each wait
   from `modelChildTaskWaits` (the contributor yes when needed, the
   PermissionRequest hooks, the paid-use popup) with `recheckAdmission`
   after every one. The recheck reads the key first, then synchronously
   checks trust for a custom agent, `childGrantRefusal` (Plan, paid
   subagents, the price, contributor and confidential, the model, the key,
   the goal) and the agent's tool intersection;
4. `spawnChild` starts the child on the last recheck's grant and tools,
   with nothing awaited between.

A model follow-up (`subagent_send_message` with a new task) and the user's
own follow-ups and reopens (`confirmOwnerChildTask`) use the same gate and
`consentToChildTask`. `askApproval`'s hook and paid-popup halves became
`permissionRequestHook` and `askPaidUse`, which the waits reuse. This
supersedes M76c's "no re-check follows the popups": a wait can change
trust, the confidential setting, the key, the model and the offered tools.
