## Findings fixed in this lane

- **P1: a changed project alias could redirect a confined read outside.**
  `readContextText` previously checked the canonical target but read the
  original alias. It now reads `resolution.checkedAbsolute`. A mutable-link
  fixture switches the alias to an outside file after resolution: restoring
  the old read yields `Outside prompt` instead of `Confined prompt`, while
  the fixed read keeps the approved file. This protects agent, skill and
  rules aliases. It does not claim an atomic snapshot of a concurrently
  mutable filesystem.
- **P1: trust lost during paid consent still created a custom-agent child.**
  `ModelApiSession.spawnChild` now checks current trust after the contributor,
  paid-use and grant waits and immediately before creating the child. Two
  regressions cover built-in Explore and project Reviewer, asserting no
  child row, paid child attempt or child request. Both failed on the inherited
  code (`expected true to be false`), then passed after the fix.
- **P2: the catalogue loader retained agents after trust loss during reads.**
  `WorkspaceContext.loadAgentCatalogue` checks trust before loading and
  discards a result completed after revocation. Two regressions withdraw
  trust while reading rules or the agent file; both failed with a populated
  catalogue before the fix, then passed with an empty one. An in-flight
  filesystem read itself cannot be cancelled by `ContextIo`.
- **P2: role text did not explicitly carry the untrusted label.**
  `MODEL_TEXT.agentRole` now names it as untrusted text while preserving its
  source/id and authority ceiling. The exact prompt assertion failed before
  the change and passed after it.
