## Diagnostics stop and explicit limitation

The TextDocument overload alone still produced Theia's reveal rejection.
Waiting for its visible-editor delta fixed opening, but the JSON diagnostics
tests still failed. Explicit activation of the installed JSON provider also
failed to produce diagnostics. Under the brief's two-failed-fixes rule,
further diagnostic rewrites stopped; the ineffective activation workaround
was removed. A final observation-only capture found:

- `broken.ts` is plaintext, with no TypeScript provider in the language list.
- `broken.json` and `tool.json` are JSON; the installed JSON provider is active.
- `getDiagnostics` stays empty while those documents are visible; the API
  emits **zero** diagnostics report events.
- The same installed provider returns real formatting edits, which now work.

The first diagnostics test exceeds its unchanged 20-second test timeout
while waiting for reports; the tool case receives no report. The product
retains explicit unchecked/noReport outcomes rather than claiming clean
files. The README directs experimental-host users to their project's check
command. We did not substitute guessed diagnostics or package a language
server. The installed VS Code TypeScript compiler alone is roughly 17 MiB
uncompressed and cannot fit the unchanged 2,252,800-byte VSIX cap. A consented
language broker is a future D84/M104 decision, not delivered here.
