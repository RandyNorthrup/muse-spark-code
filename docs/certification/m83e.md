## Source and decision

Branch `feature/m83-import`, worktree `muse-extension-m83`, from `187003e6`.
Merge `f08d2f26` joins `origin/main` `a6460cd9` (M75, PR #63), preserving
both features and main's Fixed entries. No push to origin, PR, merge to main, live
model call or credential-store operation is part of this lane.

Five review rounds found credential spellings that bypassed content
detection. D64 replaces that design. Import copies an item only to a place
no more exposed than where it was: personal stays personal, a git-ignored
file is never copied into a tracked one. It does not look for credentials
in what it copies. `m83.md`, `m83b.md`, `m83d.md` are superseded history.

| Source                      | Personal target | Ignored project target | Tracked project target |
| --------------------------- | --------------- | ---------------------- | ---------------------- |
| Personal                    | allowed         | refused                | refused                |
| Project-local (git-ignored) | allowed         | allowed                | refused                |
| Project-tracked             | allowed         | allowed                | allowed                |

Canonical paths determine home/workspace containment, including every open
workspace folder. The safe metadata git runner uses `git check-ignore`
from the file’s nearest repository (nested repositories included);
non-repositories count as tracked, failed classification refuses. Targets
are checked again after final path checks at native publication or editor
edit time. Existing bounded reads, root/link/junction guards, atomic append,
exclusive publication, live trust/activation, checkpoint leases and user
write ownership remain in place. Native writer TOCTOU remains bounded by
those guards, not eliminated.

## Implementation and findings

- Deleted `importCredentials.ts`, `credentialCue`, its three readings,
  NFKC normalization, `maskValues`, the opaque-run constant and detector tests.
  The historical leak fixture is retained solely as production-flow metadata
  isolation input. `redactSecrets` and the log adapter remain unchanged.
- `agentImport.ts` classifies exposure, refuses more-exposed targets and
  rechecks at publication. Registration keeps one Set across `add` calls;
  repeated entries in one source file reuse its classification, including a
  failed query. Project requests keep their root guard even when the folder
  leaves the workspace before planning.
- `importConvert.ts` preserves active transport values unchanged. Inactive
  transport and unknown fields are dropped by name; their values never enter
  output. Unsupported formats and narrowing restrictions remain refused.
- `agentImportCommands.ts` previews kind/name/scope/target and refusal
  reasons only. Picker details contain scope, never source paths. Logs have
  counts and fixed reasons only. No bodies, commands, args, environments,
  header values or URLs enter the preview. Names remain visible as the
  source tool names them; PRIVACY records that residual.
- `agentImportHost.ts` offers config entries as unsaved WorkspaceEdits in
  the target editor, with no clipboard or direct save. Existing settings
  and unrelated settings are preserved when merging. A server name that
  appeared after preview refuses the edit; open-only and dismissed config
  entries count as not imported. The synchronous current-folder
  guard follows the last await before both show and edit.
- README, PRIVACY, SECURITY, PLAN/D64 and the certification index describe
  this design. CHANGELOG has one M83 Added entry; no M83 Fixed entry.
  Removed keys leave all 15 tables; new/changed keys have 14 translations.

RV83e findings 1–3 and 7 are superseded by deleting detection. Finding 4 is
covered by metadata-only picker and log output, with the named residual.
Findings 5, 6 and 8 have editor-interleaving, active-field and scaling tests.
Findings 9–10 are reconciled in current-facing documentation.

## RV83f fixes

The read-only RV83f review found no automatic write to a more-exposed
target, two P2s and four P3s. Commit `580efb47` fixes all six:

- **P2-1** `agentImport.ts` `add()`: a per-base next-suffix counter
  (`Scan.nextSuffix`) starts each probe where the last one for that base
  stopped, so duplicate labels register in O(1) amortized with identical
  IDs (every skipped suffix was taken when tried, and `taken` only grows).
  New test: 2,000 identical `Stop` handlers get `base`, `base:2` …
  `base:2000` with fewer than 20,000 `Set.has` probes (linear probing made
  2,001,002). The hooks file read cap is 64 KiB, not the review's 1 MiB.
- **P2-2** `agentImportEditPrompt` adds "Save it only to that path, never
  to another file." (en.ts and all 14 tables, translated). PRIVACY records
  the Save-As residual beside the names residual. The flow test asserts
  the full prompt text.
- **P3-1** `sourceExposureOf`: a member missing from `exposures` makes the
  grouped copy personal (most restrictive).
- **P3-2** `planFile`: only `project-local` or `project-tracked` moves a
  write onto the workspace root; a map miss keeps the scope's root.
- **P3-3** `agentImportCommands.ts` `sourceScope`: an outside or
  unclassified source shows no scope; the picker detail is its refusal
  reason alone.
- **P3-4** The flow test header states the D64 rule. Comment only, so it
  has no drill.

P3-1 and P3-2 are unreachable through the scan; their tests force the miss
(a candidate whose class answers once; a personal folder that moves during
the target's classification) and assert the restrictive outcome.
