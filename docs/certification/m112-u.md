## Dock and transcript

`AttentionDock` replaces the approval dock in the same mount. Approval
ordering, locks and focus grace remain; questions and MCP forms occupy its
second group. One full dock card is visible, within 50vh and with its own
scroll. Waiting questions sort by arrival, followed by MCP selectors and
the open-question chip. The chip offers Answer and both navigation directions.

The two question views share an in-memory choices/explanation/tab draft.
Radio groups stay independent. Focus/drafts survive the host's deferral;
leaving the card folds it while retaining its draft. A subsequent navigation
request reopens it. Session changes discard question drafts and remount only
the session's cards/forms, preserving the composer. MCP retains its existing
300-second host clock and cancel path; selecting another card keeps its form
draft, settlement removes send controls, and a session boundary discards it.

Waiting/open rows have the accent, question icon and Open question label.
Folded cards show one summary row; terminal states have separate labels and
icons. Dismiss is in the row/dock menu only for open cards. Unknown settled
outcome words remain visible. Arrival countdowns use the host deadline,
localized numbers and no ticking live region. Existing modal inertness
also covers the dock. The reducer announces arrival, deferral, reminder and
late delivery through the existing live region.

`App` routes waiting replies through the existing methods, and open replies
through the frozen session-scoped `answerOpenQuestion`; dismissals use
`dismissOpenQuestion`. Local submission locks cover both views. Uncertain
delivery stays locked; an explicit nothing-taken failure permits retry.
No question action grants approval or changes the permission mode.
