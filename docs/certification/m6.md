## What the milestone rests on (verified before code, PLAN.md §6 M6)

The wire facts in PLAN.md M6 came from three token-free probes on
2026-09-22 (`scratchpad/probe-sessions.ts`, `probe-fork.ts` and a re-run
with the corrected notification handler): `session/list` row shape and
ordering, `session/resume` serving `mode: inline` with the full item array
for a one-turn session (`userMessage` items carry `turnId`, `commandId`,
`text`), `session/read` serving the same without a lease, `session/rename`
and `session/fork` refused on Windows 1.3.0 (`UnsupportedPlatform`,
`WriteFailed`), `session/listChanged` arriving with the `sessionListStream`
grant, and `Session.modelId` being the metadata fold's model rather than the
session's (the resume therefore asks `model/list` for the active row). The
Claude Code behaviour mirrored: the History dialog's grouping and search,
`archiveInactiveSessions` (1 / 2 / 7 / 14 / never), the sidebar's
"resumed if a message was sent in the last 10 minutes" rule, the unread dot,
tabs named after the conversation, and "rewind" as a fork of the turns
before a message (Claude Code's file checkpoints have no MSP counterpart;
the M5 Revert covers edits).

## Live check through the extension's own controller (real host, one real turn)

`scratchpad/live-m6.ts` drove `MuseCodeBackendManager` →
`ConversationController` with a recording surface against the workspace
`C:\muse-live-ws` and its five stored sessions from the M4/M5 runs
(`live-m6.log`, 37 s wall clock, one model call):

- **List**: `listSessions` → `session/list {workspaceRoot, limit: 200}` →
  `sessionList` with 5 rows, newest activity first, titles as stored
  (`Edit notes.md: replace "first line" with "second line". Then …`, `What
does the selected line do? One sentence, no tools.`, an `Untitled` row for
  a session with 0 turns), status `notLoaded` for all of them.
- **Resume**: `resumeSession` of the newest → `session/resume {history:
inline}` served **11 items** (`userMessage`, `reminderChild` ×5,
  `toolCall` ×4, `agentMessage`) → `historyLoaded` with them, the `Resumed …`
  notice, then `sessionInfo` with **`modelId: muse-spark-1.3`** from the
  catalogue's active row (the record's own `modelId` says
  `muse-spark-1.3-contributor`, PLAN.md M6). `setTitle("Untitled")` since the
  session has no allocated name.
- **A real turn on the resumed session**: "In one short sentence and
  without tools: what was my first message in this conversation about?" →
  "Your first message asked to edit notes.md to replace one line of text."
  — the resumed session carries its history on the host side, and the live
  events reach the surface (`turnCompleted` → `markUnread`).
- **List stream**: with the `sessionListStream` grant, `session/listChanged`
  arrived twice during that turn and was folded into re-posted
  `sessionList` messages: the row went `notLoaded` → `running` (turns 1,
  activity `16:56:04`) → `idle` (turns 2, activity `16:56:37`).
- **Rename** → the CLI's refusal as a notice: `Could not rename the
conversation: session/rename runtime admission failed: … session name
rename authority is unavailable: Unavailable(… UnsupportedPlatform)`.
- **Fork** (no cut point) → `Could not fork the conversation: invalid fork
boundary for session …: WriteFailed`. Both as PLAN.md M6 recorded; the
  conversation was unchanged after each.
- **Archive / unarchive** → `sessionList` re-posted with the id in
  `archivedIds`, then without.
- **Restore rule**: the controller's memory held `{sessionId, at: <the turn's
completion>}`; a fresh controller with `isRestorable: true` called
  `restoreRecentSession()` and resumed it (`historyLoaded items=16`, the
  new turn's items included) with the same notice.

One warning on shutdown: the sidebar controller's `dispose()` drops its
session before `manager.dispose()` closes the host, so the host's parting
`session/statusChanged {notLoaded}` finds no session and is logged as
"unknown session" — harmless, and the same order the extension uses on
deactivation.

## Security

- Session history never leaves the host except as the `historyLoaded`
  message to the panel's own webview; nothing is written to disk by the
  extension (archived ids and the last session id live in VS Code's
  `workspaceState`, validated on read).
- `session/list` is scoped to the workspace root; rows for other
  workspaces arriving on the list stream are dropped.
- Rename and fork go through the CLI's own admission; a refusal is shown
  verbatim as a notice and nothing is retried or worked around.

## Findings recorded during the milestone

- `session/listChanged` **does** flow during a turn, not only at shutdown:
  two rows arrived for the running session (status and turn count
  changes). The dialog therefore stays current without polling; the
  re-list on open remains for sessions loaded by other hosts.
- The host re-emits `session/statusChanged` for a session this connection
  unloaded (see the shutdown warning above); the "unknown session" warning
  is the M2 router's and is correct.
- Muse Code 1.3.0 on Windows refuses `session/rename` and `session/fork`
  through the extension exactly as through the probes. Both actions stay in
  the UI so Linux / macOS users get them; the Linux VM check is deferred
  with the other platform runs (PLAN.md §3).
