## Implemented scope

- Production `createSubscriptionFeatures` supplies the OpenRouter Connect
  label, exchanger and usage reader to the lazy Models panel. Both the wizard
  and quick pick already save via the provider-key path; local Connect uses
  S256 and state on a random-port 127.0.0.1 callback. The key stays in the
  host draft until Save. Remote Connect uses the documented password-box
  authorization-code route. A failed browser open is awaited and fails honestly.
- Exchange uses the existing provider DNS pinning and bounded response
  transport, with no authorization header, redirect or retry. Empty codes,
  invalid verifiers, unknown response/key shapes and HTTP failures refuse
  with fixed translated text. Fixed cloud origins now reject DNS answers
  classified as local, complementing the existing private/metadata/unusable
  address checks without changing private-network consent rules.
- The callback is retained even before its waiter is claimed. A second waiter
  cannot replace the first; duplicates refuse. Refusal descriptions never
  become exception text. All callback query values are zod-validated;
  unknown parameters are retained. Timer starts when listening, and sockets
  close on success, refusal, timeout, browser failure, panel disposal or wizard
  cancellation. Duplicate Connect deliveries join the first pending operation.
- Models & Agents reads key usage on open and after Save; its provider-row
  Refresh reads again. Account & usage merges observations with recorded
  tokens and spend, without overwriting those tallies. Both show total,
  daily/weekly/monthly usage, limit and remaining dollars. A documented null
  limit is explicitly unlimited; absent observations remain unknown. Reads
  fail visibly and discard observations if the credential rotated in flight.
- `providers connect openrouter` uses hidden terminal stdin for the PKCE code
  and stores the returned key in the existing origin-bound OS record. A key
  rotated during authorization is preserved. `providers add --preset openrouter
--model <native-id>` can use that connected key without another key prompt;
  ZDR remains default. `providers usage <id>` reads the same free endpoint.
  ACP publishes terminal auth entries for Connect, pasted-key setup and usage;
  verification requires the stored record's OpenRouter origin.
- All five new UI keys and the revised feature/help description have real
  translations in all fourteen tables. CLI reference, feature catalog,
  README, ACP guide, changelog and roadmap move with the code.

## CM952R2 review repair — lifecycle contract (2026-10-11)

Written before the lifecycle code changes. Each cell lists stored credential /
active work / visible result. `K` means the unchanged credential present at
entry (possibly absent); `B` is the independently rotated current credential;
`—` means no credential/work. An exchanged key stays only in the host draft
until Save in Models; terminal Connect stores after the locked freshness
check. `N` = K / — / idle; `W` = K / callback listener or hidden code prompt /
connecting; `X` = K / one exchange / connecting; `D` = K / — / connected draft;
`S` = saved credential / — / connected; `C` = K / — / cancelled, draft cleared;

Callbacks only belong to the active generation; late/duplicate callbacks

borrowed credentials are never written back or rollback-restored.
