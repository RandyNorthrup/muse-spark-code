## Lane U implementation

- `core/judge/use.ts` owns the memory-only background lifetime over J's real
  entry store and S's injected runner. Reviewer fences consume once,
  synchronously; cards observe a fixed caution only. Replacement, answer,
  cancellation, session/turn end and mode changes discard the handle. Parsed
  Muse Code arguments are canonicalized by J rather than keyed by JSON
  serialization order. A fresh runner binds each admitted action.
- M78 and M90 read this latch at their existing verdict fences. A ready
  caution converts ALLOW to the normal card. Pending, failed and none leave
  the reviewer unchanged. Immediate Model API allows and native edit allows
  never start Judge. Judge values and text never reach either ALLOW parser.
- Cards use an extension-owned, zod-validated `approvalCaution` message;
  this does not reissue an ACP permission request. The reducer requires the
  same approval/stage and an undecided card. Choices and click locking stay
  unchanged. The fixed note is announced once to the screen reader.
- `host/judge/judgeUse.ts` resolves at decision time, emits the status,
  rebinds after the first-charge wait and displays the subscription limits
  and isolation residual once. Explicit `same` retains J's automatic-floor
  exemption. An unasked paid source shows the consent-needed reason while
  the first-charge prompt is pending.
- First-charge consent runs through `PaidUseConsent` and `paidHost`, using
  the existing three-choice modal and `museSpark.paidDailyBudgetUsd`.
  Judge no longer asks a price-only startup modal. Allow once stays once;
  Allow always uses the existing trusted-workspace, revocable grant. Deny,
  close, unknown tariffs, invalid budgets, a missing key and switching the
  engine off cannot accept or dispatch a paid use. There is no automatic
  upgrade of an Allow once answer to an always grant.
- `JudgeUsageRows` is invoked only by the admitted transport at dispatch;
  it marks Model API rows paid, retains missing/failed/malformed receipts
  as unknown cost, and binds receipts to the dispatch model. Subscription
  rows do not touch the paid tally. Known tokens/costs stay apart from main
  conversation tokens, and duplicate completions cannot count twice.
- `JudgeReplayRecorder` measures ready rate and precision independently
  per backend. Its labels come from destructive-risk replay fixtures,
  never approvals or test outcomes. Unmeasured precision stays undefined.
- English and all 14 translated UI tables contain the caution, status,
  subscription notice and tool label. No manifest command or setting was
  added. Harness cases: `judge`, `judge-narrow`, `judge-slow`, `judge-usage`.
