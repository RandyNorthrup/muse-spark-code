# M82: awareness and budgets

Recorded 2026-09-28 on branch `feature/m82-awareness`, from main `c42c4d5f`.
PLAN.md D49.

## The request

PLAN.md §6 M82: the user knows what happened and what it cost.

- A notification when a long turn ends or waits for approval while the VS
  Code window is unfocused, and never while it is focused.
- Tokens and cost per reply, optional.
- A session budget cap on the Model API, machine-scoped, kept by
  reservation: each request's input estimated high, `max_output_tokens` set
  so input plus output at list price fits what is left, a request that
  cannot fit not sent and the turn saying why, the only overrun the
  estimate's error (named in the setting), and the turn's cost shown against
  the cap afterwards.
- Cache savings in Account & usage, on the Model API only.

## How it was made

A Muse Code instance (Muse Spark, contributor tier) drafted the milestone
and left it uncommitted. Its sandbox blocked the production build,
`npm`/`npm audit`, Semgrep and `gitleaks git`, so those never ran on the
draft; its record said the milestone was certified anyway. Claude reviewed
the draft against PLAN.md and AGENTS.md and finished it. This record
replaces the draft's.

What the review found and changed:

- **The estimate was not high.** The draft counted what was added since the
  last request at four characters a token (below the real rate for code and
  for CJK text), counted only replay items (the instructions and the tools,
  about 11 KB, never entered the first request's estimate), missed child
  results drained while the body was built, and moved its base on every
  reservation, so a retry after a dropped stream was estimated at the old
  base with nothing added. `sessionBudget.ts` now estimates from the body
  sent: the last reported input plus every part (instructions, tools, each
  input item, as JSON) the reported request did not carry, at one token per
  UTF-8 byte, matched by SHA-256; removals never subtract. The base moves
  only when a response reports usage; it resets on a model change and after
  a compaction, where Meta's count of the new context replaces it.
- **Spend that was never reported was never counted.** A Stop or a dropped
  stream after the response began spent money the cap never saw. Such a
  request now counts at its whole reservation; one refused before its
  response began counts nothing.
- **An unpriced model was priced as standard.** The cap now refuses a model
  without a verified price (`modelApiPaidTier`) instead of guessing.
- **Child tasks' spend was left out** of the conversation's, although their
  tokens count in its totals and its goal budget. It now counts as it
  reports; child tasks are still not reserved (each is priced and asked for
  on its own, D48). The setting's description names them as the second way
  past the cap.
- **The reply line showed only the last request of a multi-step turn.** It
  now carries every request since the previous line in that turn, so a
  turn's lines add up to its cost; a failed turn's usage does not leak
  into the next turn's line.
- **A reply cut short by the budget said nothing.** A response that used
  every output token the budget left is now marked in the transcript.
- **"OS notification" was claimed, but VS Code gives extensions none.** The
  notice is VS Code's own `showInformationMessage`; the docs say so, and the
  OS-level toast is an open question for the owner (PLAN.md §3 Q10).
- **Two panels on one conversation both notified.** One `BackgroundNotifier`
  per window raises each notice once by key; a failed turn now says it
  failed instead of "finished responding".
- **`notifyOnBackgroundTurn` was machine-scoped**, though it chooses nothing
  that runs or is billed (D15's rule for that list); it is now an ordinary
  setting. The budget stays machine-scoped.
- **Smaller fixes.** A JSDoc sat on the wrong method in `ModelApiHost.ts`;
  German used colloquial "rein/raus" and called a turn an "Antwort"; French
  used straight apostrophes where its tables use ’; the draft had no
  harness scenario for the reply line.

## What was built

- **Settings.** `museSpark.notifyOnBackgroundTurn` (default on),
  `museSpark.modelApiReplyUsage` (default off, display only),
  `museSpark.modelApiSessionBudgetUsd` (default 0, no cap; machine-scoped,
  in `MACHINE_SCOPED_SETTINGS`; a negative or non-number value falls back to
  no cap with a log line). Descriptions in `package.nls.json` and all 14
  translations.
- **Notifications** (`src/host/conversation/turnNotifications.ts`):
  `attentionNotice` keys a long turn's end (60 s,
  `BACKGROUND_TURN_NOTIFICATION_MIN_MS`; an unreported length counts as
  long), an approval and a question; it skips a cancelled turn, a short
  one, and a replayed card. `BackgroundNotifier` shows each key once
  (`BACKGROUND_NOTICE_KEYS_MAX` remembered), only while the setting is on
  and the window unfocused, and **Show conversation** reveals the surface
  if it is still open.
- **Per-reply usage** (`ModelApiHost.noteReplyUsage`): `usage` and
  `costUsd` on the reply's item snapshot, persisted with the transcript,
  shown by the panel while the setting is on. Muse Code attaches none.
- **The budget** (`sessionBudget.ts`, pure; `ModelApiSession.budgeted`,
  `closeReservation`, `settleReservation`): every turn request, retry and
  compaction is reserved, checked before the PreLLMCall hooks see it and
  again on the body sent. The reservation is logged with its numbers
  (tokens only, no content). Spend persists with the session. The turn's
  cost against the cap is a transcript notice after each turn with a cap.
- **Cache savings** (Account & usage): the uncached price minus the priced
  one, with its share, on the Model API only.
- **Strings.** Thirteen keys in `en.ts` and all 14 UI tables (four added in
  the review: `notifyTurnFailed`, `notifyTurnEnded`,
  `sessionBudgetUnpriced`, `sessionBudgetOutputLimited`); three setting
  descriptions in all 15 manifest tables.
- **Harness.** A `reply-usage` scenario (the reply line and the budget's two
  notices); `usage-api` now shows the cache-savings row.

## Live check

`test/e2e/modelApi.live.e2e.test.ts` case19, through
`run-live-modelapi.ps1` (the key decrypted into the child's environment
only), in an empty temporary workspace, on `muse-spark-1.3-contributor`,
with the host from `npm run build:dev`. A file of code, JSON and Japanese
text was read with `read_file` under a $0.004 cap, then the cap was set just
above the spend and one more turn sent.

- **Attempts:** 2 `POST /v1/responses`, both 200; the refused turn sent
  none. About $0.0005.
- **Estimated versus counted input:** 11,600 / 3,198 and 10,483 / 4,767
  tokens: each estimate above Meta's count.
- **`max_output_tokens` sent:** 14,200 and 13,068 (lowered from 32,768),
  accepted by Meta.
- The refused turn failed with "…It was not sent." and no request.
