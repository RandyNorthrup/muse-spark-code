## Increment 4 — retire mechanics bound (2026-10-22, macmini)

Retire is no longer deliberately untriggered: `ensureMigrated` calls
`migration.retire(key)` per key (the engine still decides — past the
2-release window, verified live copy, or nothing happens), and
retired slots read authoritatively through the shell. The engine's
`readRetired` returns the legacy envelope bytes for `retired` rows
only, with item validation and journal-digest verification (damage
refuses; anything else reads null); active slots keep reading their
legacy copy, unchanged. The controller gates on the unlocked state —
locked, uncreated and unavailable vaults read absent without
touching the journal — and damage past the gate propagates as the
truth; a lock landing between gate and read surfaces as the
broker's failure (the transient class of a failing store). The
shell consults the mirror only when the legacy copy is absent, so
present-copy reads cost nothing extra, serialized with mirror ops.
No new catch sites; the ports' snapshot type widens to carry the
vault status its implementers already return.

Broker proof, written for CI and the lead's unsandboxed run: both
suites drive a retire case (release flipped 19 → 21 via the
injected dep) — legacy entry gone, shell still serves the value,
locked reads absent, unlocked reads again, sign-out removes the
vault copy last, the log quiet. `vaultMigration.js` 43.8/45 KiB.
Pure suites here: key list 5/5; `vitest related` on the engine and
