## Implemented interfaces

| File                               | Behavior and integration contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/host/team/processLifetime.ts` | `TeamProcessLifetime` and `TeamProcessDriver`: await the flushed intent before invoking the driver, add `MUSE_SPARK_LAUNCH_ID`, validate and persist OS confirmation, then persist a separate descendant retirement outcome. Recheck dispose and load after the asynchronous intent. Retain uncertain and failed-confirmation children for disposal/recovery. A process group cannot report proved retirement.                                                                                                                                          |
| `src/host/team/teamJournal.ts`     | Schema-validated records under `team/journal/<instance>/`, serialized operations, existing atomic writer plus file sync and POSIX directory sync before acknowledgment. Bound record names and canonical paths. Corrupt owned records move to unique `*.broken` files; foreign records remain byte-exact until authority is granted. Callers supply the actual board/landing schemas.                                                                                                                                                                   |
| `src/host/team/windowIdentity.ts`  | UUID plus start time, with no guessed stable VS Code window identity. Only the exact current incarnation or a confirmed Take over with a successful durable receipt can write. The receipt callback writes this window's own records, never the foreign journal.                                                                                                                                                                                                                                                                                        |
| `src/host/team/orphanRecovery.ts`  | Find both unended launches and ended children lacking descendant proof. Marker matches are matched; PID/start-only matches are uncertain. Stop requires an explicit user confirmation and a second PID/group/start/marker check before signaling. The OS scan/signal adapter is an explicit dependency. No journal, working copy or ref is mutated.                                                                                                                                                                                                     |
| `src/host/team/windowHints.ts`     | Strict hint projection, owner-only POSIX folder, serialized periodic publication and removal, bounded fresh-hint reader, advisory totals including this window. Collision answers survive rewrites and unrelated tasks, expire when paths/servers disappear, and ask again for new paths. Freshness never grants journal authority. Missing/malformed hints do not lock work. Folder failure disables hints once. Windows requires a native ACL verifier or disables hints. The caller expands write-set globs and excludes JSON-table/changelog files. |
| `src/host/team/loadGuard.ts`       | `os.cpus()` time deltas and `os.freemem()`, sustained CPU pressure or immediate low-memory pressure, recovery and timer disposal. The owning lazy host supplies lane 0's thresholds and timing constants. It does not stop running work.                                                                                                                                                                                                                                                                                                                |

The OS drivers are **required injected dependencies**, not fake production
implementations. They are not supplied in this commit. The tests use finite
real child processes and simulated container observations: a fixture labelled
`windowsJob` is not evidence of Windows job containment.

No activation, request builder, backend manager, paid feature, UI or bundle
entrypoint changed. These modules load only if a caller imports them; there is
no activation hook or constructor-triggered probe/process/timer. This preserves
the existing request path in this checkout, but does not replace lane T's
single-model golden certification after wiring.

## Open work and ownership blockers

The lane brief says: "do not edit files another lane owns — if you must, stop
and say so in the final message." Implementation stops at those boundaries.

1. **Platform adapters and native proof, acceptance 48.** Implement
   `TeamProcessDriver` for Windows jobs, Linux user scopes, POSIX process groups
   and `setpriv`, with priority set before child execution and actual OS start
   identity. `native/windows/MuseSparkJob.cs` is unchanged. The existing
   `MuseSparkMcpJob.cs`/M50 launcher contains suspended children and binds the
   owner handle, but exposes no launch confirmation or active-process-count
   retirement channel. Extending that shared native helper and its control
   protocol needs a lead ownership decision; K owns only `MuseSparkJob.cs`.
   No duplicate Win32 launcher, uncontained fallback or taskkill was added.
2. **Real orphan scans, acceptance 48.** Supply the current-user Linux `/proc`
   and macOS `ps -E` adapters. The pure recovery decision logic is tested;
   scanning real surviving processes is not. Windows needs no ordinary search.
3. **Real team host and all child routing.** Bind worker/check/MCP spawners to
   the launcher and start a separate contained Muse Code team host. Do not
   reuse or restart the conversation's host. This requires lane W/B integration
   and has not been exercised by these seam tests.
4. **Shared settlement, acceptance 50.** Lane A/D78 must provide the team meter
   region, token measure, monotonic local-day record and settlement lookup by
   claim id with durable settled/refunded/liability outcomes. Lost-ack, midnight,
   lowered-budget and two-window spend tests remain open. Stored credentials
   must never enter worker environments; lane I/W retain environment admission.
5. **Admission and product actions.** Connect lane A's per-window worker,
   process, heavy and child-slot admission, and lane U2's actual recovery
   actions/localized refusals. The callbacks here do not implement navigation,
   quarantining copies, Resume, Discard or shared-budget reset.
6. **Lane X documentation and wiring.** Regenerate
   `docs/ide-compatibility/host-api.md` and review the import-count-only diff:
   child_process 9→10, crypto 32→35, fs/promises 34→36, os 6→7, path 65→67,
   timers/promises 3→5. Add the lazy bundle, shared constants/schema mapping,
   Windows owner-only ACL service and state-home path selection. Update README,
   PRIVACY and CHANGELOG together with the integrated behavior. These files
   were not edited by K.
7. **Certification.** All four crash barriers, detached descendants,
   pre-arming death, job breakaway/nesting, scope populated state and real
   priority remain unproved. Run native tests on Windows/Linux/macOS rigs after
   adapters exist, and bind the single-model golden proof to integrated wiring.

Owner rulings remain authoritative for integration: enhancements on for the
chosen setup; paid extras ask once before first charge through the existing
three-choice modal and shared `museSpark.paidDailyBudgetUsd`; one distinct model
keeps today's behavior. This lane does not implement or alter paid defaults.
