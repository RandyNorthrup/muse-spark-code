### Changes in K's owned files

- `processLifetime.ts`: native Windows job driver reuses the existing M27/M50
  assembly preparation and shared suspended-child READY/GO launcher. K's
  `MuseSparkJob.RunTeam` adds an outer no-breakaway kill-on-close job, priority,
  OS member confirmation and active-member retirement observation. No taskkill
  or uncontained fallback was added. The Windows natural-exit path is unfinished
  as detailed below.
- Linux selects an actual delegated cgroup-v2 user scope through
  `systemd-run --user --scope --collect`. It polls registration, reads
  `cgroup.events`, and only observed `populated 0` grants proof. A collected
  cgroup whose zero state was missed remains uncertain; absent paths or failed
  systemctl calls never become proof. Scope retirement sends TERM, then KILL
  after the supplied grace. Linux's no-scope fallback uses a separate process
  group and `setpriv --pdeathsig KILL` where available. macOS uses its own group.
  POSIX nice is applied before command execution. Group retirement stays
  uncertain even when the direct child exits.
- `teamJournal.ts`: Windows flush opens a writable handle (`r+`); the first
  Windows run exposed EPERM on a read-only fsync. Startup discovery preserves
  foreign files, reports unreadable records and never uses process liveness to
  obtain journal authority.
- `orphanRecovery.ts`: real current-user `/proc` and macOS `ps -E` scans,
  environment-marker projection and actual OS start identities. Linux includes
  boot identity and start ticks and rejects zombies or changed samples. macOS
  scans two process tables in a batch, avoiding per-process subprocess floods.
  Stop retains the existing explicit-click and second-sample checks.
- `startNativeTeamLifetime` scans foreign open/uncertain launches before
  returning the launcher. It returns recovery records and actions; it writes
  no foreign journal or working copy. End writes serialize and preserve a later
  proved result against an uncertain retry.
- `startTeamMuseCodeHost` starts a new contained process and a new SDK connection,
  then the existing `MuseCodeHost`. Its fake-CLI test uses real pipes. It has no
  reference to the conversation's backend manager or host. W supplies the
  resolved CLI/read-only flags and credential-free request environment. The
  initialize fields come from the existing captured MuseCodeHost schema and
  installed SDK's initialize/initialized/flush sequence, not a guessed frame.
  There were **zero live or paid model attempts**.
- `windowHints.ts`: personal state-home selection and native owner-only Windows
  ACL setup plus independent ACL verification in the real-process test. POSIX
  keeps mode 0700. Hints still disable on failure and never confer authority.
- Regenerated `docs/ide-compatibility/host-api.md` with its script, as FINM96K
  expressly authorizes. No hand-edited host-API data, gate configuration,
  dependency, new user-visible string, unsafe cast or suppression was added.
