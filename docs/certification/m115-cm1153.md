# C-M115-3 — Per-schedule paid authority

## Scope and implementation (2026-10-11, win11)

Base `efc8e7db7`, branch `c/m115-3`. This lane implements the existing
`createScheduleBilling` port left by C-M115-1; it does not introduce another
delivery or paid authority. Automatic delivery remains held by
`SCHEDULE_EDITOR_DELIVERY_CERTIFICATION.isReady = false`.

Creation/renewal quotes the selected provider's verified model rates, prompt,
cadence, schedule cap and shared D78 daily cap. Consent belongs to a paid key,
model and tariff, with account/provider/origin represented by the selected
host's identity. Legacy records without `payerKind` still parse, but cannot
authorize spending. A plan grant cannot authorize a paid key. Once is bound
by the existing authority CAS to one run; a consumed Once needs renewal.
Always is retained with the schedule, never in a workspace paid-extra grant.

VS Code delegates to the existing D48 modal and compares MessageItem identity.
Closing or declining it supplies no consent, reservation or HTTP request.
ACP uses the existing SDK permission channel and schedule-specific option
label, with the same complete localized question. Missing launch flags,
insufficient/nonpositive budget, missing editor, headless use and a late
trust change refuse. CLI flags authorize only their bounded schedule and
require the full quote to be printed; changing the invocation during that
publication invalidates the answer.

`scheduleBudget` supplies the same exact `UsdAmount` reservation to the editor
and standalone runtime. Journal v2 atomically admits the shared day and own
schedule cap. A failed own reservation refunds its shared nonsend; both journals
are attempted at settlement, and unknown usage retains liability. Final
dispatch rechecks the day, live D78 limit and account admission. The billing
port checks authority and key/tariff again after the reservation await, refunds
nonsends on revocation and refuses before HTTP. Runtime D78 Stop survives a
later numeric limit increase; corrupt day overrides refuse.

The standalone regression forks two real processes against one journal for
the ordinary daily cap, the schedule cap with shared headroom, and the shared
cap across different schedules. At most one is admitted. A synchronous fence
can refuse both during another writer's incomplete intent; after their nonsend
refunds a retry must obtain the last dollar, and another request must refuse.
The tests do not require overlapping journal publication to succeed.
The fixture also refunds a claim received before its final synchronous fence
refuses. A final replay exposed that missing fixture cleanup; retaining that
known nonsend incorrectly exhausted the retry's own cap. It now follows the
real transport's refund contract rather than calling a refusal a charge.

No vendor wire schema was invented. The ACP request uses the existing captured
SDK permission shape and the tests' established fake producers. Schedule payer
metadata and the detailed paid-use request are internal contracts. Model
attempts, live calls and paid calls: **0**. No new dependency, cast escape,
suppression, threshold, cap, hook or configuration change.
