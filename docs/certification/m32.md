# M32 certification — worktrees (PLAN.md M32, D30)

Recorded 2026-09-24.

## The change

- **`src/core/worktrees.ts`:** the pure parts.
  - `git worktree list --porcelain` parsed, every attribute included:
    branch, detached, bare, locked, prunable.
  - The new folder goes beside the repository,
    `<repository>.worktrees/<branch>`, the branch's slashes folded, so the
    copy never lands inside the workspace.
  - Folder comparison ignores case on Windows.
  - The git argument arrays.
  - git's own dirty-worktree refusal is recognised.
- **`src/host/commands/worktreeCommands.ts`:** the flows.
  - A trusted workspace inside a repository is required; git never runs in
    Restricted Mode (D24).
  - The branch name is validated as you type (`git check-ref-format
--branch`, and not an existing branch). The base is HEAD or a local
    branch.
  - An existing folder is refused, git's own error is shown, and the new
    window opens on request.
  - Removal never offers the main checkout or this window's own worktree,
    and confirms in a modal.
  - `--force` is used only after a second confirmation that says the
    uncommitted changes will be lost.
  - Paths are shown in the platform's own form (git prints `C:/…` on
    Windows).
- **`src/host/git.ts`:** a per-call timeout. Worktree add and remove get
  5 minutes; every other call keeps its 15 s.
- **`src/host/worktreeFeatures.ts`:** the input box, picks, modals and
  `vscode.openFolder` with `forceNewWindow`.
- **Palette and commands:** New worktree… and Remove a worktree… in
  Context on both backends. In the Command Palette they show with a folder
  open.
