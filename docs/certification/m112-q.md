## Portable registry and private storage

The holding process owns arrival-time deadlines and one serialized registry
per session. Settings are machine-only, 60 seconds by default, 0 disables
interactive deferral, 1–9 clamps to 10, and scheduled callers may request
immediate deferral. Waiting reloads as open; only explicit Stop cancels.
Matching question keys coalesce live requests and re-asks, keeping original
card IDs/text while rebinding the answer to fresh request IDs and labels.
Open questions are capped at 20. Reminders are oldest first, once per turn,
limited to two per question and suppressed while an approval waits.

Marks are saved before delivery; only proof of non-admission restores them.
Uncertain acknowledgements never retry. Failed saves restore the in-memory
state before any dispatch. Dismissals persist lazily and join a running
steer or the next real user message; they never start a turn of their own.
Only live questions and queued dismissal notes persist; terminal records
are published and retired. The registry writes no logs and has no export
path, mode change or approval grant.

Host and runtime share the filesystem adapter: private data directory,
0700 directory/0600 file on POSIX, strict zod session envelope, validated
file names, refusal of linked directories/files, exclusive temporary
creation, sync and atomic rename. Corrupt storage rejects with fixed text;
JSON parser errors cannot quote question content into an exception. Windows
uses the existing private data directory's ACL; POSIX permission drills were
run on Kubuntu. No dependency or gate was added or weakened.
