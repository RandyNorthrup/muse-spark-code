# M29 certification — `.muse/` is a protected path (PLAN.md M29, D30)

Recorded 2026-09-24.

## The change

`PROTECTED_PATH_SEGMENTS` (`src/shared/constants.ts`) gains `['.muse']`.
On the Model API backend a write anywhere under a `.muse` folder now asks
for approval in every mode but Bypass (D24), whatever the session rules
say. The reason: `.muse/hooks.json` binds shell commands that Muse Code
runs outside its sandbox and approvals, so before this change an agent on
the key backend could write a hook without asking and have it run at the
next Muse Code session in that workspace.

## Tests

`test/unit/permissions.test.ts`:

- **Now protected:** `.muse/hooks.json`, `.muse/settings.json` and
  `packages/app/.MUSE/hooks.json` (any depth, any case).
- **Still ordinary:** `muse/notes.md`, `docs/.muse.md` and
  `my.muse/hooks.json` (no false positives on look-alikes).

## Test-fire proof

With `['.muse']` removed from the list, the suite fails:

```
FAIL  test/unit/permissions.test.ts > isProtectedPath > protects what configures or runs code, at any depth and in any case
AssertionError: .muse/hooks.json: expected false to be true // Object.is equality
      Tests  1 failed | 8 passed (9)
```

The entry was restored and the suite passes again (9 passed).

## The Muse Code backend: checked live

The CLI decides its own approvals on the Muse Code backend, so this was
checked against Muse Code 1.3.0 (`1.3.0-R3401.1`, Windows 11).

- **Setup:** two short headless turns in the empty `C:\muse-live-ws`, both
  with `--approval-mode on-request --approval-judge off
--max-model-steps 3`, and the reminder agents off.
- **Cost:** 2 model attempts each, counted from the trace logs
  (`model.attempt.lifecycle … phase="admission"`), 4 in total.

| Prompt                                                         | Outcome                                                                                                                     |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| "Create the file .muse/hooks.json whose entire content is: {}" | Muse Code asked for approval (`tool denied: approval aborted`, since a headless run cannot answer), and no file was written |
| "Create the file control.txt whose entire content is: {}"      | Written without an approval (the control); the file was deleted afterwards                                                  |

Muse Code already guards its own hooks file, so no upstream issue is needed.
