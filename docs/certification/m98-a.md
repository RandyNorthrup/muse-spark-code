## What this lane owns

New `src/core/judge/admission.ts` (pure core, no `vscode` import) plus
`test/unit/judgeAdmission.test.ts` (28 tests) and
`test/unit/judgeAdmissionLedger.test.ts` (7 tests). Behaviour, per the lanes
table:

- Worst-case uncached reservation per call: estimated input at the full
  input rate plus the whole output allowance at the output rate, no cache
  discount, at the model's verified tariff (`modelApiPaidTier` whitelist).
  A batch is one call; a retry admits again for a new claim id.
- Refusal of unpriced models (no estimate without a verified tariff) and of
  any call over the remaining budget, with nothing reserved on either path.
- Settlement at the known actual cost (cached tokens discounted, as
  reported), idempotent for the same value, refusing a conflicting
  re-settle; refunds of known non-sends to zero.
- Liability for uncertain outcomes: the claim exposes no abandon path, so a
  timeout or lost response keeps the full reservation by doing nothing. A
  tariff lost before settlement also keeps liability rather than settling a
  guess.
- Re-binding after waits: `rebindJudgeClaim` purely compares the claim's
  binding snapshot to the current owner, backend, model, engine,
  confidential flag and consent; `verifyJudgeDispatch` additionally refuses
  an already-settled claim and pings the ledger fail-closed. Any refusal
  keeps the liability (refunded only for a known non-send).
- Fail-closed throughout: an unreadable ledger, a lock failure, nonsense
  remaining figures and a mismatched claim echo each refuse admission; a
  store failure at settlement throws `JudgeLedgerError` with the liability
  kept.
- Backend/billing coherence: Model API admits only metered, Muse Code only
  subscription (a Muse Code call never touches the ledger).
- Reason codes, not user text (lane J precedent): no new strings, so
  `en.ts`, the 14 `l10n/ui.*.json` and `package.nls*.json` are untouched
  and `node scripts/check-l10n.mjs` reports 0 problems.
