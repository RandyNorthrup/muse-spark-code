## What this lane owns

New `src/core/judge/admission.ts` (pure core, no `vscode` import) plus
`test/unit/judgeAdmission.test.ts` (28 tests) and
`test/unit/judgeAdmissionLedger.test.ts` (7 tests). Behaviour, per the lanes
table:

- Worst-case uncached reservation per call: estimated input at the full
  input rate plus the whole output allowance at the output rate, no cache
  discount, at the model's verified tariff (`modelApiPaidTier` whitelist).
  A batch is one call; a retry admits again for a new claim id.
- Refusal of unpriced models (no estimate without a verified tariff) and of
  any call over the remaining budget, with nothing reserved on either path.
- Settlement at the known actual cost (cached tokens discounted, as
  reported), idempotent for the same value, refusing a conflicting
  re-settle; refunds of known non-sends to zero.
- Liability for uncertain outcomes: the claim exposes no abandon path, so a
  timeout or lost response keeps the full reservation by doing nothing. A
  tariff lost before settlement also keeps liability rather than settling a
  guess.
- Re-binding after waits: `rebindJudgeClaim` purely compares the claim's
  binding snapshot to the current owner, backend, model, engine,
  confidential flag and consent; `verifyJudgeDispatch` additionally refuses
  an already-settled claim and pings the ledger fail-closed. Any refusal
  keeps the liability (refunded only for a known non-send).
- Fail-closed throughout: an unreadable ledger, a lock failure, nonsense
  remaining figures and a mismatched claim echo each refuse admission; a
  store failure at settlement throws `JudgeLedgerError` with the liability
  kept.
- Backend/billing coherence: Model API admits only metered, Muse Code only
  subscription (a Muse Code call never touches the ledger).
- Reason codes, not user text (lane J precedent): no new strings, so
  `en.ts`, the 14 `l10n/ui.*.json` and `package.nls*.json` are untouched
  and `node scripts/check-l10n.mjs` reports 0 problems.

## FIXM98A — RVM98A corrections (2026-10-05, Kubuntu)

All three P1s, both P2s and the P3 are fixed inside the four lane-A files.
No RVM98A finding remains residual. Before the fixes, the expanded owning
suites produced 14 failing regressions and 35 passing tests. The original
35-test and six-drill receipts above are historical, not proof of the fixes.

- **Finding 1, P1:** `JudgeLedgerClaim.check()` preserves D78's synchronous
  guard. Admission invokes it after durable reservation and verification
  invokes it after its final wait, using the owned claim's live cap/day/Stop/
  cancellation/validity guard. The asynchronous remaining figure is only an
  initial affordability probe, never the final budget authority. Guard
  failure refunds a known nonsent reservation; a failed refund keeps liability.
- **Finding 2, P1:** the binding is snapshotted before admission. A live
  reader is called after the remaining-budget, reservation and nonsent-refund
  waits; verification reads again after its ledger wait. Tests revoke consent
  during every one of those waits, replace the owner during both admission
  waits, change every identity field during verification, and lower the cap
  during both admission waits.
- **Finding 3, P1:** the binding is a backend-discriminated union. Model API
  consent excludes `not-required`; the runtime guard also refuses an untyped
  stale subscription consent value with `consent-needed`. Metered admission
  and dispatch both require `granted`.
- **Finding 4, P2:** each claim id owns explicit `open`, `settling`,
  `settled` and `refunded` lifecycle state. Settlement closes dispatch before
  its first store wait, coalesces identical in-flight settlements and refuses
  conflicting ones. Store failures retain both liability and the dispatch
  prohibition; identical retries may finish settlement. Verification checks
  state before and after its wait, including an actual cost equal to the
  reservation. Dollar equality no longer determines openness.
- **Finding 5, P2:** reservation and settlement resolve and validate the
  same injected `priceOf` tariff, now including `cachedInput`. Custom rates
  USD 2/0.5/8 per million reserve USD 0.0028 and settle USD 0.0028 uncached
  or USD 0.0022 with 400 cached tokens. A missing tariff throws the named
  `JudgeUnpricedError` and keeps the reservation; unusable rates refuse too.
- **Finding 6, P3:** two independent real journal instances start admission
  concurrently. A barrier records both reading USD 0.002 before either may
  reserve. A second barrier interleaves reservation so the first window owns
  USD 0.001675 before the second checks its stale admission. The second
  refuses `ledger-unavailable` through the journal's synchronous guard and
  its owned known nonsent reservation settles at zero. A fresh journal reads
  exactly USD 0.001675 and the winner still verifies. This proves controlled
  overlapping admissions and cleanup, not canonical daily scoping or every
  possible cross-process scheduling order.

### Public seam changes for M98U / FIXDEF

Existing binding-value and verification call forms remain accepted. Live
host wiring must provide `JudgeAdmissionRequest.currentBinding: () => binding`
and pass the same reader as verification's second argument when a session or
consent object can be replaced. The fallback reads `request.binding` again,
and supports a mutable supplied object, but cannot discover a replacement
outside that request.

`JudgeAdmissionBinding` is now a type union rather than an interface; Model
API excludes subscription consent. `JudgeTokenPrices` requires `cachedInput`.
`JudgeLedgerClaim` requires synchronous `check(): void` (an adapter may discard
D78's returned totals). `JudgeAdmissionClaim` adds `status()` and `check()`.
Tariff loss during settlement now throws `JudgeUnpricedError`, not a generic
ledger error. Refusal unions and remaining/reserve/settle argument shapes stay
the same. Budget/Stop/day/claim-check exceptions map fail-closed to
`ledger-unavailable`, with no string-based error classification.

The sender must read/rebind once more after awaiting verification, then call
the synchronous claim check immediately before its actual send, with no
intervening await. A later wait requires those checks again. Lane A creates
no process, dispatch, modal, store, lock or journal.
D78/FIXDEF owns canonical daily namespaces, lock stability, network-home
refusal and its production adapter. Those original integration dependencies
remain open; this lane does not certify them. No shared guard or gate changed.

CHANGELOG/PLAN/README remain lead/lane-D-owned under the lane scope. Suggested
Unreleased entry for integration: “Fixed Muse Judge admission against stale
budgets and consent, closed-claim reuse and injected-tariff settlement;
concurrent journal reservations now prove known nonsent cleanup.” No command,
setting, script, dependency, translation or wire shape was added here.
