## What this lane owns

New `src/core/judge/same/` (backend-agnostic; no `vscode` import) and new
`src/host/judge/` host adapters, with new `test/unit/judgeSame*.test.ts`
(54 tests). Behaviour, per the lanes table:

- `sideRequest.ts`: the Model API side request from ModelApiHost's own built
  body — the cached prefix (model, instructions, tools: exactly what
  `promptCacheKey` digests) copied byte-exact with the redacted judge tail
  appended, everything else identical (model, tools, cache key). Redaction
  first: a changed prefix byte goes standalone. Below the cacheable minimum
  goes standalone. The main body is never edited, reordered or trimmed.
- `allowRules.ts`: the CLI user-settings allow-rule check. Missing settings
  or no standing selection stays on; a standing write allow
  (`filesystem.mode: write`), a standing network allow (`network.mode:
enabled`), non-empty network targets, unidentified dimensions (a parentless
  profile needs two more than `network` and `filesystem`, and either may
  allow shell), dangling/cyclic `extends`, and anything malformed turn the
  judge off. Shapes captured from the installed Muse Code 1.4.2 binary (see
  below).
- `sessionSpec.ts`: the hidden-session spec — Plan approval mode
  (`denyUnmatched`, as M90), the conversation's model, the batch's own folder,
  no MCP servers at all — and the M90 item guard (message, reminder,
  reasoning and reply kinds only; any tool item cancels).
- `scheduler.ts`: background calls with a timeout abort — never awaited on a
  user path — reporting failures once and never escaping.
- `batches.ts`: the dispatch both adapters share (added while clearing the
  duplication gate): the `SameJudgeRunnerDeps` seam, one batch per question
  kind over the full state, background launch, the latch-and-cache commit
  that drops late results, and the single `judgeHeldAction` entry.
- `resultCache.ts`: the per-window, memory-only result cache, bounded with
  oldest-first eviction. Nothing is written anywhere.
- `answers.ts`: the shared stated settle both backends run — reply JSON
  decode (whole text or its outermost object), lane J's parser per question,
  labelled assembly. Only a `noul` at or above `JUDGE_ADVISORY_THRESHOLD`
  settles `caution`; a "safe" answer settles `none` and changes nothing.
- `wording.ts`: lane J's injected wording built from the new
  `JUDGE_MODEL_TEXT` at call time; the standalone turn fences the judged text
  as data on its own with "Use no tools."
- `src/host/judge/modelApiSameJudge.ts`: the Model API adapter. Reads the
  host's own keyed body through the injected `ModelApiJudgeSource`, refuses a
  model switch without sending, sends one batch per question kind in the
  background through the injected transport, settles the latch, and caches
  only while the entry stands (a late result is dropped, never cached).
  Uncaptured models state (D77): the injected capability defaults to
  logprobs-refused, so phase 1 always states; a non-stated selection settles
  failed loudly rather than guessing.
- `src/host/judge/museCodeSameJudge.ts`: the Muse Code adapter. Settles from
  the cache, re-checks the allow rules before each batch, then judges each
  kind's batch in its own fresh hidden session (`session/start` on the same
  host, empty temp folder deleted after even on failure, thinking off), with
  the tracker attached before the turn is sent so no frame is missed. Never
  M90's session, never the main one, never held across calls.

Shared-file touches (minimal, lane-owned additions only): `JUDGE_MODEL_TEXT`
plus `JUDGE_MIN_CACHED_PREFIX_TOKENS` and `JUDGE_RESULT_CACHE_MAX` in
`src/shared/constants.ts`, and the `JUDGE_MODEL_TEXT` guard entry in
`scripts/check-bundle-split.mjs` with no readers yet — lane D names the

## Seams for the parallel lanes

- `ModelApiJudgeSource` (`readMainBody`, `keyPrefix`, `prefixTokens`) and
  `ModelApiJudgeTransport` (`send`): one-line wiring each in the Model API
  integration reads the host's own builder/counter and streams the side body
  through the conversation's model and endpoint. The fakes in
  `judgeSameModelApi.test.ts` are annotated with these types, proving the
  seam.
- `MuseCodeSameJudgeDeps` (`startSession`, `readSettingsText`,
  `makeTempRoot`/`removeTempRoot`, `onSideSession`, …): the window wires the
  host, the settings-file read, and an extension-owned temp root outside every
  workspace.
- `measureTokens` is a required dependency on both adapters: the wiring hands
  the model's own counter (lane J's backstop reads it).
- `capability` defaults to logprobs-refused: phase-2 section 2e fills it from
  captured per-model capability blocks; nothing else changes.
- Costs ride the jobs (`reservedCostUsd`, `settledCostUsd`): lane A fills them
  from its reservation; unset stays unset.
- Reason codes (`standing-allow-rules`, `settings-unreadable`, `no-settings`;
  settle failures) are lane U's to display through lane 0's strings.

## Captures (all on this rig, 2026-10-05)

- MSP `session/start` params/result and `turn/start` params: `muse schema
generate-json-schema` on Muse Code 1.4.2 (offline, exact for the binary);
  `approvalMode` is closed (`allowAll`, `promptUnmatched`, `onRequest`,
  `denyUnmatched`); plan maps to `denyUnmatched` (already in
  `src/shared/permissionModes.ts`, as M90 uses).
- CLI user settings: ~175 offline probes (`serve --provider echo` with
  `XDG_CONFIG_HOME` pointed at scratch files, plus `skills list` and `config
status`; no model call, no cost). Observed: `schema_version: 1` at both
  levels; the `permissions` block holds `default_profile` (dangling names are
  refused per session) and `profiles`; a profile holds `description`
  (string), `extends`, `workspace_roots`, `network`, `filesystem`; `network`
  has `mode` (`restricted`, `proxy_only`, `enabled`) and `targets` (a map);
  `filesystem` takes `{"mode": ...}` (`read`, `write`, `deny`); a parentless
  profile must define all four dimensions. `run.code_mode` is an
  `enabled`/`off` toggle of unknown purpose and is not read.
- Residuals, honestly labelled: the two dimension names beyond `network` and
  `filesystem` are unidentified (any profile carrying them fails closed);
  `JUDGE_MIN_CACHED_PREFIX_TOKENS` (1024) is a conventional floor — Meta's
  own minimum cacheable length is unmeasured and is open for lane G on the
  M91-G harness; TUI "always allow" answers persist per session (retained
  amendments), not in user settings, so a fresh judge session is unaffected
  by them.
