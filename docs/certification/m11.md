## What the milestone rests on

- VS Code's workspace-trust contract for extensions (`capabilities.
untrustedWorkspaces`, `restrictedConfigurations`, `virtualWorkspaces`,
  `extensionKind`), applied in M10's manifest edit and exercised here by
  the Diagnostics report and the Restricted Mode paths.
- GitHub's reusable-workflow rules: a same-repository `workflow_call`
  receives `GITHUB_TOKEN` without `secrets: inherit`; semgrep's
  `secrets-inherit` rule flagged the first draft of `ci.yml` and
  `release.yml`, and the line was removed rather than excused. Dependabot's
  `cooldown` option (semgrep's `dependabot-missing-cooldown`): seven days
  on both ecosystems.
- Private vulnerability reporting was enabled on the repository
  (`PUT /repos/RandyNorthrup/muse-spark-code/private-vulnerability-reporting`),
  so `SECURITY.md` points at a form that exists.

## Security

- Session files hold conversation text, tool outputs and patches, in the
  per-user, per-workspace storage directory VS Code assigns, never in the
  repository; the API key is never in them (`snapshot()` has no field for
  it). Ids are validated before they name a file.
- The Diagnostics report writes booleans for credentials and a count for
  environment variables; the logger's redaction still applies on top.
- The workflows pass no secret to the reusable build; the Marketplace PAT,
  when the owner adds it, reaches only the publish job as `VSCE_PAT`.
- Dependabot waits seven days after a release before proposing it.

## Findings recorded during the milestone

- semgrep's `secrets-inherit` and `dependabot-missing-cooldown` rules are
  in the `auto` config now; both were right and both fixes are the
  documented ones.
- The fork's save is queued behind earlier saves; the host gained `flush()`
  so a caller (and the test) can wait for the queue, and `close()` awaits
  it before the host is forgotten.
- Prettier's YAML parser refuses `key: value with: colon` unquoted; the
  bug template's description is quoted.
