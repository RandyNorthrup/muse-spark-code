## What the milestone rests on (verified before code)

- The Meta Model API documentation, read on 2026-09-22 (dev.meta.ai/docs:
  `api-reference/responses/create-response`, `protocols/responses`,
  `tool-calling`, `reasoning`, `error-handling`, `token-counting`,
  `api-reference/models`, `pricing-rate-limits`, `models`, `coding-agents`,
  `muse-code/auth`, `muse-code/subscriptions`): the request fields, the
  output item and streaming event shapes, `tool_choice` only `"auto"`, the
  function tool format, `function_call_output` results, encrypted reasoning
  replay with `store: false` and `include: ["reasoning.encrypted_content"]`,
  `reasoning.effort` with `max` on Standard 1.3 only, the error envelope
  and the retry policy (429 / 500 / 503 retryable with backoff and
  `Retry-After`; 400 / 401 / 402 / 403 / 404 / 413 / 504 not), the model
  list shape, and the 1,048,576-token window.
- The owner's billing finding: the CLI "uses `META_API_KEY` if set, then a
  stored key, and only then a stored browser session", and "the subscription
  applies to the Muse Code API key that is automatically connected in the
  Muse Code CLI onboarding process … for use with Muse Code only". The CLI's
  own `auth.json` on the owner's machine holds `obtained_via: device_code`,
  `mechanism: oauth`, an access token and a CLI-minted key (metadata read,
  values never printed). The extension's `META_API_KEY` injection (M2) was
  therefore routing subscription work to the pay-as-you-go key whenever a
  key was pasted into the panel; removed in this milestone (PLAN.md D1).

## Security

- The pasted key is read from SecretStorage per request, sent only as the
  `Authorization` header to `https://api.meta.ai/v1`, never logged (the
  logger redacts `LLM|…` shapes anyway) and never passed to any child
  process.
- Tools resolve every path against the workspace root and refuse escapes on
  both path styles; the shell runs one command line through PowerShell /
  bash as an argument array with a capped timeout and output; edits are
  gated by the permission engine in Manual and Plan, commands in every mode
  but Bypass.
- Requests are stateless (`store: false`): the conversation is replayed
  from the extension's memory each turn and nothing is kept on Meta's side.
- The contributor tier needs an explicit yes per conversation and is
  unavailable in a confidential workspace.

## Findings recorded during the milestone

- **The billing leak** (above): fixed by removing the injection, with the
  backend selection making the two credentials mutually exclusive.
- `Array.fromAsync` needed the `ESNext.Array` lib entry in the unit
  project (Node 22 has it; the ES2024 lib does not list it).
- TypeScript 5.5+ infers type predicates from `filter` callbacks, which the
  lint rule `no-unnecessary-condition` then enforces: `events.filter((e) =>
e.type === 'x').map((e) => e.field)` is already narrowed.
