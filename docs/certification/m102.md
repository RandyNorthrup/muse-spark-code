## Composition

Merge commits preserve Efix (`ba8a9de8`), Sfix (`7cb2900a`), L (`9aac9456`),
U (`66e3ad61`), R (`c4baf4d2`), then M104 C (`da79fd51`) in that order.
Documentation and translation conflicts retain the union. C's additional release
train changes, including paid admission, browser checks and What's New, are
retained alongside R's observation hooks and M95 provider policy. Generated
host API and notice records are regenerated rather than resolved by hand.
The combined plan keeps M101–M104 in §6 and unions the gate receipts into one
§7. Four standalone usage browser programs are real Knip entry points; the
unused host trace-log compatibility re-export is removed. Repeated local-date
formatting and test fixture code are shared, without duplication exclusions.

S's separate `src/runtime/usage/companionServer.ts` is removed. Usage is a
handler on `src/runtime/companion/server.ts`: one-use `/#k=` launch codes,
separate memory bearers for windows, Authorization headers, fetched event
streams and no cookies. Anonymous `/` serves only the bootstrap; assets,
controller requests and streams require a bearer. Cross-window and wrong-count
answers cannot approve deletion. Closing a stream cancels its pending approval.

W composes J's store with S's service/formatter and U's page in three lazy Node
entries. Native VS Code, the browser companion, ACP, CLI and headless reads use
that composition. Page reads settle the recorder first. Exports use the same
journal snapshot as their checked page state. The daily budget view reads an
existing ledger without creating one, includes reservations as uncertain
liability, and leaves every admission operation intact. Installed usage tables
are embedded as `usage/table` messages before mounting.
Native history changes persist the shared preference too. Native reads combine
their configured switch with that preference, so a companion's history-off
choice is reflected in both the recording writer and the native page.
