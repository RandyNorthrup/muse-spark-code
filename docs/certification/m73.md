## What is built

PLAN.md M73 "Status 2026-10-01" lists it. In short: an output over 8,000
characters rides whole for 2 requests, then as a sticky placeholder under
the threshold; a request counts at the client's last step before `fetch`,
once however often it is retried; `recall_output(id, offset)` returns the
original in 4,000-character pages; the replay keeps every original; the
ledger is the estimated tokens left out, shown in Account & usage only
while a session packs. The M75 `packing` arm turns it on, and since its
run passed, the setting (below).

## Acceptance (PLAN.md M73)

- `recall_output` returns the original bytes: `pages the original back
byte for byte` (store) and `recalls the original bytes back, page by
page` (host over the fake Model API) rebuild the output exactly.
- The swap happens once per output: `sends an over-threshold output whole
for its first requests, then packs it`, `keeps the swap sticky`,
  `packs each output on its own count`, `counts a retried attempt of the
same request once`, and the host's retry tests.
- The ledger matches the tokens left out: `matches the tokens the packed
sends left out` and `counts the ledger in tokenUsage` compare it with
  `estimate(full) − estimate(placeholder)` per packed send.
