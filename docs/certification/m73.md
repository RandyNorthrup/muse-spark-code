## What is built

PLAN.md M73 "Status 2026-10-01" lists it. In short: an output over 8,000
characters rides whole for 2 requests, then as a sticky placeholder under
the threshold; a request counts at the client's last step before `fetch`,
once however often it is retried; `recall_output(id, offset)` returns the
original in 4,000-character pages; the replay keeps every original; the
ledger is the estimated tokens left out, shown in Account & usage only
while a session packs. Only the M75 `packing` arm turns it on.

## Acceptance (PLAN.md M73)

- `recall_output` returns the original bytes: `pages the original back
byte for byte` (store) and `recalls the original bytes back, page by
page` (host over the fake Model API) rebuild the output exactly.
- The swap happens once per output: `sends an over-threshold output whole
for its first requests, then packs it`, `keeps the swap sticky`,
  `packs each output on its own count`, `counts a retried attempt of the
same request once`, and the host's retry tests.
- The ledger matches the tokens left out: `matches the tokens the packed
sends left out` and `counts the ledger in tokenUsage` compare it with
  `estimate(full) − estimate(placeholder)` per packed send.

## The M75 run for M73: not run

The live harness reads the Model API key only from the ACP agent's OS
credential entry (`Muse Spark Code (Unofficial)`, account
`museSpark.modelApiKey`; PR #63's thread P1). This machine holds no such
entry (Windows Credential Manager lists no target with "muse"); the test
key exists only DPAPI-encrypted for `claude-muse-mode\key.ps1`, an
apiKeyHelper that prints it. Putting it into the entry stores the key in a
new place, and a new key source in the harness changes PR #63's reviewed
design; both need the owner (PLAN.md §3). Nothing was improvised: no model
call was made, so there are no attempts and no cost to report.

Expected when it runs (`MUSE_LIVE_MODEL_API=1`,
`MUSE_EVAL_REPORT=docs/certification/m73-run`, `npm run build:dev` first):
two arms × (the ten small tasks, 39 calls measured in M75's baseline, + two
long-output tasks at about 6 calls each) ≈ 102 model calls, a few cents at
contributor rates; the harness stops at $0.50 or on any sent call whose
usage is unknown. Acceptance: verdict `pass` (both splits ran, every arm
holds 0.75), and `unengagedLongOutputTasks` empty. Then the setting is
added, off by default, with its README and CHANGELOG lines.
