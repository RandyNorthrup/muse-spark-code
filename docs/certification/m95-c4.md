## Failure-path findings (all fixed, all tested)

- llama.cpp's HTTP 400s carry a **numeric** `code` (`{"error":
{"message": "…", "type": "exceed_context_size_error", "code": 400}}`).
  The shared `errorBodySchema` rejected it, so overflows read as a bare
  `HTTP 400` and the overflow classifier never fired. The schema now
  decodes numbers to their decimal text.
- LM Studio's HTTP 400 is a **bare string** (`{"error": "Invalid
tool_choice type: 'object'. …"}`). The schema now decodes a string to a
  message-only object. Its engine failures stream as SSE error events
  under HTTP 200, which the chat codec already maps (golden-pinned).
- llama.cpp echoes its **model id as the GGUF file path** in lists and
  chunks; LM Studio reports a clean id. Paths stay in the frames (that is
  the wire truth; no secret in them) and the panel shows them as
  untrusted text beside the preset label.

## Probe fetch (M95 step 1)

Scan this computer no longer uses VS Code's patched `fetch` (it honors
`http.proxy`, and its loopback bypass depends on user settings and VS Code
version). New `src/host/providers/loopbackFetch.ts`: plain `node:http`
GETs to 127.0.0.1/::1 only — anything else (including `localhost`, which
can resolve off loopback), non-`http:` URLs, credentials and non-GET
methods are refused before any lookup or connection; bodies past
`LOOPBACK_FETCH_MAX_BODY_BYTES` (64 KiB, new constant) are refused rather
than read. Wired as `loopbackFetch` in `modelsPanelEntry.ts`.

## Environment-blocked work (evidence, not green paint)

- **vLLM serve.** `VLLM_TARGET_DEVICE=cpu` selects the CPU platform, but
  the 0.31 engine's ZMQ control plane uses `ipc://` with no TCP fallback
  and this sandbox denies `AF_UNIX` entirely (bare `socket(AF_UNIX)`
  raises `EPERM`). Retry `capture_vllm.py` (kept in lane scratch, not
  committed) off-sandbox; the preset and its `wireCapture: false` are
  untouched.
- **5 socket tests in `providerLoopbackFetch.test.ts`.** This sandbox
  diverts default-Agent `node:http` client connections to its proxy
  (HTTP 502 `upstream connection failed`), while `node:net`, Python and
  `agent: false` loopback all go direct — reproduced 3/3 each way, plus
  `checkProxy.test.ts` 14/14 green (it uses `node:net`). The 4 refusal
  tests pass here; the 5 socket tests follow the established real-socket
  pattern and run wherever loopback is real (CI, the lead's machines).
- **VS Code's patched fetch** could not be measured here (no VS Code on
  the rig); the probe sidesteps it by construction instead, so there is
  nothing version-dependent left to measure.
