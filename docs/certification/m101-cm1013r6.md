## Item 1 — the frozen digest is the same on every platform

At `38151e597` the Windows host computed `963f0269…` where the pin was
`0efbcc53…`, with LF files on both sides, so `--live-m75` refused
before any credential or call. The freeze read working-tree bytes and
enumerated working-tree files (a `readdir` walk plus esbuild metafile
keys), so anything a checkout adds or rewrites per platform moves the
digest even when the committed content is identical. The digest is now
a pure function of canonical inputs (`src/core/eval/mechanisms.ts`):
repository-relative forward-slash paths, CRLF pairs and lone CR folded
to LF, UTF-8 byte-order sorting, and the `src` family walk intersected
with the files Git tracks. A file the run actually loads stays hashed
through the resolver graph, tracked or not, so the freeze still
refuses a dirty tree; untracked scratch, editor backups and merge
leftovers never move it. The exact stray input on the Windows box
cannot be reproduced from macOS, so the fix excludes the whole class
rather than the one file; the lead verifies on Windows with
`node scripts/m101-e.mjs --check-freeze`.

Round 6 blamed the checkout platform for the Windows mismatch; the lead
measured instead of guessing. Every component of `freezeEvalHarness()`
was printed on both machines at `01bcd633a`: exactly one differed,
`searchWorker.code` (40,450 characters there, 40,369 here). The 81

`// ../../../node_modules/zod/v4/core/util.js` (nine such lines) there,
`// node_modules/zod/v4/core/util.js` here. The other checkout is a Git
worktree nested three folders below the main repository, resolving its

text contained the relative location of the dependencies folder: any
worktree, hoisted or linked install, or monorepo layout moves the
digest, on any operating system.

The worker build now uses the build tool's own whitespace minification
(`minifyWhitespace: true, legalComments: 'none'` in
`src/core/eval/mechanisms.ts`): no path comments are emitted, and
identifiers and syntax are untouched. Sweep of every other `buildSync`
output that reaches a hash or the frozen record: the arm bundles
already build with `minify: true, legalComments: 'none'` (verified free
of `node_modules`/`../` text); the runner-config reader, the
resolver-graph metafile and the launcher's scratch adapter are executed
locally, never hashed or stored. The frozen worker bytes still run:
the new test executes them through `searchOnWorker` against real files.

`test/unit/eval/evalFreezeLayout.test.ts` proves the real case. It
