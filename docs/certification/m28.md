# M28 certification — macOS dictation asks under its own name; the release token's environment (PLAN.md M28, D29)

Recorded 2026-09-23. The macOS part ran on the owner's Mac mini (Intel,
macOS 15.7.4, Swift 6.1.2, the owner logged in at the console), over SSH,
building the helper from this branch with `native/darwin/build.sh`
(universal, version embedded, ad-hoc signed).

## The helper disclaims the app that started it

`Dictation.swift` now starts a copy of itself before it asks macOS for
anything:

- **The copy:** started with `posix_spawn`, its attributes marked by
  `responsibility_spawnattrs_setdisclaim`. The call is looked up with
  `dlsym`, and where it is missing the helper runs as before and says so
  on stderr.
- **The parent:** stays as a thin relay. It forwards SIGTERM, SIGINT and
  SIGHUP to the copy and exits with the copy's status (128 plus the
  signal when the copy was signalled).
- **stdin, stdout and stderr:** inherited unchanged.
- **The refusal text:** names `muse-dictate` and its System Settings entry.

## What tccd did

The helper was launched from an SSH shell, `--app-name "Visual Studio Code"`.

| Launch                            | tccd                                                                                                                                                                                                                                                                                                        | Outcome                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| As built                          | `AUTHREQ_ATTRIBUTION … requesting={identifier=dev.randynorthrup.muse-spark-code.dictate, pid=71462, binary_path=…/muse-dictate}` with no responsible app; then `AUTHREQ_PROMPTING … service=kTCCServiceSpeechRecognition, subject=Sub:{dev.randynorthrup.muse-spark-code.dictate}Resp:{… the same process}` | macOS prompts for the helper itself; the request waits for an answer |
| The same binary, disclaim skipped | `AUTHREQ_ATTRIBUTION … responsible={identifier=com.apple.sshd-keygen-wrapper …}` then `Policy disallows prompt for Sub:{/usr/libexec/sshd-keygen-wrapper}`                                                                                                                                                  | refused at once, exit 2                                              |

- **The process tree:** parent 71457, disclaimed copy 71462 at the absolute
  path.
- **The relay:** a SIGTERM to the parent alone ended both, and the parent
  exited 143.

Not observed: the prompt on screen and a grant. `screencapture` over SSH
has no screen-recording rights and shows only the desktop; answering the
prompt and dictating in VS Code need a person at the Mac. No grant was
recorded: each test prompt ended with its process.

## The check CI runs

`native/darwin/check-disclaim.sh`, a step of the macOS CI job after the
build, runs the helper with the copy's marker cleared and requires three
things:

- **Its own name:** stderr says "asking macOS for speech recognition for
  muse-dictate", which only the disclaimed copy says.
- **A pending request:** the parent has a copy of the helper as its child,
  and a SIGTERM ends both within 15 s, the parent with 143.
- **A request answered at once:** the exit code is the refusal code, 2.

Fired on the Mac mini, each break built from a copy of the source:

| Break                    | Result                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| As built                 | "disclaimed request pending; SIGTERM ended both processes (exit 143)", exit 0                                                    |
| The re-launch removed    | "the request was not made under the helper's own name: step: asking macOS for speech recognition for the disclaim check", exit 1 |
| The signal relay removed | "the helper did not end within 15 s of SIGTERM", exit 1                                                                          |

A first version of the check was fooled by setting the copy's marker by
hand, which also makes the helper use its own name. The check now clears
the marker and looks for the child process, and the breaks above are code
changes. No helper process was left on the Mac after any run.

## The release token's environment

- **Created:** the `marketplace` environment
  (`gh api -X PUT …/environments/marketplace`, custom deployment policies),
  whose only policy is the tag pattern `v*` (type `tag`).
- **Wired:** `release.yml`'s publish job names `environment: marketplace`.
  Until the environment holds `VSCE_PAT`, the repository secret still
  reaches the job, so nothing changes in between.
- **The token:** a new Marketplace-Manage PAT scoped to the `securecoast`
  organisation, since Azure DevOps stops all-organisation PATs on
  2026-12-01, so the current one would stop before its 2026-12-22 expiry.
  It is checked with `vsce verify-pat` before it is stored, set as the
  environment's secret from the clipboard, and then the repository secret
  is deleted. The record of that step follows below once it is done.
