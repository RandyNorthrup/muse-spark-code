# M28 certification — macOS dictation asks under its own name; the release token's environment (PLAN.md M28, D29)

Recorded 2026-09-23. The macOS part ran on the owner's Mac mini (Intel,
macOS 15.7.4, Swift 6.1.2, the owner logged in at the console), over SSH,
building the helper from this branch with `native/darwin/build.sh`
(universal, version embedded, ad-hoc signed).

## The helper disclaims the app that started it

`Dictation.swift` now starts a copy of itself before it asks macOS for
anything:

- **The copy:** started with `posix_spawn`, its attributes marked by
  `responsibility_spawnattrs_setdisclaim`. The call is looked up with
  `dlsym`, and where it is missing the helper runs as before and says so
  on stderr.
- **The parent:** stays as a thin relay. It forwards SIGTERM, SIGINT and
  SIGHUP to the copy and exits with the copy's status (128 plus the
  signal when the copy was signalled). The relay is in place before the
  copy exists (the review, below).
- **stdin, stdout and stderr:** inherited unchanged.
- **The refusal text:** names `muse-dictate` and its System Settings entry.

## What tccd did

The helper was launched from an SSH shell, `--app-name "Visual Studio Code"`.

| Launch                            | tccd                                                                                                                                                                                                                                                                                                        | Outcome                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| As built                          | `AUTHREQ_ATTRIBUTION … requesting={identifier=dev.randynorthrup.muse-spark-code.dictate, pid=71462, binary_path=…/muse-dictate}` with no responsible app; then `AUTHREQ_PROMPTING … service=kTCCServiceSpeechRecognition, subject=Sub:{dev.randynorthrup.muse-spark-code.dictate}Resp:{… the same process}` | macOS prompts for the helper itself; the request waits for an answer |
| The same binary, disclaim skipped | `AUTHREQ_ATTRIBUTION … responsible={identifier=com.apple.sshd-keygen-wrapper …}` then `Policy disallows prompt for Sub:{/usr/libexec/sshd-keygen-wrapper}`                                                                                                                                                  | refused at once, exit 2                                              |

- **The process tree:** parent 71457, disclaimed copy 71462 at the absolute
  path.
- **The relay:** a SIGTERM to the parent alone ended both, and the parent
  exited 143.

The prompt on screen could not be seen from here: `screencapture` over SSH
has no screen-recording rights and shows only the desktop. The owner, at
the Mac, clicked Allow, and tccd recorded the grant for the helper itself:

```
AUTHREQ_RESULT: msgID=71462.1, authValue=2, authReason=2   (allowed, by the user)
```

That was the first test request. A correction to what was assumed while
testing: a prompt does not end with its process. tccd kept each test
run's request queued after the helper was killed, and showed them one
after another (msgIDs 72298.1, 73108.1, 73595.1, each then allowed). So
every run on a Mac where the helper has no grant leaves one prompt behind.
The runs were therefore kept to the ones recorded here. Dictating in VS
Code itself (the panel starting the helper, then speaking) needs a person
and a microphone at the Mac; the mini has no input device.

## The check CI runs

`native/darwin/check-disclaim.sh`, a step of the macOS CI job after the
build, runs the helper with the copy's marker cleared and requires three
things:

- **Its own name:** stderr says "asking macOS for speech recognition for
  muse-dictate", which only the disclaimed copy says.
- **A pending request:** the parent has a copy of the helper as its child,
  and a SIGTERM ends both within 15 s, the parent with 143.
- **A request answered at once:** the exit code is the refusal code, 2.

Fired on the Mac mini, each break built from a copy of the source:

| Break                    | Result                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| As built                 | "disclaimed request pending; SIGTERM ended both processes (exit 143)", exit 0                                                    |
| The re-launch removed    | "the request was not made under the helper's own name: step: asking macOS for speech recognition for the disclaim check", exit 1 |
| The signal relay removed | "the helper did not end within 15 s of SIGTERM", exit 1                                                                          |

A first version of the check was fooled by setting the copy's marker by
hand, which also makes the helper use its own name. The check now clears
the marker and looks for the child process, and the breaks above are code
changes. No helper process was left on the Mac after any run.

## The review of PR #15

The Codex review raised two threads, both real:

- **The cast was not in the escape-hatch register (P1).** It is now in
  PLAN.md §8, beside the join statement's `catch { }` from M27, which was
  missing too.
- **A signal between the spawn and the relay (P2).** The relay was set up
  after `posix_spawn`. A SIGTERM in between ended the parent alone and left
  the copy holding the pipes and its prompt. Now `SignalRelay` registers
  the signal sources first, on a queue of their own, and only then ignores
  the three signals. The copy is spawned with `POSIX_SPAWN_SETSIGDEF`, so
  it keeps their default actions. A signal caught meanwhile is sent on to
  the copy as soon as its id is known, or, if the spawn fails, re-raised
  after the dispositions are restored. The window is microseconds wide and
  cannot be hit from outside on purpose, so this rests on the ordering. The
  rebuilt helper passed `check-disclaim.sh` on the mini ("disclaimed
  request pending; SIGTERM ended both processes (exit 143)").

## The release token's environment

- **Created:** the `marketplace` environment
  (`gh api -X PUT …/environments/marketplace`, custom deployment policies),
  whose only policy is the tag pattern `v*` (type `tag`).
- **Wired:** `release.yml`'s publish job names `environment: marketplace`.
  Until the environment holds `VSCE_PAT`, the repository secret still
  reaches the job, so nothing changes in between.
- **The token** (2026-09-24 03:00 UTC): a new Marketplace-Manage PAT,
  "vsce publish muse-spark-code (marketplace environment)", scoped to the
  `securecoast` organisation and expiring 2027-09-22, the longest Azure
  DevOps offers. It is org-scoped because Azure DevOps stops
  all-organisation PATs on 2026-12-01, so the old one would have stopped
  before its 2026-12-22 expiry.
  - **Minted:** through the browser, the page not read after "Success".
  - **Moved:** the owner copied the token to the clipboard, and one
    PowerShell run took it from there into a variable. Only its length was
    printed (84) before `vsce verify-pat RandyNorthrup` checked it: "The
    Personal Access Token verification succeeded for the publisher
    'RandyNorthrup'." That settles whether `vsce` accepts an org-scoped
    token, which had been open since 0.5.0.
  - **Stored:** the token was piped to `gh secret set VSCE_PAT --env
marketplace`, all output redacted, and the clipboard was cleared.
- **The old tokens:** the repository-level `VSCE_PAT` was deleted
  (`gh secret list` now lists none). The three all-organisation tokens this
  project had used, "vsce publish muse-spark-code" (0.1.0), "… 0.1.1" and
  "… 0.5.0", were revoked in Azure DevOps with the owner's go-ahead.
- **The first real use:** the next `v*` tag's publish job, the first run to
  read the secret from the environment.
- **The Mac mini:** `tccutil reset` needs a registered bundle, which the
  helper is not, so the test grant stays in System Settings > Privacy &
  Security > Speech Recognition as "muse-dictate". It matches only the
  deleted test build's signature, so nothing can use it; resetting the
  service for every app was not an option.
