# M30 certification — skills, imports and export (PLAN.md M30, D30)

Recorded 2026-09-24.

## What the CLI does

These facts were read from Muse Code 1.3.0 (`1.3.0-R3401.1`, Windows 11)
before any code was written. None of the commands below calls a model.

- **`muse skills list --json --workspace <root>`** returns `{ "skills": [...] }`.
  - Each entry carries `id` (`bundled:grill`), `name`, `display_name`,
    `description`, `scope` (`bundled`, `user`, `project`, `plugin`) and
    `activation` (`on`, `off`, `user-only`).
  - `enable` and `disable` take `<name> --scope user|project|built-in|plugin`.
    The listed `bundled` is spelled `built-in` on these commands.
- **`muse skills import --from claude --dry-run --json`** returns `source`,
  `dry_run`, `candidates` (`id`, `action`, `valid`, …), `installed`,
  `quarantined`, `skipped` and `failed`.
- **Does a running `muse serve` follow activation changes?** Probed with the
  SDK: `XDG_CONFIG_HOME` pointed at a throwaway folder so the owner's
  settings were untouched, and `session/start` plus `skill/list` only.
  - `muse skills disable grill --scope built-in` returned
    `"activation": "off"`.
  - Yet `grill` stayed listed, in the running session and in a new session
    on the same host.
  - So the change applies only after a restart, and both commands end by
    offering one.
  - The same probe showed `resume-claude` and `resume-codex` among the
    session's selectors.
- **`muse export --session <id> --out <file>`** writes the session's JSON
  trajectory (`export_schema_version` 1) and reads local files only.
- **Session messaging (not built, D30):** `muse session-message list --json`
  answers `{"status":"unavailable","error_code":"session_messaging_unavailable"}`
  on Windows, and the docs exclude headless sessions, which every panel
  session is.

## The change

- **`src/core/backends/musecode/skillsCli.ts`:** zod schemas for both JSON
  shapes, the argument builders, and the diff from the checklist to
  enable/disable calls. A scope the CLI cannot toggle is left out.
- **`src/host/commands/skillsCommands.ts`:** the Manage and Import flows.
  - The CLI runs by absolute path with an argument array, in `muse serve`'s
    environment, with `--trust-workspace` only in a trusted folder.
  - Changes run one at a time, since each rewrites the settings file.
  - Failures are reported per skill, and the restart is offered only when
    something changed.
- **`src/core/export/transcriptMarkdown.ts`:** the Markdown renderer.
  - Every kind the panel shows; hidden kinds are left out.
  - Fences are longer than any backtick run in the content.
  - File names are safe on every file system.
- **`src/host/conversation/exportConversation.ts`:** the export itself.
  - The title comes from the session's name, else its first prompt.
  - The session log is refused on the Model API backend before anything
    is read.
- **`src/host/cliFeatures.ts`:** the VS Code side.
  - The multi-select pick, the source pick, the modal confirmation and the
    restart prompt.
  - The save dialogs, and the log export refused for a target that is not
    a local file.
- **Palette** (`src/shared/palette.ts`):
  - Manage and Import head the Skills group on the CLI backend.
  - The Continue rows show only where the session lists the skill.
  - `/export` shows on both backends; Export session log… on the CLI
    backend only.
- **Protocol:** the host actions `manageSkills` and `importSkills`, and the
  message `exportConversation` with format `markdown` or `sessionLog`.
- **Commands:** Manage Skills, Import Skills from Claude Code or Codex, and
  Export Conversation. Export shows in the Command Palette only with a
  panel in view.
