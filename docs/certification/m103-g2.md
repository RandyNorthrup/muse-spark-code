## Design in six lines

1. Host maker enablement, project detection, board presence, roots or machine inventory establishes hardware context.
2. Every model shell there needs a fresh exact-command host answer, except the single strict read-only argv table.
3. Standing grants, reviewer decisions and hook grants cannot authorize these commands; Bypass and unattended origins deny even reads.
4. Classification adds warnings and known irreversible refusals; a missed label cannot grant a hardware shell command.
5. Approvals bind exact bytes, parsed/staged arguments, every observed target identity, one use and expiry; Stop stays out of band.
6. Shared core policy serves Model API/MSP/ACP; first-use guard and shell bundles preserve startup size and ordinary workspace behavior.

## Allowlist and corpus

One table has thirteen exact argv rows. A test per row admits it in the named
dialects and proves one-character prefix/suffix mutations ask through the real
PermissionEngine. Extra flags, chains, wrappers, aliases, substitutions,
expansions, comments, redirects and interpreters cannot match. A workspace
file must be regular, within the lexical and real root, outside board roots,
and reached through no symlink/junction. Reserved Windows device components,
missing paths and missing roots ask. File-system identity races and trusted
executable behavior are not an OS sandbox claim.

Plain git status/diff are deliberately absent: repository fsmonitor/textconv
helpers can execute code. The log row disables paging, signature programs and
decoration. The documented table is conservative rather than a prefix grant.

The original 37-command corpus and all 63 second-review additions are retained:
100 unique commands, **300 command/dialect pairs**. Outside hardware, zero
new physical asks/false positives; standing grants and all four original modes
have their prior verdicts, with absent context identical to empty/false
context. Inside hardware, **13 allowlisted pairs and 287 fresh asks**; every
pair is denied unattended, in each mode. Documentation and board-backup
commands intentionally ask inside hardware under the owner's third design.
