## Launch registry

`ResourceTreeRegistry` implements lane 0's `ResourceTreeReader`. At launch,
`register(ticket)` validates and copies the ticket, reserves its id/root/scope,
and requires the OS reader to prove the exact root's membership. Pending
registrations have no authority. `tickets()` returns private copies for
local consumers; it is never an egress payload. Completion calls
`unregister(ticket)` after the whole tree ends, rather than at root exit.
Readers may implement `forget(ticket)` to retire local accounting state.

Only an exact registered ticket reaches the reader. An actuator calls
`contains(ticket, identity)` anew before every change. Retirement during an
in-flight proof invalidates its result. The harness's own process is refused.
Failed/invalid accounting is null, never a successful zero. Kinds/classes and
session identity use lane 0's contract unchanged.

The launch proof is an injected OS dependency, not an implementation that
pretends registration succeeded. C1/C2 supply only tickets for children they
actually launched, with their kernel start identity and created scope. Lane A
must perform the final identity/membership check at its mutation boundary;
the Windows actuator should check and mutate through the same process/job
handle. No action is implemented by T.

## Platform readers and accounting

- **Windows:** `WindowsResourceTreeReader` uses M27's lazily compiled,
  source-digested assembly. Its `Identity`, `Contains` and `Query` results
  are validated before use. The C# query opens the job with query rights,
  holds each process handle through creation-time and membership checks,
  and returns numerical identities plus lifetime job CPU (including exited
  members) and summed current resident working sets. Enumeration is bounded;
  inaccessible or failed reads become unknown at the reader. T's region
  never joins, terminates, suspends or changes a process. `Contains` proves
  exact creation FILETIME and membership through the same handle. The reader
  also requires the registered root or an observed exact member to anchor
  the job, so reusing its name cannot confer authority. Immutable local
  witnesses retain an observed orphan job across root checks and are cleared
  on retirement.
- **Linux:** exact `/proc/<pid>/stat` start ticks, process group, user/system
  CPU and RSS pages; OS `getconf` supplies clock ticks/page size lazily.
  Concurrent tree samples share one numerical `/proc` scan. The cgroup lane
  accepts only a canonical descendant of the injected harness-owned,
  delegated root under this user's slice. `/proc/<pid>/cgroup` proves current
  membership (including nested scopes), followed by another start-time read.
  Cgroup `cpu.stat` supplies lifetime CPU; RSS still comes from process
  resident pages rather than treating `memory.current`'s page cache as RSS.
- **macOS:** concurrent samples share one numerical `ps` call
  (`/bin/ps -axo pid=,pgid=,time=,rss=`). The injected native inspection port returns pid,
  pgid and exact kernel start microseconds from one `proc_pidinfo` read;
  `ps lstart`'s seconds are never used as identity. Both the numerical table
  and native identities are validated; changed groups/ids are refused.
- **POSIX proof:** a group must be led by the registered root. Current
  group plus exact start identity excludes older/foreign/recycled processes.
  After root exit, a previously observed, still-current member can anchor the
  orphan group; without that continuity witness the tree becomes unknown,
  and a new group cannot take its authority. Targeted Linux/native macOS reads
  recheck membership after the accounting scan before returning an action
  proof. Registry retirement clears the POSIX accounting state.

The Windows orphan parser moves to portable `processTable.ts`, with its
existing host export preserved. POSIX schemas/parsers stay in `posixTable.ts`,
so the tree-kill/activation import does not eagerly load resource contracts
or a governor. Probe processes use absolute paths, argument arrays, bounded
execution and a minimal environment, not the parent's credentials or PATH.
No secret, environment, command line or process name enters resource usage.
The existing Windows orphan-kill parser still retains its name column for
its existing diagnostic path; that is not a resource-history record.

Group fallback CPU is the cumulative **observed** per-process time, retaining
last readings across exits. It is a lower bound: a short-lived process wholly
between samples, or its CPU after its last reading, cannot be recovered from
`ps`/`proc` after exit. RSS is an adjacent-read snapshot, not an atomic global
measurement. Job/cgroup lifetime CPU counters cover exited work. Unobserved
orphan groups fail closed. These are accounting limits, not permission to act
on an unproven member; W should carry them into the final security/accounting
record. The registry's trusted caller is the launch site; it must never
register arbitrary roots from workspace/model input.

## Named handoffs

1. **C1/C2 launch binding:** select the OS reader, acquire `identity(pid)`
   after the child joins its actual scope, and `register` the ticket before
   handing it to a governor/actuator. Generate a fresh ticket id and job/scope
   per launch. Preserve kind, class and session. Register every governed
   spawn; only these lanes can certify all spawn-site coverage. Retire the
   ticket after the whole tree completes, including observed orphans.
2. **A action binding:** use this registry as its `ResourceTreeReader` and
   call `contains` immediately before every change, including recovery.
   Native Windows mutation must keep the identity/membership check and change
   on the same handle. POSIX actions must retain their own final check at the
   OS mutation boundary. T never kills, suspends, elevates or writes controls.
3. **M96 K delegated scope:** inject Linux's actual harness-owned cgroup
   parent as `ownedCgroupRoot`; absent/undelegated scopes use a registered
   detached group. This base has no M96 scope implementation. T does not
   fabricate one or write any cgroup file.
4. **M96 K/W macOS native binding:** implement/bind
   `MacTreeDeps.inspect(pid)` with `proc_pidinfo(PROC_PIDTBSDINFO)`, returning
   only `{pid, pgid, startTime}` (exact decimal microseconds), null only for a
   vanished process, and a failure for an unreadable identity. The base has no
   exact native inspection bridge. The reader therefore requires this port;
   there is no permissive fallback or production fake. Existing lane 0's
   Mac native probe is evidence for this binding, not a shipped adapter.
5. **W/J packaging/history:** include these readers only in the lazy
   resource-governor bundle, bind M27's compiled assembly path on Windows,
   regenerate the host API record, and consume `tickets()` only locally.
   Sum `usage(ticket)` by kind into the strict numerical journal contract;
   tickets/identities/scope paths never cross an egress boundary. W owns the
   final PLAN/CHANGELOG/docs/reference and bundle-entry updates.
6. **Win11 certification:** run the committed real-job test on Windows,
   with the normal M27 compiler, and the native membership/CPU/query failure
   drills there. The local C# 5 syntax compile does not certify Win32 runtime
   structure/layout or operating-system behavior. The full four-platform
   quality gate, including these native controls, belongs to the lead.
