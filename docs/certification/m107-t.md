## Launch registry

`ResourceTreeRegistry` implements lane 0's `ResourceTreeReader`. At launch,
`register(ticket)` validates and copies the ticket, reserves its id/root/scope,
and requires the OS reader to prove the exact root's membership. Pending
registrations have no authority. `tickets()` returns private copies for
local consumers; it is never an egress payload. Completion calls
`unregister(ticket)` after the whole tree ends, rather than at root exit.
Readers may implement `forget(ticket)` to retire local accounting state.

Only an exact registered ticket reaches the reader. An actuator calls
`contains(ticket, identity)` anew before every change. Retirement during an
in-flight proof invalidates its result. The harness's own process is refused.
Failed/invalid accounting is null, never a successful zero. Kinds/classes and
session identity use lane 0's contract unchanged.

The launch proof is an injected OS dependency, not an implementation that
pretends registration succeeded. C1/C2 supply only tickets for children they
actually launched, with their kernel start identity and created scope. Lane A
must perform the final identity/membership check at its mutation boundary;
the Windows actuator should check and mutate through the same process/job
handle. No action is implemented by T.
