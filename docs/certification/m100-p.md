## Delivered P implementation

- `src/core/devices/pairing.ts`: fixed bounded DER X.509 v3 profile using Node
  `crypto`, P-256 and SHA-256/ECDSA. `X509Certificate` reparses/verifies it;
  reconstructing its TBS enforces the exact reviewed profile. No general ASN.1
  parser or cryptographic arithmetic. Public canonical invitation text is
  bounded before JSON; duplicate keys, reflected identities, changed pins,
  expiry, clock skew and altered profiles fail closed. Domain-separated signed
  confirmations bind the entire ordered invitation transcript and the full
  fingerprint each user compared. Both proofs are required; a screenshot or
  copied invitation cannot prove key possession.
- `src/core/devices/grants.ts`: strict local grant binds pair, receiver
  incarnation, repository, revision, exact base/tree/manifest/dirty-preview,
  mode ceiling, approved check/toolchain or ready canonical role/model entry.
  Offer, entry and request caps intersect in all six dimensions. No provider
  config, credential, arbitrary command or permission token is accepted.
- `src/host/devices/deviceSecrets.ts`: qualified local desktop and execution-
  host key placement are mandatory. Private material only uses the injected
  platform secret store, under a per-invitation namespace, with collision,
  write/read/delete/corruption and byte-bound checks. There is no environment,
  file, setting, log or child-process fallback. Returned keys must match the
  exact local certificate. Temporary string references are cleared; this is
  not a claim of memory zeroization.
- `src/host/devices/deviceStore.ts`: explicit owner-only nonsync initialization,
  exclusive per-storage-folder window lock, serialized reads and writes,
  native handle/path identity checks, bounded strict canonical state,
  durable file flush → atomic replacement → directory flush. Missing/corrupt
  state, abandoned lock/stage, native protection or persistence failure blocks
  further work. No timeout recreates an empty store. Used invitations and
  revocations are permanent bounded evidence; exhaustion refuses setup.
  Windows requires a real injected ACL/durability binding and refuses without
  it. The metadata contains public certificates/proofs, never private keys.
- `src/host/devices/devicePairing.ts`: explicit typed UI action adapter, strict
  validation in both bridge directions, resumable offline setup, bilateral
  completion, manual address hint, current-window grants, Pause offers and
  Unlink. Pair completion is paused with no grants. No socket, discovery,
  engine or model is started. Revocation/pause closes this pair's connections
  synchronously before persistence; authorization rechecks state after an
  asynchronous secret read. Only current-incarnation offers are returned.
  Grant revisions replace both the prior grant id and repository mapping;
  persisted state also rejects foreign grant owners and duplicate ids/mappings.
  Unlink preserves unrelated pairs and E's attempt journal; durable key cleanup
  can be retried when the platform store refuses deletion.

Certificate lifetime remains distinct from the five-minute invitation.
Completed pairs do not disappear when setup expires; current certificate
validity is still checked. The caller selects certificate expiry, conservatively
bounded by lane 0's existing 30-day retention ceiling. **P-I-CERTIFICATE-LIMIT**:
I should give this lifetime its own named `DEVICE_LIMITS` constant when
serializing the shared constants region; P did not edit lane 0/I's constants.

These are P's reusable implementation and fake-only/real-local-TLS proofs,
not installed Devices support. Local POSIX owner/mode protection was exercised
on Kubuntu. Same-user processes, the OS account/credential store and the
extension host remain trusted as in PLAN §9. The lock bounds one owner of this
storage folder, not machine-wide worker/resource leases or M96d coordination.

## Findings resolved during implementation

- An initial DER EKU length was wrong. The generated certificate is reparsed
  immediately and the owning tests exposed it; the exact profile was corrected
  before the first commit. A real mutually verified TLS 1.3 exchange now uses
  the production generator, and removing serverAuth fails that exchange.
- A key-store collision could remove a preexisting key during cleanup. The
  adapter now deletes only its attempted newly stored item; a collision is a
  hard failure, preserving the original platform value.
- An asynchronous key read could outlive pause/revoke. State and current offer
  are rechecked after it; unlink's memory revocation and socket closure precede
  the durable update. Three held-read/held-persistence tests prove this ordering.
- A restored offer could belong to a previous receiver incarnation. The
  current incarnation is injected and checked before reading a key, installing
  a grant or authorizing work; returned grants are filtered by that identity.
  This never rewrites historical E attempt ownership.
- A normal metadata replacement could race the native identity check of a
  concurrent read and falsely poison storage. Reads and writes now share the
  same queue; a held native-check test proves replacement cannot start early.
- Public export originally relied on the caller's TypeScript shape. It now
  validates a strict invitation itself before serializing, so extra fields
  cannot escape into copyable text or QR input.
- Reusing a grant id for a revised repository could retain ambiguous rows.
  Replacement now removes the prior id as well as the repository mapping;
  load-time checks reject corrupted pair/device ownership and duplicate grant
  ids/repositories. Positive replacement and four independent corruption
  cases exercise the behavior.
- An oversized metadata test originally only saw the later byte check. It now
  spies on open/JSON to prove the stat bound fires before allocation/parsing.
  The receiver-grant test also advances revision to isolate the incarnation
  guard from its neighboring monotonic-revision guard. After adding persisted
  grant ownership, that defense masked an adapter-guard mutation; a callback
  observation now proves the adapter refuses before changing scope, while the
  real store's persistence validation still runs. The rerun fails by name.
- Duplication exposed repeated test setup/cleanup. Owning test helpers share
  that setup; no production behavior or duplication threshold changed.

## Named integration bindings and incomplete prerequisites

- **P-I-LAZY-HOST** — I constructs the real store/secrets only on an explicit
  Devices action in the lazy bundle, qualifies local execution-host storage,
  supplies the current selected receiver incarnation and setup's actual
  listener application/interface/address/port. No activation/chat secret read,
  socket, module import or model probe is added by these files. Standalone,
  headless, remote SSH/tunnel, WSL/container and web receivers stay refused.
- **P-T-AUTH** — T installs dedicated per-pair TLS contexts using P's matching
  key/certificate and exact actual peer DER pin, with verification enabled,
  no resumption/early data or default unknown-pair context. Receiver listener
  and inbound work use `material`'s default approved-current-offer requirement
  at handshake and per frame; E calls `authorize` before admission. The
  `requiresOffer=false` identity accessor is for explicit setup/receiver grant
  preparation, not an inbound listener/admission bypass. T implements
  synchronous `disconnectPair` socket closure. Port collision requires a
  fresh invitation; no wildcard/alternate-port fallback. Old TLS tickets,
  DNS/interface restrictions, firewall/manual route and reconnect reconciliation
  remain T/E's proofs.
- **P-E-GRANT** — E builds each grant from the receiver's actual trusted local
  repository, approved exact snapshot, role/model/toolchain and caps. P's
  comparison is a scope ceiling, not policy, ordinary approval, paid consent
  or an atomic resource lease. E applies current trust/protected paths, local
  model capabilities/auth/prices/paid consent and M96 admission/retirement.
  Historical attempts, unresolved processes and liabilities remain in E's
  separate durable journal through unlink, restart and re-pair. The owning
  test keeps fake execution evidence byte-exact across those actions.
- **P-I-WINDOWS-STORAGE** — I must supply and qualify real owner-only native
  ACL checks and replacement/directory durability via `DeviceStorageProtection`.
  Missing/refusing bindings fail before opening a usable store. No Windows
  ACL success or macOS credential-store result is claimed on this Linux rig.
- **P-U-QR** — public canonical invitation/proof bytes are available for the
  real lazy QR renderer; text is always available. Lane 0 explicitly records
  that no QR package/pin/audit was selected on this base and the brief forbids
  an unnamed dependency. I must select/audit/pin it in its owned plan/package/
  notice/build files, then U binds rendering. There is no fake QR, home-made
  encoder or claim that the QR path is complete. U also owns keyboard/focus,
  320px, four themes, pseudo-locale, and actual blocked/unreachable recovery.
- **P-I-FLOOR-GATES-DOCS** — only Node 24.18.0 was available here. I/P must run
  the production generated profile on Node 20.18.3 / VS Code 1.99 and current
  installed desktop hosts before opening a supported listener; I qualifies all
  four rigs' secret stores, execution locations and actual default/denied/
  authorized firewall outcomes. I owns lazy packaging/split/knip and the
  inherited `DEVICE_MODEL_TEXT` split guard, plus README, CHANGELOG, PLAN,
  PRIVACY, SECURITY and host API record. No feature catalog exists on this
  base: integration should document Pair, import public invitation, compare
  fingerprint, import proof, manual address, Pause offers and Unlink. There are
  no new public CLI commands/settings here. Other actions use mandatory real
  injected T/E/S ports; tests use fakes only under `test/**`.
