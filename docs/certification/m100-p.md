## First finished piece: offline identities and bilateral confirmation

`src/core/devices/pairing.ts` generates P-256 keys with Node built-ins and a
fixed bounded DER X.509 v3 profile. OpenSSL reparses it through
`X509Certificate`; validation reconstructs the exact TBS profile and checks
self-signature, curve, serial, dates and DER pin. No general ASN.1 parser or
cryptographic arithmetic is introduced. Validity is caller-selected, with
30 days as the conservative upper bound already expressed by lane 0's
retention ceiling; I should give certificate lifetime its own named constant
when serializing the shared constants region. Invitation validity remains
five minutes and independent of the certificate.

Canonical public text carries only lane 0's invitation. QR uses these same
public bytes; U/I bind the renderer (no QR dependency was selected on this
base). It contains no bearer token or private key. Confirmation compares the
entire peer fingerprint and signs a domain-separated canonical transcript,
including both ordered invitations and endpoints. Both signatures must match.
Stored completed pairs validate signed invitation times without expiring
merely because setup's five minutes elapsed; current certificate validity is
still enforced. Activation, chat, network bootstrap and execution are absent.
