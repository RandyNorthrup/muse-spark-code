### State machine and integration contract

1. Lease: `requested → granted → releasing → released`, with unique id,
   generation, window, task, attempt and server. Registry instances in the
   same window also mint distinct ids.
2. Call: `pending → dispatched → answered/failed/abandoned`, with independent
   call id and lease token. Settlement never looks up a holder counter.
3. Pending cancellation abandons only its record. Dispatched cancellation,
   timeout and transport loss retain liability; only terminal results/RPC
   errors, proved process exit or explicit Release anyway end it.
4. Release names its own lease id/generation and waits for all active records.
   Forced abandonment removes the old generation before queue admission;
   old replies, timers, release requests and duplicate completions cannot
   affect a replacement.
5. Shared admission reserves concurrent call slots before continuations run.
   Configured clients use caller-registration/server namespaces; duplicate
   live ids refuse and cancellation snapshots exact records before re-entry.

`ResourceRegistry` owns every transition. The bridge validates tools and
arguments before `acquireCall`, rechecks assignment, asks `dispatch`, and
settles the returned call id. It holds no lease/call counter or in-flight
controller map. `acquire` returns a lease token for reservation; `release`
requires that token. Command runners must use `acquireCall`/`dispatch`, keep
the record until proved process exit, then `settle` and release the token.
The removed holder-based `callStarted`/`callEnded` API must not be recreated
by integration callers. The IDE server keeps failed-start/closed-start retry,
but an obsolete start closes its listener and cannot publish an endpoint.
