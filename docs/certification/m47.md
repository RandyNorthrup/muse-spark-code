## The live capture

The card is built from what Muse Code 1.3.0 actually sends (AGENTS.md rule

checks (contributor model, empty workspace, count afterwards):

- **Where:** an empty folder, `C:\muse-live-m47`, still empty afterwards.
  The owner's `settings.json` has no `run` block, so the workflow tool was
  offered as Muse Code offers it by default; no settings file was edited
  or copied.
- **How:** `muse serve --trust-workspace` driven over MSP by a capture
  script adapted from M43's, approval mode `allowAll`, every notification
  written to a JSON lines file. Model `muse-spark-1.3-contributor`.
- **One turn:** "Use a workflow with exactly one child agent, labelled
  "ping". The child's only task is to answer with the single word pong…"
- **Cost: eight model attempts**, all on the contributor model, counted
  from the CLI's trace logs (`event="model.attempt.lifecycle"
phase="admission"`):
  - a first run stopped after five seconds when the capture script itself
    crashed reading another capture's locked trace log: 2 attempts (the
    turn and a reminder), `cli-a4bc62be-….log`;
  - the run itself: 6 attempts (the turn that launched the workflow, the
    workflow's one agent, the turn the run's completion started, and three

- **The cap.** The script was to interrupt the turn and cancel the run past
  60 attempts. It could not read the trace log while `muse serve` ran

  the run finished in three seconds. A future capture that needs a live cap
  has to count from the MSP stream instead.
- **Free probes** afterwards (three more `muse serve` starts, 0 model

## What was built

- **The card** (`src/webview/components/WorkflowRun.tsx`, read by
  `src/webview/workflowDetails.ts`): name, status, agents, tokens, what
  started it, each agent's state, attempt, time and tokens, the result or
  failure; **Cancel workflow** while the run is in progress, **Skip** and
  **Retry** on an agent that is running (`started`, `usage`), keyed by its
  current attempt. The same view lists the runs in the Agent map.
- **The state** (`src/webview/state/uiState.ts`): a `workflow` row kind,
  saved and validated with the conversation; agents merged by `childId`,
  each read on its own so a shape that differs costs that agent or field.
- **The host** (`MuseSession.cancelWorkflow`, `controlWorkflowChild`): the
  two MSP verbs; `commandRejected` with a reason becomes
  `WorkflowControlRefusedError`, which the controller shows as a warning in
  words (the three captured reasons and msp.d.ts's `stale_attempt`; any
  other as it came). The Model API backend refuses both.
- **The setting**: `run.workflow_trigger_mode` read from Muse Code's
  settings file (never written), each `run` member on its own; the Agent
  map explains the mode and how to change it, and Diagnostics names it.
  Opening the map reads these facts itself (before, the delegation note
  waited for Account & usage).
- **The pill** counts workflow agents with the subagents.

**Token limit (inference from code):** the displayed run number sums each
child's latest reported attempt. `mergeChild` resets usage on a new attempt;
the one-attempt live capture cannot establish a lifetime total across
retries. The panel does not present this number as the subscription bill.
