## What was built

- **The card** (`src/webview/components/WorkflowRun.tsx`, read by
  `src/webview/workflowDetails.ts`): captured generated label (or raw
  `entryId`/fallback), status, agents, tokens, what started it, each
  agent's state, attempt, time and tokens, and the result or failure.
  The same read-only view lists the runs in the Agent map.
- **The state** (`src/webview/state/uiState.ts`): a `workflow` row kind,
  saved and validated with the conversation; agents merged by `childId`,
  each read on its own so a shape that differs costs that agent or field.
- **The host** maps captured workflow items and tool rows. Owner-control
  requests and accepted acks are not parsed or exposed by this milestone;
  the refusal probes above remain research evidence for a follow-up.
- **The setting**: `run.workflow_trigger_mode` read from Muse Code's
  settings file (never written), each `run` member on its own; the Agent
  map explains the mode and how to change it, and Diagnostics names it.
  Opening the map reads these facts itself (before, the delegation note
  waited for Account & usage).
- **The pill** counts workflow agents with the subagents.

**Token limit (inference from code):** the displayed run number sums each
child's latest reported attempt. `mergeChild` resets usage on a new attempt;
the one-attempt live capture cannot establish a lifetime total across
retries. The panel does not present this number as the subscription bill.
