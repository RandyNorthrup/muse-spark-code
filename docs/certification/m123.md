| Guard                                             | Break                                        | Failing test                                         |
| ------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------- |
| Never force (`nativePushArgs`)                    | add `--force` to the plain push              | pushes exactly the remote and the refspec            |
| Argument allowlist (`assertNativeGitArgs`)        | drop `push` from the subcommands             | accepts every command the service builds             |
| Push/fetch user environment (`isUserEnvironment`) | strip even with the flag set                 | keeps the user environment through the real runner … |
| Token grep (`nativeFailureText`)                  | show git's words raw                         | redacts a credential-shaped failure …                |
| Cancel reaches git (window signal)                | stop passing `signal` to the run             | stops a push when the window closes                  |
| Last-line push check (`isPlainRefspec`)           | accept any refspec                           | refuses a push whose refspec … at the last line      |
| Unmatched upstream (`toPushHead`)                 | fall back to no upstream instead of refusing | refuses an upstream no remote answers …              |

Findings while drilling. Killing git mid-hook settles the run only once
the orphaned hook drains its inherited pipes: in the bare test process
(no M107 admission) a `sleep 5` hook held `close` past the test timeout,
so the drill uses `sleep 1` and asserts Cancel wins either way; with
admission bound (every real host) `stopResourceTree` ends the tree.
Process-table inspection (`ps`) is blocked in this lane's shell sandbox,
so the drill proves settlement and timing instead. The pre-existing
`duplication` failure on `3e9c740d4` (one self-pair in
`modelApiLoopGuarantees.test.ts`) is untouched; this lane adds no pair.
