## Controller (first finished piece)

`ResourceActuators` uses the launch registry before opening controls and before every mutation or recovery. It saves originals once, serializes each ticket, reports failed reads/writes/readbacks as unknown, and retains failed restoration for retry. Foreground work is excluded; Muse Code acts only at pause. Irreversible controls act only at pause and report `lifetimeLowered`. Result rows contain only fixed control/status codes, never identities, paths or original OS values.

The complete `actuators.test.ts` suite passes (16 tests). The first serialization mutation remained green because the assertion ran before the queued microtask; the strengthened regression yields one event-loop turn before checking that retirement has not dispatched. The same mutation now fails.

### Direct Kubuntu facts

- User id 1000; `/sys/fs/cgroup` is cgroup v2. The global controller list includes CPU/I/O/memory, but the disposable owned user service with `Delegate=yes` exposes **CPU, memory, pids**. Its subtree starts empty. The native fixture creates only its own `DelegateSubgroup=supervisor` service and `governed` child scope, enables CPU/memory in that disposable parent, and cleans its child/scope in finally; it never changes the existing user slice.
- Native `cpu.weight`: **100 → 1 → 100**. Native `memory.high`: **max → 67108864 → max**. Both actuator rows are applied only after readback. The nonexistent delegated `io.weight` row is **unknown**, not 0 or applied. Restoration/retirement succeeds for the available controls.
- The real detached `/bin/sleep` child reaches nice **19** and I/O **idle**. Recovery restores its original I/O string and leaves nice **19**, with a lifetime-lowered result. The child is terminated only by the test fixture's finally cleanup, never by the actuator.
- These child probes use credential-free environments and absolute executables. The Linux process mutation implementation in the fixture performs a targeted exact `/proc` start/group check, then the syscall or ionice call. It is a test adapter; it does not certify an atomic POSIX native mutation binding or ship a fallback that acts by a bare PID. The production port remains mandatory until M96 K provides its final native proof.
- The existing installed .NET SDK 10.0.112 / local reference assemblies compile the concatenated shell/shared helper as **C# 5**, exit 0. ### Further binding handoffs

1. **C completion binding:** `retire` restores a living tree before unregister. After Stop/natural completion, `releaseCompleted` closes retained controls only through `ResourceTreeCompletionPort.hasCompleted`, which must independently prove the **whole tree**, including observed orphans, has ended. Empty/failed registry reads are not that proof. This path serializes behind in-flight controls, changes no OS policy and never delays Stop itself.
2. **M96 K Linux binding:** pass the actual delegated parent, positive `memoryHighBytes` derived from the governor/lifetime allocation, and birth-bound nice/ionice ports when no delegated scope exists. Native process ports must validate birth and membership at their OS mutation boundary, scrub helper environments, avoid elevation, and report failed readback as unknown. The portable implementation rejects missing bindings explicitly.
3. **M96 K/W macOS binding:** implement the `proc_pidinfo` policy read (exact start/group and external background bit) and guarded taskpolicy run. Set `reversible` only for the platform qualified by lane 0. Run actual read/set/read/restore on the Mac rig.
4. **Win11 binding/receipt:** M27 supplies the lazily compiled, source-digested assembly plus SystemRoot. Run `actuatorsWindows.test.ts`'s real-job case and native mutation drills on Win11. It must prove the below-normal/idle classes, CPU rate 5000, false reused-birth mutation, original per-process priorities, job flags/rate restoration, structure layout and rights without elevation. A live member with no original birth/priority baseline refuses restoration as **unknown**, rather than inventing an original or raising a new process. The explicit `WindowsPriorityBaselinePort` lets K/W supply the launch record for later members by ticket and exact birth; missing or invalid metadata refuses recovery before dispatch. Positive/negative fake cases prove that binding. Physical all-restored behavior for children born under a changed job policy still needs the Win11 receipt.
5. **W delivery:** these portable ports serve VS Code, MHP, ACP/headless and all other editors through the same lazy governor. There is no editor-specific entry. Bind G and C, include them in the lazy resource governor, certify real startup/self-cost/fifteen-check behavior and full coverage/quality, regenerate the host API record, and update PLAN/CHANGELOG/README/SECURITY/feature help. `featureCatalog.ts` is absent on this base: list the resource governor/priority recovery feature in the integrated reference when its public entry ships. No settings, commands or UI strings are added here, so no localization/manifest table is altered.
