## Delivered behavior

- `src/core/judge/sampling.ts`: explicit opt-in, captured per-model
  eligibility, exact adoption identity, full-request preflight, independent
  samples, empirical frequency distributions for noul/choice/score,
  cancellation and explicitly bounded retries. Forced reasoning is always
  refused, including the high-stakes exception. Otherwise cache capability
  and the **whole k-sample/retry uncached cost per question** are required;
  high stakes can waive those eligibility conditions, never admission.
- A warm run issues k independent parallel attempts. A cold run uses its
  **first of k samples** to establish the shared prefix, then issues k−1
  parallel reads. There is no additional priming inference: total k calls
  without retries, two rounds when cold. The first answer never enters a
  later request. The source owns exact prefix bytes, cache controls,
  redaction and the provider's randomness/output-token normalization.
  Cache savings are not assumed for eligibility or reservation.
- `src/core/judge/contrastive.ts`: one complete request carries adjacent
  question/inverse pairs, aligned by internal ids, with the entire state.
  Binary nouls only: choice/score inverses are refused rather than invented.
  It returns mean(p, 1−p′), using bounded, normalized distributions, and
  never issues a second POST or conditions one answer on another.
- Both measure input **including the complete system/user/envelope
  overhead**, reserve room for maximum output, retain the provider minimum,
  enforce the loaded context and shared ceiling, and refuse unpriced calls.
  Contrastive refuses excess pairs/oversized bodies without splitting them.
  Sampling can split questions only; every attempt carries the full state.
- Every result is labelled `uncalibrated`, with our entropy confidence.
  No source's calibrated label or vendor confidence is inherited. Unseen
  sampling alternatives are exposed as `partial`. Failed samples never
  become a smaller successful ensemble. Retry receipts retain uncertain
  liability alongside known settlement; all admitted peers finish their
  settlement before the function returns a cancellation or failure.

The source/model/version/endpoint, capture, technique, family, prompt and

## Admission seam and integration obligations

owned sampling module, shared with contrastive. Its synchronous `prepare`
must build a captured, redacted request, measure its complete token budget,
price the maximum output and the full input at the worst applicable
uncached/cache-write rate, and return a dispatcher for **one inference
attempt only**. A sampling dispatcher normalizes an observed categorical
token into a one-hot answer; it must not substitute stated confidence or
top-1 complement probabilities for a sampled observation. Provider response
parsing remains with the capture-owning source lane, using its zod schemas.

The injected `admission.run(call, signal)` instance must be bound to the
expected owner/source/model/endpoint/measurement/mode/confidential snapshot.

with price and `museSpark.paidDailyBudgetUsd`, source permission, cancellation
and the current budget. It commits a **new durable worst-case claim for
each invocation before dispatch**, settles by claim id, refunds only known
non-sends, and keeps crash/timeout liability. Its returned outcome and
reserved/settled/uncertain receipt are schema-validated here. Retries invoke
admission again; they never reuse a claim. The daily journal stays the
existing D78 journal. There is no local paid-policy fallback.
