## Delivered changes

- `src/runtime/panel/controllerRegistry.ts` owns published/adopting sessions,
  current claims, replacement stop barriers and host-exit retirement. Failed
  preparation and superseded requests publish no controller. Session/host
  bindings are checked before publication. Binding rejection disposes the
  incoming session even when the bad controller owns a different one. `src/acp/agent.ts` delegates the
  former private lifecycle maps and accepts an embedding runtime's registry;
  a SDK-client test discovers and closes the actual session through it.
- `src/runtime/settingsStore.ts` implements setting defaults and workspace
  precedence using the existing schemas, separate global/workspace storage,
  and setting-change callbacks. Per-key hashed filenames prevent path keys
  from becoming paths. Writes are serialized per store instance/key and
  atomically renamed from exclusive 0600 temporary files; new directories
  use 0700. Independent-key writers do not replace a shared whole-map file.
  Reads validate bounded versioned/key-bound JSON and refuse symlink records.
  Named credentials, credential environment entries and recognized secret
  text are refused before persistence and when reading records.
- `test/e2e/acpStdio.e2e.test.ts` source-layout builds replace native keyring
  with a test-only empty binding; its marker is checked before starting any
  child. The original regression assertions remain. Installed-artifact mode
  remains a separate qualification and was not run here.

Store limits: 1,048,576 encoded bytes per record and 1024 key characters.
The caller must supply its canonical workspace root and private data root.
Same-key ordering is within one store instance; independent processes writing
one key still have atomic last-publication semantics. This lane makes no
cross-process transaction or Windows ACL qualification claim.

## Why the panel path stopped

The shared common rule says, “If an approach needs more than ~300 new lines
for one finding, stop and report instead.” Full portable composition is larger
than that limit on this base: `ConversationDeps` remains in
`src/host/conversation/conversationController.ts` (line 298), and its existing
VS Code composition spans `src/extension.ts` lines 2111–2381. No lane A
`src/host/compose/**` factory or lane D `src/webview/bridges/**` exists here.
The current bridge still calls `acquireVsCodeApi` in `src/webview/hostBridge.ts`.
Replacing those dependencies with unavailable adapters would fail the brief's
same-feature requirement. The larger path was stopped and recorded in PLAN §3.

The merged companion server also needs additive MHP 1.1 alignment:
`src/runtime/companion/server.ts` currently admits `/post` and `/events` and
returns 202 for post; `events.ts` emits unnamed data events. The frozen carrier
requires `/panel/message`, `/panel/surface`, `/panel/events`, 204 admission,
typed errors and `event:mhp` frames with sequence IDs. Runtime surface/drop
and companion disconnect lifetimes must agree with that carrier. Authentication
from lane C must be preserved during alignment; no C guard was weakened here.

Remaining B work is required, not optional certification:

1. Integrate portable full conversation composition and create one registry
   controller that ACP, panel, native/editor/LSP and future Node views share.
2. Implement and wire both panel commands, negotiation, request correlation,
   validated surface admission, bounded ordered delivery, detach/drop and
   fatal/close behavior against frozen 1.1.
3. Bind companion and browser bridge to those handlers and wire runtime
   settings/storage ports.
4. Run both panel process suites with the fake model and their failure drills,
   then perform full feature/editor qualification and aggregate quality.

No new command, setting or user-facing panel feature is advertised. README
and help-reference generation therefore have no new command to document.
