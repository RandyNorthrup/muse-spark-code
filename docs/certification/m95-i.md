## Resolved host seam

The configured registry resolution binds model reference, provider, native
model, origin, capabilities, price card, client and current source revision.
The factory is shipped in the lazy providers bundle; host entry loads its
injected factory on the first registry list/resolution. Creating a Meta host
does not load it.
All capability reads go through `modelPolicy.ts`. Missing evidence is unknown,
not a Meta default. The adapter accepts native effort values and recorded
output maxima; output reservation and every request use the clamped limit.
Tool declarations and unsolicited tool execution require verified support.
BYO hosted search needs a captured native tool/price adapter, so a raw positive
search capability cannot activate Meta's shape/fee.

| Existing client call site            | Resolution                                                        |
| ------------------------------------ | ----------------------------------------------------------------- |
| Ordinary `streamAttempt`             | selected model client, final key/revision fence                   |
| `streamOnce` retry delay             | same selected model client                                        |
| `streamOnce` retry wait              | same selected model client                                        |
| `autoReview` key digest              | selected review model                                             |
| `newChildGrant` key digest           | requested child's resolved model                                  |
| `recheckAdmission` digest            | requested child's resolved model                                  |
| `collectText` side/compaction stream | resolved model, producer-filtered dispatch                        |
| `runCompaction` token count          | resolved model counter; existing context policy untouched         |
| `listModels`                         | provider registry list plus Meta list only with a Meta credential |
| `reviewerEntry` stream               | bound selected model, origin, effort, output and pricing          |

The Meta image service intentionally keeps its separate Meta client/key even
while a BYO chat model runs. Profile journal ownership is distinct from the
provider key digest. Held confirmations, hooks, retries and final credential
reads reject stale selection/source/credential bindings. A later model
selection wins when earlier asynchronous resolution finishes last.

Price admission uses the public price-card reservation with worst-case cold
writes, flat request fees and all replayed image fees. Settlement uses
authoritative reported totals first, preserves cache reads/writes and the
one-hour subset, and retains unknown liability rather than inventing zero.
Local is zero; plan is plan-paid; unpriced stays unknown and cannot enter a
dollar-capped dispatch. P2's module at this base ignores the one-hour subset.
The registry therefore keeps that receipt uncertain without a reported total;
P2 integration must remove this temporary refusal and update its named test.
The old reviewer tariff observer cannot skip durable settlement if it throws.
CAPPAR still owns its provider-aware tally implementation.

The five captured wire tests cover Responses, Anthropic, Gemini, chat and
Ollama: real codecs decode captured frames, a real host executes `read_file`,
and the native follow-up contains its workspace result. They use a test-only
structural client, not a fake HTTP server or the missing T transport. These
are host/codec proofs, not production transport/security certification.

The implementation is core-based and shared with ACP/runtime consumers.
Actual production editor/runtime composition remains with T/W; this lane
does not add a VS Code-only capability or claim those paths are assembled.
