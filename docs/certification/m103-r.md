## Implementation and boundaries

`RuntimeMakerHost` implements the existing MakerHost port. Machine records
live in the agent data folder; hardware grants use a canonical-workspace hash
outside the repository. Grants require current trust, an attended context,
a nonblank reason and successful scrubbed audit before persistence. Invalid
grant shapes remain off. Writes use capped, atomic files and reject linked
directories/files. Runtime secrets adapt the existing OS credential store;
keys arrive only through private stdin and never go to children or records.

Permissions show the entire engine snapshot and offer Allow once and Reject
once only. The host forwards answers to MakerApproval; it does not mint or
interpret an actuation grant. Correlated malformed replies consume their
slot, valid replies cannot replay, and expiry/revocation/disconnection cancel
pending requests. Engine-owned target binding and final synchronous admission
checks remain authoritative. G4 is not duplicated: absent classification
refuses serial writes. Native preparation and identity discovery refresh
runtime admission before the final guarded open.

CLI commands execute hardware enable/disable/status, machines add/list/remove,
Stop and panel. `--key-stdin` refuses empty input. ACP requires `--hardware`
and the persisted workspace grant. It handles `/hardware`, `/machines` and
`/stop-machine` without starting a model turn. Exactly one attended top-level
ACP session may answer; idle/Plan/worker contexts offer no physical actions.
Bypass cannot be selected while maker is installed. The Model API resolves
dynamic tools again when a streamed call arrives and excludes those tools
from Plan, side chats, review, scheduled requests and subagents.

Stop cancels local serial work and pending permissions, and attempts controller
Stop alongside cross-process owner cancellation. Stop all also enumerates P's
existing validated v2 lease records, so a separate CLI process reaches a
Thonny/serial owner that has no registered machine. Corrupt resources are
reported after other owners receive Stop. It waits on neither hardware
admission nor an ordinary tool queue. Stop remains exposed while disabled or
untrusted. Service shutdown waits for native sessions to close. Software Stop
is explicitly distinguished from the physical emergency stop.

Companion HTTP binds a literal loopback address, checks Host and Origin,
caps request bodies and slow-reader event queues, and serves installed assets
only. A single-use private launch capability becomes an HttpOnly SameSite
cookie; browser and MCP capabilities are distinct. MCP credentials cannot
answer permissions. Surface traffic uses makerProtocol schemas, and MCP uses
the existing validated JSON-RPC handler. The shared browser bridge embeds the
installed language, serves hashed chunks, and uses `data-surface="maker"` for
U's shared mount. No separate maker UI was invented here.

Thonny's v2 provider accepts only hello, context responses and explicit port
acquire/release control. It accepts no device bytes or approval answers. Acquire
acknowledges only after the approved native session opens; release acknowledges
after closure. Disconnect cancels an uncertain acquisition and releases before
a replacement provider is admitted. A failed release latches refusal.
