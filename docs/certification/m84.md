## How it was built

A Muse Code instance (contributor model) drafted M84. Claude reviewed and
reworked the draft (2026-09-28). A completion review on 2026-09-29 repaired
four gaps:

- `transferInvalidField` lacked its translations;
- a JSON syntax error could quote the file;
- an unknown field's name reached a notice unscrubbed;
- item ids and error labels skipped the export's credential scrub.

It also bounded the file picker and applied the imported start mode in the
ACP agent. The tree was then ported to the release candidate (`e41a914c`).
The independent review RV84 found fourteen problems on that tree. This
record covers the fixes and every guard's proof.

## What M84 is, on this tree

- **One format**, `muse-spark-session-export` version 1
  (`src/core/export/sessionTransfer.ts`), for export, import and share: the
  history the Markdown export reads, with only the fields a reader needs.
  Live state and the Model API replay stay out.
- **Scrubbing.** Every string, ids and error labels included, goes through
  `redactSecrets` (`src/core/redact.ts`), the one list of credential shapes
  the extension keeps (the log uses the same list), and a key-digest
  pattern. That is always done; paths and e-mail addresses are redacted by
  default as well. The UI and docs promise what a pattern list can keep:
  known credential shapes are removed, and a secret in another shape stays,
  which is why the redacted file is shown before it is saved (RV84 #1).
- **Scrub cost.** `redactSecrets` tests one literal prefilter
  (`MAY_HOLD_SECRET`) before its 24 patterns. `buildSessionExport` is async
  and yields with `setImmediate` after each 64 KiB of text, so a long
  conversation never holds the extension host for long (RV84 #9,
  measurements below).
- **Preview first.** The redacted file opens read-only and in memory; then
  **Save redacted…**, **Save without redaction…** or close. Either save goes
  through the M72 checkpoint lease and action guard (`saveExport` in
  `cliFeatures.ts`, RV84 #5).
- **Every imported byte parsed.** The picker accepts a local `file:` URI
  only, read through one checked descriptor with the 16 MiB JSON cap, a PDF
  header included. A file that is gone by the time it is read is reported
  as missing (RV84 #6), and bytes that are not UTF-8 get the translated
  `textFileInvalid` (RV84 #7). Then come the header, the version, the schema
  with its caps, and any unknown field anywhere. A refusal never quotes the
  file, and a field name is scrubbed before it is shown.
- **Import** (Model API only) gives the session fresh ids, the user's model,
  no rules, goals, todos, outputs or patches, and each imported turn as
  untrusted data in a user-role message. The session is marked `imported`
  and opens in `untrustedStartMode` every time it is adopted. So does the
  ACP agent's load and resume.
- **What an imported conversation cannot do.** A plan written in one is
  implemented as untrusted content, in `untrustedBriefMode()` (lead
  decision, RV84 #2). Its code blocks offer Copy only, never Insert or
  Apply (`historyLoaded.imported`, RV84 #11).
- **Share view.** The file renders read-only with Copy and links, and no
  Insert, Apply or session. The file's `redacted` flag is shown as the
  file's claim, "The file says … that is not checked here", never as a fact
  (RV84 #8).

## Measurements

The scrub (RV84 #9) was measured with `buildSessionExport` in memory and a
1 ms timer that records the longest gap. The e41a914c code was compared with
the final code in one run on each rig. The inputs were:

- a conversation of 4 KB messages with paths under a local root
  (`C:\Users\Randy Northrup`);
- the export test's two single-string inputs.

| Input                        | Mac mini, e41a914c: total / loop held | Mac mini, now | Windows 11 VM, e41a914c | Windows 11 VM, now |
| ---------------------------- | ------------------------------------- | ------------- | ----------------------- | ------------------ |
| 1 MiB conversation, redacted | 383 / 383 ms                          | 91 / 8 ms     | 658 / 658 ms            | 114 / 19 ms        |
| 4 MiB conversation, redacted | 1,432 / 1,432 ms                      | 365 / 11 ms   | 2,528 / 2,528 ms        | 419 / 14 ms        |
| 4 MiB conversation, full     | 95 / 95 ms                            | 199 / 6 ms    | 147 / 147 ms            | 121 / 7 ms         |
| one 18 MiB string, redacted  | 712 / 712 ms                          | 371 / 370 ms  | 1,027 / 1,027 ms        | 517 / 517 ms       |

The Mac mini "now" figures were taken before the timer yield became
`setImmediate`, so its full pass carries the timer's wait. A zero timer
first cost the Windows VM 996 ms on the 4 MiB full pass, because its ~15 ms
tick is paid once per slice; `setImmediate` brought it to 121 ms. A single
string is never cut, so one huge string still holds the loop for its own
scrub.

For the share view (RV84 #14), `ShareView` was rendered in jsdom on the Mac
mini, with messages of a paragraph and a code block:

| Items  | First render |
| ------ | ------------ |
| 200    | 397 ms       |
| 2,000  | 1,928 ms     |
| 20,000 | 18,154 ms    |

That is linear, about 0.9 ms per item. A real webview is faster than jsdom,
and its figure was not measured.

## Open

- **RV84 #10, confirmed by reading.** An import may be 16 MiB and 20,000
  items, while the Model API window is 1,048,576 tokens
  (`MODEL_API_CONTEXT_WINDOW`). Neither `importSession` nor
  `sanitizeImportedSession` compares the replay with the window. Every
  request replays all of it, and so does `/compact` (`runCompaction` sends
  the whole replay; `budget.fit` bounds images only). There is no automatic
  compaction. A large import is accepted, and then every message and
  `/compact` go past the window. The API's own refusal was not observed,
  since there was no live run. The fix (a token estimate at import, and a
  refusal or a cut, with a translated notice) is not small, so it is left
  for the lead.
- **RV84 #14, confirmed in kind.** See the jsdom measurement above. Paging
  or virtualizing the share view was not built.
- **RV84 #13: no change needed.** `scripts/check-host-api.mjs` holds only
  `PORTABLE_ROOTS` (`src/core`, `src/shared`, `src/webview`, `src/acp`,
  `src/runtime`) and the `PORTABLE_HOST` files to the `vscode` boundary.
  `transferDialogs.ts` is neither, and the conversation controller takes it
  as a dep (`SessionTransferFiles`), so the gate passes and records it as
  the 17th adapter file. The sibling dialogs live in `src/host/*Features.ts`
  (`cliFeatures.ts` already holds the export's dialogs). Moving it there is
  a tidy-up for the lead to choose.
- **The bundle budgets** (above), for the lead (D6).
