### Native Windows process lifetime

promoted C# helper. A test-only copy wraps the actual

waited to exit. Real `cmd.exe /d /c exit 0` processes force new PID
allocations within 16 of that PID while its original kernel process handle
remains held. The native wait must refuse the exited process, regardless
of those new generations; the client writes zero bytes.

## Source delivered against P0

`createLocalJudgeSource` implements `JudgeRuntime`. Configuration, native
installation evidence, complete request token measurement, and model-facing
chat wording are explicit injected interfaces. Default model verification
and transport perform actual filesystem and socket work. Test doubles stay
in tests. Importing the source opens no socket and pulls no model.

The local option must be enabled. An unverified endpoint requires explicit
selection, refuses a confidential workspace before opening a socket, and
uses the translated `judgeLocalUnverified` label. Judged state and criteria
pass through the existing secret-pattern redactor before content dispatch;
question IDs stay stable. This redactor recognises its documented credential
shapes, not arbitrary secrets. There is no paid or other-provider fallback.

Verified requests require this platform's explicit certification record and
native host posture. Each metadata connection and each content connection
proves the exact process generation. Content sockets additionally verify
the served manifest and every disk blob, then prove the connected peer
again before HTTP headers or body. A configuration change after an await
invalidates the turn. No peer/hash TTL, proxy agent, redirect or reconnect
is used. Cancellation and the unchanged 60-second request deadline also
bound an asynchronous verifier; tests count actual written content bytes.

Captured `/api/tags` and `/api/ps` responses must name exactly one matching
served and loaded model with the same digest. Admission uses the lesser of
the loaded context, captured capability and existing state-token ceiling,
including full serialized request overhead and output allowance. All
batches are admitted before content; only questions split, never state.
Cold models return `source-unavailable`: the adapter does not silently load
one with an unmeasured context window. Qwen uses one token and one question
per request. Sparse choice keys are addressed as contiguous A–Z prompt
tokens and mapped back to the original keys. Answers and usage merge with
a final P0 result-schema parse.

SystemOne uses the captured noul/choice/score wire shape. Every requested
answer, type, probability alternative, probability mass, choice and score
legend aligns or refuses. Extra vendor fields are retained. Entropy
confidence and vendor confidence are separate; all results are labelled
uncalibrated. Ollama's native noul contains no probabilities; the adapter
adds its two binary masses to satisfy P0. This is explicit normalization,
not a claim that that answer is byte-identical to the native response.
Qwen's captured top-5 candidates reuse P0's distinct-alternative math and
honest `partial` flag; missing evidence never creates success. Qwen is
excluded from automatic selection until calibrated.

`LOCAL_JUDGE_RECOMMENDATIONS` records the existing tev1 and qwen models and
their measured download sizes. `pullLocalJudgeModel` requires an explicit
user action and consent showing the exact model and byte count, then
rechecks cancellation and the action. The host implementation hashes a
vetted canonical executable and invokes only `pull <model>` without a
shell, credentials or proxy environment, with a fixed local Ollama host.
Tests inject a fake executor; no download was executed on this rig.

## Platform proof and limits

The reviewed Windows helper is promoted from its test-only source to
`native/windows/MuseSparkLocalJudgePeer.cs`. It retains the held process
handle, exact connected TCP tuple, SID, FILETIME creation identity,
executable path and pinned digest. Its new root operation accepts canonical
roots on fixed NTFS, rejecting network/unknown volumes. Real Windows
fixtures prove root acceptance and junction refusal; existing live child
socket tests prove IPv4/IPv6 owners and Node relay refusal. Remote hosts,
containers, WSL and unknown posture cannot claim native verification.

The Linux adapter reads the exact reversed connected tuple in `/proc`, its
UID/inode and unique descriptor owner, network/user/mount namespaces and
start time (including process names with spaces). The macOS adapter parses
numeric NUL-field `lsof` output for the full tuple, numeric UID and unique
established owner; queue fields cannot overwrite connection state. Both
require a held native lifetime lease, canonical installed runtime/root,
local-volume proof, pinned binary digest and a repeated tuple/generation
sample. Missing probes, permissions or lifetime proof fail closed.

`PosixPeerDependencies.acquireProcess` and `verifyLocalVolume` remain
required native seams. No JavaScript PID cache or dummy production lease
implements them. Linux pidfd/macOS lifetime integration and their real
installed-host receipts remain necessary before outcome (a) is available
there. `judgeLocalPosix.test.ts` supplies fake OS/native evidence and proves
refusal logic only. `judgeLocalPosixNative.test.ts` runs real IPv4/IPv6
lookup on those platforms and refuses a Node relay; it supplies no positive
lifetime attestation. Its two tests are platform-inapplicable on win11.
No Windows receipt is inherited by Linux or macOS. The reviewed spike's
unproven installed-extension transport and authenticated self-SSH drill
remain open. The original J2 run supplied no CPU-only latency receipt;
FIXM98J2 above now records the bounded qwen CPU result.

An exploratory late-path-redirection fixture was stopped: Windows refused
directory renaming while these handles were open (EPERM), and a replacement
fixture could not spy on Node's immutable ESM `realpath` export. The two
attempts were removed, per the common rule against continuing a failing
path. Neither is counted as a red drill or positive path-race evidence.
