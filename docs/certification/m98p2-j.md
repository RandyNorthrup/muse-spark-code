## Reviewed spike correction

RVM982J's P2 is reproduced by `judgeLocalModel.test.ts`:
“refuses blobs that never matched in one consistent snapshot”. Synthetic
weights start valid and a template starts invalid. After the weights are
hashed, the test corrupts them and repairs the template. The original
verifier returned success; the regression exited 1 before the correction.

All blob handles now stay open through the whole check. After the last
initial hash, every referenced blob is hashed again from offset zero and
its native file identity, size, mtime and ctime are compared with the
original handle and the named file. This also detects changed bytes when
Windows caches metadata on an open reader. Handles close in `finally`.
The extra pass increases provenance latency; no hash/peer TTL is introduced.
As in the spike, mutation after verification and arbitrary same-user code
injection remain outside the proof. This is not file immutability through
inference.

The snapshot guard was deliberately removed. The named regression failed
(exit 1), source bytes were restored with equal SHA-256, and the whole
owning file passed 12 tests. Full hashes: [m98p2-j-drills.json](m98p2-j-drills.json).
Scoped ESLint and the unit typecheck pass. All checks run directly on win11.
