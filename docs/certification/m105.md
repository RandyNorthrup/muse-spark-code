### Seam 3 core — trusted converter binding

**Design (lead decisions).**

- **One POSIX verifier.** `src/runtime/trustedPath.ts` is M104's REDM104L3
  file (blob `9fb91c4a`) verbatim, plus an additive executable-file mode,
  `verifyTrustedExecutable`:
  - it resolves the real path first;
  - every ancestor of the canonical path passes the same StrictModes walk;
  - the target must be a regular file owned by root or the user, with no
    group or other write, and executable;
  - the open handle must still be the pathname (no swap).

  `posixTrustedPathVerifier` exposes it through the shared
  `TrustedPathVerifier` port (`trustedPathPort.ts`), whose
  `{ ok, path } | { refused, component, reason }` contract is unchanged.

- **Windows.** `converterTrustedPath` (`src/runtime/converterTrust.ts`)
  resolves the canonical target first, then runs the existing owner, ACL and
  reparse verifier (`windowsTrustedPath.ts`) on it. A winget link, or a
  profile folder that is a junction or lives on another drive, is judged by
  what it resolves to. PowerShell is launched from `%SystemRoot%`, never
  found on `PATH`.
- **Where converters come from** (`locateMediaConverter`, `convert.ts`):
  - A configured path, when given, is the only candidate. If it fails, the
    refusal names the reason (`converterConfiguredRefused`) and there is no
    fallback to discovery.
  - Otherwise, documented installs:
    - Linux: `/usr/bin`, `/usr/local/bin`.
    - macOS: avconvert, `/opt/homebrew/bin`, `/usr/local/bin`,
      `/opt/local/bin`.
    - Windows: `%ProgramFiles%\ffmpeg\bin` and winget's
      `%LOCALAPPDATA%\Microsoft\WinGet\Links`, read from the environment.
      There is no drive literal, and no guessed fallback when the variable
      is absent.
  - `PATH` is never consulted.
  - Launcher shims (Chocolatey, Scoop, `/snap`) are refused at their
    canonical path, because they launch a second binary that was never
    verified.
  - A converter found under a shared-writable folder (Intel Homebrew's
    `/usr/local/bin`) names the fix (`converterSharedFolder`).
- **The verified canonical path is what runs.** The version probe launches
  it. The recheck immediately before encoding must verify the same canonical
  path again, or the conversion refuses.
- **Memory watch.** Encoding runs under either a bounded RSS sampler or a
  kernel-enforced cap (`memoryLimitedRun`, the Windows job object that
  MEDIAVB builds). A cap hit is reported as "memory cap". With neither
  available (off Linux), conversion refuses before launch.
- **Reaped-PID fix.** Node reaps the child before `exit`. From then on an RSS
  sample proves nothing, so:
  - a sample that loses the race with the exit no longer fails the
    conversion;
  - after `close`, only the output's type and size cap decide;
  - a live child's failed sample still refuses.

**Windows: `memoryLimitedRun`.**

```ts

  spawnJob?: (launch: McpJobLaunch) => ChildProcessWithoutNullStreams // tests only

```

- `JobEncoderRunOptions` is structurally `convert.ts`'s `LimitedRunOptions`:
  `cwd`, `env`, `timeoutMs`, `signal?`, `outputPath`, `maxOutputBytes` and
  `maxRssBytes`.
- Bind `jobExecutable` to an M50 preparation (`mcpJobExecutable`).
  - **VS Code** already has one: `windowsMcpJob` (`extension.ts:1916`,
    `windowsJobHelper(mcpJobExecutable, …)`).
  - **The runtime (ACP, exec) has none yet.** `runtime/backends.ts:268`
    composes only `shellJobAssembly`, and `scripts/package-acp.mjs:99`
    deliberately omits `MuseSparkMcpLauncher.cs` from the package.
  - Lane V's runtime wiring therefore needs two changes. First, ship that
    file in `JOB_SOURCES`, updating the comment and any packaging test that
    asserts its absence. Second, compose
    `mcpJobExecutable({ storageDir: agentDataFolder(dataInput), systemRoot, readJobSource: jobSourceReader(path.dirname(deps.distDir)), log })`
    beside `shellJobAssembly`.
  - Without them, Windows conversion in the runtime refuses: an absent
    launcher is a refusal, never an unbounded launch.
- On Windows leave `readRssBytes` unset, so that `memoryWatch` picks the
  kernel path.
- `maxRssBytes` becomes the job's `jobMemoryLimit`. A cap that is not a
  positive safe integer refuses before anything starts, because 0 would
  mean no limit. So do:
  - a relative command, folder or output path;
  - an aborted signal;
  - an absent or failed launcher. The encoder is never started unbounded.
- The encoder is created inside the job (`PROC_THREAD_ATTRIBUTE_JOB_LIST`),
  so the launcher ended at any instant leaves no child.
- Output size (watcher plus the 25 ms watchdog), the deadline and
  cancellation all end the launcher. Its exit closes the job's only handle,
  and kill-on-close ends the encoder and everything it started.
- Every output check, outstanding and final, is bounded by conversion's
  100 ms sample deadline. A stat that never answers is a failed check, so the
  run always settles.
- A clean exit still answers for its final output. No final RSS sample is
  owed, because the kernel enforces the cap (RVM105M12).
- Today every failure is `EMEDIA_JOB_FAILED`, because M50's launcher reports
  only an exit code. The seam is `conversionJobFailure(enforcedLimits)`. Once
  M109's attested RESULT record (`limits: ['jobMemory', …]`) is wired through,
  `jobMemory` becomes `EMEDIA_MEMORY_CAP`, which lane V's `isMemoryCap` reads.
- `MEDIA_CONVERSION_MEMORY_CAP_CODE` is added with lane V's exact line and
  position, so the two branches merge as one identical insertion.

**macOS: `readRssBytes`.**

- `macRssSampler(child, deps?)` returns `(pid) => Promise<number>` in bytes,
  for that one child. `child` is the encoder's `ChildProcess` (`pid`,
  `exitCode`, `signalCode`, `once('exit')`).
- Lane V's wiring therefore needs one change. `runConverter` calls
  `readRssBytes(child.pid)` today, so make the darwin option a per-child
  factory, e.g. `readRssBytesFor: (child) => macRssSampler(child)`, called
  right after the spawn.
- It reads one PID through the governor's own absolute `/bin/ps` with the
  numeric columns and parser (`trees/posixTable.ts` `readMacProcess`; the
  table reader in `trees/mac.ts` shares the constants), plus `lstart`. There
  is no new sampler.
- Every ps run checks:
  - the PID;
  - that the process is live and not a zombie;
  - that its parent is this process;
  - that its start time is the first run's.

  A PID reused under the same parent is therefore refused.

- Between runs the child handle vouches for the reading. The child's exit
  drops it, and from then on every call refuses; this is checked again after
  each await.
- `ps` runs at most once per 250 ms per PID, bounded at 1 s and 4 KiB per run.
  A reading older than 500 ms is never returned: the call waits for the run
  in flight, which conversion's 100 ms sample deadline bounds.
- Measured on the MacBook, 40 one-PID runs at load 9.9 took a median of
  2.6 ms and at most 6.2 ms.
- One failure is final for that child.

**All platforms: `openPrivateRoot`, then `createPrivateDirectory`.**

- `openPrivateRoot(directory, { reader?, acl? })` returns
  `Promise<PrivateRoot>` (the resolved path and its file identity). It is
  called once per host, with a dedicated folder: `media` in the host's own
  per-user storage (VS Code's global storage, the runtime's data folder).
  - Links above the root are followed (a relocated profile). The root itself
    must not be a link.
  - **Windows.** The owner is the user, SYSTEM or Administrators. On the
    root, nobody else holds any grant. On its parent, nobody else holds a
    write-class grant; sandbox groups that only read, as on the owner's PC,
    are fine.
  - **POSIX.** The root is the user's, has no group or other bits and (on
    macOS) no ACL. Every folder above it is root's or the user's and is
    writable by nobody else unless it is sticky.
  - **An absent root** is made only after its parent passes, and is made
    owner-only before any check passes it.
  - **An existing root** is checked and never repaired.
  - Any failure throws `PrivateRootRefused` (`EPRIVATE_ROOT`). There is no
    fallback to a temporary folder.
- `createPrivateDirectory(root, { acl?, name? })` returns `Promise<string>`.
  - It first re-checks the root's identity (and, on POSIX, its mode and
    owner).
  - It then makes a fresh `muse-media-<32 hex>` folder with an exclusive
    mkdir. The folder inherits the root's private DACL, or sits under a 0700
    root, so no other principal has an instant in which to open it.
  - `secureOwnerOnly` still sets it owner-only explicitly and reads that
    back, and the folder is read back empty. On Windows this runs one
    `SystemRoot` (or `windir`) PowerShell per conversion; none per encoder
    launch.
  - Any failure throws `PrivateDirectoryRefused` (`EPRIVATE_DIRECTORY`),
    removes only what the call made and carries no path.
