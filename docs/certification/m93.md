## Lane I: what was wired

- **Command and entry points.** `museSpark.reportProblem` (package.json,
  lane 0's title); the palette's Support item "Report an issue…" now opens
  the dialog (no bare link); "Report this" on recorded error notices and on
  failed-turn rows (`agentEvent.reportRef`); the crash screen. With no
  conversation open, the command opens one and the dialog shows once it is
  ready.
- **Flight recorder.** `ReportRecorder` (`src/host/support/reportRecorder.ts`)
  in activation answers and queues; R's `ReportJournal` behind it loads from
  `dist/recorder.js` just after activation (or at the first failure), sets
  the marker and prunes. Activation failures are recorded; `deactivate`
  clears the marker last. It records Muse Code exits nobody asked for (the signal or
  `exited`, never the description), failed turns and tool calls, error
  notices, and the webview's scrubbed failures; host frames only inside the
  installed package's shipped bundles. At most 20 records a window a
  minute. A stale marker is offered once after activation.
- **Facts.** Local reads only (`src/host/support/reportFacts.ts`): the CLI's
  sign-in from its credential file's structure (no `account/read`, no CLI
  start), key presence, and the names of changed settings from the
  manifest's list.
- **Lazy bundle.** `dist/report.js` holds the builder, its scrub, the export
  paths and the dialog's handler, loaded on first open (controller's dynamic
  import, the build's deferred plugin). The export paths take the editor's
  clipboard, browser, save picker and issue reporter as `ReportEditorIo`
  (`src/host/support/reportEditorIo.ts` is VS Code's), so the conversation
  controller, portable host code (D60), still reaches no `vscode`: the host
  API check caught the first wiring. The split check guards the bundle.
- **Both backends.** Nothing in the workflow depends on the backend: the
  dialog needs no session or sign-in. Muse Code's process exits are recorded
  at the window's exit listener; both backends' failed turns and tool calls
  are recorded where the controller forwards their events.
- **BigInt.** Lane R's `REPORT_STORAGE_LINK_COUNT = 1n` in `constants.ts`
  broke vitest's shared module cache (ENOENT under `/tmp/.../ssr/`) for every
  suite run after one that loaded the constants. Reproduced on Kubuntu,
  confirmed by swapping the literal; it is a number compared as `BigInt(...)`.

## Amortized pruning (coordinator, 2026-10-05)

R's `record()` pruned the whole journal before and after every append. That
reads and validates up to 256 KiB twice per failure, so a long session costs
quadratic time. R11 (320 appends) took 20 s under the full suite and hit the
5 s default. It is no longer slow: the window measures its journal once,
counts its bytes and oldest record as appends land, and reads the file again
only when one of those crosses a bound. Past the 256 KiB cap it prunes down
to 192 KiB (`REPORT_JOURNAL_PRUNE_TARGET_BYTES`), so the next rewrite is
about 64 KiB of appends away. An expired oldest record triggers a prune at
that append. R's bounds are unchanged. R11 runs within the default timeout,
and the 60 s override is gone. It counts whole-file reads: fewer than 10 for
320 appends. Drill R12 restores the prune on every append, and the test then
sees 321 reads.
