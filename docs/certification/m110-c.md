## Scope and boundaries

Implements D90.4, D90.15 and D90.23's image packaging. The image uses
Node 24.18.0 on Debian trixie slim. Both the Node build stage and the
Debian runtime base are pinned by their multi-platform index digests. Debian direct dependencies are pinned, including bubblewrap and
rootless Podman. Native PTY compilation happens in a separate build stage.
Neither Muse Code nor Chrome, weights, sign-ins or user data are bundled.

The root entrypoint initializes only empty volumes, refuses symlinks and
unexpected ownership or modes, then drops root and every capability before
the node and tool host run. The node is UID 10001; tools are UID 10002.
State is node-owned, mode 0700. Workspaces are tools-owned, mode 0700, and
the node accesses them through the tool host. Both environments are built
with `env -i`. A separate group, 10003, permits the socket connection.
Terminal attachment through `docker exec` also drops root. The wrappers
retain the default seccomp policy, read-only root and no-new-privileges,
and never mount the host's engine socket. This is one shared sandbox;
nested Podman/bubblewrap qualification belongs to lane 0 and M110b.

The rig lacked Docker and Podman. The brief authorizes their installation;
Docker 29.1.3, buildx 0.30.1, Podman 5.7.0 and QEMU user binfmt were installed.
Compose 2.40.3 was also installed. The existing shellcheck 0.11.0 and
gitleaks remain in use; image CI uses the separately SHA-256-pinned tools
in `deploy/container/tool-pins.json`. No npm dependency
was added to the repository.

## Named integration handoffs

- **N → C, node runtime package:** `scripts/package-node-image.mjs` takes an
  explicit runtime directory and a new build-context directory. Required
  files are in `deploy/container/policy.json`. In particular it requires
  `dist/node.js` (the node entry, accepting `serve`, `init`, etc.),
  `dist/nodeToolHost.js` (accepting `--socket` and `--workspace`) and
  `dist/acp.js` (the public CLI, including `tui`). All lazy runtime bundles,
  web assets, translations and schemas live under `dist/`, `l10n/` and
  `schemas/`. The package and v3 lock must pin node-pty 1.1.0 and
  @napi-rs/keyring 2.1.0. The image compiles the PTY, with dependency install
  scripts otherwise disabled. Lane N's package must provide these real
  artifacts; none exists on this base. An ACP-only package fails closed.
- **N tool socket:** `/run/muse-tools/host.sock`, tools-owned, group 10003,
  mode 0660, in a 0710 tools-owned directory. Authenticate the node's UID
  before accepting requests; close on owner loss and report tool-host loss
  to the supervisor. The entrypoint provides `MUSE_NODE_DATA_ROOT`,
  `MUSE_NODE_WORKSPACE_ROOT` and `MUSE_NODE_TOOL_SOCKET` to the node only.
- **0 → C:** the contract and capture files named by PLAN are absent on
  this base. These deployment paths and CLI arguments must be reconciled
  against lane 0's accepted contracts during integration. No listener,
  sign-in or service wire schema was guessed here.
- **J:** README, CHANGELOG, operator/editor documentation and feature
  reference are J-owned, so this lane leaves those files untouched. Document
  the two packaging/check scripts, digest-selected Compose and docker-run
  recipe, rootless Quadlet, signature verification and the limitations
  recorded here. `src/shared/featureCatalog.ts` does not exist on this base.
  No enhancements or paid-consent defaults change in lane C.

## Image and release behavior

The final runtime copies only Node's executable and complete bundled-library
licence from the pinned Node stage into pinned Debian. npm, Corepack, compiler
headers and the unused Podman test binary stay out. A trusted direct node-gyp
invocation compiles node-pty: npm 12's rebuild command had reported success
without producing the native PTY. All other dependency install scripts stay
disabled. Native dependency audit passed; native licence inventory refuses
missing or unreviewed notices and admits only the captured, exact 2.1.0 MIT
keyring binary split's parent notice. Debian package/source versions and each
copyright, Node's full licence, runtime notices and native licence text ship.
No repository npm dependency was added.

Release admission uses the exact release ACP artifact, requires its real node
and tool-host bundles, and builds on separate native amd64 and arm64 runners.
Before any registry upload: safe bounded extraction, SHA-256/size validation,
all original layers (including deleted files) and OCI metadata scanned with
Gitleaks's full built-in rules and allow-comments disabled; 200,000,000-byte
compressed budget; unofficial title; no credential config; reviewed bootstrap
bytes; final notices; SPDX and SLSA bound to every runnable digest; Trivy's
fixable CRITICAL gate. Scanner/tool failures expose fixed diagnostic words,
never their raw output. Extraction never follows archive links or devices;
file and directory whiteouts cannot resurrect removed notices.

Only checked OCI bytes are pushed, with digest preservation and a registry
token on the pinned Skopeo helper's stdin, held in private tmpfs. Temporary
build tags precede publication. A joined index is keylessly signed, receives
both architectures' SBOM/provenance predicates, and verifies the exact
`node-image.yml@refs/tags/vX.Y.Z` identity and GitHub OIDC issuer before the
version and stable/preview tags appear. Promoted tags must equal the signed
digest. The release summary and M80 major tag require this job's success.
CI uploads only small receipts, for 14 days; fake images and large OCI archives
are never uploaded. Registry retention preserves ten release graphs, current
channels, manually tagged graphs, untagged platform/attestation manifests,
subject references and matching cosign attachments; malformed graphs or no
roots refuse deletion. Workflow concurrency prevents collection racing a
staged build. No registry mutation or OIDC sign-in was performed on this rig.
