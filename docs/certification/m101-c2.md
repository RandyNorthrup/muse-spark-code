## Decision rule (six lines)

1. Require the setting, evaluated latch, owned active turn and replaceable dispatched history.
2. Measure the last sent body, including placeholders; estimate replacement from the previous real summary.
3. Price post-compaction cache writes plus summary input/output/fees; add unpaid debt and repay it on ordinary POSTs.
4. Cost path requires a registered todo completion, 50% occupancy, two ordinary POSTs and break-even within the observed todo horizon.
5. At 90% occupancy, or once per turn after classified overflow, bypass economics while preserving admission and Stop.
6. Ask the shared paid gate, check every actual send, tally every attempt, flush memory through policy and restore exact host todos/goal.

The cost model uses `saving = max(0, removable - summary) * read`,
`written = max(0, context - max(0, removable - summary))`, and
`newDebt = written * max(0, write - read) + summaryCost`.
Break-even is `(carriedDebt + newDebt) / (previousSaving + saving)`;
the task horizon is the mean dispatched ordinary requests per registered
completion times the remaining registered pending/in-progress tasks.
Failures/refusals clear economic debt and suppress another decision until real
tool work or new user input. This debt is an optimization estimate, **not**
the paid ledger: clearing it never clears a billed/uncertain liability.

The host conservatively estimates two summary requests (cached-prefix response
and possible tool-less fallback), zero assumed summary cache hits, and the
bounded summary output until a real summary exists. Every actual retry/fallback
still requires the shared guard and individual settlement; the estimate never
authorizes an unbounded retry. This deliberately conservative choice is for
lane E to measure. Summary tools never execute. Automatic memory notes are a
deterministic untrusted snapshot, so they need no additional summarizer call.

## Core, memory, permissions and editor paths

`autoCompact.ts` is pure and imports no editor API. `ModelApiHost.ts` decides
once after the entire tool batch, hooks and verify checks settle, before the
next model round; it does not decide after a final answer. The overflow catch
owns one recovery attempt for the whole user turn, including errors separated
by actual tools. Compaction remains reachable when ordinary context admission
refuses an overfull body. The ordinary M82 account/key/budget/final-send fences
still run on each extra POST. Stop uses the active turn's original signal.

The memory flush calls `add_memory` through `runCall`, the existing permission
engine and MemoryStore. Manual prompts; Plan and Restricted Mode refuse the
write. A refused write does not block compaction. The snapshot labels all
contents untrusted and preserves exact todos, the current goal, successful
file metadata and any previous real summary. A successful compact adds a
trailing hidden user replay entry containing the **full byte-exact host todo
list**, including completed items, and current goal. Generated summary text
never supplies the restored task list.

The panel reads the machine-scoped default-on
`museSpark.modelApiAutoCompaction` setting. ACP and headless use the same engine
and accept `--no-auto-compaction`. Runtime option parsing/forwarding is covered
by the complete ACP/runtime/exec importing suites. There is no separate
editor-specific scheduler. The setting's English and all 14 translated
manifest/source tables are included. The evaluation notice is read at runtime,
once per session, when the panel/runtime supplies the enabled setting reader.
