## Behavior and accounting

- `ModelApiHost.ts` checks the selected record's `hosted.webSearch` and
  `hosted.maxToolCalls`. Both must say yes; the current Responses transport
  must recognize the declared hosted tool; the search tariff and configured
  integer bound must be valid. The configured bound is captured once per
  session. A supported request carries `max_tool_calls` even when it has no
  session cap. Deny and explicit off omit both the hosted tool and bound.
- Daily admission holds estimated input tokens, the entire requested output
  allowance, and `bound × search price`. Session admission deducts the same
  hosted allowance before allocating affordable output tokens. A bound
  that cannot fit stops before dispatch. No input, tool declaration,
  instruction or cache-key digest receives the per-response bound.
- `client.ts` settles completed, incomplete and failed terminal responses
  using every returned `web_search_call`, once per call, including failed
  calls and calls carrying multiple queries. Counts above the bound are
  charged in full and logged using counts only. Streamed completion events
  are deduplicated and reconciled with the terminal count.
- The client's terminal count reaches the session before token settlement.
  Thus terminal-only searches in a failed response reach the session ledger
  and paid tally too. Streamed rows and terminal items do not charge twice.
  Search rows retain their paid marking and existing presentation.
- Missing terminal usage retains the token allowance and settles the known
  search count. An interrupted stream retains the entire allowance and any
  observed excess search fees. The session deducts only already recorded
  fees within the reserved search allowance from its uncertain claim; excess
  calls cannot consume the retained token liability. A known nonsend refunds.
- `paidFeatures.ts` exposes the verified Meta per-call search price,
  USD 0.0025; an unknown model gets no assumed tariff. The client accepts
  injected search and token prices, so the bounded daily path also works
  with a non-Meta native model. Invalid or unavailable prices refuse before
  reservation or fetch; a settlement-pricing failure retains liability.
- `extension.ts` forwards the computed amount through the existing durable
  daily amount-reservation port, with cancellation and its synchronous
  check after key retrieval. Ordinary paid requests keep the existing
  body-based adapter. No accounting engine enters the activation bundle.
- With the capability port absent, legacy uncapped search retains its
  current request and tally behavior; capped and daily search remain refused.
  The headless parser still refuses `--web-search`, including with an
  explicit hard budget. ACP flags are unchanged.

The changes in `ModelApiHost.ts` are H's availability, request reservation,
and hosted-search accounting regions. No L1 stream dispatcher or L2 tool
batch/continuation region was changed in the original H implementation.
FIXM106H additionally changes the shared tariff contracts and journal required
by the review fixes, as listed above; it changes no unrelated lane regions.
There are no new user-visible strings, dependencies, suppressions, casts or
escape hatches.
