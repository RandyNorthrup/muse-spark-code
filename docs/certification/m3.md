## Findings recorded during the milestone

- `approval/request` is **not** an MSP server request: the SDK's approval
  facade documents that `approval/requested` is a notification and the
  decision goes out as `approval/decide`. A prompting approval mode therefore
  makes the host wait on the client, which is why every prompting mode stays
  `denyUnmatched` until M4 renders the notification (`HAS_APPROVAL_UI`).
- `muse --help` names the CLI's approval modes `untrusted | on-request |
never` (default `on-request`, LLM judge on) and its default reasoning
  effort `high`; the mapping in PLAN.md D7 and the extension's default effort
  follow that.
- The SDK requires `data.kind` on every JSON-RPC error response; the fake
  server now answers a throwing handler with a typed `commandRejected` error
  instead of throwing through the transport (which had made every later
  command fail in the tests).
- `skill/list` needs a session, so the palette's Skills group reads "Start a
  conversation to load skills" until the first send or the first palette open
  (which starts the session).
- A greedy subsequence scorer latches onto folder letters (`c` of `src/` for
  `cfg` against `src/config.ts`); the fuzzy scorer rescoring the file name on
  its own fixed the ranking and is covered by a test with a negative case.
- On Windows the unit-test project service could not tell
  `palette.test.ts` from `Palette.test.tsx` apart; the registry test is
  `paletteRegistry.test.ts`.
- `react-hooks/set-state-in-effect` (eslint-plugin-react-hooks 7) rejected
  resetting palette state in effects; the active index is now derived and the
  palette remounts per view (`key={view}`).

## Security

- Images are validated by header parsing before they are stored; anything
  that is not PNG/JPEG/GIF/WebP, over 10 MiB, or beyond 20 per message is
  refused with a reason and never reaches the host.
- Bypass permissions (`allowAll`) is applied only after a modal confirmation.
- `git ls-files` runs with a fixed argument list in the workspace root; no
  user text reaches its command line.
- Dropped `text/uri-list` entries are mapped to workspace-relative paths and
  inserted as text only; URIs outside the workspace are dropped.

## Visual verification

**Owner F5 check (first round) failed**: "/" did nothing (not even a slash),
the slash button and the pill did nothing, `@src` showed no menu, and the
header button opened a new editor tab instead of a new conversation. Root
cause of the first three: the palette was absolutely positioned against the
whole panel (`bottom: 100%` of `.app`), which put it above the viewport; the
mention menu shared the same rule set. Fix: a `.composer-area` positioning
wrapper around the palette and the composer. The header button now starts a
new conversation in place (as in Claude Code); a new editor tab is
`Ctrl+Shift+Esc` or the `+` in the view title.

Verified after the fix with `npm run harness:shots` (the webview bundle in
headless Chrome behind the scripted fake host in `test/harness/`, one
scenario per URL): `m3-palette.png` (palette with all groups, slider and
toggles), `m3-models.png` (model list, "1M context", current model ticked),
`m3-mention.png` (`@src` menu), `m3-chips.png` (`image.png 686×695` chip),
`m3-pill-toggle.png` (second pill click closed the list, composer refocused).
Transcript, Shift+Tab cycling and the effort slider were checked the same
way. The theme variables in the harness are approximations of VS Code's
light theme; layout is what is being verified.

Two more owner notes from the same round, both fixed and covered by tests and
the `pill-toggle` scenario: the pill (and the slash button) now toggle, a
second click closing what the first opened; the version label in the corner
overlapped the Send button and was removed.

**Second owner F5 check pending** for the same list: `/`, slash button, pill
(click on, click off), `Shift+Tab`, paste, `@src`, header button.

Steering, checked live (`scratchpad/live-steer.ts`, one real turn): the
`turn/steer` for a running turn was accepted 3.7 s in, after 24 streamed
characters, but the answer (a 40-line count) finished unchanged. MSP applies
steer input to the model calls that follow; a single streamed answer has
none, so the effect is only visible in multi-step (tool-using) turns. The
optimistic echo appearing at once is expected.
