## What landed

- `src/core/support/flightRecorder.ts` (new, no `vscode` import): record
  shapes, write-time scrub + validation, journal parsing, pruning, crash
  ownership. A record holds a fixed event kind, a known error code (anything
  else becomes `unknown`), extension/host versions, an optional backend and
  count, and bounded frames with verified package-relative paths. Lane 0's
  shapes are reused, not redefined: webview posts must first pass
  `reportWebviewErrorSchema`, and every bound (kinds, code/path lengths,
  frame count, entry/age/size caps) comes from lane 0's constants.
- `src/host/support/reportJournal.ts` (new): the `ReportJournal` adapter.
  One journal file per window instance
  (`<globalStorage>/reports/journal-<instance>.jsonl`), one activation
  marker per window (`marker-<instance>.json`), a reader merging every
  window's journal. All file work runs through one queue; every method is
  total — storage failures disable recording with one logged warning
  (errno word only, never a path) instead of throwing, and the failure is
  never recorded back into the journal.
- `test/unit/flightRecorder.test.ts` (new, 38 tests).
- `src/shared/constants.ts`: lane-R block with `REPORT_STORAGE_DIR`
  (`'reports'`) and `REPORT_VERSION_MAX_CHARS` (`32`), each with its
  one-line reason.
- `PLAN.md` §8: one row for the two test-only `as never` casts. Lane R
  product code holds no cast, `any`, `eslint-disable` or `@ts-expect-error`.

## Decisions the plan left to the lane

- The original implementation applied 256 KiB per journal file. This was
  not the D72 aggregate disk guarantee; see the named FIXM93R-R7 residual
  below. Invalid-only cleanup and merged report capping are corrected below.
- Versions are stamped by the adapter (`ReportEventInput` carries no
  `ext`/`host`), so every record a window writes carries that window's
  versions. Callers cannot stamp another window's versions.
- Marker staleness is pid liveness (`isAlive` is a required option, no
  silent default): a marker is a crash hint only for another instance whose
  process is gone. Own and live markers are never touched.
- A stale marker is consumed (deleted) before it produces an offer, so
  dismissal is remembered; only a successful consume offers. A raced
  consume (ENOENT) offers nothing.
- `isAlive` has no default: lane I must pass a real process check (the
  checkpoint code's `isProcessAlive` shape). Lane I must also pass
  `context.globalStorageUri.fsPath`, a `crypto.randomUUID()` instance, and
  the extension/host versions.

### Corrected behavior

- **1, P1:** unknown token-shaped codes become `unknown`. The fixed vocabulary
  contains JavaScript error classes and named errno values; code, extension
  version and host version are secret-revalidated on read. Versions must have
  a dotted numeric triple. No arbitrary caller token survives.
- **2, P1:** paths must be exact JavaScript members of the shipped VSIX list,
  checked against `.vscodeignore` by the owning suite. Relative syntax is an
  additional refusal check. Multiline prose, workspace filenames, unknown
  package files and query/fragment suffixes are dropped on write and rejected
  on read. A new bundle must join the vocabulary before frames can be kept.
- **3, P1:** native storage rejects linked/junction report roots, symlinked or
  hard-linked leaves and non-files. Opens use no-follow and non-blocking flags,
  held regular-file identity is compared with the exact BigInt sampler, and
  canonical directory checks precede mutations. Stages use random names and
  exclusive creation, with private file modes. Startup preserves entry types.
  Native tests use disposable targets wholly inside this worktree, never a
  real credential or external user file.
- **4–5, P2:** only own/closed journal files can be rewritten/deleted; a valid
  live ownership marker prevents peer mutation even after a held stale read.
  Shutdown closes append admission before clearing the marker. Stage cleanup
  parses its process owner and preserves live processes, including legacy
  predictable stage names.
- **6, P2:** every actual append repairs a torn tail first and prunes age/size
  afterward, independent of current file size. Oldest-first eviction inspects
  physical bytes before a report read can mask the append behavior.
- **8, P2:** repair compares normalized bytes, not valid-entry counts;
  invalid-only and empty eligible files are removed, and torn/malformed bytes
  alongside valid records are rewritten. Native reads allocate at most one
  256-KiB tail buffer; an oversized prefix is represented by a fixed invalid
  line so maintenance repairs the physical file too. A cut first record is
  discarded; complete newest records survive.
- **9–10, P2:** non-missing journal/marker read failures disable recording and
  warn once using a fixed errno word. `isAvailable` is false; the report read
  returns no recent events. Missing files remain harmless races. Shutdown
  still attempts own-marker deletion after recording has been disabled.
- **11, P3:** the append eviction regression now calls `record` 320 times and
  checks the physical journal immediately. Disabling append pruning fails it.
- **12, P3:** English and all fourteen real translations ask the user to review
  the scrubbed preview and warn that descriptions can disclose confidential
  information. The unchanged-input promise is gone.

### Named residual

**FIXM93R-R7 (finding 7, P2) — aggregate on-disk retention budget.**
The merged report now has one 256-KiB budget; each journal remains capped at
256 KiB. Multiple live/retained journals can still exceed 256 KiB in aggregate
on disk. The R7 regression deliberately demonstrates that limit and proves
merged reporting is bounded. Safely enforcing aggregate disk eviction requires
all processes to share an append/maintenance transaction; doing it from a
peer's queue would reinstate finding 4's silent loss of a successful append.
This is a redesign rather than a local predicate fix. For this unintegrated
recorder lane the content stays scrubbed, journals remain individually bounded,
and report reads exclude expired data; live disk files wait for their owner's
queue or a later closed-file sweep. Follow-up: cross-process admission,
oldest-first aggregate eviction and native process-interleaving tests before
claiming D72's aggregate disk budget. Also recorded in PLAN §9.

**Native race boundary:** Node lacks portable directory-relative file syscalls.
An actor able to mutate this user's storage can still swap an ancestor between
its last canonical check and a syscall. Static redirects and leaf races are
refused; resistance to that actor requires native directory-handle operations.
This is D72's stated local-user/admin limit and is explicit in PLAN §9.
