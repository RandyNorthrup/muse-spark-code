## Delivered scope

- `src/core/providers/accounts.ts`: shared operations for adding, labelling,
  ordering, grouping, editing thresholds and removing accounts. An absent
  accounts field exposes the existing credential as `default`; the next
  metadata edit persists it. An explicit empty field stays empty after
  removal. Mutations serialize within one store and recover after a failure.
  The metadata port writes only accounts, preserving the provider envelope.
- `credentialRecord.ts`: local record validation, exact provider/account/origin
  binding, and one shared secret-name function. A host, scheme or port change
  refuses credential use. Invalid data and secret-store errors use fixed
  error codes. No vendor response shape is introduced.
- `src/host/providers/accountSecrets.ts`: injected credential vault, a real
  SecretStorage adapter, legacy default reads without copying or rewriting,
  and revocation before deletion for OAuth/subscription sign-ins. Failed
  revocation leaves the secret and account; failed deletion cannot report
  successful metadata removal. If metadata writing fails after deletion,
  removal rejects; a retry can remove the remaining metadata row.
- `src/runtime/providers/accountStore.ts`: the same operations and names
  through the existing OS-store adapter, or an injected replacement vault.
  Tests use a fake entry factory; the actual keychain was never opened.
- `src/host/auth/metaAccountKey.ts`: a second Meta key enters through the
  existing injected password prompt, is validated and trimmed, and is stored
  independently. Cancellation and invalid input never call the store. All
  Meta accounts remain bound to the fixed Model API origin. The subscription
  CLI receives no stored Model API key.
- The registry/scan seam creates a separate client using the requested
  account's credential and binding. Model visibility is scanned per account;
  no shared credential or header fallback exists. Missing credentials fail
  authenticated lookup explicitly. Unauthenticated local providers receive
  no stale secret and cannot add credential accounts. Products whose policy
  says `notOffered`, editor-owned credentials, and the uncaptured Muse Code
  config-home flow cannot be admitted, including credentials planted in
  metadata by hand.
- The shared redactor registers exact values, including keys without a
  recognizable vendor prefix, for logging, scanners and exports. Registrations
  are reference counted and retained after replacement/removal for late
  errors, then released at store disposal. Pending reads cannot publish a
  secret after disposal. Export chunks cannot split a registered multiline
  value. Lazy callers may inject the parent bundle's registration function.
