# M99: What's New after an update

Recorded 2026-10-04 on branch `feature/m99-whats-new`, from main
`bf77aabe`. PLAN.md D79 and M99. The owner's request: "after the app updates
it opens a whats new/changelog in whatever editor so the users can take
advantage of any changes we make"; enhancements are on by default.

## What M99 is, on this tree

- **Activation** (`src/host/whatsNew/whatsNew.ts` over
  `src/core/whatsNew/whatsNewVersions.ts`): the version check against
  `globalState` `museSpark.whatsNewLastSeenVersion` (synced with
  `setKeysForSync`), the exclusive claim file per version under global
  storage, the wait for a quiet window, the page-or-notice choice and the
  loader of `dist/whatsNew.js`. `extension.ts` reads the signs of earlier use
  before anything stores state, wires the edit tracker (output channels
  excluded), the command and the panel's palette item, and calls the check
  at the end of activation.
- **The bundle** (`dist/whatsNew.js`: `whatsNewEntry.ts`, `whatsNewPanel.ts`,
  `whatsNewHtml.ts`, `src/core/whatsNew/whatsNewContent.ts`,
  `src/shared/whatsNewMessages.ts`): reads `dist/whatsNew.json` through its
  zod schema, renders the page on the host with a strict CSP and every text
  escaped, opens links from its own list through `openExternal`, runs a Try
  it from the list of buttons it rendered, writes the toggle to the setting.
- **The page script** (`dist/webview/whatsNew.js` and `whatsNew.css`, from
  `src/webview/whatsNew/`): passes clicks back as indexes; imports only the
  dependency-free markup contract `src/shared/whatsNewPage.ts`.
- **The content** (`scripts/lib/whatsNewContent.mjs`, run by
  `scripts/build.mjs` before esbuild): released CHANGELOG sections into a
  text-only tree; `[Unreleased]` is checked and left out; a Try it naming a
  command or setting the manifest does not contribute fails the build.
- **The release guard** (`test/unit/changelogVersion.test.ts`): a minor or
  major `package.json` version needs a `### Highlights` list of 1 to 5
  bullets in its section.

## Deviations from the brief, recorded in D79

- **One-window claim:** an exclusive file create (`open(…, 'wx')`) in global
  storage instead of a `globalState` claim re-read after a delay: atomic on
  one machine, where `globalState` propagation between windows has no
  ordering guarantee.
- **Upgrades from versions before the feature:** no stored version plus signs
  of earlier use counts as an upgrade from an unknown version, or every user
  updating to the release that brings What's New would be taken for a new
  one.
- **Setting scope:** machine, not application: the manifest test allows only
  machine or window scope for this extension's settings.
- **No click-time re-check of a Try it:** the renderer is the allow list and
  the page sends only an index into the list of buttons it rendered. The
  re-check first written in the panel could never fire; its red drill (below)
  proved that, so it was removed rather than kept as decoration.
- **Activation:** no `onStartupFinished`. The page shows on the first
  activation after the update.
