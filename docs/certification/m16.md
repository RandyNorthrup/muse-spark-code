## What the milestone rests on

- `usage/read` before a turn, re-probed 2026-09-22 through the extension's
  own backend code with no model call (`scratchpad/probe-usage.log`):
  `undefined` after the host started, three seconds later, after a session
  started, and five seconds after that. The CLI reports a window only once
  it has seen a reply, so the dialog's "as of" cache is the only way to
  show numbers on open.
- MSP `userInput/cancel` (SDK `msp.d.ts`): "decline to answer; the tool
  call resolves with a cancelled result the model sees". The answer shape
  carries `freeText`, which is what the card's "Other" row sends.
- Claude Code's question card (the owner's brief and screenshot): stacked
  radio buttons or checkboxes, tabs for several questions, always an
  "Other" free-text option, Submit greyed out until a selection, Cancel.

## Security

- `openFile` opens only the path the CLI reported for the tool call,
  resolved against the workspace when relative; it selects lines, never
  edits.
- The usage cache holds percentages and timestamps only; a malformed
  stored value is ignored (schema-validated on read).
- Cancel goes through the CLI's own `userInput/cancel`; the Model API tool
  answers the model with fixed text.

## Findings recorded during the milestone

- `usage/read` is empty until the CLI has seen a reply (above); no other
  source exists without using the CLI's token, which the rules forbid.
- Muse Code 1.3.0 on Windows fails its reply to `approval/decide` on its
  approval-ledger flush after the decision applied ("retained
  acknowledgement fence left records unflushed"); a CLI fault, relayed.
- VS Code's `Memento.update` returns a `Thenable`, not a `Promise`; a
  dependency typed `Promise<void>` needs an `async` wrapper.
