## M70e: Revert restructured (RV69, 2026-10-02)

The fourth review round on Revert (RV69 findings 1–4; finding 5 was the
wiring test, fixed in `5f600299`). The lead's decision: stop patching and run
every Revert (edit review's and the pane's, write and delete) as one
operation under checkpoint admission: take the lease, read the saved bytes,
rebuild from them, re-resolve the canonical target inside the workspace,
refuse a dirty editor, publish only while the file still holds those bytes
with no link on the way, let the lease go. `EditReview` now takes
`withAdmission` and a `RevertIo`; activation passes `withCheckpointEdit` and
`createRevertIo` (`src/host/editor/revertIo.ts`) over the tools' own
`ToolIo.writeFileIfUnchanged` (not their checkpoint copies). A created file is
trashed through the new `fsAtomic.deleteFileIfUnchanged` (bytes, canonical
path, then device/inode/size/mtime last); a file absent when read is written
through `fsAtomic.writeFileIfUnchanged` with an absence expectation, as a
restore does. No raw `workspace.fs` write or delete remains in Revert; VS
Code's trash is only the removal step of the conditional delete.
