## What was built

- **`/review`** (`src/shared/reviewCommand.ts`): `/review` (the uncommitted
  changes), `/review branch [base]`, `/review commit [revision]`,
  `/review <what to look at>` (custom, no git), each with an optional
  leading `security`. A keyword counts only with at most one revision word
  after it. A revision is one word that never starts with `-`; the wire
  schema (`startReview`) refuses anything else, and `commitOf` refuses a
  leading `-` again before git runs. The palette's **Review** group has the
  presets, **Security review** (`/security-review`) and the pane
  (`/changes`).
- **The material** (`src/core/review/reviewMaterial.ts`,
  `src/host/review/reviewCollector.ts`): git in the workspace folder with
  `GIT_METADATA_OPTIONS (empty core.fsmonitor, no signature program, no replace refs)`, `--no-color
--no-ext-diff --no-textconv --relative`, and the files that may hold
  secrets excluded by pathspec (the M54 attachment rule, now
  `src/shared/privateFiles.ts`, shared with the composer and the attach
  path) and only named. The uncommitted changes against `HEAD` (staged,
  then unstaged, before a first commit); a branch from its merge base; one
  commit against its first parent, a root commit whole. The diff is cut on
  a line end at 200,000 characters. A missing base or commit is picked in a
  quick pick (`origin/HEAD`'s branch, else `main` or `master`, first).
- **The turn's text** (`src/core/review/reviewPrompt.ts`, `REVIEW_MODEL_TEXT`):
  scope, the security preset's focus (injection, secrets, authentication,
  unsafe APIs), the findings block to end with, and everything git said
  (branch name and commit message included) between random markers under a
  sentence that calls it untrusted data. A marker the material holds is
  replaced, three tries, then the review is refused.
- **Model API: the Reviewer** (`src/core/backends/modelapi/reviewer.ts`,
  `ModelApiSession.review`): the conversation's own turn run with its
  prompt (role, workspace, environment, the method, the workspace rules)
  and only `read_file`, `search`, `list_files` and
  `mcp__ide__getDiagnostics`. No shell, write, memory, MCP, subagent, image
  or web search is offered, and any other call is refused in every mode,
  Bypass included. No paid-use popup: it is the user's own turn (D49). A
  child task whose role is `reviewer` runs as the Reviewer and is still a
  paid child task (D45, D48).
- **Muse Code** (`src/core/review/planModeHold.ts`): the same text, the
  role and method at its head, as the turn's text, no skill. `PlanModeHold`
  sets `denyUnmatched`, sends the turn, and sets the user's mode back when
  that turn ends (or when its send fails). A mode the user picks meanwhile
  wins; a dropped session releases the hold; a revoked Bypass comes back as
  Manual. The panel says the review is not strictly read-only there (D46).
- **Findings** (`src/shared/reviewFindings.ts`,
  `src/webview/components/ReviewFindings.tsx`): the reply's `muse-review`
  block, parsed with zod, as a list with severity, title, detail and a
  `file:line` button that opens the file at those lines. A model-chosen
  severity is shown as it came; a location that leaves the workspace is
  text. A block that does not parse stays a code block.
- **The review pane** (`src/webview/components/ReviewPane.tsx`,
  `readReviewChanges`, `revertReviewHunk`, `EditReview.describe` and
  `revertHunk`): the conversation's edits, its agents' included, in the
  order they landed, file by file and hunk by hunk, at most 200 edits and
  20,000 lines. Accept marks a hunk; Revert reverse-applies that one hunk
  to the file as it is now (M36's exact matching, workspace-confined as Edit
  Review), once per hunk; a comment on a line quotes the file, the line and
  three lines around it as a `chat_reference` from `diff` and goes as a
  steer or as the next message.
- **Strings**: 70 keys in `en.ts` and the 14 tables (`reviewItem` stays
  `/review` everywhere, in `untranslated.json`); `check:l10n` 0 problems.
