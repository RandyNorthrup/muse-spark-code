## What lane L added

`src/host/tab/tabLedger.ts` (new): one file per window per local day
(`<directory>/<YYYY-MM-DD>/<window>.json`, holding `reservedUsd` and
`reportedUsd`), written through `writeFileAtomically` (host/fsAtomic.ts,
the session store's pattern: temp file beside the target, renamed over it),
with the cross-window daily total read from all of today's files.

- Admission is write-then-check: the window writes the request's worst
  case into its own file, then reads today's total across all files
  (its own write included) and sends only while the total stays within
  the budget; a refusal rolls the reservation back. Two windows therefore
  never pass the budget together: the later reader always sees the
  earlier writer's reservation (both-admit with a combined over-budget
  total would need each read to precede the other's write, impossible
  since each write precedes its own read), and each window writes only
  its own file, so concurrent windows cannot lose each other's spend.
  One instance serialises its own steps, so concurrent admissions in the
  same window cannot lose one either.
- Fail closed, never throwing into the provider: a missing, corrupt,
  partial or otherwise unreadable file (bad JSON, schema failure, date
  or window mismatch with the file's name, unreadable folder) refuses
  the request as budget-reached and says which file; a corrupt file
  never counts as zero spend. `settle` replaces the reservation with
  the reported actuals; a request that never reports keeps its whole
  reservation. Day boundary is the local calendar day. Windows note:
  this platform answers ENOENT (not ENOTDIR) through a file used as a
  folder, so a base that is not a directory refuses explicitly instead
  of reading as zero.
- New literals: none user-facing. `'.json'`, `'ENOENT'`, the window-id
  alphabet and the `YYYY-MM-DD` assembly follow the session store's
  file precedents; every tunable and every user string is lane 0's.

`src/shared/paid.ts`: the `PaidUseRequest` `tab` variant (`modelId`,
`budgetUsd`) — the case m94-0.md's "Notes for later lanes" assigns to
lane L. No other file needed a change for it: every other consumer
passes the request through opaquely.

`src/core/paid/paidFeatures.ts`: `PaidUsage.add('tab')` counts
`tabRequests` (lane 0 left it logging-only), plus `addTabRequest` /
`addTabUsage` mirroring the best-of-N unknown-then-settle pattern
(`tabUnknownRequests`, `tabTokens`, `tabCachedTokens`, `tabCostUsd` at
the request model's rates; unreported requests stay unknown, never zero
cost; unpriced models and invalid counts throw).

`src/core/paid/paidConsent.ts`: the `tab` popup question (Tab's title;
the request model's per-token rates via the shared tier formatter,
today's budget, the contributor training note, empty for Standard),
and the window-scoped Allow once: a `windowOnceFeatures` dep, an
in-memory-only grant set (never stored, so nothing persists past the
window), bypassed by `requiresAsking`, revoked by `revokeWindowOnce`
when a price acceptance changes, and cleared by `forget`. "Allow
always" is untouched and stays workspace-scoped.

`src/host/paid/paidHost.ts` (Tab wording region): the confirmation
keeps quoting both tiers (the popup quotes the request's own model);
`askPaidUse` refuses Tab on an unpriced model or an unusable budget
before any popup; `windowOnceFeatures: {'tab'}` is wired, and
`writeAccepted` revokes this window's once for every feature whose
acceptance changed (the workspace "always" lapses through the
generation bump as before).

### Finding 1 (P1): a reservation keeps its day

- **Defect:** settlement subtracted from the current day's file, and
  admission read the clock twice (once for the write, once for the total),
  so a reservation could be wiped from the wrong day or checked against
  another day's total.
- **Fix (`src/host/tab/tabLedger.ts`):** `admit` reads the clock once;
  the write, the total check and any rollback use that one date. An
  admission returns `reservation: { date, worstCaseUsd }`
  (`TabLedgerReservation`); `settle(reservation, actualUsd)` writes to that
  reservation's day, also after midnight. `todayTotal(date?)` reads any day.
  A day that is not `YYYY-MM-DD` never reaches a path: the total refuses it
  and settlement keeps the reservation.
- **Regressions (`test/unit/tabLedger.test.ts`, "TabLedger reservations
  keep their day"):** "settles yesterday's request into yesterday, so
  today's reservation still counts" (the review's $0.05 case: reserve
  $0.03 yesterday and $0.03 today, settle yesterday's for $0.001; today
  still holds $0.03 and another $0.03 is refused); "reads the clock once
  per admission, so midnight cannot split its write from its check"
  (midnight injected just after admission's first clock read); "settles
  after midnight into the day that holds the reservation". Also "never
  lets a reservation or a total name a folder that is not a day".
- **Drill R1a:** in `settle`, `const { date } = reservation` became
  `const date = tabLocalDate(deps.now())`. Slot `m94fl-2`: 2 failed, 18
  passed. The $0.05 case: `expected 0.001 to be close to 0.03` (today's
  reservation wiped). Settling after midnight:
  `expected { ok: true, totalUsd: 0.6 } to deeply equal { ok: true, totalUsd: 0.001 }`.
  Restored.
- **Drill R1b:** in `admit`, `dayTotal(date)` became
  `dayTotal(tabLocalDate(deps.now()))`. Slot `m94fl-3`: 1 failed, 19

  That is the review's case: approved against the empty new day while the

### Finding 6 (P2): one first question per window

- **Defect:** two first Tab uses that reached `allows` before either popup
  was answered both found no grant and each asked, so two price and budget
  popups appeared instead of the promised once-per-window question.
- **Fix (`src/core/paid/paidConsent.ts`):** while a window-once feature's
  first question is open, ordinary uses of that feature wait for it
  (`pendingWindowOnce`, one promise per feature, cleared when it settles)
  and share its answer. A use with `requiresAsking` still gets its own
  question. The popup and the grant logic moved unchanged into a private
  `decide`.
- **Regression (`test/unit/paidConsent.test.ts`):** "shares one first
  question between concurrent uses (RVM94LC finding 6)". Two concurrent
  first Tab uses make one `ask` call and both resolve from it: true after
  Allow once, false after Deny. A concurrent `requiresAsking` use asks
  separately. Once the question closes, Allow once covers the window and
  Deny lets the next use ask anew.
- **Drill R6:** removed `this.pendingWindowOnce.set(feature, decision)`.
  Slot `m94fl-6`: 1 failed, 19 passed,
  `expected "vi.fn()" to be called 1 times, but got 2 times`: the
  review's two popups. Restored.
