## Implementation

`disk.ts` reads watched locations with bigint `fs.statfs` counters, caches
30 seconds (5 seconds below twice the floor), preserves unknown readings,
and estimates time to the floor over a bounded five-minute history.
G retains its levels, hysteresis, dwell, stepwise recovery and override.
Disk entry uses the existing `disk` event reason, preserving the frozen
exec-event contracts. The disk setting reads only inspected machine values.
Local volume roles contain no user path; peer headroom contains only free
and floor bytes and a missing/unknown field refuses disk-heavy placement.
Critical write checks use a fresh destination/nearest-existing-ancestor
reading and name that volume in the localized refusal. All 14 tables have
real translations. The Model API/CLI never provides these local readings.

First finished piece committed as `eab239ef0` with normal lint-staged and
gitleaks hooks. Its disk/G/contracts passed 78 tests. The finished registry,
queue and adapters extend that piece; final results below supersede the
initial fixture runs. No test timeout, threshold, rule level or ignore changed.
No new dependencies, casts, suppressions or escape hatches were introduced.

Every leased tree receives an owned root and all three temp variables.
Browser check folders/profiles are created inside that root. CLI, shell,
MCP, hook, Git, browser and voice spawn environments project those values;
wrapper leases preserve the temp and failure marker. Failed exit/spawn and
logical errors mark retention separately from exact whole-tree retirement.
The persistent registry uses native identity plus canonical paths, a private
atomic JSON manifest, whole-tree exit proof, 24-hour failed-temp retention,
and archived/merged-and-clean proof for worktree/dependency cleanup. It
never discovers deletion authority by scanning a directory. Pressure cleanup
and the failure deadline invoke this same registry cleaner. Observed free-space
change can include concurrent volume activity, so it is not exact reclaimed-byte
accounting. Cancellation does not prove tree exit and does not delete its root.

## FIXM107DK review repair — ownership and cleanup

RVM107DK's P1-1, P1-2, P2-7 and P2-8 are repaired. Every record is a direct
`muse-tree-<random>` child of one base, checked as canonical, non-link and on
POSIX current-uid-owned and not group/world-writable on every open/operation.
Existing public bases and manifests are refused without chmod. A private
marker contains the creation id and a random 128-bit token; the manifest
stores only its SHA-256. Loaded timestamps never substitute for fresh exact
tree-exit proof. Old manifests without markers/intents fail closed.

Creation saves and syncs an intent before mkdir. A failed first save creates
nothing; a failed final save leaves a recoverable pending intent. Pending
paths without a valid marker remain protected. Cleanup renames into the
same base's `.muse-trash-<id>`, rechecks identity and marker, and removes only
that quarantined entry. Linux pins the base through an open fd and uses
`/proc/self/fd/<fd>` for mkdir/rename/lstat/removal. Refusals are flagged,
returned as `CreatedCleanup.refused` ids, and do not stop other entries.

The owner defines content a same-user process moves into a harness root as
that tree's content. External leftover paths are not an exception to
confinement: their existing integration handoff needs a separately reviewed
ownership adapter. Native Windows/macOS receipts remain the lead's scope.
