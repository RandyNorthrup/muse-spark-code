## How it was built

A Muse Code instance wrote the first draft (`5094e6b4`). Its sandbox could
not run the build, `npm audit`, semgrep or gitleaks over history, so none of
its gate claims were taken as given. The draft was reviewed as another
model's first draft and most of it was rewritten. What it got wrong:

- **Scope rule broken both ways.** A repository's MCP servers were offered as
  copies for the user's own `settings.json`, and every hook, the user's
  included, went to the project's `.muse/hooks.json`. The user's
  `~/.claude/CLAUDE.md` was appended to the project's `AGENTS.md`, even in
  Restricted Mode.
- **Wrong sources.** User MCP servers were read from `~/.claude/settings.json`,
  which holds none; Claude Code keeps them in `~/.claude.json`, which was
  never read (and at 71 KiB on this machine was over the draft's own
  64 KiB cap). `.mcp.json` was not read. Codex prompts were read from a
  project `.codex/prompts`, which Codex does not have. The project's
  `AGENTS.md` was imported into itself. `CLAUDE_CONFIG_DIR` and `CODEX_HOME`
  were ignored.
- **Wrong target shape.** Converted MCP entries had no `type` or
  `mode: "optional"`, turned `sse` into streamable HTTP, and carried `cwd`.
  The copy text left out the server's name. Hooks dropped their matchers,
  so a `Bash` hook would have run on every tool. `if`, `args` and `shell`
  were ignored, which widens a hook.
- **A hand-written TOML subset.** It misread `[mcp_servers.x.env]`
  sub-tables as servers named `x.env`, and dropped multi-line arrays. Both
  appear in real Codex files, this machine's among them.
- **Secrets and content in the log.** Warnings carried `JSON.parse`
  messages, which quote the file on Node 20 and later. Only secret-named
  keys were masked, so `env` values under other names showed.
- **Overwrites and escapes.** `isPresent` was checked, then the file was
  written with a plain write. Two entries with one destination overwrote
  each other. Nothing was confined: a repository's `.claude/commands` link
  to `~/.ssh` would have been read, and an `AGENTS.md` link to `~/.bashrc`
  appended to. The personal agents folder was `~/.config/muse/muse/agents`.
- **A preview that was not the write.** File bodies were cut at 2,000
  characters inside a modal, and the rest was written unseen.

## What was built

- **Sources** (`src/core/import/agentImport.ts`). Each path comes from that
  tool's documentation, read 2026-09-28, or from Muse Code
  1.4.0-R4302.1's bundled `migrate` skill (read from the binary's

  `agentImport.test.ts` match this machine's real `~/.claude.json`,
  `~/.claude/settings.json` and `~/.codex/config.toml`, which were checked
  by key name only.
- **Conversion** (`importConvert.ts`). Every file is parsed, then checked by
  zod: JSON, `smol-toml` for Codex, and the Markdown front matter. The MCP
  entry is the `migrate` skill's shape. Hooks follow Muse Code's M51
  grammar, where matchers take Claude Code's tool names. SKILL.md front
  matter is written as single-quoted YAML. A rules section is headed from
  `MODEL_TEXT`, with the workspace-relative path and no user path.
- **Masking** (`importMask.ts`). Every `env` and header value; URL user-info
  and query values; values after credential-like flags or in assignments;
  token shapes. Entries are masked when they are converted.
- **Plan and apply.** Nothing that exists is replaced, and the first of two
  entries with one destination is kept. Muse Code's servers are left alone
  by name. `settings.json` and `hooks.json` are always copy texts: the whole
  file when it is missing, otherwise the members to merge. Apply confines
  each destination again, a project's to the workspace root itself. It
  creates with `wx` and re-checks rules headings at write time.
- **Flow** (`src/host/commands/agentImportCommands.ts`,
  `src/host/agentImportHost.ts`, `src/host/importIo.ts`). The flow runs
  pick tools → scan → check entries → a read-only preview document →
  Import in a non-modal notification → write → copy and open each file.
  The notification is non-modal so the preview can still be read. A
  missing file opens unsaved at its path. `extension.ts` now opens the
  read-only documents before it builds the CLI features.
- **Strings.** There are 29 new or changed keys in `en.ts` and all 14
  tables, and 5 keys were removed. The loanword allowlist is per language.
  `check:l10n` reports 0 problems.
- **Docs.** README (with a From / Becomes table), CHANGELOG, PLAN (M83 as
  built, a D3 row for `smol-toml`, and an M76 note on the agents folder),
  SECURITY, docs/PRIVACY, and THIRD_PARTY_NOTICES (regenerated, 76

## Completion review, 2026-09-29 — implemented, verification pending

Source worktree: `muse-extension-m83`, branch `feature/m83-import`, base
`4c7b2d34`. The earlier gate and drill results above describe earlier trees.
Issue #58's M83 review was checked against this WIP first: it already had

This review strengthens the existing filesystem boundary: project path
components are checked with `lstat`, including dangling file links and
Windows junctions; bounded file reads open a handle and verify its inode
before using bytes, with `O_NOFOLLOW` where supported. Project preview
reads carry their root to that same boundary. New files stage complete
bytes and publish with a never-replace hard link; verified owned staging
files are removed on failure. A filesystem that cannot create the link
reports an import failure. Rules append through the existing atomic writer,
retain the checked prior text, and refuse changes or a result past 64 KiB.
The same-window queue covers the complete picker, preview, write and
clipboard/editor flow. A trust revocation while the preview waits aborts
project actions before apply. Node offers no
handle-relative publication API here, so these checks do not claim to close
every race with an arbitrary filesystem writer between native operations.

Copy targets are checked both before clipboard access and after its await.
The actual project editor-open adapter checks before loading a document
and before showing it. Malformed settings now get the same honest
unreadable skip as oversized or undecodable settings. Generated command
and agent content is masked before planning, so it matches the accepted
preview instead of writing an unseen raw secret.
Commands with unsupported metadata (`allowed-tools`, `model`, `context`,
or other fields the native skill does not preserve) are shown without
creating an unrestricted skill.

M76 is a planned integration dependency: its current canonical reader is
`src/core/context/customAgents.ts`, `parseAgentFile`, with agents stored at
