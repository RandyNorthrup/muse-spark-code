## Remaining live owner-command capture plan

live subagent drill, with delegation enabled only there. Remove any
`META_API_KEY` from the child environment; the CLI signs in through its

## Paid child admission checkpoint, 2026-09-26

`modelApiSubagents`, strict published model tariffs and a fresh one-use task
decision in every mode including Bypass. Plan refuses spawn and later task
admission. A task has four actual `/responses` POST attempts, shared by
tool rounds, HTTP retries and whole-stream retries. Running-child notes use
the same grant; a new follow-up, reopen or resume needs a new decision.
Grants live in memory only. The client reads the key afresh and checks the
grant, gate, model, originating goal, request cap and any included paid web
search tool immediately before each child POST. An abort after the key read
prevents admission and the fetch. A pending reopen consent is invalidated
by Stop, disposal or another child state change. A pending spawn card cannot
be approved after a switch to Plan.
Deleting the key after consent gives the localized changed-key refusal,
both after an owner modal and at final child HTTP admission. A restored
queued child with retained note B previously showed only original objective
A for Resume or only new message C for Follow-up, while the request sent B
as well. Both variants failed before the fix. One task-composition helper
now builds the modal preview and actual child request, and revision plus
task-text checks invalidate a modal if that work changes while it is open.

Each attempted POST increments the paid child request tally. Missing usage
leaves its cost unknown; reported usage, including on `response.failed`, is
charged once to the child tally and the parent's already inclusive token
total, and to the originating goal while it remains the same goal. The
estimated child cost is shown as a subset of the conversation estimate.
The four-request limit is not a token or dollar maximum. Other paid tools
