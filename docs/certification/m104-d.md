## Implementation and boundaries

`PanelBridge` covers validated posts, incoming messages, UI state, disposal and
lazy fallback loading. The VS Code implementation acquires its API once and
uses a private validated message bus. Invalid host messages reach the existing
error reporter instead of becoming uncaught window errors. The native bridge
uses the frozen `window.museHost` API. The companion bridge uses POST SSE and
ordered POSTs through lane C's memory-only authenticated fetch closure, with
the frozen envelope, queue-byte and queue-message limits. Complete and partial
SSE data are bounded before JSON parsing; disposal cancels the reader and
unblocks queued work. Companion UI snapshots use per-surface session storage;
no authentication credential is persisted there.

Chat retains synchronous VS Code mounting. Tasks and What's New select the
same bridge, retaining their existing payload vocabularies. What's New keeps
its small click script and dynamically imports the bridge module. Native and
companion transports, Tasks, and fallbacks stay behind dynamic imports.

The lead's CSS decision is `--ms-*`. The M61.3 description and M104 lane table
are corrected; frozen MHP `--muse-*` theme names map at the HTML boundary.
Stock colors come from the existing captured `test/harness/themes/*.json`.
Unspecified optional colors remain unspecified; invented defaults had changed
warning/selection and high-contrast colors. Existing VS Code variables alias
into the portable tokens. `buildPageHtml` validates binding/theme data, escapes
the embedded binding and rejects CSS rule/URL injection, with a nonce CSP and
surface-specific connection policy. It takes no credential.

The local browser adapter implements `ui/confirm`, `ui/pick`, `ui/input`,
`ui/notify`, `ui/status` and `ui/progress`. Prompts queue, cancel and reject on
disposal, make the surrounding page inert, and restore opener focus. Each
consecutive prompt gets fresh component state. Settings await the supplied
host's `settings/update`, refuse nonfinite values and retain successful edits.
Numeric and string opaque IDs keep distinct React identities, including diff
hunk/version pairs; `1` and `"1"` no longer produce duplicate keys or reuse the
wrong row's state. Diff decisions, terminal Stop, walkthrough actions and manager actions call
their supplied real ports; failures remain visible. Text is escaped by React.
No production fake host, fake records, secret setting or consent bypass is added.

Eleven UI keys were added to English and all fourteen translated tables, with
runtime `UI_TEXT` reads. No dependency or escape hatch was added.

## Integration blockers and touched regions

1. The frozen `MuseEmbeddedHost` exposes only shared chat/Tasks/What's New
   payloads. It has no route for MHP `ui/*` requests/results to this browser
   adapter. The carrier/controller lane must provide the integration contract;
   this lane does not invent a second panel vocabulary.
2. Lane C authenticates fetch and initial inline bundles under its nonce CSP.
   Native ES-module imports cannot attach that memory bearer; protected static
   and lazy chunks require an authenticated loader. The asset guard/CSP was
   retained. Browser fakes prove local components, not this missing delivery.
3. The unchanged deferred cap is 50 KiB, and chat startup must not grow. The
   expanded UI fails those acceptance requirements: **71,064 deferred bytes**
   and **903,255 startup bytes**, up **4,573** from **898,682**. No cap increase
   or chunk exclusion is proposed.
4. `plan/m105-m107` is not present; inspected available later plan refs did
   not contain the requested M110a0 contract. The shared-rule feature catalog,
   reference generator and `check:reference` script are also absent from this
   base. They cannot truthfully be regenerated or checked here. The lead must
   supply the plan/tooling and complete the reference/editor registry at integration.
