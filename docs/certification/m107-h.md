## Implementation plan and integration boundaries

- One lazy runtime resource host composes G's governor/events/queue with
  injected sampler, running-tree counts, machine settings and history ports.
  Importing it starts no sampling. First admission starts sampling; explicit
  status refreshes once. Stop, approval and paid paths never use admission.
- The machine store is under the runtime data folder, never the workspace.
  Missing settings use lane 0's defaults; malformed/unreadable settings fail
  explicitly. M104 B can inject its machine settings reader. A separate
  bounded resume marker lets the terminal request a fifteen-minute override
  without IPC or a new listener. Loaded hosts consume it on their next sample,
  with its original deadline, never an additional fifteen minutes.
- ACP gets `/resources`, `/resources resume`, `/usage resources`, session
  notices and privacy-bounded `_meta` on a deferred call. Local commands do
  not submit a model turn. The spawner supplies session/tool identity only
  through a separate local delivery port; none enters status/events/history.
- Headless flags override the same validated settings; relocation is forced
  off. Its v2 event adapter preserves M80's frozen v1 result and existing
  privacy/redaction rules, sequencing resource and ordinary events together.
  M80's existing sink remains unchanged because H does not own it.
- W binds the lazy `dist/resourceGovernor.js` entry, build/package/split
  guards, schema generation and documentation/help reference. C1/T bind
  admissions and registered-tree counts. J binds durable history. Missing
  history or registry bindings fail explicitly or report unknown, never
  empty successful history or idle occupancy. M104/companion/native clients
  use this same host through their existing status bridge; U owns the chip.

No new dependency or user-visible copy is planned: lane 0's translated
labels, templates and Intl helpers cover these surfaces. The base has no
featureCatalog; commands/settings are listed for W's reference handoff.
Receipts, named red drills and residual bindings follow as executed.

Runtime notices retain local session/tool correlation separately from
public events and records. Cancellation and failed admission drop that
correlation; a running permit retains it until observed retirement.
Registry changes call `workChanged()` to wake the queue. A wrapped parent
permit maps back to its original queue identity, retaining G's rule that
a worker cannot wait on its own slot.

The machine file is `resources.json` under `agentDataFolder`, containing
only `museSpark.resource*` machine values. `resource-resume.json` holds
only the absolute override deadline. Status does one explicit refresh;
admission starts the periodic sampler. Resume writes no settings and
starts no sampler. Loaded processes consume a terminal marker on the
next sample/admission/status read, retaining its exact deadline. Disabled
governance stays disabled. An expired or excessively future marker never
becomes a new fifteen-minute grant.

  fabricates records or returns empty success. Its read boundary validates
  each strict record again before text/JSON output.

  settings store. The file adapter reads only machine-level
  `museSpark.resource*` values; workspace values cannot change thresholds.
  Terminal `resources resume` uses a **machine-wide** absolute-deadline
  marker: other loaded runtime hosts consume it on their next sample,
  admission or explicit status (nominal sampling interval five seconds).
  It does not renew the grant in each process and leaves explicit OFF off.
  The ACP resume command uses that same machine scope.
- **M104/M96 status bridge:** a new terminal command process samples the
  machine and reports its own host’s level/queue, not another running
  process’s sustained-CPU state or pending queue. Bind the active-host
  status/control connection before describing terminal status as a view of
  existing sessions. The resume marker works without claiming that IPC.
- **U/M104 native clients:** VS Code, JetBrains, Visual Studio, Eclipse,
  Zed, Xcode and Neovim/Emacs/Sublime companion/native hosts all consume
  `status()` and `subscribeEvents()` from the same runtime host via their

  The UI chip and native widget are their lanes’ bindings, absent here.
  ACP receives the same validated status/events in `museSpark.resources`
  metadata and localized text; headless receives sequenced resource v2
  events and one-line stderr notices. No surface renders unknown as idle.
