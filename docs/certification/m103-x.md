## Rig and boundaries

The launchers own real QEMU, simavr, rp2040js and Renode processes. Serial
bytes come from executing firmware, not a transcript or an echo process.
P's production discovery parser receives synthetic Arduino CLI metadata
for the actual PTY. VID/PID is neither an OS USB capture nor proof of the
MCU behind a bridge. Every session goes through `runSerialAction`; the host
seam answers each fresh request with its exact id/digest and `allow_once`.
No standing approval, model-visible token or guard setting is introduced.

The test classifiers exercise P's existing dependency contract only. Context,
classification refusal, host rejection and known flash mismatch prevent the
transport from opening. G's irreversible-command classifier/dispatcher is
absent on `39970a36`; its efuse/fuse/lock/OTP/RDP refusals remain **pending**,
as do D's `onPi.ts`, M's machine adapters and W/editor/ACP/companion wiring.
The test flash transport has fixed esptool/avrdude arguments, accepts approved
bytes only through stdin, and refuses any port resolving outside `/dev/pts/`.
It cannot request fuses, locks, OTP, protection, RF or machine operations.
No maker product source, guard, dependency, bundle budget or threshold changed.

Flashing uses the real `esptool` ROM protocol on QEMU's UART and real
`avrdude` STK500 protocols on simavr's UART. ESP32/C3 marker writes at
`0x3f0000` and S3's actual IDF app at `0x10000` are verified by esptool's
hash and the actual MTD backing bytes. S3 starts with its app region erased;
the upload must restore it before the rebooted firmware can produce output.
AVR flash writes are verified by avrdude. Cancellation is admitted only after a
real programming-progress receipt, then P kills the tool's process tree.
The Uno rig uses Arduino's ATmegaBOOT/STK500v1 at 57600, not modern Optiboot;
Mega uses STK500v2 at 115200. simavr is paced by simulated CPU cycles so the
bootloader's timeout does not disappear before the host connects.

Pico loads and validates a genuine UF2 into rp2040js memory and executes
MicroPython with emulated USB CDC. It exposes no UF2 mass-storage volume or
flash-write peripheral, so a tool-driven UF2 upload/Stop is **unavailable**.
Renode loads actual STM32 UART firmware and nRF52840 Zephyr ELF; no STM32 or
Nordic ROM/JTAG programmer is supplied. ELF load is not claimed a guarded
firmware upload. Pi uses snapshot disks; no SD-card flashing flow is claimed.

## X2: Pi consoles and S3 application flashing

Pi preparation extracts `kernel8.img`, `bcm2710-rpi-3-b.dtb` and
`bcm2711-rpi-4-b.dtb` from the pinned image's FAT boot partition. Copies of
the DTBs assign PL011 to `serial0`, mini-UART to `serial1`, set
`stdout-path=serial0:115200n8`, disable the PL011 Bluetooth node, and remove
its firmware-only `skip-init` property. QEMU's first serial backend is
PL011; its second backend is explicitly `null`. The kernel command line
uses `console=ttyAMA0,115200`. The real guest receipts contain its stock
Pi 3/4 model, getty's `root (automatic login)`, `/dev/ttyAMA0`, and the reply
to the transmitted shell command.

Both Pi models use `maxcpus=1`; Pi 4 mounts `/dev/mmcblk1p2`, Pi 3
`/dev/mmcblk0p2`. The guest runs `setsid --wait agetty` into a development
`/bin/sh` session. This avoids the stock login/PAM path's epoch-clock warning
and slow session setup while giving the shell a controlling terminal.
The first Pi monitor operation is bounded to 30 seconds: the initial
15-second capture intermittently ended after the real OS reached PID 1 but
before its initialization completed. The test deadline stays 120 seconds,
session limits and all output/Stop/approval/lease assertions remain in force.
Pi 3's capture retains the secondary MMC timeout and deferred LED probe;
Pi 4's retains the `fe340000.mmc` regulator dependency warning. Neither
prevents mounting the configured root disk and reaching the measured getty.
Renode's initial capture also uses 30 seconds after one 15-second cold-start
capture returned no bytes during the first deliberate-break run.
SMP, a full systemd boot, the mini-UART transport and physical SD-card
programming are not qualified by these receipts.

S3 retains Espressif's documented `strap_mode=0x00`, a 4 MiB MTD image,
`--no-stub --before no-reset --after no-reset`, and explicit
`write-flash --flash-size 4MB`. Stock all-zero simulated efuses let the ROM
select USB Serial/JTAG, which this model does not implement. UART input
then enters the ROM fatal exception handler. The captured `0x5ffd0000` fault
address and ROM ISR disassembly imply `UartDev` port 4, the USB Serial/JTAG
selector. Direct TCP, a boot-banner preflight,
and a two-second esptool SYNC wait did not repair it. A raw SYNC occasionally
received ROM replies, which did not establish a working programming path.

The disposable QEMU input sets only the two USB-download disable bits:
`DIS_USB_SERIAL_JTAG_DOWNLOAD_MODE` (BLK0 bit 132) and
`DIS_USB_OTG_DOWNLOAD_MODE` (bit 159), from the pinned
[ESP-IDF 5.4.2 efuse table](https://github.com/espressif/esp-idf/blob/f5c3654a1c2d2a01f7f67def7a0dc48e691f63c0/components/efuse/esp32s3/esp_efuse_table.csv).
The [upstream S3 QEMU guide](https://github.com/espressif/esp-toolchain-docs/blob/main/qemu/esp32s3/README.md)
documents loading that simulated state through the efuse drive. No
`espefuse`, burn, security-key or irreversible operation runs; the test
also verifies the drive remains byte-identical to its initial fixture.
Normal application boot uses the stock simulated state.

The S3 flash case first fills its app region with `0xff`, then uploads the
actual 210,816-byte IDF UART binary at `0x10000`, under a bounded 256 KiB
test-only payload limit. Esptool reports `Hash of data verified`, the
backing bytes match the approved artifact, and a fresh SPI-flash boot
produces `MUSE_ESP32S3_READY`. Flash, reboot monitoring and the second flash
each get a fresh host-only approval. Stop is admitted after the real
`Writing at 0x00010400` receipt, returns `stopped`, and kills esptool's
process tree. This establishes UART ROM flashing and reboot output;
native USB download and hardware reset wiring remain unqualified.
