Lane `m103/x`, Kubuntu, 2026-10-05, base `39970a36` (lane P).
No attached hardware, model attempts, paid calls or credentials.

## Process lifecycle

`test/unit/makerEmulatorRig.test.ts`: five tests pass directly on Kubuntu
with `npx vitest run test/unit/makerEmulatorRig.test.ts --maxWorkers=3
--testTimeout=120000`. They prove idempotent start/Stop, minimal child
environment, real character-device PTYs, removal of links and all child
processes, explicit startup failure, private directories and missing-command
refusal. Tests use an actual socat process and a bounded test-only child.
Red drill: replace both environment filters with inherited environment;
the then-current three-test file exits 1 at the environment assertion. Restore
the original bytes in `finally`, SHA-256
`a08517095e1f2e68db624b735a13b7465fbf7da6ad317d2026a60a321e3675c6`.
Typecheck of the unit project and ESLint on the new test exit 0. The final
restored run and Prettier check pass before the lifecycle commit; Husky's
pre-commit script exists and staged hooks remain enabled.
Start reports UART/process readiness; firmware readiness requires a UART
receipt. An initial test expected a short-lived process to have already
exited after 100 ms; that timing assumption was replaced by a deterministic
missing-executable failure. No production test seam returns emulator data.

The supervisor validates PID birth stamps, serializes control with a bounded
kernel flock, and bounds each run to ten minutes. Stop terminates child
process groups and escalates within its deadline. SIGTERM/INT run cleanup;
SIGKILL and host power loss are outside that cleanup guarantee.

The rig brief prohibits full quality, merges and pushes. Full quality is the
lead's integration gate; focused checks and hook receipts are recorded here.
The base lacks G's guard/flash dispatcher, D's `onPi.ts`, machine adapters,
and editor wiring. These cannot be claimed certified by test classifiers.

## Rig and boundaries

The launchers own real QEMU, simavr, rp2040js and Renode processes. Serial
bytes come from executing firmware, not a transcript or an echo process.
P's production discovery parser receives synthetic Arduino CLI metadata
for the actual PTY. VID/PID is neither an OS USB capture nor proof of the
MCU behind a bridge. Every session goes through `runSerialAction`; the host
seam answers each fresh request with its exact id/digest and `allow_once`.
No standing approval, model-visible token or guard setting is introduced.

The test classifiers exercise P's existing dependency contract only. Context,
classification refusal, host rejection and known flash mismatch prevent the
transport from opening. G's irreversible-command classifier/dispatcher is
absent on `39970a36`; its efuse/fuse/lock/OTP/RDP refusals remain **pending**,
as do D's `onPi.ts`, M's machine adapters and W/editor/ACP/companion wiring.
The test flash transport has fixed esptool/avrdude arguments, accepts approved
bytes only through stdin, and refuses any port resolving outside `/dev/pts/`.
It cannot request fuses, locks, OTP, protection, RF or machine operations.
No maker product source, guard, dependency, bundle budget or threshold changed.

Flashing uses the real `esptool` ROM protocol on QEMU's UART and real
`avrdude` STK500 protocols on simavr's UART. ESP marker writes at `0x3f0000`
are verified by esptool's hash and the actual MTD backing bytes. AVR flash
writes are verified by avrdude. Cancellation is admitted only after a
real programming-progress receipt, then P kills the tool's process tree.
The Uno rig uses Arduino's ATmegaBOOT/STK500v1 at 57600, not modern Optiboot;
Mega uses STK500v2 at 115200. simavr is paced by simulated CPU cycles so the
bootloader's timeout does not disappear before the host connects.

Pico loads and validates a genuine UF2 into rp2040js memory and executes
MicroPython with emulated USB CDC. It exposes no UF2 mass-storage volume or
flash-write peripheral, so a tool-driven UF2 upload/Stop is **unavailable**.
Renode loads actual STM32 UART firmware and nRF52840 Zephyr ELF; no STM32 or
Nordic ROM/JTAG programmer is supplied. ELF load is not claimed a guarded
firmware upload. Pi uses snapshot disks; no SD-card flashing flow is claimed.

cached, hash-verified assets and regenerated the firmware. A sanitized setup
