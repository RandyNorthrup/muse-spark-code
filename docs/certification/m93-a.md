## What landed

- `src/runtime/reportCommand.ts` (new): `parseReportJournalBytes`
  (bounded, versioned, strict-shape journal read; oversize, undecodable,
  unparseable or off-contract content reads unavailable, while a missing
  file reads as no events), `collectReportFacts` (allowlisted local facts
  only: versions, platform, backend/sandbox defaults, CLI presence from
  file discovery, sign-in/key booleans from structure and presence —
  never values), `runReportCommand` (exit `ok` when the draft went out,
  `internal` when it could not be built or written; stdout carries only
  the draft text, or nothing at all with `--out`), `reportJournalPath`
  (the agent's data folder, no workspace needed) and
  `appendReportJournalEntry` (facts-only append, capped oldest-first,
  never throws). The module imports no backend, auth, keystore, model
  client, child process or fetch; an owning test guards those imports.
- `src/runtime/cliArgs.ts` (report region): `ReportOptions` and strict
  `report` parsing (`--out`, `--description`, `--no-facts`, `--no-events`;
  positionals, unknown flags and an empty `--out` refuse with exit 2 and
  the new `reportUsage` text; `--help` answers the top-level help).
- `src/runtime/main.ts` (report case + ACP wiring): `report` runs after
  the UI table loads, with every side effect injected — it never calls
  `runtimeFor`, `loadSecrets` or a backend. `serve` wires the observer to
  the journal adapter (atomic tmp-plus-rename writes; failures swallowed).
- `src/acp/agent.ts` (error-observer region): optional `reportError`
  dep carrying `AcpErrorFact` (fixed `errorNotice` kind, fixed short code
  per site — `updateNotSent`, `skillsUnavailable`,
  `permissionRequestFailed`, `approvalWithoutDenial`, `questionFailed`),
  observed after the log call at five failure sites. Never touches ACP
  stdout; a throwing observer never breaks the session; absent, the agent
  behaves exactly as before.
- `src/shared/constants.ts`: `ACP_REPORT_JOURNAL_FILE`
  (`problem-report-journal.json`) beside the folders' own, with its
  one-line reason.
- `src/shared/l10n/en.ts` plus all 14 `l10n/ui.*.json`: the `report`
  line in `acpUsage` and the new `reportUsage` key, each really
  translated. `check-l10n` reports only the known lane-I manifest finding
  (lane 0's `command.reportProblem.title`, cleared when lane I registers
  the command).
- `test/unit/reportCommand.test.ts` (28 tests) and
  `test/unit/acpReportObserver.test.ts` (3 tests).
- `docs/acp.md` (report section, after the scanner section), `CHANGELOG.md`
  under `[Unreleased]`, and this record.

Deliberate non-goals: no `ModelApi`/Muse Code backend start, no sign-in
flow, no `--backend`/`--sandbox` flags on `report` (it reports the

## Journal contract (for lane R)

The runtime adapter reads and writes one file,
`<data-folder>/problem-report-journal.json`, shaped
`{ version: 1, entries: [{ kind, code, frames, atMs }] }` with `atMs` in
epoch milliseconds; entries already carrying `ageMs` read the same way.
Lane R's extension-side recorder writes its own journal under
`globalStorageUri`; if the two journals are ever unified, this file's
shape is the read contract to keep.
