### The controller's rules

- **Which messages an Edit may name.** A message is kept only when its
  submission said `queued` or `steered`, its session has `withdrawQueued`,
  and (for a queued one) its turn had not already started or finished when
  the ack landed (D26). An Edit naming any other card, or the right card
  with another `turnId` or `userMessageId`, is refused with `queuedTooLate`
  before the backend hears of it. A signed-out panel's Edit is refused with
  `notSignedInReason`, so the card never waits on an answer.
- **When a message stops being offered.** Its queued turn starts, is
  withdrawn or ends; a `messageAdmitted` names its user item; or, for a
  steered one, the turn it joined ends (whatever that turn did not read has
  by then moved to a turn of its own through `userMessageTurnChanged`,
  which the controller follows: the message is then offered as queued under
  its new turn). A session change clears them all.
- **One Edit at a time per card.** A second Edit while the first is in
  flight is left to the first's answer. `tooLate` and a withdrawal both end
  the card's entry; a backend failure keeps it, so the Edit can be tried
  again, and its reason (the panel's words) is the refusal's while the log
  gets only `failureForLog`.
- **The images.** The host released a message's images when the backend
  accepted it (D26), so they come back from the backend in the outcome and
  go into the composer as `attachmentAdded`, as M53's rewind does (the two
  share `returnImages`). `attachmentsKept` is true only when every one came
  back.
- **A late answer** (the conversation changed, the panel signed out) posts
  nothing.
- **The tasks tab** opens for the conversation's session, or the one a
  restart resumes; a tab opened before the first message takes the session
  that message starts. It gets `update` with the whole view (the
  conversation's name, `UI_TEXT.untitledConversation` while untitled, and
  the list) whenever that session's list or name changes or it attaches
  again (a restart resuming it), and `ended` once when the conversation is
  cleared, another session takes the panel, the account boundary clears it
  or the panel closes. Between sessions (an opening, a restart) nothing is
  said. With no port the action posts `hostActionFailed`; a port whose
  `open` throws says so and binds nothing. The action never reaches
  `extension.ts`'s `runHostAction`.

### The reducer's first cases

- `queuedWithdrawn`: the card leaves; its text goes into the composer, alone
  in an empty box, else first and a blank line before the draft (D66); the
  draft's revision moves, so a command waiting on the old draft (a `/goal`)
  cannot clear the merged one; focus goes to the composer. Images arrive
  through `attachmentAdded` before it.
- `withdrawRefused`: the card stays; the reason is a warning notice and is
  read out.
- `messageAdmitted`: nothing changes yet. Lane C adds the `queued` status,
  which this event (and `turnStarted`) ends.

## For the lead and lanes C and D

- **Lane C, Model API steers.** A withdrawn steer must not be reported as
  `turnWithdrawn` with the running turn's id (step C6 reads so): the
  controller would then mark the running turn finished, and the reducer
  would fail every card of that turn. `queuedWithdrawn` already removes the
  card; `turnWithdrawn` fits a queued turn only.
- **Lane C, admission.** The Model API must emit `messageAdmitted` when
  `drainSteered` puts a steer into a request (and when a queued turn starts,
  if it wants the event there too); until then a steer stays offered until
  its turn ends, and a late Edit is answered `tooLate` by the backend.
- **Lane C, images.** `WithdrawOutcome.images` carries the message's
  `ImagePart`s on the Model API; Muse Code keeps no bytes (`undefined`).
- **Lane C, the reducer.** `turnAccepted.disposition` is there for the
  `queued` status. The webview cannot tell from the protocol whether a
  session can withdraw: D66's rule by backend (`authState.backend`) decides
  Edit or the delivered note. A per-message flag (`TurnSubmission` and
  `turnAccepted`) would make it the backend's call; not built, as the plan
  does not list it.
- **Strings (the lead).** A refusal for a session that cannot take messages
  back has no string: it reads `queuedTooLate`. Nor has a withdrawn message
  whose images did not come back (`attachmentsKept: false`).
- **Lane D.** One `TasksTabPort` per surface, through
  `ConversationDeps.tasksTab`. The controller calls `update` only after
  `open` and before `ended`; the port keeps the last view for `tasksReady`.
  `extension.ts`'s `runHostAction` never receives `openTasksTab`.
- **Lane W.** The index in `docs/certification/README.md` is not lane P's.
