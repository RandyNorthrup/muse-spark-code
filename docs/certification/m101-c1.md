## Implementation and base seams

`ModelApiHost.ts` captures the actual POST body at `onRequestStarted`, after
all admission fences. Compaction retains its instructions, tools, routing key,
retention and packed/media-fitted input byte-for-byte, appends the later replay
items and the summary request, and limits output to the smaller of the last
request cap, the session-budget cap and the summary allowance. A resumed
session without that in-memory prefix, or a changed selected model, rebuilds a
request retaining required tools; an old model's body is never reused. Returned function calls are discarded; one tool-less fallback is
allowed for ordinary compaction. A second tool call, blank summary or
incomplete response leaves the replay intact. No compaction tool executes.
A last request containing paid hosted search takes the tool-less path directly:
its previous search consent does not authorize another hosted search.

The prompt asks for Goal / Constraints / Progress / Decisions / Next steps /
Critical context, exact paths/errors and untrusted-content labels. An update
request explicitly retains the previous summary's relevant facts. Host data
supplies exact unfinished todos, including status and active form, and read /
write / edit paths. These JSON snapshots are appended both to the prompt and
the resulting summary, independent of the model's prose, and stay fixed when
later task lists change. File snapshots carry across updates; a task containing
the file-list label cannot impersonate the metadata's line delimiter.

The summary allowance is `min(8192, floor(contextTokens * 0.05))`, at least one
token and also limited by the request/session budget. The recent tail is whole
trailing turns, up to `min(20000, floor(contextTokens * 0.08))` estimated tokens
(using the existing four-characters-per-token estimate). A first compaction
replaces at least its oldest turn; an update may retain all later turns while
replacing the previous summary. Calls and outputs are never cut apart.
Supported reasoning entries are retained without reconstruction. The existing
conservative rewind boundary stays at the last completed turn at compaction.

An already compacted replay/tail is a no-op, including after resume. Host
metadata records the retained entry count, so newly appended background
context remains compactable even when the latest transcript row is the
compaction row. Legacy summaries without a tail count remain readable. HTTP and
stream retries share the turn retry allowance. Each stream retry reruns the
pre-call hook, refreshes spending and reserves afresh; Stop and final key /
account / trust / model / budget fences still apply. Failed calls settle their
liability and successful usage is counted normally. `compactContext(signal)`
is callable by C2 at its held, settled tool-loop boundary and bypasses manual
PreCompact; manual `/compact` retains existing hook behavior.

This base lacks M95's host/provider-registry wiring and D78's shared paid gate.
The narrow `compactionModel(modelId)` dependency accepts the selected record's
`contextTokens`, `capabilities.toolCalling`, `keepToolsWithHistory` and
`reasoningReplay`. Meta retains its documented default window/quirks without
that reader; unknown BYO metadata enables neither cached tool reuse nor
reasoning replay. This seam is intended for the registry wiring lane, not a new
transport or provider implementation. Per-format retry classification remains
P2's work; compaction consumes the same current classifier as normal turns.

`ModelApiHost.forkSession(..., {withSummary: true})` is the opt-in engine action;
ordinary forks make no extra call. It copies completed turns and host todos,
requires `admitSummaryFork(sourceSessionId, modelId, signal)` to return an
admission guard, and calls that guard after credential retrieval for every
actual attempt. Its `onRequestStarted` receives the actual-dispatch tally.
The existing usage observer/session budget receive the summary's usage. A
summary fork uses a tool-less call directly and cannot add a tool fallback.
Pending forks are neither announced nor saved by ordinary change callbacks;
a successful stored fork is saved before publication. Durable budget liability
can still be retained for a dispatched failed attempt, as M82 requires.
Workspace constraints are loaded before the fork summary and the fork startup
hook fires once. The source replay is untouched. No UI action, setting or manifest command
exposes summary forks on this base: D78 integration must own consent, price,
daily budget, paid row/badge/tally and settlement before enabling the action.
No private paid-feature gate or remembered grant was added.
