# M96 lane L certification — Pipelines and history

Lane L owns `src/core/team/pipelines.ts` (built-ins, loading, rounds,
`redesign`, the hand-off to `merge`) and `src/core/team/teamHistory.ts`
(the ledger's queries). Tests: `test/unit/teamPipelines.test.ts` (36),
`test/unit/teamHistory.test.ts` (30). Plan of record e23ec61c; D75
"Pipelines" and "The team ledger", acceptance 21 and 42.

## Scope delivered

- Built-ins **Change** (`engineering` work → `code-review` review → `qa`
  check → orchestrator merge) and **Spec** (`research` → `design`),
  validated (`validatePipeline`: non-empty, a work step, no review/check
  before a writer to send back to).
- Rounds: a failing review (findings at/above `reviewSeverity`, default
  `high`) or a failed check loops back to the first work step on the same
  branch with the findings. The round past `maxRounds` (schema-bound 1–3,
  the owner's third-round rule) stops at `redesign`, naming the final
  findings and the recurring ones (title match across rounds).
- No merge: no merge step kind, transition, or dependency. The terminal
  `handoff` carries branch, reports and rounds used for the orchestrator's
  `merge`. One approval's data: `approvalSteps` (steps + each step's first
  entry) and `pipelineCeiling` (each step's ceiling times the rounds).
- Loading: personal `<config>/muse/pipelines/*.json` (full definitions;
  the user owns the folder), then project `.muse/pipelines/` in a trusted
  workspace only, which may solely lower rounds or remove steps of a
  pipeline the user has. Unknown ids, raised rounds, added/changed steps,
  unknown keys and unparseable files are refused whole and reported, never
  thrown. A fourth round cannot be configured (`maxRounds` 1–3 in schema).
- History: filters (role, entry, model, outcome, `[from, to)` date range),
  brief search, stable cost/duration/tokens sorting (missing values last),
  totals by role, entry and agent for today (the caller's local day in the
  injected time zone), trailing-7-day week and
  all time (reported vs estimated apart; unpriced counted, never costed;
  hook-added and paid-tool lines apart), per-entry record figures in pool
  order, retention helper (`selectRetained`; 0 keeps all), CSV/JSON export
  with transcript bodies only on `includeTranscripts` plus an injected
  loader, and `redactSecrets` re-applied at export.

## Decisions where D75 leaves a choice

- A made-up severity word loops back rather than merging blind (fail-safe).
- Personal files may replace a built-in (user's folder); project files may
  only narrow. Personal shadowing a built-in with wider rounds is still
  capped by the schema's 1–3.
- Unknown finding words bucket as `unknown` in figures (shown, never
  dropped, per the "shown as it came" spirit).
- Figures cover exactly the pool's entries in its order; rows for removed
  entries stay in totals but leave figures. Durable `selectRetained`
  pruning and the stored reset-record figures are lane A's ledger region;
  `selectRetained` is its pure helper.
- `TeamHistoryRow` is the structural subset of lane A's row / lane 0's
  `shared/team.ts` schema that history reads — an explicit seam, no fake.
- No `en.ts` / `l10n` / `package.nls` edits: the modules return reason
  codes and data, no user-facing sentences (lane 0 owns strings;
  `check:l10n` reports 0 problems). No `constants.ts` edits (lane 0 owns
  `TEAM_*`); `PIPELINE_MAX_ROUNDS` / `PIPELINE_DEFAULT_SEVERITY` are
  module-local until lane 0 hoists them. Time math reuses
  `MILLISECONDS_PER_DAY`, `DAYS_PER_WEEK`, `MILLISECONDS_PER_SECOND`,
  `SECONDS_PER_MINUTE`. No new dependency.
- Owner rulings: single-model invariant holds by construction — these are
  pure functions called only from team flows; nothing loads at activation
  and no request path is touched. Paid policy needs nothing here beyond
  the ceiling data the popup (lanes A/T) presents.
