## Scope and delivery boundaries

Only new `src/core/resources/sampler/**`, owning tests and this record are
changed. G owns the sample timer and governor transitions; T owns tree
accounting. W owns the lazy bundle, build maps, constants, manifest,
feature/help catalog and delivery docs (including CHANGELOG/README/PLAN).
No settings, command, surface or model behavior is added by S alone. The
portable sampler implements the existing `ResourceSampler` contract behind
an explicit injected `MachineSamplerPort`, with no production fake.

CPU uses per-core counter deltas, not load averages. First/failed readings,
CPU hotplug, rollback, nonfinite counters and unsafe aggregate deltas are
unknown. Linux PSI keeps avg10 CPU-some/memory-some/memory-full separate
from CPU utilization. Memory combines valid OS readings and cgroup v2
limits, including every visible ancestor. Missing cgroup controller files
are distinct from failed reads; the rig's real hierarchy root has no
`memory.max`. All filesystem data stays private to the sampler.

Darwin uses `availableMemory()` per lane 0's measured fact. It neither uses
free-page-only `freemem()` as headroom nor scales `memorystatus_level` into
bytes. If available memory cannot be read there, it is unknown. GPU/disk
ports load only with their respective threshold set and the governor on;
unset probes never run. The sampler shares concurrent calls, bounds GPU
cadence to five seconds and disk cadence to fifteen, clears unset cached
readings, validates samples with the shared strict schema and reports
failed probes as null.

This first piece delivers the machine logic and its injected optional-probe
seam. Real OS adapters, GPU/disk probes and self-cost measurement follow in
the next piece. The lead retains aggregate quality/coverage/editor gates;
the explicit brief prohibits `npm run quality` and whole-unit runs here.
No gate/ignore/cap is weakened; no escape hatch is added.

## OS adapters and optional probes

`createMachineResourceSampler(settings, limits)` is the production entry.
It reads CPU/memory only on `sample()`. The optional module is dynamically
imported on the first enabled GPU/disk threshold. Discovery happens inside
the corresponding probe only. Clearing a threshold also resets its delta
baseline, so re-enabling disk cannot reuse an observation from its disabled
interval. Concurrent callers share one sample promise.

Linux GPU reads whole DRM cards' `gpu_busy_percent`; the Nvidia fallback
queries utilization with an installed absolute `nvidia-smi`. Windows uses
Nvidia when present, otherwise the GPU-engine CIM utilization counters;
disk is 100 minus the physical-disk idle counter, excluding `_Total`.
JSON counter arrays are schema-checked and the busiest reading wins.
Linux disk uses cumulative I/O-busy milliseconds against a monotonic
clock, selects whole devices through `/sys/block`, omits memory disks,
and resets on failed readings, device changes, counter rollback and
reused device identities. No process details enter a sample.

Child probes use absolute paths and argument arrays, no shell/profile,
an OS temporary cwd, a strict timeout no longer than the five-second
sample window, and bounded stdout AND stderr. Only Windows' SystemRoot
and windir are passed; POSIX receives an empty environment. No inherited
credential variable, loader injection, credential-store route or PATH is
copied. Bounded UTF-8 file reads reject oversized/invalid data and
separate ENOENT (absent attribute) from other failures (unknown).

Darwin GPU is unavailable as planned. Darwin disk also returns unknown:
unprivileged iostat throughput is not disk busy time, and this base has
no qualified duty-cycle counter. S does not invent one or invoke a root
probe. This is an explicit platform qualification gap, not a zero or a
claimed supported disk reading. Windows CIM execution and cost, Mac cost
and any future Darwin disk counter require the lead's platform receipts.
Fixtures exercise our generated counter projection, not a live Windows
capture. No Muse/Meta wire shape or model request is added.
