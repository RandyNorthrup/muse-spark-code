# Threat model — RLM110B phase b: sandboxes, workspaces, Live peek (W1, W2, K)

Reviewed 2026-10-22 by the lane author before any phase-b code was written;
lead review pending at integration. Scope: per-workspace sandboxes and the
egress proxy (W1), brokered git/devcontainers/snapshots (W2), and local Live
peek (K). D90.5, D90.6 and D90.22 govern; D121/D208 forbid any limit of ours.

## Assets

- The host and other workspaces (isolation between sandboxes).
- Credentials (never written in a workspace or sandbox; brokered uses only).
- The cloud instance's credentials (metadata addresses must stay unreachable).
- Agent stream contents shown to peek viewers (scrubbed; read-only).

## Trust boundaries

- Sandbox ↔ node: tools run untrusted repository code; the agent engine,
  vault, broker, listeners and journals stay outside every sandbox.
- Sandbox ↔ network: denied by default; only the egress proxy's allowed names.
- Peek viewer ↔ agent: one-way, read-only, scrubbed; a viewer never slows,
  steers, or approves for the agent.

## Threats and mitigations

| #   | Threat                                                                                | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1  | A sandbox escapes to the host (root, devices, host network).                          | Rootless engine, non-root user, read-only rootfs, `no-new-privileges`, dropped capabilities, default seccomp, AppArmor/SELinux where present; gVisor/Kata where the host offers them.                                                                                                                                                                                                                                                                            |
| B2  | A sandbox reaches a host it was not allowed (direct IP, DNS rebinding, proxy bypass). | All egress through the node's proxy (CONNECT + TLS SNI checked against the policy, address checks on every answer as M81's proxy does); the network layer drops anything bypassing it; DNS answers logged per workspace.                                                                                                                                                                                                                                         |
| B3  | A sandbox reads cloud instance credentials.                                           | Metadata addresses (`169.254.169.254`, `fd00:ec2::254`) blocked in every sandbox on every host, whatever the policy.                                                                                                                                                                                                                                                                                                                                             |
| B4  | A sandbox scans or abuses remote networks (port scan gets the server locked).         | New outbound connections rate limited per sandbox; policy is an allowlist of names, never open egress.                                                                                                                                                                                                                                                                                                                                                           |
| B5  | A git credential lands in the workspace or sandbox.                                   | Clone/pull through M109's broker (agent socket with host binding for SSH; scoped ephemeral helper for HTTPS); neither key nor token written down.                                                                                                                                                                                                                                                                                                                |
| B6  | A devcontainer lifecycle command runs outside the sandbox or before trust.            | `initializeCommand` (host-side by design) refused outright; the rest run only inside the sandbox, only after the person trusts the workspace, under its egress policy. Dockerfile builds run daemon-side on node network under that same trust (the build predates the box, so no box egress can cover it); dockerfile and context confined to the workspace. Image digest read back via inspect (drill-proven); durable recording waits on the workspace store. |
| B7  | An upgrade/restore/cleanup destroys uncommitted work.                                 | Snapshot (git bundle + worktree patch + untracked archive, or fs snapshot) before any of them — the bundle alone would lose dirty tracked files.                                                                                                                                                                                                                                                                                                                 |
| B8  | A peek viewer steers the agent, answers an approval, or slows it.                     | Read-only by construction: one `subscribe` method, no send path; read-only Bearer [REDACTED] the guard refuses elsewhere; bounded per-viewer queues with "skipped N" markers, never backpressure; coalesced updates.                                                                                                                                                                                                                                             |
| B9  | A peek stream leaks a secret (tool args, command output, diffs).                      | Every event through M109's scrub service then the redactor before leaving the process; D80.9 caps on output and diffs.                                                                                                                                                                                                                                                                                                                                           |
| B10 | A share link grants more than read-only, or lives forever.                            | Read-only bearer from a one-use launch code in the URL fragment; person-chosen expiry, said on the link; revocable; audited; opening warns the viewer sees code and model output.                                                                                                                                                                                                                                                                                |
| B11 | A cgroup OOM-kill is reported as an agent failure.                                    | D87.9's "never kill" binds the governor; a kernel kill is reported exactly as that.                                                                                                                                                                                                                                                                                                                                                                              |
| B12 | Small hosts (Pi, LXC without nesting) cannot nest sandboxes.                          | Single-workspace mode: the node's own container is the sandbox, and the dashboard says so.                                                                                                                                                                                                                                                                                                                                                                       |

## Residual risks

- Kernel/container escape is bounded by the engine and host hardening, not
  eliminated; the qualification record (M110f Q) names what each host proved.
- SNI-based enforcement sees only TLS it does not intercept; non-TLS
  protocols to allowed names are still name-checked at CONNECT/DNS time.
