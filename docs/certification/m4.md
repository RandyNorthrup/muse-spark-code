## Render cost (the "10k-token reply without jank" acceptance)

`node scripts/measure-markdown.mjs` renders `MarkdownView` with
`react-dom/server` (parse + tree build, no DOM diffing) for replies of the
given size; a delta near the end of a streaming reply re-renders either the
whole text (naive) or only the tail `splitForStreaming` isolates (what the
transcript does), the head being memoised.

| Reply (tokens / chars) | Whole re-render, median / max | Streaming tail (chars) | Tail re-render, median / max |
| ---------------------- | ----------------------------- | ---------------------- | ---------------------------- |
| 2 500 / 10 249         | 23.3 ms / 30.2 ms             | 1 507                  | 3.6 ms / 5.2 ms              |
| 5 000 / 20 221         | 43.8 ms / 82.3 ms             | 1 507                  | 1.2 ms / 3.4 ms              |
| 10 000 / 40 165        | 29.9 ms / 39.5 ms             | 1 507                  | 1.0 ms / 1.0 ms              |

(Node 24 `react-dom/server` timings on the dev machine, 5 runs each after a
warm-up; the 10k row is faster than the 5k row because the JIT has warmed up
on the same grammar by then.)

The whole-reply re-render exceeds a 16 ms frame from about 2.5k tokens on, so
streaming replies are split at the last blank line outside a code fence
(tail ≥ 1.5k chars) and the tail alone re-parses per delta; the assistant
text is additionally read through `useDeferredValue`, so React can yield to
input while the render is in flight. The harness `long` scenario streams 333
deltas of a 40k-character reply and renders it fully (`m4-long.png`).

## Findings recorded during the milestone

- The SDK's `Connection` treats `approval/request` / `userInput/request` as
  server requests, but the notification twins carry the enrolled contract;
  the host now declines those two at info level and everything else at warn.
- `item/completed` can arrive for an item never started (the schema says so,
  and `approval/requested` can precede its `item/started`); the reducer
  creates the row from whichever arrives first.
- `turnId` is `null` for `userShell` items; the mapper drops the null so the
  snapshot type stays `string | undefined`.
- `muse-spark-1.2` rejects `max` (M3 D10) — unchanged, but the M4 controller
  now also clamps the effort when the model switches.
- Prettier + a shell heredoc corrupted backslash escapes in a harness patch
  twice (`\\n` → newline); scripts and fixtures now go through files
  (`scratchpad/*.txt` + a python patcher), and the harness reports scripting
  errors and dropped host messages inside the page so a screenshot never
  hides them.
- `React.memo` on `MarkdownView` and stable default props on `App`: a fresh
  default function per render re-ran the message effect and re-posted
  `ready` on every render (caught by the App tests' "last call" assertions).

## Security

- Markdown: no raw HTML path exists (react-markdown without rehype-raw, plus
  `skipHtml`); images never load (alt text only; the CSP has no remote
  `img-src` anyway); links are opened by the host only for `http:`,
  `https:` and `mailto:` and refused with a notice otherwise.
- Highlighted code is highlight.js output of escaped text; unknown languages
  are escaped by hand (tested against `<script>`).
- Approval decisions echo the host's own `requirementId` stage token; a stale
  one is rejected by the host, never applied to a later stage.
- Insert-at-cursor writes only into the active text editor through the
  editor API; nothing runs.
