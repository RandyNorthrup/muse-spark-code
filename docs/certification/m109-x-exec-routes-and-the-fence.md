## Fence (first piece)

D89.5 now fences existing VS Code Model API shell processes and runtime
credential/keyring routes. Case variants are removed, git config environment
is reset (empty credential.helper, useHttpPath), terminal prompts are disabled,
and inherited askpass paths and agent sockets are removed. The trusted launcher
may supply a refusing helper and a requester-specific socket. Empty helper paths
fail closed while the installed helper binding is pending. The Muse manager
keeps Muse Code's credential variables and replaces only SSH/git/askpass routes.
Its injected fence-off switch is only for the main interactive conversation.
The VS Code shell samples the machine setting per command. Workers and headless
callers retain default-on fencing.

## Exec routes (second piece, 2026-10-06)

Lane X implements the portable host service, handle-only tools, private feeder,
scoped git/askpass helpers, broker-material adapter and host spawning interfaces.
All absent lane dependencies are explicit injected ports. A missing port refuses
before ticket release; there is no fake production broker, scrubber, native peer
check, OS containment or platform store. Lane W composes and ships the executable.

- `schema.ts`, `routes.ts`, `service.ts`, `tools.ts`: strict env/stdin/TOTP/git/
  sudo/askpass/SSH routes, grouped environment uses, canonical executable/cwd/
  sudo paths, exact ticket digests and native admission checks after awaits.
  `secret_list` omits hidden/first-party/device/internal rows; `secret_request`
  returns only a handle. No tool accepts approval answers or discloses values.
  Windows sudo is refused before authorization and again in the private feeder.
- `feeder.ts`, `brokerLease.ts`: authenticate the requester's B binding, validate
  all uses before redemption, own unpooled material copies, keep revocation live,
  synchronously erase on cancellation/lock/revoke, reject late acquisitions, and
  close every lease independently. B/L supplies only a current six/eight-digit
  TOTP code; a seed is never an X material route. stdout/stderr pass through
  independent injected T streams before becoming result strings. Callback errors,
  cleanup failures and arbitrary broker errors produce fixed public refusals.
- `sudoFeed.ts`, `gitHelper.ts`, `helpers.ts`: absolute sudo with `-S -k`, empty
  prompt, exact argv/cwd, independently timed and path-rechecked `sudo -K`;
  askpass's three-use/ten-minute cap; git `get` only for exact protocol/host/path,
  expiry and ephemeral reply, never `store`; bounded strict helper frames and
  injected OS peer/pid-start/approved-tree authentication on both ends. The
  serialized helper owner tags acquisitions by generation and erases replies
  during close, including late effects.
- `entry.ts`, `vaultExecSpawn.ts`: inherited private pipe only, bounded envelope
  and public result, input/output copy erasure, no ticket argument/environment/
  file route. The parent requires native containment and termination on every
  platform; Windows additionally requires a prebound job before pipe release.
  It awaits full-tree termination, refuses invalid/oversized output even with a
  valid prefix and exit zero, and bounds an uncertain termination attempt before
  returning failure. Its fallback is best effort, never proof of full shutdown.
  The host owns the command clock and background lift; sudo cleanup has a
  separate hard clock. Helper wrappers contain executable and endpoint paths
  only. Windows directory protection requires P's native ACL verifier.
- Existing shell/Model API/IDE adapters now accept optional `secrets` and the
  lazy service/tool ports. Ordinary shell text containing `secret://` refuses
  before spawn. Model API roles without shell do not receive `vault_run`.
  Private exceptions never become model output. The IDE callback runs after
  existing bearer authentication and reports only a fixed binding failure.
  Its global bearer is not a per-requester vault identity.
- The fence also removes case variants of Git SSH overrides and shell/loader
  startup routes; fenced Bash skips profile/rc files. Muse Code retains its own
  credentials under D1 and gets only trusted SSH/git/askpass replacement. The
  setting read is machine-only, default on; no workspace setting can turn it off.

Static JSON tool descriptors were generated from the strict schemas and are
checked against zod's converter in a drift test. Importing the converter into
production initially failed the existing validation split gate, which does not
export it; static descriptors fixed the split without editing shared validation,
adding a dependency or changing a budget. The legacy shell-declaration snapshot
failed on the new field, then was updated to retain an exact platform-stable
expectation including `secrets`.
