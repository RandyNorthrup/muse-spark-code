  runs through `execResourceFile` / `spawnResourceProcess`: checked
  read-only argument forms take probes, everything else stays contained;
  the checkout gate travels as `beforeSpawn`; a held batch keeps its
  launcher settlement, and a refusal or enforced cap wins over an
  unreadable batch; failures show git's own redacted message
  (`GIT_STDERR_MAX_CHARS`, already on main).

  (`src/runtime/panel/pullRequests/unconfiguredGit.ts`): only absent
  admission selects it, exactly as the shared git runner; the caller gate

  `nodeGitProcesses`, as before: no production entry imports checkout).

  `gitResourceUnavailable`, `gitMemoryLimit`) in English plus all 14

- The source branches' stand-in tests were not carried: main had deleted
  those files, and the merge keeps the deletions. Real-code proof instead:
- `test/unit/governedCheckoutGit.test.ts`: real git through the real
  governor (the product's own Windows job on win32): the gate runs in the
  spawn turn on both `run` and `start`, and a refusing gate surfaces its

  rejecting launcher settlement fails the batch with the refusal.
