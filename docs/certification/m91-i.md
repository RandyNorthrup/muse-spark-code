## The import record (for lanes P and W)

Every foreign hook converts into one `spark-hooks.json` group. These field
names are the ones lane P's adapters already take at `0bd2eaec`
(`HOOK_FORMATS`, `CursorAdapterOptions`, `CopilotAdapterOptions`,
`KiroAdapterOptions`). Lane P's redesign takes (source format, source
event, protocol flavor, payload); the first three are here, by these names:

## The restructure

Round 1 lost information at its readers. They kept a few fields per entry
and dropped the rest before any converter saw them: Kiro's `timeout`,
`enabled` and `confirm`; Gemini's `sequential`; the files' disable
switches.

Round 2 makes the readers lossless instead of patching field by field.

- **`FoundHook`.** It keeps three things:
  - `raw`, the entry as written;
  - `group`, the Claude-shaped group around it, without its `hooks`;
  - `disabled`, set when a file-level switch in the source turns the hook off.
- **`KiroHook`.** It keeps `raw` whole.
- **Every converter accounts for every field.** A field is carried, or
  dropped by name (`name`, `description` and `show_output` are
  documentation only), or it refuses the entry by name with
  `agentImportSkippedField`. An unknown field is refused by name, never
  ignored.
- **Matchers are no longer rewritten textually.** `translateToolMatcher`
  decides which of the source's documented tool names a matcher selects,
  under that source's own rules. It writes our names as Muse Code's exact
  name list, and MCP tools as anchored patterns over
  `mcp__<server>__<tool>`. Anything it cannot decide is refused.
  - **Anchored sources:** Copilot, Kiro, and explicit `^…$`. A token must
    equal a documented name.
  - **Unanchored sources:** Gemini and Cursor tool events. The source's
    `new RegExp(m).test(name)` also selects longer names that contain the
    token. So a token must equal a documented name, and it also selects the
    documented names and MCP names that contain it.
  - **Refused:** a partial token (Gemini `read_`), any other regex, a
    Gemini MCP name whose server/tool split is ambiguous, and a matcher
    that selects only tools this extension lacks.
- **The scan reads each source file once.** A source's switches are read
  before its hooks, from the same text. The switches are:
  - Claude's and Copilot's `disableAllHooks`;
  - Gemini's `hooksConfig`;
  - Codex's `[features] hooks`.

  A switch anywhere in the scan applies to every hook of that source,
  across user and project. An import is never more on than its source.

## Refused instead of translated

Each of these is refused rather than guessed. The preview names the
reason, and the field where it is a field.

- **Kiro `confirm` / `confirmCommand`.** There is no confirmation step
  before a hook here.
- **Kiro `timeout: 0` and any timeout over 600 s.** No limit, or a longer
  limit, cannot be honoured. Cutting the bound short would make a slow
  guard fail where it blocked.
- **Kiro `UserPromptSubmit` matchers.** They filter on prompt text; our
  UserPromptSubmit takes no matcher.
- **Gemini groups with `sequential: true`.** The whole event is refused.
- **Matchers:**
  - partial tokens and general regexes in tool matchers;
  - Gemini MCP names unless anchored with a single split;
  - Kiro `@…` forms other than `@mcp`, `@builtin`, `@powers`, `@server`
    and `@server/tool` with canonical names;
  - matchers on events whose subject has no shared vocabulary here
    (Cursor `subagentStop`, Copilot `notification` and `subagentStart`,
    Gemini `SessionEnd`);
  - a matcher that would select only tools this extension lacks;
  - a translated matcher over 256 characters.
- **Copilot fields:**
  - `exec` and `args`, which run without a shell;
  - `env`, for its secret risk;
  - `http` and `prompt` handler types;
  - `userPromptTransformed`;
  - the undocumented PascalCase `SubagentStart` and `Notification`.
- **VS Code Local `linux` and `osx` that differ.** Our handler has one
  command off Windows.
- **Windsurf `working_directory`.**
- **Cursor `type:"prompt"`, and `loop_limit` outside `stop` and
  `subagentStop`.**
- **Unchanged from round 1:** Claude `WorktreeCreate` and `ConfigChange`,
  and Cursor `subagentStart` (weaker); Codex
  `additionalContextLimit`, its prompt, agent and `mcp_tool` handlers, and a
  sync `Interrupt`; the Cursor Tab hooks (kept waiting for M94).

## For the lead (other lanes' code)

- **Lane P must apply the new `commandPattern`** to the shell command, as
  it applies Kiro's `pathPattern`. Without it, a Cursor shell guard runs on
  every shell command.
- **Lane P's Kiro adapter refuses `Manual`** at `0bd2eaec`. The import now
  carries it (`sourceEvent: 'Manual'`), so the adapter must accept it.
- **Lane P must filter Kiro `PostFileCreate`, `PostFileSave` and
  `PostFileDelete` by operation**, using `sourceEvent`. All three reach
  PostToolUse on `Edit|Write`, per the lead decision, and our runtime has
  no delete tool.
- **Lane P or W must honour Cursor `loop_limit`.** Cursor's default is 5;
  ours is `HOOK_MAX_STOP_CONTINUATIONS`, 8.
- **Lane W's dispatcher must route `format` groups to the adapters.**
  Lane E's native parser, as of `486c449b`, warns on and skips any group
  field it does not know, `format` included. That keeps foreign groups from
  running natively; lane W wires them.
- **The shell and cwd caveats from the review still stand.** Whether a
  Cline `.ps1` and a Windsurf `powershell` command run under PowerShell
  where their source does, and the cwd of Cursor's personal relative
  commands, are lane W's integration proof. They are not claimed here.
