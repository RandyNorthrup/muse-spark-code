# M91 lane I: importers for every agent's hooks

Branch `m91/i`. Owns `src/core/import/agentImport.ts`, `importConvert.ts`,
the `AGENT_IMPORT_*` constants, and their tests.

## What it does

"Import from other agents" now reads hook configurations from eight sources.
Codex converts into Muse Code's own files and runs on both backends. Claude
Code's extension set and every other agent's format convert into
`spark-hooks.json` with a `format` tag; lane P's adapters run them, the Muse
Code backend never does. Renaming the event alone would fail open: a foreign
guard's output does not validate against Muse Code's strict schema, so the
tag keeps each entry on the adapter path.

M83's rules are unchanged: MCP servers and hooks are offered as unsaved
target editor edits the user reviews and saves; nothing is written without
the user; D64's exposure check runs on every destination; project sources
are read only in live trust.

| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Codex             | `~/.codex/hooks.json`, `<repo>/.codex/hooks.json`, `[hooks]` in `~/.codex/config.toml` and `<repo>/.codex/config.toml` | Claude-shaped blocks; the TOML table uses `[[hooks.Event]]` arrays like the JSON                                                |
| Claude Code       | the settings files lane M83 already reads                                                                              | the 11 extension events of `AGENT_IMPORT_CLAUDE_SPARK_EVENTS`                                                                   |
| Gemini CLI        | `~/.gemini/settings.json`, `<repo>/.gemini/settings.json`                                                              | Claude-shaped `hooks` block, entry `{name?, type, command, timeout-ms, matcher?}`                                               |
| Cursor            | `~/.cursor/hooks.json`, `<repo>/.cursor/hooks.json`                                                                    | `{"version":1,"hooks":{event:[{command, matcher?, permission?, failClosed?, followup_message?, timeout?}]}}`                    |
| Copilot / VS Code | `<repo>/.github/hooks/*.json`, `~/.copilot/hooks/*.json`, inline `hooks` in `~/.copilot/settings.json`                 | `{"version":1,"hooks":{event:[{type, bash?, powershell?, cwd?, env?, timeoutSec?, matcher?}]}}`, camelCase and PascalCase names |
| Windsurf          | `<repo>/.windsurf/hooks.json`, `~/.codeium/windsurf/hooks.json`                                                        | `{"hooks":{event:[{command\|powershell, show_output?}]}}`, exit codes only                                                      |
| Kiro v1           | `<repo>/.kiro/hooks/*.json`, `~/.kiro/hooks/*.json`                                                                    | `{"version":"v1","hooks":[{name?, trigger, matcher?, action}]}`                                                                 |

`CODEX_HOME` still replaces `~/.codex` when absolute. A Codex `config.toml`
is read once for its servers, its `notify` program, and its `[hooks]` table:
a file that is not TOML warns once, whatever was wanted from it.

## Mappings (research §4.3 with the lead decisions)

- **Codex** (12 events, all kept): into Muse Code's files. `apply_patch`
  matchers name `Edit|Write`; `commandWindows` is kept; `Interrupt`
  converts only with `async:true`.
- **Claude Code** (11 extension events): `InstructionsLoaded`,
  `UserPromptExpansion`, `PermissionDenied`, `PreModelSwitch`,
  `PostModelSwitch`, `TaskCreated`, `TaskCompleted`, `FileChanged`,
  `WorktreeRemove` into `spark-hooks.json` with no format tag.
- **Gemini** (10 of 11): `BeforeTool→PreToolUse`,
  `AfterTool→PostToolUse`, `BeforeAgent→UserPromptSubmit`,
  `AfterAgent→Stop`, `SessionStart/End`, `PreCompress→PreCompact`
  (async), `Notification`, plus the lead decision
  `BeforeModel→PreLLMCall` and `AfterModel→PostLLMCall`, once per request
  and response here (Gemini fires them per chunk). Tool names map
  `run_shell_command→Bash`, `read_file→Read`, `write_file→Write`,
  `replace→Edit`, `mcp_<s>_<t>→mcp__<s>__<t>`; unknown tool names pass
  through and, like Muse Code, simply never match. Milliseconds round up
  to whole seconds, at most 600. Entry `name`s are dropped.
- **Cursor** (16 of 21): the six direct tool hooks, `subagentStop`,
  `sessionStart/End`, `beforeSubmitPrompt`, `preCompact`, `stop`,
  `afterAgentResponse→PostLLMCall` (async); shell/MCP/readFile events map
  to `Pre/PostToolUse` with matchers `Bash`, `mcp__.*`, `Read`,
  `Edit|Write`. `Shell` matchers name `Bash`. `permission`, `failClosed`
  and `followup_message` stay with the entry for the adapter
  (`permission→decision`, `ask` forces a card, `followup_message→Stop`
  block); `preToolUse` errors fail closed there.
- **Copilot / VS Code** (13 of 14 + VS Code's 8, one family):
  `userPromptSubmitted→UserPromptSubmit`, `agentStop→Stop`,
  `errorOccurred→StopFailure`, the rest by name, either spelling. `bash`
  and `powershell` become the command and its Windows spelling; `cwd`
  stays for the adapter, which runs it only when relative and confined;
  `timeoutSec` becomes the timeout. `preToolUse` errors fail closed there.
- **Windsurf** (11 of 12): each `pre_*→PreToolUse` and `post_*→PostToolUse`
  with the matcher for its kind (`Read`, `Edit|Write`, `Bash`, `mcp__.*`);
  `pre_user_prompt→UserPromptSubmit`,
  `post_cascade_response→Stop` (async),
  `post_setup_worktree→WorktreeCreate`. Pre hooks stay synchronous so a
  block still blocks. `show_output` is dropped.
- **Kiro v1**: command actions on `SessionStart`, `SessionEnd`,
  `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop` map one to one.
  `PostFileCreate/Save/Delete→PostToolUse` with matcher `Edit|Write`;
  the adapter (lane P) applies Kiro's path regex itself, kept as
  `pathPattern`, so the scope stays the same. `PreTaskExec→TaskCreated`
  and `PostTaskExec→TaskCompleted`; the preview says in plain words that
  Kiro spec-task triggers run on todo items here
  (`agentImportKiroTaskNote`, new in all 15 tables). Agent actions become
  `prompt` handlers under lane H's paid-feature gates. Kiro tool matchers
  map `fs_read→Read`, `fs_write→Write|Edit`, `execute_bash→Bash`.
- **Cline v1** (8 scripts): `TaskStart/TaskResume→SessionStart`,
  `TaskCancel/TaskComplete→SessionEnd` (a task is a session here, not a
  todo item), the four tool/prompt/compact events by name. The script stays
  where it is; the entry runs it by absolute path. A JSON spelling of an
  event, and `hooks.json` itself, are the newer SDK/CLI formats.

## Refusals, each with its lane-0 reason

| Refusal                                                                                                                                                                                                                                          | Reason key                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| Claude `WorktreeCreate`, `ConfigChange`; Cursor `subagentStart` (each blocks where it comes from, observes here)                                                                                                                                 | `agentImportSkippedWeaker`                                     |
| Gemini `BeforeToolSelection` (chooses a tool)                                                                                                                                                                                                    | `agentImportSkippedChooses`                                    |
| Codex `additionalContextLimit`; Copilot `env` (secret risk)                                                                                                                                                                                      | `agentImportSkippedField`, naming the field                    |
| Claude `FileChanged` without a matcher (watches nothing)                                                                                                                                                                                         | `agentImportSkippedNeedsMatcher`                               |
| Cursor/ Copilot/ Kiro wrong `version`; Cline JSON formats                                                                                                                                                                                        | `agentImportSkippedUnknownFormat`                              |
| Cursor Tab hooks (wait for inline completions, M94 lane K)                                                                                                                                                                                       | `agentImportKeptWaiting`                                       |
| Codex `notify` (a program, not a hook; listed, not converted)                                                                                                                                                                                    | `agentImportSkippedNotify`                                     |
| Codex prompt/agent/`mcp_tool` handlers, sync `Interrupt`; Kiro `Manual` and agent/task narrowings that cannot convert; Copilot `userPromptTransformed`; Windsurf transcript answer; unknown fields, blank commands, bad timeouts; unknown events | `agentImportSkippedUnsupported` / `agentImportSkippedUnmapped` |

Field-level drops that keep the entry (`name`, `show_output`) travel in
`dropped` and render as `not carried over: …`. Copilot `env` refuses the
whole entry: dropping it would run the hook without its environment, and
re-adding a secret by hand into a tracked file would be worse.

## The preview shows metadata only

Labels are event and hook names, Kiro names, `notify`, and file base
names. The preview, the picker detail, and the completion warning render
labels, kind/source/scope, dropped field names, the Kiro task note, and
fixed reason strings. Command text reaches only the unsaved editor edits
the user reviews and saves (the sanctioned M83 flow), and the Kiro task
note says what the mapping means instead of showing anything runnable.

## Contracts for the other lanes

- **Lane E** (`spark-hooks.json` parser): groups carrying `format` are
  adapter-run; the native parser must leave them to lane P, never run
  them. `pathPattern`, `permission`, `failClosed`, `followup_message`,
  `cwd`, and the `prompt` handler shape in `agent` conversions arrive for
  the adapters.
- **Lane P** (adapters): per-event stdin/stdout translation per §4.3;
  Kiro `pathPattern`; Copilot `cwd` relative and confined, `env` never;
  Gemini model-call fields that modify the request/response refused, block
  and observation kept; `failClosed` and card/`Stop`-block mappings above.
- **Lane H**: Kiro agent actions arrive as `{type:'prompt', prompt}` with
  format `Kiro`, under the paid-feature gates; Claude prompt/agent
  handlers stay refused at import (open: convert them too once H's
  handler schema for the spark file is fixed).
- **Lane W**: the source switch is done (`agentImportSourceEvery`,
  `agentImportDetailEvery`, five new source rows); delete
  `agentImportSourceAll` and `agentImportDetail` now. `reasonLabel` and
  the picker gained the new sources and refusal reasons with their tests
  in `test/unit/agentImportCommands.test.ts` (still green); the preview
  renders `previewNote` and the refusing `field`.
- **Not imported, by design**: Amp and OpenCode (lane X, in-process
  plugins), Continue (nothing to import), VS Code's own settings-file
  location for its 8 events (unverified path; same names convert from the
  Copilot files) — open question below.
