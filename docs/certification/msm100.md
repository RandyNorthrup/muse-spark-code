Not green on this rig, all environmental (no code change made for them):

- `attemptJournal` (29), `deviceReceiver` (49), `deviceIntegration`
  (10), `deviceRecovery` (37), `deviceReconnect`, `deviceWorkerDarwin`,
  `deviceWorkerHost`, parts of `deviceProductionStorage` and
  `actionGrants`: every failure is `DeviceJournalError: storage` from
  `src/core/devices/attemptJournal.ts:173`. The journal's ancestor
  check (`checkPrivate`, `attemptJournal.ts:501`) requires every ancestor
  directory to be uid 0 or the process uid; on this rig `/` and `/home`
  are uid 65534 (`stat`: `65534 555`, `65534 755`; `id -u` = 1000), so no
  on-disk journal can open. Corroborated by direct `lstat` audit of the
  whole `TMPDIR` ancestor chain. These suites pass on rigs with
  root-owned `/` (see `m100-e`, `m100-phase2`); weakening the check to fit
  this container would falsify a security gate, so it is untouched. The
  lead should run these suites on a normally-owned filesystem.
- `deviceProductionStorage` "never claims…": fixed for real — the setup
  relied on `mkdir(mode 0755)`, which this rig's umask 0077 narrows to
  0700; the test now `chmod`s 0755 explicitly (hermetic everywhere).
- `devicePairingAdapter` "unlinks only this key…" and "keeps unrelated
  A–C authorizable…": each timed out once at 5 s across runs and passes
  on retry (51/51 green on the third run; also green in isolation and in
  a labelled exploratory 60 s run). Cause is box I/O, not code: a durable
  write+sync+rename cycle costs ~31 ms on this rig's tmpdir (measured),
  and these tests perform dozens of fsync'd store updates across 2–3
  full pairing ceremonies. No per-test timeout was added: the operation
  fits 5 s on fast disks and the repo default stays authoritative.
