### Runtime, egress and integration piece

`parseExec` accepts an optional Model API schema file. `runExec` reads and
validates it before backend construction, key input or HTTP. The injected
`ExecOutputSchemaPort` resolves only the selected model's evidence-backed
formats; O2 selects strict schema, schema, then forced tool. Configuration
completes before `session/prompt`. No schema means no capability read or
configuration. The paired fake runs share a cwd and compare actual fetch
body strings byte-for-byte, without normalization.

The sink returns JSON `output` only for an independently completed, priced
run whose whole final answer matches. The final ledger includes the exact
file's `outputSchemaSha256`; paths and schema contents are not ledger data.
JSON strings and sensitive fields are scrubbed after decoding, then the
scrubbed value is validated again. A raw mismatch cannot become a pass
through redaction. Incomplete/stopped/accounting-unverified runs retain
their status and accounting and carry no `output`. A mismatch uses existing
M80 **failed / exit 4**, with the machine-readable error kind
`output_schema_mismatch`, retains spend and digest, withholds the answer,
and propagates the emitted code to the process. This lane introduces no
new exit/status enum outside its ownership. If integration requires a
separate numeric mismatch code, W must bind it in the shared protocol and
constants together; the scoped implementation does not claim that code.
