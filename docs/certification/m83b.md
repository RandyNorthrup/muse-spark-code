## RV83b finding 1 (P1): quoted URL query values

RV83b reviewed `57d01413`→`6db3cc9d`. It found that embedded-URL matching
stopped at the first quote mark or backtick. In
`https://example.test/mcp?signature='opaque-demo-value'` only
`…?signature=` reached `maskUrl`, so the value after `[masked]` reached the
preview, the clipboard and the published `AGENTS.md`. The double-quote and
backtick forms leaked the same way.

`maskText` (`src/core/import/importMask.ts`) still finds each URL with the
same pattern. A new `urlEnd` step then takes quoted parts onto it before the
one `maskUrl` masks the whole URL. There is no second masker. A part goes on
the URL in these cases:

- a closed quote (`'…'`, `"…"`, `` `…` ``, even empty);
- a quote left open where a value starts, right after `=`, which runs as far
  as a URL can;
- parts a shell joins into one word (`'a'"b"`, `abc'def'`, `''value''`).

Whitespace ends every part, so a stray mark never takes a sentence. The mark
the URL is wrapped in closes the wrap, unless a word character follows it,
as in the shell's `'https://…?k='value''`. So `curl "…?q=" -o out.json`,
`fetch("…?q=")`, `["…?q=1","…"]` and the rest of a line keep their text.
Markdown-link parentheses and full stops are still given back. The new
pattern has no nested quantifiers, and the loop is sticky, so every pass
consumes text.

Scratch probes (not committed) on adversarial text of 10,000, 100,000 and
1,000,000 characters grew about tenfold per step, 0.1–2.7 s at a million.
They also found that `a.a.a.…` text without any URL is quadratic: about
0.4–0.7 s for 10,000 characters and 62 s for 100,000. That cost
comes from the scheme prefix `\b[a-z][a-z\d+.-]*:\/\/`, which this fix did
not change. `6db3cc9d` takes the same time (389 ms against 364 ms), and the
log redactor's `URL_USER_INFO` on main has the same prefix (190 ms on its
own). It was recorded for the lead in `93fd8572`, and is bounded since; see
"Linear-time masking" below.

Regressions, synthetic values only:

## Linear-time masking (lead follow-up)

The lead asked for the quadratic scheme prefix found above to be bounded
as the release candidate's `16f1e908` bounds the log redactor's
(`\b[a-z][\w+.-]{0,31}:\/\/`). That covers both copies of the prefix in this
tree. The scratch timings then found more patterns in the masker that were
not linear, and those are fixed here too. Scratch probes (not committed)
measured the scheme alone, then each pattern on its own:

- **URL scheme** (`URL_IN_TEXT`, and `redact.ts`'s `URL_USER_INFO`): now at
  most 32 characters. `redact.ts` and `redact.test.ts` are byte-identical to
  `16f1e908`'s (blob check), so the integration merge is clean.
- **A credential flag in text** (`COMMAND_FLAG_VALUE`): at most 31
  characters either side of the credential word. Unbounded, it was cubic on
  dashed credential words: 87 s for 10,000 characters of `-key-key…`. A match
  may start at any inner dash, so long dashed flag names still match.
- **A credential assignment** (`COMMAND_ASSIGNMENT`): the match now starts at
  the credential word, with at most 31 characters after it. The name before
  the word stays in the text as before, so the output is unchanged and long
  names lose nothing. Unbounded, it was quadratic on one long word.
- **Argument checks** in `maskArgs`: a flag-shape test plus a
  credential-word search, exactly equivalent to the old single patterns.
  Those were quadratic on one long argument (7.7 s for 40,000 characters).

The trade-off is that a scheme over 32 characters is not taken as a URL,
unless its last 32 characters start at a word boundary. A flag or assignment
name with more than 31 characters after its credential word is not taken as
a credential. Guards confirm that a 32-character scheme, a 39-character
assignment name and a long dashed flag name still mask.

`importMask.test.ts` checks four long lines through `maskText` and
`maskArgs`. Each must come back unchanged within 1 s:

| dotted words `a.…` (50,000) |             111 ms |              29.7 s |
| dashed words `a-…` (50,000) |             133 ms |              46.9 s |
