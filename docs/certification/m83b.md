## RV83c: masking redesigned

RV83c reviewed `6db3cc9d`→`a895dbb4`. It found three problems in
`src/core/import/importMask.ts`:

- **P1, quoted values.** The masker still showed a credential when a shell
  joined a part that starts with punctuation or another quote onto the
  closing quote: `curl '…?signature='-value''` and `'…?signature='"value"`.
  It also showed one when a quoted value held whitespace:
  `[service](…?signature='prefix value')`.
- **P1, length caps.** The previous round's caps failed open: a name with
  more than 31 characters before or after its credential word, and a scheme
  longer than 32 characters.
- **P2, quadratic scans.** Two scans grew with the square of the line: the
  URL's trailing punctuation pattern (16.6 s for 64,000 characters on this
  host) and the log redactor's JSON Web Token pattern (3.1 s).

Its further probes, which every revision leaked, were a JSON object, and
`TOKEN=''value` and `cmd --token ''value`. Each round had found a new way to
misread where a value ends, so this round redesigns the masker (the owner's
rule) to the lead's design rather than patching it.

### Design as built

Free text fails closed, line by line, with no quote parsing. On each line
(`[^\r\n]+`) the first credential cue is found, and everything from its
value's start to the end of the line becomes the mask. The cues are:

- **A URL with a query or user-info.** After `://`, the first `?` with
  something after it, `@` or whitespace is found. A `?` masks from just
  after it, and an `@` from just after `://`, where user-info starts.
  Whitespace ends that URL, and the search goes on after it.
- **A credential name.** This is a run of `[\w.-]` that holds a word from
  the existing `CREDENTIAL` alternation, at any length either side. Quote
  marks may follow it. Then comes `=`, `:` or whitespace, then a value,
  which is masked from its first character.
- **A known token shape.** These are the existing `TOKEN_SHAPE` entries,
  case-sensitive as vendors issue them, plus a JSON Web Token's start. The
  mask starts at the token.

The earliest of the three on a line wins. Every secret starts at or after its
own cue, so nothing secret precedes the mask. In an argument vector, each
argument is one "line", and the mask runs to the argument's end across its
own line breaks. The argument after a bare credential flag (`^--?[\w.-]*$`
holding a credential word) is masked whole. The log redactor then sweeps
what is left, and its `[redacted]` is shown as the mask word. Dedicated
fields are unchanged: `env` and header values are masked whole. `maskUrl`
keeps the scheme, host, path and query names and masks user-info and every
query value. It sweeps the host and path, and each query name, as free text
separately: as one string, the `@` and `?` it builds would mask the host and
names. Masking already masked text changes nothing, which the preview relies
on.

Each scan is linear. A credential name is tried only where a run starts
(`(?<![\w.-])`). Its credential word is found by one lazy pass over the run,
and on a failed separator the run backtracks once. A URL's stop search goes
on from the whitespace that ended the last URL, so each character is read
once. Token shapes fail within a bounded number of characters. No pattern
nests quantifiers.

### Deviations from the lead's design

1. **No scheme pattern; `://` alone marks a URL.** The suggested
   `(?<![a-z0-9+.-])[a-z][a-z0-9+.-]*://` misses a URL glued to a preceding
   `.`, `-`, `+` or digit (`see...https://x?k=v`, `1.https://…`), so it
   would fail open. A literal `://` is found in linear time and needs no
   scheme or cap.
2. **A `?` counts only with something after it** (`\?(?=\S)`). A question
   that ends at a URL is then no query: in "Have you read
   `https://example.test/docs?` It is short." the `?` is followed by a
   space, which ends that URL, so no query value can follow it.
3. **`Authorization` is a credential name.** `auth(?!or)` became
   `auth(?!or(?!i))`. The old alternation excluded `Authorization` along
   with `author`, so `-H "Authorization: <bare key>"` was shown. `author`,
   `authors` and `authored` stay excluded (`git commit --author Randy` is
   unchanged).
4. **Quote marks may close a name** before its separator
   (`{"token":"…"}`), for RV83c's JSON probe.
5. **A JSON Web Token's start (`\beyJ[\w-]`) joined the token shapes.**
   `redact.ts` belongs to the release candidate and is untouched. Its JWT
   pattern retries at every `eyJ` of a near-miss run, which is quadratic.
   With each line masked from its first `eyJ` before the sweep, the
   redactor never reads such a run through the importer. `redactSecrets`
   alone is still quadratic on that input for logs, which the release
   candidate owns.
6. **One extra linear test at 512,000 characters**, beside the 64,000
   rows. `.claude.json` is read up to 16 MiB, so an MCP argument can be that
   long. Without the URL skip, a 64,000-character line costs only about
   0.25 s per call, too cheap to detect within 1 s. At 256,000 characters
   the broken code failed by only 97 ms (1,097 ms), so the test uses
   512,000 (4,447 ms red).
