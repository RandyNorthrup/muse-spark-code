## Live wire capture

Muse Code 1.3.0 was driven over MSP in empty folders `C:\muse-live-m46`
(Windows managed shell sandbox enabled) and `C:\muse-live-m46b` (sandbox
disabled), using `muse-spark-1.3-contributor`. The capture scripts and frames
are in session scratchpad `m46/live-m46*.mjs` and `m46/capture-m46*.jsonl`.
The CLI trace counts were **10 + 17 = 27 model attempts** in the two runs,
identified by their session IDs. Both capture scripts exited 0. The first
run's sandbox refused user shell commands, so the second run supplied the
successful command, nonzero exit, background and stop frames.

The captured protocol facts used by the tests:

- `session/userShell` needs the `userShell` handshake grant. Its `userShell`
  item has `turnId: null`, `commandText`, and a final `exitCode`, `durationMs`
  and output. `task/stop` rejects its item ID because the command cannot be
  stopped through Muse Code's task API. `task/stopAll` does not stop it.
- `task/background` accepts a running shell task and returns its `taskId`;
  `item/updated` marks `background: true` and
  `backgroundInitiator: "user"`. `task/stop` accepts the ID and the item
  ends `cancelled`. A missing task returns `commandRejected` with
  `data.reason: "invalid_target"`.
- `userInput/clarify` sends `clarification: { format: "text", content }`.
  The question settles as `clarified`, with the explanation and no choices.
  A later model turn recalled output of the user's own shell command.
