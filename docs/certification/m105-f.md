## Ledger and integration contracts

`UploadLedger.ensure(sessionId, sha256, source, signal, onProgress)` shares
an account/provider-local SHA-256 across sessions. M2 supplies a freshly
computed source digest. A missing or expired upload opens that source again,
verifies its original hash before another POST and replaces the ID once.
M2 limits the model replay retry to one; it must persist returned `fileRefs`
and keep them in fork/rewind/compaction snapshots. If replacement is shared,
the digest resolves to the new ID for every owning session.

`SessionUploadLifecycle.syncSession/releaseSession` is the binding for
`FileSessionStoreDeps.uploads(accountId)`. It covers nested child references
under the root session's ownership. Saves retain old and incoming snapshots
until the session's atomic rename succeeds, then release removed references.
Delete and retention purge release ownership after local removal. Provider
failures leave durable zero-reference entries for retry; expiry also bounds
a process crash before the upload receipt can be recorded.

- **F-ledger-storage:** bind `UploadLedgerStorage.read/write/withLock` to
  provider/account-scoped, atomic private storage, with a lock shared across processes
  and windows. Missing storage starts an empty ledger; corrupt storage refuses
  use. No production storage stand-in is supplied by this lane.
- **F-provider-adapter:** the ledger accepts a provider-neutral injected
  Files port. The captured Meta `FilesApi` normalizes account metadata through
  `accountFiles`; vendor lanes bind their captured adapters only where the
  selected model's Files capability supports them. Every request is bound at
  final dispatch to the ledger's account digest. A changed or absent key makes
  cached metadata read-only and prevents remote cleanup.
- **F-account-bridge:** bind `ConversationDeps.uploadedFiles` and the
  `UsageDialog` file props/callbacks in lane W's webview/MHP/runtime bridges.
  The controller validates the report and carries explicit foreign-file
  confirmation, filling `UI_TEXT.media.otherAppFileConfirmation` before calling
  `confirmForeign(question)`. It can read retained metadata after sign-out. Register the
  Delete uploaded files command there; no existing protocol message is
  invented or extended in another lane's region.
- **F-export:** M2/W must include metadata in exports, shares and problem
  reports with IDs stripped as D85 requires. `fileRefs` itself admits neither
  bytes nor source paths. Existing pre-M105 inline replay remains unchanged
  in F's region; M2 owns its new uploaded-part encoding.
- **F-documentation:** lane W owns README, PRIVACY, SECURITY, ACP/CI guides,
  host compatibility records and settings/command manifests. The file-list
  help entry should state ownership, size, session references, expiry, pool
  total, foreign-file confirmation and retained read-only metadata.

An account cleanup action refuses a file still referenced by any session.
Remove those references (or delete the sessions) first. Delete all ours
cleans only our zero-reference entries; it never removes a foreign or shared
file. The UI marks and disables files in use with a localized explanation.
