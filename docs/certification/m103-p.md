## Wiring and platform qualification

- `SerialSessionDependencies` requires the host's context/trust/hardware check,
  G's classification, current port metadata, a metadata busy check, the actual
  bounded opener, the host-only confirmation callback, append-only log and
  turn signal. It supplies no permissive classifier or production fake.
  G owns the irreversible/machine-motion rules; all writes refuse a connect
  classification. V/R adapt `allow_once` / `reject_once` to their native or
  shared UI. Surface boundaries must use I's frozen schema when available.
- `log` records approved attempts, approval rejection, target replacement,
  sent/failed/stopped transport results, and aborts dispatch if append fails.
  Hosts/G/M must also record early refused results (context, bounds,
  classification, identity/mismatch) and redact sensitive payloads in the
  device log; they receive those explicit reasons from `runSerialAction`.
- `startSerialProcess`, `NativeLeaseHelper`, the Windows compiler runner and
  discovery runner take an explicit sanitized environment/bounded executor
  from the host. Keys never enter P's APIs or native arguments. W must ship
  `native/posix/serial.py` and `native/windows/MuseSparkSerial.cs`; `.vscodeignore`
  and the ACP package currently do not include these new helpers.
- Windows first-use compilation uses portable `JobBuild` with
  `System.Web.Extensions.dll`, source-digest names and sanitized compiler
  environment. Its fake compiler tests prove caching/failure cleanup and
  environment propagation. Actual .NET Framework compilation, SerialPort,
  current-user pipe DACLs and C# guard red drills remain **Windows-rig pending**.
  No Windows runner was contacted from this network-prohibited lane.
- The POSIX kernel mutex requires a host-discovered Python 3 (stdlib only),
  even with the shell data adapter; missing helpers are explicit errors.
- Native Windows and pyserial adapters set DTR/RTS. `posix-raw` and plain
  `stty` cannot promise those modem-line states: the native driver may change
  them on open. The approval always warns about reset; hosts must render this
  limitation and select pyserial or reject a request requiring guaranteed
  line states. The shell fallback relies on lease + fuser/lsof for busy
  detection; only the Python raw/pyserial helper additionally uses TIOCEXCL.
- The per-user lease directory must be the same across editors/runtime and
  short enough for the platform's Unix socket path limit. POSIX owner uid and
  modes are checked; Windows' storage host must provide a private per-user
  directory, while the native helper explicitly restricts each pipe's DACL.
- Real macOS ioreg/sysfs-equivalent discovery, Mac mini socat, pyserial with
  attached boards and nonempty Windows/Linux board captures remain platform
  qualification. No MCU flash or physical board connection ran. Match means
  the known USB **family** agrees with the project, not verified chip revision.
- W owns the portable/bundle/package records, README/CHANGELOG/PLAN entries,
  strings and actual host wiring. This lane adds no setting or command and
  changes no model request/catalogue. Hardware contexts still come from the
  host; unattended, disabled, untrusted and Plan must make `canUseHardware`
  false. No paid operation or model call was used.

### Protocol and proof

1. Create a unique private preparation with `open(..., 'wx', 0600)`, write
   the complete record, fsync and close. It contains session UUID, claim
   generation, canonical resource, holder, PID and OS start identity.
2. Prepare/fsync Stop's index separately and publish its exclusive link
   before admission. It has its own inode: corrupting the claim cannot
   corrupt Stop discovery. Its owner-only socket/pipe calls the session's
   Stop callback directly.
3. Admission is one exclusive hard link to the current port claim slot.
   Start at `claim-v1.<resource-hash>.head.claim`; later slots are named by
   the previous generation. A successful publication returns the release
   handle immediately, without another fallible step or helper check.
4. The immutable slot names its generation's live marker:
   `claim-v1.<resource-hash>.<session>.<generation>.json`. Matching PID/start
   is busy. Proven absence or PID reuse publishes a matching immutable
   retirement receipt before idempotent unlink of only that marker. A missing
   marker without a receipt is unknown while the holder may be alive. Unknown, unreadable,
   corrupt, oversized, foreign or cyclic state stays busy without invented
   holder metadata. A reclaimer always competes for a new exclusive slot.
5. Release closes the endpoint, checks the captured generation, publishes its
   retirement receipt and removes its marker/Stop index. Already removed is
   success. A valid receipt permits later admission despite a failed cleanup
   unlink while the parent remains alive. Endpoint-close failure
   still attempts cleanup; once removed, another release is a no-op. Stop
   never reads the claim chain, acquires a mutex or asks approval. The serial
   caller acts on its process directly and treats lease cleanup after Stop
   as best effort.

A reusable fixed filename plus portable unlink has no atomic compare-and-
delete operation: one cleaner's delayed deletion can erase a replacement.
Retaining the old routing slot and unlinking only its unique generation
makes that submitted operation harmless. Exclusive publication is the
source of truth. `LeaseDependencies.exclusive` is optional and is never
called for admission, release or failure cleanup. No new native lock exists.

Files are directly in the already validated private root. An intermediate
per-resource-directory design exposed Windows default Administrators
ownership before provisioning completed; flat names eliminate that setup
race. All ancestors refuse symlinks before descent. POSIX validates owner/
0700; Windows validates current-user owner/DACL before opening lease files.
Reads allocate at most `maxRecordBytes + 1`. A concurrent Windows unlink can
return EPERM; it is done only if subsequent lstat proves ENOENT. EPERM while
the marker still exists remains an error.

## FIXM103P3 — RVM103P6 active-holder Stop (Win11, 2026-10-06)

The review of `448eecee..31ea1b5b` confirmed one P2 and no P1/P3: an indexed

generation replies as a cancelled contender and cannot subsequently publish.

approval or opening. A committed generation stopped during publication still

unknown party with a timeout, unavailable or invalid-response reason; they
cannot create success. `stopped` requires a holder acknowledgement and no
holder/unknown failure. `didStopHardwareLease` preserves its boolean API by
returning that predicate. Callback exception prose stays private.
