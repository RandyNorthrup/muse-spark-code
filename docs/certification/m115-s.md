## Implementation plan and ownership

1. Shared core store with validated records, atomic revision CAS,
   permanent identifiers/occurrence receipts, workspace isolation and a
   cross-process Node filesystem adapter. Publish complete, synced files
   exclusively; a crashed writer cannot expose a partial snapshot.
2. Copy/reopen/verify/remove M52 migration, including its crash receipts,
   replay fences, counters and original provenance. No old approval becomes
   unattended authority. A failed verification leaves the source intact.
3. Shared scheduler with injected time/event/admission/delivery ports;
   creation-order queues per target and explicit parallel fresh conversations;
   permanent time/event claims, clock discontinuity detection, catch-up/end
   handling, final settlement records, and failure pausing. `runNow` and
   manual `fire` use the same admission and accounting path.
4. Owned tests and deliberate guard mutations with SHA-256 restoration;
   scoped lint/format, all typechecks, localization, dead-code, duplication,
   host API and production build directly on this rig. Commit finished parts
   early with repository hooks enabled. Full quality is integration W's
   responsibility: the explicitly invoked rig/common brief forbids that run
   in an individual lane.

Final storage review adds a bounded snapshot change within S: after
exclusively publishing a new revision, atomically retire the previous full
snapshot to a small validated tombstone. Its filename remains a permanent
CAS fence, so stale writers still lose. Readers that raced retirement rescan
the latest revision; a tombstone at the latest revision fails explicitly.
This avoids retaining quadratic copies of run history on disk without
deleting any claim, identifier or journal filename. Cover the disk shape,
read/retirement race and stale-writer fence with real filesystem tests and
deliberate red controls before completing certification.

The Node adapter and data-folder region belong to S. Time computation is T,
event filtering/coalescing is E, unattended/grant/paid admission is U,
settled delivery is D, CLI/editor/OS bindings are X/W, and report execution
is RA/M113. Missing dependencies are injected interfaces, with named
integration bindings recorded here; no fake production implementation or
new provider wire shape. W owns shipping docs, bundle/manifest/help wiring
and the combined PLAN/CHANGELOG updates. No new command is registered by S.

## Verification and drills

The implemented files are `src/core/schedules/{store,scheduler,fireRecord,migrate}.ts`,
`src/runtime/schedules/nodeScheduleFs.ts`, the migration-owned region of
`src/host/backend/fileScheduleStore.ts`, and `schedulesFolder` in
`src/runtime/dataFolder.ts`. Tests use the actual filesystem and independent
Node processes; fake clocks, sessions and time planning stay under `test/`.

The index is a revision journal with permanent CAS filenames. Exclusively publishing the next
complete, flushed snapshot is the CAS linearization point. The filesystem
adapter checks path confinement and directory links before creating storage,
uses private POSIX modes, and publishes through an atomic hard link. Staging
files cannot become index revisions. IDs remain issued after removal; time
and event receipts remain claimed after removal, process exit and restart.
Long event identities are preserved in records and hashed only for filenames.
Workspace limits are enforced inside the revision CAS. Corrupt stored JSON
throws a fixed technical code without quoting private prompts or event data.
After publication, the preceding full snapshot is atomically retired to a
small validated tombstone; its filename remains an exclusive CAS fence.
A reader racing retirement rescans, while a latest tombstone fails explicitly.

Rich admission receipts retain recovery facts before delivery. The index CAS
also decides the after-N limit across simultaneous parallel runs; declined
receipts stay declined even if the user later raises the limit. The richer
`ScheduleRunJournalPort.advance` returns that durable boolean decision, which
dispatch and recovery both honor. Counters and time cursors advance once;
older recovery cannot regress a newer cursor or
confuse it with a manual wall timestamp. Startup recovers only owners proved
dead and records conservative final accounting without replaying a send.
Settlements are immutable and preserve actual cost, uncertainty, retained
liability and refused actions. Failure streaks follow admission order even
after clock rollback and out-of-order final settlements; three failures pause
the schedule. Unclaimed legacy-style records fall back to occurrence order.

Target queues work across real processes and remain held through the final
delivery settlement. Each target batch uses creation order, including tied
timestamps; independent targets proceed independently. Parallel runs use the
lane-0 schema's required fresh-conversation target. Every queued candidate is
reopened before admission and again before dispatch: fresh grants/modes apply,
while removed, paused, expired, retargeted or no-longer-owned runs do not send.
Time planning sees wall/monotonic deltas and startup/jump information on every
poll; catch-up Skip is recorded before any paid dispatch. `runNow` and manual
`fire` use durable event identities and the same settlement path. A manual
event composed with a time trigger is handed to E/T for persistence and due
delivery rather than sent early.

Migration seals v1 admission first, copies recovered counters and shifted
cadence, burns every legacy receipt (including empty/corrupt crash receipts),
reopens and verifies the v2 record, and checks the original job/receipt
fingerprint before removing source JSON. Verification failure retains the
source and its seal. Receipts and seals remain as forensic replay fences;
legacy cleanup skips them. Old schedules remain paused, with an empty grant,
zero paid cap and no unattended paid consent.

## Integration bindings (named handoffs)

- **T / TIME:** implement `ScheduleTimePort.plan` against T's real interval,
  calendar, zone and DST engine. Consume `ScheduleClockReading`; return at
  most one catch-up and its next cursor. Elapsed interval occurrence/cursor
  timestamps may be ahead of wall time after rollback; calendar plans may
  not fire in the future. The default timer uses the existing one-minute
  constant. Core contains no guessed calendar implementation.
- **E / EVENTS:** own source capability checks, scrubbing, debounce,
  coalescing and persistent composed-event readiness. Bind mandatory
  `deferEvent` for manual `afterEvent` requests; call `fireEvent` only when
  T says the composed instant is due. S revalidates kind/source/conditions,
  rejects future due instants, and claims the full source/event tuple once.
  Event fields remain data separate from `ScheduleRunContext` authority.
  Fan out a shared event through `store.list` creation order and await serial
  deliveries; S's target mutex then preserves that order across hosts. Future
  event-source batching must retain this ordering contract.
- **U + D / ADMISSION AND DELIVERY:** bind `ScheduleHostPort.deliver` to the
  final, typed settlement, including refusal transcript rows and actual paid
  spend. Recheck current model/key/price, grant and per-schedule/shared budget
  immediately before any dispatch. Unattended approvals and physical D83
  actions must be refused by U, including Bypass/remembered/session rules.
  M112 questions defer immediately as D92.8 amended by D95 requires; they
  remain answerable later without holding this unattended delivery open.
  Bind required `failureSettlement(intent, error)` for thrown dispatches and
  dead-owner recovery with conservative uncertainty/retained liability; an
  exact zero must never be invented after a possibly paid send. S validates
  every settlement identity and stores the returned facts unchanged.
- **X + W / HOSTS AND STORAGE:** use
  `createScheduleStore(createNodeScheduleFs(schedulesFolder(input)))`, pass
  that same store as `runs`, and create `createNodeScheduleQueue` at the
  same root. M102 supplies the canonical workspace key. Bind clocks,
  held-workspace ownership, startup/disposal, typed requests, v1 migration
  source and the user's IANA zone. All Node editor/runtime hosts consume the
  same core; remote hosts must share the authoritative store/claim owner,
  not copy local files and claim equivalent deduplication.
  The richer journal's boolean `advance` is part of this S port; adapters
  must preserve atomic after-N decisions rather than discard its return.
  Custom `ScheduleFsPort` adapters must also bind atomic `retire`, preserving
  the canonical filename while replacing only an older snapshot's content.
- **RA / M113:** route `report` jobs through the same host settlement port,
  using `occurrenceMs` as `asOf`. Keep report jobs model-free and paid-free;
  report content/retention/destination execution belongs to RA. S preserves
  the frozen prompt/report union without adding a model path for reports.
- **W / SHIPPING AND HELP:** wire the lazy schedule bundle, manifest,

## Limits of the evidence

Journal filenames and permanent receipts grow linearly with runs; retirement
avoids normal quadratic retention of full snapshots. A crash between publication
and retirement can leave an older full snapshot; that extra copy is safe and
its CAS filename still prevents stale writes. Follow-up maintenance may retire
such copies but must never remove a claim fence. PID reuse conservatively keeps
work pending rather than authorizing a replay. Windows files inherit the
trusted user data folder's ACL; POSIX files/directories request 0600/0700.
Node does not support Windows directory fsync here, so the evidence covers
process crashes and exclusive whole-file visibility, not power-loss durability.
Path/link checks assume a trusted per-user root; they do not promise protection
against concurrent hostile mutation by another process of the same user.
No unsupported editor command or full M115 shipping completion is claimed by
this S-only certification.
