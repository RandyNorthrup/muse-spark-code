## Design as built

The workspace index contains one immutable, fsynced generation and a bounded
journal (64 operations, 256 KiB). A reserved final slot seals the old
generation before compaction. Activation atomically replaces `current.json`
and exclusively publishes a tiny generation-epoch fence. That fence, rather
than the mutable pointer hint, decides committed state even when an expired
writer resumes a pointer rename already in flight. Epoch fences are segmented
and carry no prompts. Old generations and interrupted staging are retired;
locked retirement is retried on later mutations without failing a commit.
Readers share the writer lease, so ordinary retirement starts after they finish.

Transient publication/activation/release errors have five bounded retries
with named backoff. Committed hard links are recognized by BigInt file
identity; completed publication cannot fail merely because temporary cleanup
was locked. Leases contain PID, process start, random token and heartbeat;
dead or expired owners can be replaced, including failed releases while the
original PID remains alive. Guarded writes refuse an owner that lost its lease.

Run identities, admission decisions and settled digests are separate hash
segments. Their retained content grows linearly, never recopied with the
workspace state. Fences survive the schedule lifetime plus eight days after
removal. Permanent identifier tombstones prevent recycling even after grace.
Audit retains at most 100 fires per schedule and 30 days. Completed migration
receipts are archived separately from the live state. These tiny identity and
generation fences have no historical prompt payload.

An intent is durable before its occurrence fence. Each poll drains up to 32
pending runs, including living owners after transient advance/record errors.
The target admits a run id idempotently and exposes a durable ledger. Absent
means definitely unsent and safe to admit. Admitted means its own recovery
queue owns progress. Settled/uncertain carries final validated accounting;
ambiguous paid dispatch is never replayed. Durable acknowledgments preserve
known spend and retained liability even when final storage fails. Per-target
dispatchers reread the persisted creation-time/id queue before every pop.
Parallel remains the schema's explicit fresh-conversation opt-in. Time
admission compares the captured cursor/trigger/zone with current state;
already admitted recovery still accounts exactly once. Admission chronology
is independent of fire counts and wall-clock rollback.

Migration saves source identity/fingerprint, target identity/revision and
copied receipt counters before source removal. Reconciliation atomically
updates counters and the receipt while preserving current authority and
legitimate v2 edits. A changed v1 job is refused; raced receipts are reconciled.
A failed entry retains its source while later independent entries continue.

## Changed internal contracts and integration bindings

- `ScheduleHostPort.lookupRun(runId)` is required. `deliver` must durably admit
  the id before sending and refuse duplicates across hosts/restarts. A target
  owns recovery of admitted work and exposes ambiguous sends as `uncertain`
  with honest cost/liability and a person-visible final record. This is an
  internal delivery contract change; no provider wire shape was invented.
- The S-only run journal now exposes durable `pending`, `acknowledge`,
  `acknowledged` and `maintain`; `advance` remains a boolean atomic decision.
  The filesystem port adds guarded replacement and guarded exclusive writes.
- T still supplies real calendar/DST planning. E supplies persistent event
  readiness and identities. U/D bind paid/grant admission, durable target
  ledger and final accounting. X/W bind the shared store and queue root,
  canonical workspace identity, ownership and lifecycle in every editor and
  runtime. RA owns model-free report execution. W owns shipping commands,
  localized surfaces, reference and the combined full-quality platform matrix.
- No new registered command, setting, dependency, locale key or escape hatch.
  S modules are not yet bound into shipped entry bundles. No paid/live call,
  credential read, install, push, merge, rebase or manual stash occurred.

## Historical guard receipts (superseded implementation)

Each drill runs all three owned test files with three workers and the rig's
120000 ms test timeout. There are no test-name filters or skips. The driver
saves the source bytes, deliberately breaks the named behavior, requires
exit **1** and the named assertion failure in Vitest's JSON report, and
restores in `finally` with an exact SHA-256 comparison. Full JSON reports,
receipts, logs and the driver are retained under the ignored
`temp/m115-s/` in this worktree. The final receipts below use the final
production source, including atomic after-N admission.

The first exploratory D17 mutation accidentally removed the release CAS
along with its ownership check. Its run hit the driver's 240-second watchdog;
the source was still restored byte-exactly, but that run is **not** counted
as a named guard receipt. The mutation was corrected to remove only the
token comparison and passed the intended red drill. The first D24 search
missed a formatting-merged expression and stopped before mutation; its
corrected search also passed. No test, timeout, hook or gate was weakened.
D49's first final-source search likewise stopped before mutation because
the lint hook had converted its `if` return into a ternary. Targeting the
same comparison in its final form corrected that control search.
D16's first retirement-era run did not overlap two short child jobs and
failed another scheduler assertion instead of its intended queue assertion.
The test now holds the first actual process behind a release file, waits for
the second process's ready marker, verifies exclusion while the first is
held, and releases/drains both in `finally`. This strengthens the existing
assertion without changing the production guard or the test timeout.
After adding the atomic after-N decision, D35's old pending-run test was
protected by that second guard. The mutation still failed the pre-admission
eligibility test; the driver stopped, restored its bytes, and was updated
to require that more precise named failure before rerunning D35. Assertions
and production guards were unchanged by this control correction.
