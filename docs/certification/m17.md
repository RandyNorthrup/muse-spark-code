## What the milestone rests on

- The M5 mechanism for hidden context: a turn's input is a list of parts,
  the typed text stays as `displayText`, so the transcript and the durable
  log show what the user wrote while the model also gets the reference.
  Neither MSP nor the Model API has a reply-to field; the tagged part is
  the way both backends learn it.
- The payload names the intent (`reply`, `question`, `comment`) and the
  author of the passage (`assistant` → "you, the assistant", `user`,
  `tool`), then the passage in a fenced block clipped at 8,000 characters
  with a note, so the model knows what the user is doing and with what.
- A webview's right-click is the browser's menu; the panel intercepts it
  only with a non-empty selection inside a transcript row. Rows carry
  `data-entry-id` and `data-role`; the row owning the selection's anchor
  renders the menu at its top-right (no inline positioning, which the CSP
  forbids).

## Visual verification

## Security

- The payload is text the transcript already shows, clipped; nothing
  outside the conversation is read. The typed text stays the durable
  transcript's record (`displayText`).
- The right-click is intercepted only with a selection inside a row; the
  browser's menu is otherwise untouched.

## Findings recorded during the milestone

- `unicorn/consistent-function-scoping` also applies to helpers inside a
  `describe`; module scope is the place.
- A reducer action gaining a field breaks every existing dispatch in tests;
  an optional field with a doc comment is the honest shape when the value
  is absent for a plain send.
