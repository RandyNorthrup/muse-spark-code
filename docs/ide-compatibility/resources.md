# Resource governor routes and qualification (M107)

Every host uses the portable policy and validated status/history schemas.
W delivers artifacts and settings without inventing missing native wire fields.
The table records the required equivalent route and what is still unbound.
Existing host support status is unchanged.

| Host                                                                   | Equivalent route                                                                                  | Integration handoff                                                                                                           |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| VS Code family, remote/WSL                                             | Status item, shared chip/popover, Resume now/Settings/Show resources, Resources history           | U/C1 bind cached checked source, commands/status disposal and shared lazy entries to the window governor; J/M102 bind history |
| JetBrains, Visual Studio, Eclipse                                      | MHP native status widget plus the same embedded chip/controls/history                             | M104b–d bind the supplied status port and machine store; capture real bridge shapes and test installed hosts                  |
| Companion page                                                         | Same chip/controls/history in shared React                                                        | M104 B binds source and callbacks; serve the independent entries through its CSP/asset origin                                 |
| ACP clients: Zed, Xcode, Neovim, Emacs, Sublime, JupyterLab and others | `/resources`, notices/deferred-tool metadata, `/resources resume`, `/usage resources`             | H binds the active runtime/spawn source; M102 supplies retained history; editor receipts remain open                          |
| Any terminal/native TUI                                                | `resources status`, `resources resume`, `resources history`, `usage resources`, optional `--json` | Status/resume CLI tested; process-local snapshot and machine marker, explicit unavailable history until M102                  |
| Headless/CI                                                            | Exec flags, version-2 resource event envelope, stderr and run ledger                              | H binds the active lease/resource sink; relocation refused; M80 live support limits remain                                    |
| Traffic/tasks/paired devices                                           | Deferred rows, Move to/Keep here, headroom buckets                                                | M96/M96c TeamCapacityPort and runner ports, M100 offer/receiver dispatch, U/J rows/notices/journal                            |

`dist/webview/resourceSurface.js` is a named-export browser entry for U's
`ResourceSurface`; `dist/webview/resourceHistory.js` exports J's default
`ResourcesSection`, with `resourceHistory.css`. They share main's React/text
chunks and are excluded from chat startup. The U source/loader boundary and
J's lazy section boundary remain the host mounting ports. They must be loaded
only when used, with the caller's installed table, CSP and accessible error/
retry behavior. Distribution alone does not prove those host mounts.
