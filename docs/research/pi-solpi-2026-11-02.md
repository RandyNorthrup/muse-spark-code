## 1. What is new since 2026-10-05, and what we had not read

### Pi: v1.0.3 → v1.5.0 in four weeks (read in code and changelogs)

Releases: v1.0.4 (10-05), v1.1.0 (10-07), v1.2.0 (10-12), v1.3.0 (10-15),
v1.4.0 (10-21), v1.5.0 (11-02); 621 commits since 2026-10-05 in the clone.
Repo scale on 2026-11-02: 119,577 stars, 15,353 forks, 315 open issues
(REST API). The engineering centre of gravity moved: most non-fix commits
in October are **Chord** (a hot-reloadable multi-process object runtime),
**Durable** (an experimental commit-before-show agent harness on Chord),
and **pi-schema** — i.e. Pi is becoming a platform under the CLI, while the
CLI surface stays small. Items that matter to us:

- **Summaries lost their fixed output cap (v1.4.0).** Compaction and branch
  summaries now use the model's output limit; `reserveTokens` only decides
  when compaction starts. Cause: reasoning models spent the fixed summary
  budget thinking and deterministically failed ([#9512](https://github.com/earendil-works/pi/issues/9512),
  [#9075](https://github.com/earendil-works/pi/issues/9075)). We still cap
  summaries at a fixed 8,192 tokens — see §2 row C2.
- **System prompt tightened again (v1.5.0, `705d047cb`, 2026-10-31).**
  Shorter preamble, shorter edit guidelines. The prompt is now structured
  sections (`SystemMessage.sections`) diffed per request
  (`diffSystemPromptSections` in `system-prompt.ts`): only changed sections
  are resent as a patch message, so tool/rule changes do not rewrite the
  whole prefix. This is the general form of our M101 item 1 fix.
- **Tool argument validation moved to `pi-schema` (v1.5.0, breaking).**
  TypeBox dropped; every JSON Schema (including MCP tools) gets the same
  coercion (numeric strings → numbers, single value → array, `null` →
  `"null"` for a required string); model-facing errors became
  `- edits.0.oldText: missing`. Package claims 2,222/2,223 JSON-Schema
  test-suite passes, 8.5 KB gzipped, no `eval` (claimed; not reproduced).
- **Incremental streamed tool-call parsing (v1.5.0, [#9265](https://github.com/earendil-works/pi/issues/9265)).**
  Previously every stream delta re-parsed the accumulated arguments —
  O(n²) CPU/memory on large `write` calls, freezing the event loop. Fixed
  across `pi-ai`, Chord, Durable and the coding agent (`f715a15c1`).
  Renderers also stopped re-highlighting unchanged code per frame
  (`0f21a3319`, [#10971](https://github.com/earendil-works/pi/issues/10971)).
- **Codemode + `tool_search` matured.** The model may write a JavaScript
  script (QuickJS sandbox, no Node/fs/network) that calls tools, filters
  large results before they reach the model, and runs non-LLM classifier /
  image models. Deferred-exposure tools (MCP by default) are **not**
  declared; scripts find them via BM25 `searchTools()` / `describeTool()`.
  Inline declarations share a 3,000-token budget
  (`codemode.inlineBudget`). October fixes: BM25 ranking by matched terms
  and name-over-description (`cc44fa216`, `e033f255f`), Unicode word
  segmentation for CJK/Thai queries (`79006f061`), codemode description
  bloat from union types (`#11501`), worker queueing instead of failure
  (v1.4.0, `PI_CODEMODE_MAX_WORKERS`).
- **Cache tactics kept accumulating.** GPT-6 thinking-level changes keep
  the prompt cache (v1.3.0); Kimi Code moved to Chat Completions so
  mid-conversation tool additions stop invalidating cache (v1.3.0);
  deferred tool loads after a removal stopped losing the Responses cache
  (`#10940`, `resolveTranscriptTools`); changing the same active tools in
  a different order no longer triggers a system-prompt update (`#11495`);
  summarization requests disable prompt-cache **writes** (one-off prompts
  are unlikely to be reused — compaction doc). Model switching now drops
  the previous model's thinking instead of showing it as text (v1.3.0).
- **Overflow/robustness.** LiteLLM `ContextWindowExceededError` recognised
  as overflow (`d3398f826`, `#11494`); Copilot HTTP 413 on large bodies
  compacts and retries; whitespace-only tool output no longer 400s
  (`#8720`); truncated tool call + kept tool results no longer poisons
  every later request (`#11227`); retry matching no longer fires on digits
  inside request ids (`6e491cfa9`); Zhipu usage-limit `1308` and ChatGPT
  Business limits are not retried.
- **Extensions/packages.** In-process TypeScript extensions remain the
  core customisation story (3,347-line `docs/extensions.md`): tools,
  commands, providers, renderers, session/tree control, `before_agent_start`
  now also for extension-triggered runs (v1.2.0, breaking union type).
  Packages distribute via npm/git with trust gating; v1.5.0 shows package
  changelogs after update. Security posture is stated plainly in
  `docs/security.md`: no per-call approval, no sandbox, extensions run in
  the Pi process; safety = OS user / container / VM. Project trust gates
  resource loading only — and even that has a documented hole (`sessionDir`
  is read before trust resolves). October also fixed a saved "Do not
  trust" being ignored for folders with only `AGENTS.md` (`#10947`), MCP
  OAuth non-http(s) URLs reaching the platform handler, and terminal
  escape injection via titles/URLs.
- **What hurts users (most-reacted open issues, REST API 2026-11-02).**
  [#4945](https://github.com/earendil-works/pi/issues/4945) Codex
  connection reliability (35 reactions); [#7730](https://github.com/earendil-works/pi/issues/7730)
  high CPU on macOS with long sessions (15); [#11021](https://github.com/earendil-works/pi/issues/11021)
  ChatGPT sign-in stuck at 272K context (12); [#6665](https://github.com/earendil-works/pi/issues/6665)
  TUI pinning a core while streaming (9); [#7553](https://github.com/earendil-works/pi/issues/7553)
  configurable model/thinking for compaction (6). Of 832 issues closed
  since 2026-10-05, the most-reacted include the O(n²) parse (`#9265`),
  compaction inheriting thinking level (`#9075`), and `before_agent_start`
  prompt loss re-billing the prefix (`#10267`). Pattern: **cost, CPU and
  cache correctness dominate; feature requests are provider/model breadth.**

### SoL-Pi: quiet code, loud claims (read in code)

No mechanism change since 2026-10-05. Merged: Pi 1.x + codemode
compatibility for all four mechanisms (`a9d1ee3`, PR #111, tested against
Pi 0.84.2 / 1.0.4 / 1.3.0; warns that fresh Pi 1.0.x/1.1.0 installs break
because Pi did not pin internal packages), a **SoL-Pi Skill** example
(hand a Claude Code `/sol-pi` or Codex `$sol-pi` task to SoL-Pi in the
background), and **SoL-Pi Visual** (Blender scene reconstruction). Repo:
3,625 stars, 87 open issues (REST API). Open issues worth noting: Action
Fusion breaks on Pi-compatible hosts with reduced extension surfaces
(#119, #120, #48 — the cost of replacing built-in tools), ObservationPack
packing its own recall output into a loop (#118, closed), a GSAR proposal
claiming one corrected reducer attempt recovers 35–55% of failures (#96,
open, unproven). About 20 PRs remain open, mostly the October report's
list (reducer secret detection #28, placeholder edges #31/#34, plan
progress reaching compaction #32).

The paper (arXiv:2609.20519) is the load-bearing claim. Method as stated:
auto-research loops propose harness changes; two sequential gates keep a
candidate only if capability metrics stay within predeclared tolerances
**and** an efficiency metric improves; EdgeBench (51 tasks) is held out and
the harness frozen before evaluation. Headline numbers (Table 2, read from
the HTML full text):

| GPT-5.6 Sol | SoL-Pi Efficiency (all 4)                   | 1.0990 (−49.0%) | $894 (−33.2%) | 42.003 (93.7% of Pi) |

Read critically (inferred from the paper's own tables): "performance
comparable" for the full stack means **≈6% relative score loss** for
≈33% cost saving — a trade, not a free lunch; the "Performance" point is a
**different single mechanism per backend, selected after seeing Table 4**,
so it is an upper envelope, not one configuration a user can pick blind;
n=51 tasks with no confidence intervals in the abstract/tables this lane
could extract; hourly savings ($4.36–$5.71 vs Pi) are derived estimates,
not measured bills. SoL-Pi Visual's "37% lower cost per scene vs Codex,
13% fewer calls" (README News, 2026-10-13) rests on 15 VSI-Bench scenes,
GPT-6 Astra, model-graded visual scores (claimed; figures only in the
example README). None of this invalidates the mechanisms — we already
ship two of them — but it caps how much weight the 49% headline can carry
for our defaults.

### Research since October that changes the packing/compaction picture

- **The Physical Cost of Context** (arXiv:2610.34763, 2026-10-26 — the
  newest and most directly relevant). Prompt-token savings are the wrong
  metric when a caching runtime prefills only past the longest cached
  prefix: **rewriting cached history can cost more than it saves.** On
  100 SWE-bench Verified tasks (mini-SWE-agent), keep-last-5 observation
  masking cut prompt volume 33.3% but raised uncached prefill **608.5%**,
  energy proxy 125.6%, and missed its quality gate; anchored compaction
  passed a 5-point non-inferiority gate but saved nothing further once
  prefix caching was on; preloading retrieved blocks (fewer calls) won.
  This does not refute our ObservationPack (ours replaces a result once,
  then keeps the placeholder byte-stable — a different policy from
  re-masking every turn), but it **does** refute judging packing by
  prompt tokens alone. Our M75 packing arms must report uncached/cached
  tokens and dollars, or the default-on decision rests on the metric this
  paper shows is misleading.
- **The Complexity Trap** (arXiv:2508.21433, JetBrains; v3 Oct 2025).
  Simple observation masking ≈ LLM summarization on SWE-bench Verified
  across five model configs, at half the raw-agent cost; a hybrid beats
  either alone by 7–11%. Supports cheap-first context reduction — with
  the 2610.34763 caveat that _when_ you mask decides whether the saving
  is real under caching.
- **Beyond Compaction / CWL** (arXiv:2606.11213, 2026-04). Deterministic,
  LLM-free eviction over typed, dependency-linked episodes; explicitly
  attacks summarization's lossiness, causal-structure destruction,
  blocking cost and compression hallucination. Single-harness evaluation;
  no replication found by this lane. Worth a design read for M74's next
  iteration, not a port.
- **OpenDev** (arXiv:2603.05344, 2026-03). Terminal agent with five-stage
  progressive compaction (masking/pruning before LLM summarization) and
  lazy tool discovery — independent convergence on "cheap reductions
  first, summarize last" and on deferred tool declarations.

### Why people choose Pi, and what its smallness buys (read + inferred)

Pi's README states the pitch: "a minimal, extensible agent harness that
you can make your own… Pi ships with powerful defaults but skips features
like sub-agents and plan mode. Ask Pi to build what you want, or install a
package that does it your way." Measured smallness: the default prompt +
4 default tools are **1,334 tokens** (§2.1); `coding-agent + agent + ai`
sources are ≈108k lines vs our ≈673k lines of `src/**/*.ts(x)` (both
counted with `wc -l` on 2026-11-02; ours includes the VS Code host,
webview, vault, makers and ACP, so this is a scope difference, not an
efficiency verdict). What smallness buys, concretely:

1. **Cache stability by construction.** Four tools and a 517-token prompt
   leave little to churn; section-diffing then makes even that churn cheap.
2. **Hackability.** One in-process extension API can replace tools,
   prompts, providers and UI; users fork behaviour instead of filing
   feature requests. SoL-Pi existing at all is evidence.
3. **Provider breadth without product surface.** `models.json` + compat
   quirks + per-key catalogues serve bring-your-own endpoints that a
   curated product would never list.

What it costs (from Pi's own docs/issues): no approval or sandbox
boundary, no sub-agents/plan mode/teams in the box, TUI CPU issues at
scale, and extension fragility across hosts (SoL-Pi #119/#120). **Can we
have the benefit without losing what we have?** Mostly yes, and §3 is
built on this split: Pi's _token_ smallness is separable from its
_feature_ smallness. Deferred tool declarations (`tool_search`/codemode
exposure) and section-stable prompts buy the cache/token benefit while
keeping sub-agents, teams, approvals and the editor. Pi's _trust_
smallness (no approvals, in-process extensions) is the part we must not
copy — it contradicts our permission, paid-consent (D48) and
secret-handling decisions.

### 2.1 Measured: system prompt and tool definitions (this lane, 2026-11-02)

Method. Pi: built the clone, ran `buildSystemPrompt` and
`createCodingToolDefinitions` / `createAllToolDefinitions` through Pi's
own jiti loader (scripts in `temp/rsch-pi/measure*.mjs`), cwd `/ws`, no
context files, no skills. Ours: parsed the first request body in each
checked-in golden (`test/fixtures/golden-requests/*.json`) — real wire
bytes our tests pin. Tokenizer: `tiktoken` cl100k_base (o200k_base agreed
within 2 tokens on every artifact; cl100k shown). Neither tokenizer is
Meta's; treat counts as comparative, ±a few percent absolute. Pi's prompt
embeds absolute documentation paths, which on this rig are long
(`/home/randy/lanes/RSCH-PI/temp/...`); a typical install path is shorter,
so Pi's prompt number is an overestimate by roughly 40–80 tokens.

| Configuration                                 | Prompt tokens | Tool tokens | n tools | Fixed cost / request |
| --------------------------------------------- | ------------: | ----------: | ------: | -------------------: |
| Pi default (`read,bash,edit,write`)           |           517 |         817 |       4 |            **1,334** |
| Pi all built-ins (+`grep,find,ls,powershell`) |           541 |       1,613 |       8 |                2,154 |
| **Ours, plain turn (golden 01)**              |       **440** |       2,071 |      12 |            **2,511** |
| Ours, skills+rules (golden 07)                |           541 |       2,165 |      13 |                2,706 |
| Ours, subagent child (golden 06)              |           547 |       3,554 |      21 |                4,101 |
| Ours, team on (golden 08)                     |           811 |       3,740 |      17 |                4,551 |

Findings (measured):

- **Our instructions are already smaller than Pi's prompt** (440 vs 517).
  The gap is entirely tools: ours declares 12 tools where Pi declares 4.
- Per-tool prices are comparable (Pi `read` 173 / ours `read_file` 228;
  Pi `bash` 125 / ours `bash` 125; Pi `edit` 272 / ours `edit_file` 427 —
  ours carries `then_run`, byte-range editing and format-on-edit prose).
- Our always-on overhead with no Pi counterpart: `ask_user` 235,
  `todo_write` 147, and four goal tools (`create_goal` 124 + `get_goal`
  102 + `update_goal` 93 + `report_progress` 135 = **454 tokens on every
  request, goal or not**, golden 01). Goal/todo tools are exactly the
  kind of rarely-first-turn surface Pi's deferred exposure exists for.
- Every fixed token is re-sent (usually cache-read) on every request;
  at contributor cache-read prices the 1,177-token delta to Pi-default is
  small per request but it also lengthens time-to-first-token prefill on
  cache miss and on small-window local models, where 2,511 fixed tokens
  exceed a quarter of an 8k window before the user types anything.

## 3. Ranked: what to do, and what not to do

(measured here or replicated), **M**edium (single solid source),
