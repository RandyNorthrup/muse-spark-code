# Azure OpenAI (Azure OpenAI in Microsoft Foundry Models): models, features, limits — research and product comparison

Research date 2026-10-17. Official sources only (Microsoft Learn, §1); every
value read on 2026-10-17 (each page's `ms.date` / `updated_at` is in §1).
Product: `main` at `3d30a73214` (read only). Owner's rule (2026-10-17,
binding): "the limits we set on our agents hardcoded are **ONLY** the limit set
from the providers" and "**ALL** every model available through every provider
all hooks all features all limits etc".

Classes: **(a)** matches Azure; **(b)** differs (both values given); **(c)**
missing from the product; **(d)** hard-coded in the product but not an Azure
limit. "not documented" rows name the capture that would settle them (§7).

**The product cannot send an Azure request today.** The preset exists
(`src/core/providers/presets.ts:330-352`: resource origin
`https://{resource}.openai.azure.com/openai/v1` from `azureOrigin`,
`presets.ts:847-860`; `api-key` header; models list `/openai/v1/models`;
strict tools on) but it has no recorded wire capture (`wireCapture: false`,
`presets.ts:351`), so it stays out of the panel (`presets.ts:300`) and
`transportFor` refuses any entry that names it (`configured.ts:209-215`); the
key test is a paid token request that is never dispatched
(`presets.ts:345`, `configured.ts:994-998`). Every row below therefore says
what the product would do once the preset is enabled, and is class (c) where
the whole path is missing.

## 2. Summary

- **Models.** MODELS (Azure OpenAI pivot) lists **75** model ids that are not
  stamped retired (**86** model-version rows), plus 5 ids kept as retired
  "historical specifications"; RETIRE and REGIONS add `o1-pro`,
  `o3-deep-research` (Foundry Agent Service only) and `model-router` (a
  Microsoft model in the Azure OpenAI quota tables). All **83** are covered
  in §5 (one table each).
- **Counts** (class tags on the 320 classified rows of §3-§5; a row may
  carry two): **(a) 10, (b) 5, (c) 306, (d) 4** — nearly every row is (c)
  because the Azure path cannot run (item 1). Itemised changes (§6): 5 (b),
  10 (c), 4 (d).
- **Most important mismatches.**
  1. **The Azure path cannot run** (`configured.ts:209-215`; `presets.ts:351`).
  2. **Deployment names, not model ids.** Azure's `model` field is the user's
     deployment name (APIV1, PTUOPS); the product looks up the catalogue by
     the name it sends (`configured.ts:438`), so even the 36 matching
     snapshot `azure` rows would never apply. The wizard asks for "the model
     family behind" a deployment (`presets.ts:848-850`), but no code maps it to
     a record.
  3. **Entra ID** (Microsoft's recommended auth, `Authorization: Bearer` with
     scope `https://ai.azure.com/.default`) is missing; only `api-key`.
  4. **Foundry endpoints** `https://{resource}.services.ai.azure.com/openai/v1/`
     are documented (APIV1) but `azureOrigin` builds only `.openai.azure.com`
     (`presets.ts:852-860`).
  5. **429 handling**: Azure sends `retry-after-ms` (and `retry-after` on PTU),
     `x-ratelimit-reset-requests/-tokens`; the transport reads only
     `Retry-After` (`transport.ts:1086`) and Meta's header reader
     (`pacing.ts:30-44`). Azure's RPM is enforced over 1 or 10 seconds
     (QUOTAHOW), not a 60 s window (`constants.ts:2257-2260`).
  6. **Azure limits the product would break**: 128 tools / functions per
     request (QUOTA) vs the product's 128 per MCP server with no total
     (`constants.ts:4812`); structured outputs "up to 100 object properties
     total, with up to five levels of nesting" (SO) vs depth 12
     (`constants.ts:2393-2400`); 2,048 Chat messages; 10 custom headers
     (431 above); content-filter 400 (`content_filter`) not interpreted.
  7. **Azure's own context differs from OpenAI's for some models** (e.g.
     `gpt-4.1` 300,000 on standard deployments and 128,000 on provisioned and
     batch; the realtime models 32,000 / 4,096): a per-provider record is
     needed, not OpenAI's values.
