# Claude Code hooks: every event, payload, matcher, timeout and decision field — research and product comparison

Research date 2026-10-17. Official sources only (§1); every value read on
2026-10-17. Product: `main` at `3d30a73214` (read only). Owner's rule
(2026-10-17, binding): "the limits we set on our agents hardcoded are **ONLY**
the limit set from the providers" and "**ALL** every model available through
every provider all hooks all features all limits etc".

Classes: **(a)** matches Claude Code; **(b)** differs (both values given);
**(c)** missing from the product; **(d)** hard-coded in the product but not a
Claude Code limit.

What the product does with Claude Code hooks: the agent import (M91) reads
`hooks` blocks from Claude Code settings files and converts each handler
(`src/core/import/agentImport.ts:667-702`, `src/core/import/importConvert.ts:453-475,887-995`).
Fifteen events with Muse Code's names go into Muse Code's own hook files and
run under Muse Code (Muse Code backend) or the product's runner
`src/core/backends/modelapi/hooks.ts` (Model API backend); eighteen other
events go into the product's `spark-hooks.json`
(`src/core/backends/modelapi/extensionHooks.ts`). So every row below compares
Claude Code's contract with the contract an imported hook meets in the
product.

## 2. Summary

- **Events**: Claude Code documents **33** hook events (HOOKS) — the same
  count the product's import names ("the rest of Claude's 33", `constants.ts:3427`). All
  33 are covered in §6. The Agent SDK's TypeScript callbacks list the same 33
  names; its Python callbacks only 10 (SDKHOOKS).
- **Counts** (class tags on the 78 classified rows of §3-§6; a row may carry
  two): **(a) 29, (b) 34, (c) 21, (d) 5**. Itemised changes (§7): 18 (b),
  9 (c), 6 (d).
- **Most important mismatches.**
  1. **Only `command` handlers import**, and only with the fields `type`,
     `command`, `timeout`, `async`, `statusMessage`
     (`importConvert.ts:406-419,901-916`). Claude Code's `args` (exec form),
     `asyncRewake`, `shell`, `onFailure`, `if` and `once` make the whole hook
     refuse; `http`, `prompt`, `agent` and `mcp_tool` handlers refuse too.
  2. **The product's runner fails a hook on any output field it does not
     know** (`hooks.ts:1789-1799`). Claude Code fields such as
     `permissionDecision: "defer"`, `updatedPermissions`, `interrupt`,
     `updatedToolOutput`, `updatedMCPToolOutput`, `classifierContext`,
     `terminalSequence`, `sessionTitle`, `initialUserMessage`, `watchPaths`,
     `reloadSkills`, `suppressOriginalPrompt` turn a working Claude hook into a
     failed one.
  3. **Rules stricter than Claude Code's**: `allow` without `updatedInput` is
     refused (`hooks.ts:1825-1830`), `deny` needs a reason
     (`hooks.ts:1822-1824`), `reason` needs a block (`hooks.ts:1850-1852`); Claude
     Code requires none of these.
  4. **Exit 2 blocks where Claude Code does not block**: `PermissionRequest`
     and `PostToolUse` are in the product's blockable set
     (`hooks.ts:1716-1727`); Claude Code: PermissionRequest "Exit 2 not
     honored", PostToolUse "Shows stderr to Claude" without blocking.
  5. **Payload differs**: `transcript_path` is `null` (`ModelApiHost.ts:3068`,
     `extensionHooks.ts:583`); `permission_mode` carries Muse Code's
     `allowAll`/`promptUnmatched`/`onRequest`/`denyUnmatched`
     (`permissionModes.ts:72`), not Claude Code's `default`, `plan`,
     `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`; `prompt_id`,
     `scratchpad_dir`, `effort` are absent; extension payloads say
     `model_provider: 'meta'` for every provider (`extensionHooks.ts:584`).
  6. **No `CLAUDE_PROJECT_DIR`** (nor any `CLAUDE_*` variable) is set for
     hooks (searched `CLAUDE_PROJECT_DIR`, `PROJECT_DIR`, `_PLUGIN_ROOT` in
     `src`): the most common Claude Code hook command,
     `"$CLAUDE_PROJECT_DIR"/.claude/hooks/x.sh`, runs with an empty path.
  7. **Limits that are not Claude Code's**: timeout maximum 600 s (import
     refuses above it, `importConvert.ts:555-562`; runner `hooks.ts:537-539`),
     prompt/agent default 600 s (Claude Code 30 s / 60 s), 4 commands at once
     (Claude Code: all matching hooks in parallel), stdout 16 KiB and
     `systemMessage` 1,000 chars (Claude Code: 10,000 chars, then a file and a
     2,000-char preview), SessionEnd 10 s (Claude Code 1.5 s, raised by
     per-hook timeouts up to 60 s).
  8. **Matcher syntax**: Claude Code treats letters, digits, `_`, `-`, spaces,
     `,` and `|` as an exact list; the product's exact class is only
     `[A-Za-z0-9_|]` (`hooks.ts:400`), so `Edit, Write` or `general-purpose`
     become regular expressions. Matchers on `TaskCreated`, `TaskCompleted`,
     `TeammateIdle`, `WorktreeRemove` are honoured by the product but ignored
     by Claude Code (an imported hook then runs less often than at its
     source); matchers on `PreModelSwitch`, `PostModelSwitch`,
     `ElicitationResult` are refused; `InstructionsLoaded` and
     `DirectoryAdded` matchers mean load reasons / sources in Claude Code but
     paths in the product.
